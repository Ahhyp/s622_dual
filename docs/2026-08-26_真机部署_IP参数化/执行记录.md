## 4. 关键认知（记录在案）

1. **cmdT 与 update_rate 必须匹配**：cmdT 是"告诉控制器的指令周期"，控制器按它插值；
   实际下发间隔（1/update_rate）与 cmdT 不匹配 → 指令速度被虚高（10ms/1.6ms=6.25 倍）→ 控制器"速度超限"报警 + ServoJ 14。
2. **JTC 以轨迹 header.stamp 为起点**：TOTG 输出相对时间（从 0 起），header.stamp 必须清空；
   保留规划时刻 stamp → 短轨迹在规划→执行延迟后过期被拒。robotarm 未遇到是因为 demo 默认 50mm（轨迹长 ~1.7s > 延迟 ~1s）。
3. **启动不应改变机械臂状态**：Mode/RobotEnable 等调用不要放进 on_activate（launch 启动即生效，违背"只读验证"原则）。
4. **robotarm "久经验证"有盲区**：只验证过 50mm 长轨迹；20mm 短轨迹暴露了时间戳过期问题。
5. **用户现场观察**：生效因素可能不止 500Hz（也可能含"未强制切自动模式"）。
   证据：500Hz+Mode(0) 在场的那次已无 14（支持 500Hz）；但为严谨记录此候选，双臂验证时再确认。
