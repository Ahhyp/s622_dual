明白了，这次信息非常关键：**`wsl --status` 还能用，但 `wsl` 进不去**，这基本不是 WSL 服务完全挂死，而是 **WSL2 里的 Ubuntu/VM 在 colcon 编译时被压到假死**。

你这个编译现场很像典型的 **内存/CPU 并发过高**：

```text
[14/22 complete] [6 ongoing]
trajectory_retime_server
fairino_planning_ros
behaviortree_ros2
s622_bt_manager
fairino_hardware
yolov8_grasping
```

也就是说 colcon 同时跑了好几个包，而且每个 CMake 包内部还可能继续多线程编译。`colcon` 的默认并行 worker 数会按逻辑 CPU 数来，官方文档里 `--parallel-workers` 就是控制同时处理多少包；而 CMake 还可以用 `CMAKE_BUILD_PARALLEL_LEVEL` 控制包内部并发。([colcon.readthedocs.io][1]) ([cmake.org][2])

### 现在先救回来

在 **Windows PowerShell** 里先看发行版名字：

```powershell
wsl -l -v
```

假设名字是 `Ubuntu`，执行：

```powershell
wsl -t Ubuntu
```

如果你的名字不是 `Ubuntu`，用 `wsl -l -v` 里显示的那个名字替换。微软文档也说明，`wsl --shutdown` 会关掉所有 WSL2 发行版，`wsl --terminate <distroName>` 可以只终止一个正在运行的发行版。([微软学习][3])

如果 `wsl -t Ubuntu` 也卡，那就用：

```powershell
wsl --shutdown
```

然后重新进：

```powershell
wsl
```

### 进来后先查是不是 OOM

回到 Ubuntu 后跑：

```bash
free -h
df -h
dmesg -T | egrep -i "out of memory|oom|killed process|segfault|memory allocation|panic" | tail -80
```

如果你看到类似：

```text
Out of memory
Killed process
oom-killer
```

那就坐实了：**colcon 编译把 WSL2 内存打爆了**。

### 下次不要这样全速编译，先用保守版

在 `~/my_S622` 里重新编译时用这个：

```bash
cd ~/my_S622

export CMAKE_BUILD_PARALLEL_LEVEL=2
export MAKEFLAGS="-j2 -l2"
export NINJAFLAGS="-j2"

colcon build --merge-install --symlink-install \
  --executor sequential \
  --parallel-workers 1 \
  --cmake-args "-DPython3_EXECUTABLE=$(which python3)"
```

这个组合的意思是：

* `--executor sequential`：一次只构建一个包；
* `--parallel-workers 1`：包级别并发限制到 1；
* `CMAKE_BUILD_PARALLEL_LEVEL=2`：每个 CMake 包内部最多 2 个并发编译任务。

这会慢一点，但大概率不会把 WSL 打挂。等能稳定过，再尝试：

```bash
export CMAKE_BUILD_PARALLEL_LEVEL=4
colcon build --merge-install --symlink-install \
  --parallel-workers 2 \
  --cmake-args "-DPython3_EXECUTABLE=$(which python3)"
```

### 建议给 WSL2 限一下资源

在 Windows 里编辑：

```powershell
notepad $env:USERPROFILE\.wslconfig
```

写入类似这个，内存按你机器情况调：

```ini
[wsl2]
memory=8GB
processors=4
swap=8GB
```

保存后执行：

```powershell
wsl --shutdown
```

再重新进 WSL。`.wslconfig` 是 WSL2 的全局配置文件，可以控制 WSL2 VM 的内存、CPU、swap 等；微软文档也写了默认 memory 是 Windows 总内存的 50%，swap 是内存大小的 25% 左右。([微软学习][3])

如果你电脑是 **16GB 内存**，建议先用：

```ini
[wsl2]
memory=8GB
processors=4
swap=8GB
```

如果是 **32GB 内存**，可以用：

```ini
[wsl2]
memory=16GB
processors=6
swap=16GB
```

### 如果上一次中途挂了，最好清一下构建产物

因为你用了 `--merge-install`，中断后 `install/` 可能处于半写入状态。最稳的做法是：

```bash
cd ~/my_S622
rm -rf build install log
```

然后用保守版命令重新编译。

你这个情况我优先判断是：**colcon 并发 + CMake 内部并发 + WSL2 内存/swap 不够，导致 Ubuntu 假死，新 wsl 连接超时，但 WSL 管理命令仍然能回应。**
不是你的 ROS 包“玄学炸了”，也不一定是 WSL 安装坏了。
