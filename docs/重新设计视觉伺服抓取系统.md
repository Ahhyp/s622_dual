## 1. 新架构总体解释

新架构是：

```text
粗定位 MoveIt
+ 图像空间 XY 闭环
+ OBB yaw 闭环
+ 下降阶段小幅视觉反馈
+ 抓取后验证
```

核心变化：

```text
target_base 不再是抓取真值。
target_base 只用于 MoveIt 粗略移动到目标附近。
真正抓取前，必须用实时 YOLO OBB 像素误差闭环修正 gripper。
```

对于你现在的 Gazebo 固定外部相机，我建议默认误差不要写成：

```text
error_u = target.center_x - image_center_x
error_v = target.center_y - image_center_y
```

因为固定外部相机下，物体静止时，机械臂移动不会改变物体像素位置。更合理的是：

```text
error_u = YOLO_target_u - project(grasp_frame)_u
error_v = YOLO_target_v - project(grasp_frame)_v
```

也就是让：

```text
物体中心像素
```

闭环对齐：

```text
当前 /grasp_frame 在相机图像里的投影像素
```

这样机械臂移动会改变 `/grasp_frame` 投影点，误差才是可控的。

完整代码里默认参数是：

```text
visual_reference_mode: ee_projection
```

也保留了：

```text
visual_reference_mode: image_center
```

但这个模式更适合 eye-in-hand 相机，或者你已经把 gripper 投影点标定成固定像素的特殊情况。

## 2. 新状态机设计

状态机改成：

```text
IDLE
→ DETECTING
→ COARSE_PLANNING
→ MOVING_TO_PREGRASP
→ VISUAL_ALIGN_XY
→ VISUAL_ALIGN_YAW
→ DESCEND_WITH_FEEDBACK
→ GRASPING
→ LIFTING
→ VERIFY_GRASP
→ DONE / FAILED
```

旧逻辑里的：

```text
APPROACHING / DESCENDING 使用 locked target_base 做 3D 误差控制
```

被替换为：

```text
MoveIt 只粗到 pregrasp；
pregrasp 之后进入图像闭环；
DESCEND 阶段也只允许小幅 XY 视觉修正。
```

## 3. 每个状态的进入、退出、失败条件

| 状态                    | 进入条件                             | 退出条件                                  | 失败条件                                                   |
| ----------------------- | ------------------------------------ | ----------------------------------------- | ---------------------------------------------------------- |
| `IDLE`                  | 节点启动或 trigger false             | 收到 `/servo_trigger=True`                | 无                                                         |
| `DETECTING`             | trigger 后进入                       | 连续 `stable_detection_frames` 帧检测稳定 | 超过 `detecting_timeout`；检测无效；目标靠边；OBB 尺寸异常 |
| `COARSE_PLANNING`       | 稳定检测后，计算 rough `target_base` | 启动 MoveIt 粗规划                        | rough depth/TF 失败；IK 不可达                             |
| `MOVING_TO_PREGRASP`    | MoveIt 开始执行 pregrasp             | MoveIt 到达 pregrasp                      | MoveIt 失败或超时                                          |
| `VISUAL_ALIGN_XY`       | 到达粗 pregrasp                      | 像素误差连续稳定小于阈值                  | YOLO 长时间不可见；对齐超时                                |
| `VISUAL_ALIGN_YAW`      | XY 对齐完成                          | yaw 误差连续稳定小于阈值                  | yaw 对齐超时                                               |
| `DESCEND_WITH_FEEDBACK` | yaw 对齐完成                         | 到达 `grasp_goal_z`                       | 下降超时；目标丢失超过策略允许时间                         |
| `GRASPING`              | 到达抓取高度                         | 夹爪闭合等待完成                          | 一般不失败，除非接口异常                                   |
| `LIFTING`               | 夹爪闭合完成                         | 抬升到 `lift_goal_z`                      | 抬升超时                                                   |
| `VERIFY_GRASP`          | 抬升完成                             | 验证成功                                  | 验证超时                                                   |
| `DONE`                  | 抓取完成                             | trigger false 或新 trigger                | 无                                                         |
| `FAILED`                | 任意失败条件触发                     | trigger false 或新 trigger                | 无                                                         |

## 6. 图像误差到 base/ee 小位移的控制方法

默认固定外部相机模式：

```text
target_uv = YOLO OBB center
ref_uv    = project(/grasp_frame)
error_uv  = target_uv - ref_uv
```

控制律：

```text
delta_xy = visual_align_gain * J_img_to_base * error_uv
delta_xy = limit_norm(delta_xy, visual_align_max_step)
v_xy     = delta_xy / dt
v_xy     = limit_norm(v_xy, visual_align_max_vel)
```

下降阶段使用更保守的参数：

```text
delta_xy = descend_xy_gain * J_img_to_base * error_uv
delta_xy = limit_norm(delta_xy, descend_xy_max_step)
v_xy     = limit_norm(delta_xy / dt, descend_xy_max_vel)
```

这样有几个好处：

```text
1. pixel_to_base 的误差不会直接决定最终抓取点。
2. J 不需要特别准，只要方向大致对，闭环就能收敛。
3. 每周期小步修正，避免一次大幅横移。
4. 下降阶段自动降低横向修正幅度，避免撞物体或夹爪扫飞目标。
```

## 7. 是否需要标定 J_img_to_base

需要。

但它不需要像 hand-eye calibration 那么精确。它只是一个局部经验雅可比：

```text
像素误差变化方向
→ base_link XY 小位移方向
```

你至少要确认：

```text
du 正方向时，机械臂应该往 base x/y 哪个方向移动
dv 正方向时，机械臂应该往 base x/y 哪个方向移动
```

如果符号错了，闭环会发散；如果比例不准，只是收敛慢或振荡。

初始可以先用保守矩阵：

```yaml
j_img_to_base: [0.00020, 0.0,
                0.0, 0.00020]
visual_align_gain: 0.3
visual_align_max_vel: 0.02
```

然后根据日志调整符号和比例。

## 8. 在线微调或手动标定方法

### 方法 A：手动符号标定

把 gripper 放到目标附近，观察日志：

```text
[VISUAL_ALIGN_XY] e_uv=(+du,+dv)
```

然后手动让机械臂小幅移动：

```text
base +x 方向 5 mm
base +y 方向 5 mm
```

观察 `/grasp_frame` 投影像素怎么变。

得到近似关系：

```text
A = d(ref_uv) / d(base_xy)
```

然后：

```text
J_img_to_base ≈ inverse(A)
```

如果不想矩阵求逆，直接经验调：

```yaml
j_img_to_base:
  [du 对 dx 的影响, dv 对 dx 的影响,
   du 对 dy 的影响, dv 对 dy 的影响]
```

### 方法 B：在线微调

可以加一个 calibration service，自动做：

```text
1. 记录当前 /grasp_frame 投影 ref_uv_0
2. 命令 base +x 小移动，例如 5 mm
3. 记录 ref_uv_x
4. 回到原位
5. 命令 base +y 小移动，例如 5 mm
6. 记录 ref_uv_y
7. 计算 A
8. J = inverse(A)
```

伪代码：

```python
def calibrate_jacobian():
    p0 = lookup_ee_in_base()
    uv0 = project(p0)

    move_relative(dx=0.005, dy=0.0)
    uv_x = project(lookup_ee_in_base())
    move_to(p0)

    move_relative(dx=0.0, dy=0.005)
    uv_y = project(lookup_ee_in_base())
    move_to(p0)

    A = [[(uv_x.u - uv0.u) / 0.005, (uv_y.u - uv0.u) / 0.005],
         [(uv_x.v - uv0.v) / 0.005, (uv_y.v - uv0.v) / 0.005]]

    J = inverse(A)
```

## 9. 关键函数伪代码

### DETECTING

```python
while state == DETECTING:
    det = get_fresh_yolo_obb()

    if det invalid:
        continue

    if same_as_previous(det):
        stable_count += 1
    else:
        stable_count = 1

    if stable_count >= N:
        locked_det = det
        rough_target_base = pixel_depth_tf(det.center)
        pregrasp = rough_target_base + hover_offset
        state = COARSE_PLANNING
```

### VISUAL_ALIGN_XY

```python
while state == VISUAL_ALIGN_XY:
    det = get_fresh_yolo_obb()

    target_uv = [det.center_x, det.center_y]

    if visual_reference_mode == "ee_projection":
        ref_uv = project_tf_point_to_image(/grasp_frame)
    else:
        ref_uv = desired_center_uv

    error_uv = target_uv - ref_uv

    if norm(error_uv) < pixel_tolerance for stable_frames:
        state = VISUAL_ALIGN_YAW

    delta_xy = gain * J_img_to_base @ error_uv
    delta_xy = clamp_step(delta_xy)
    publish_twist_xy(delta_xy / dt)
```

### VISUAL_ALIGN_YAW

```python
while state == VISUAL_ALIGN_YAW:
    det = get_fresh_yolo_obb()

    target_yaw = sign * det.angle + offset
    current_yaw = yaw_of(/grasp_frame in base_link)

    yaw_error = normalize(target_yaw - current_yaw)

    if yaw_pi_symmetry:
        yaw_error = normalize_to_half_pi(yaw_error)

    if abs(yaw_error) < yaw_tolerance for stable_frames:
        state = DESCEND_WITH_FEEDBACK

    publish_twist_wz(yaw_gain * yaw_error)
```

### DESCEND_WITH_FEEDBACK

```python
while state == DESCEND_WITH_FEEDBACK:
    if ee_z <= grasp_goal_z:
        state = GRASPING

    if target visible:
        error_uv = target_uv - ref_uv
        vxy = small_gain * J @ error_uv
        vz = -descend_speed

    else:
        if lost_short:
            vxy = 0
            vz = 0
        elif policy == continue_slow:
            vxy = 0
            vz = -descend_lost_speed
        elif policy == hold:
            vxy = 0
            vz = 0
        else:
            state = FAILED

    publish_twist(vxy, vz)
```

# 几个值得讨论的点：

1. j_img_to_base 是否需要标定
你现在默认 [0.00035, 0.0, 0.0, 0.00035]（0.35 mm/pixel）。实际上在 z≈1m、fx≈466 时，1 像素在相机系 ≈ 2.1mm，经 79° 倾斜 TF 变换到 base_link 的 XY 平面后约 2mm。0.35 mm/pixel 比物理值小 5-6 倍，但因为有 gain=0.45，实际有效的 mm/pixel ≈ 0.35×0.45/0.02 ≈ 7.9 mm/s per pixel。不会发散，但可能需要调。这个矩阵的最佳值可以从一次实验反算：让臂移动已知量，看像素变化。

2. VISUAL_ALIGN_XY 失败后没有重试
当前如果 visual_align_timeout 超时，直接 _fail 进入 FAILED。如果物体暂时被遮挡或 YOLO 短暂掉帧，更合理的做法也许是回到 DETECTING 重新锁定——但作为原型，先严格 fail 便于调试。

3. ee_projection 模式的参考点是 grasp_frame
_lookup_ee_pose_in_base() 查的是 grasp_frame。这意味着 VISUAL_ALIGN_XY 的终点是"grasp_frame 投影到物体的像素位置"。如果 grasp_frame 定义在两指中心，那对齐后夹爪正好在物体正上方——设计合理。

4. 盲降的 grasp_goal_z 来自 rough target
_compute_grasp_goal_z() 用的是 rough_target_base 的 z，而你的实验数据显示地面目标 z 极准（≤1cm），所以盲降终点 z 是可靠的。这正好利用了"z 准、y 偏"这个特点——把准的部分用来算高度，不准的部分交给图像伺服修正。

这个架构方向是对的。你想先跑起来测一下 VISUAL_ALIGN_XY 能不能收敛，还是有其他想讨论的？
