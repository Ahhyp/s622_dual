## 2. 现状分析（重复关系核查结果）

当前 `src/` 共 21 个包，存在三组重复/半重复：

### 2.1 `fairino_description` ↔ `s622_moveit_descriptions`（半重复）

| | `fairino_description` | `s622_moveit_descriptions` |
|---|---|---|
| 内容 | 厂商原件：7 款机型（fairino3/5/10/16/20/30/3_mt），纯 `.urdf` + STL | 项目定制：只有 S622，xacro 化，带夹爪、带相机、带 `prefix` 参数 |
| 夹爪 | ❌ | ✅ |
| 前缀支持 | ❌ | ✅（双臂依赖） |
| 消费方 | 仅 `fairino3_v6_moveit2_config` | `gz_launch` 全部 s622 launch + `s622_moveit_config` |

**结论**：`fairino3_v6` 就是 S622 的底子（DH 参数一致，见 `docs/机械臂参数.md`）。`fairino_description` 是厂商原件备份，模型本体已被 `s622_moveit_descriptions` 定制版完全覆盖。

### 2.2 `fairino3_v6_moveit2_config` ↔ `s622_moveit_config`（高重复）

两者是 MoveIt Setup Assistant 输出的同构包（config/launch 文件名一一对应），差异：

- group 名：`fairino3_v6_group` vs `robot_arm` / `robot_arm_tip`
- 夹爪：fairino3_v6 版无 finger；s622 版有
- 附加能力：s622 版多出全套双臂配置（`s622_dual_arm.*`、`dual_arm_*.yaml`）、servo 配置、`ompl_planning.yaml`
- kinematics 参数本体一致（仅 group 名和搜索超时不同）

**额外发现**：`gz_launch/launch/gazebo.launch.py`（用 fairino3_v6 系）是一个**无人引用的孤儿影子 launch**——CLAUDE.md 主命令是 `ros2 launch gz_launch s622_gazebo.launch.py`，visual_servo 的标定脚本里写的也是 `s622_gazebo.launch.py`（此前 grep 命中的是子串误匹配）。`robot_gazebo.friction.urdf.xacro` 中 fairino3_v6 的引用已全部注释。

### 2.3 `yolov8_grasping` ↔ `visual_servo` + `yolov8_obb`（目标重复，路线相悖）

| | `yolov8_grasping` | `visual_servo` + `yolov8_obb`（自写主力） |
|---|---|---|
| 路线 | 开环：OBB 像素 + 深度 → `PoseEstimator` 反投影 → 3D 位姿 → MoveIt 一次规划执行 | 闭环：2D 图像空间 IBVS 伺服状态机（锁目标、盲降、视觉对齐） |
| 依赖 | `fairino3_v6_moveit2_config`（demo launch 引用） | `s622_moveit_config` + `s622_bt_manager` |
| 结论依据 | — | `docs/AI_CONTEXT.md` 第 7 节已验证：YOLO 像素→base 误差 25-40mm，**3D 盲降不可靠，2D 图像空间伺服才是正确方案** |

**结论**：`yolov8_grasping` 的"像素→3D 位姿→盲降"路线与项目已验证结论相悖；检测消息格式已被自写 `yolov8_obb` 覆盖。

### 2.4 `manipulation_common`（值得保留，待并入）

- 独立 ament_python 包，**零运行时依赖**（对 gazebo_launch / yolov8_grasping 的引用均为注释里的兼容说明）
- 提供通用能力：`MoveItMotion`（运动执行封装）、`detection_cache`（检测缓存）、`target_selector`（目标选择）、`abort_manager`（急停/取消）、`keepout_manager`（禁入区）、`pose_tools` / `tf_tools`
- 与其他包无重复，是 fairino_robotarm-main 体系里值得吸收的基础设施

## 3. 重构原则

1. **不动任何包名**——`$(find ...)`、launch 引用、文档均按包名解析，改名牵一发动全身
2. **不照搬 fairino_robotarm-main 的分层元包结构**——当前 21 个包（清理后约 18 个）没有聚合需求，嵌套是它的组织方式，不是我们的
3. **只做"删除 + 归档 + 顶层整理"**，不做架构级重构
4. **归档用 `COLCON_IGNORE` 软删除**——比 `rm -rf` 安全，随时可恢复
5. **主路径（s622 生态）零改动**——所有改动不得影响 `s622_gazebo.launch.py` 等主 launch 的启动

> `COLCON_IGNORE` 机制：在目录中放置空文件 `COLCON_IGNORE`，colcon 构建时跳过该目录（不编译、不报错、不装进 install）。相当于"软删除"，随时移除该文件即可恢复构建。

## 6. 验收标准

Phase A 完成后必须通过：

1. `colcon build --merge-install --symlink-install --cmake-args "-DPython3_EXECUTABLE=$(which python3)"` 成功，且 install 中无 fairino3_v6_moveit2_config / fairino_description / yolov8_grasping 的产物
2. `ros2 launch gz_launch s622_gazebo.launch.py` 正常启动（仿真主路径不受影响）
3. `ros2 pkg list | grep -E "fairino3_v6|fairino_description|yolov8_grasping"` 为空（或 archive 内的包不可见）
4. `ros2 launch gz_launch s622_dual_arm.launch.py` 正常启动（双臂路径不受影响）
5. `git status` 中删除/归档的包有迹可循（git 历史可回滚）

## 7. 风险与回滚

| 风险 | 等级 | 应对 |
|---|---|---|
| 误删有价值代码（yolov8_grasping 未提交改动） | 中 | A4 归档而非删除，先审查未提交改动 |
| fairino_description 被某处引用遗漏 | 低 | A3 前再做一次全量 grep；归档不删除，可随时恢复 |
| 主 launch 受影响 | 低 | 全部动作不触碰 `s622_*` 包；验收标准强制跑主 launch |
| archive 目录被 colcon 意外编译 | 低 | `COLCON_IGNORE` 是官方机制，双保险：archive 目录下每个包子目录各放一个 |

**回滚**：所有删除项均有 git 历史（`git checkout` 恢复）或归档副本（移回 `src/` 即可）。
