## S1：FairinoIKPlugin / FairinoPlannerManager 双臂识别（C++ 小改）

### 问题
双臂 tip 是 `left_grasp_frame` / `right_grasp_frame`，group 是 `left_arm` / `right_arm`，现有代码只认精确名 `grasp_frame` / `robot_arm` → 工具模型判定落到 **FLANGE**（工具偏移 0.1168 丢失 → IK 全错）。

### 改动

**`src/fairino_planning_ros/src/fairino_ik_plugin.cpp`** — `resolveToolModel()`（约 331 行）
```cpp
// 夹爪相关的名称
if (tip_frame == "gripper_tool_link" ||
    tip_frame == "grasp_frame" ||
    tip_frame == "tool_link" ||
    tip_frame == "ee_tool_link" ||
    // ★ 双臂支持：left_grasp_frame / right_grasp_frame
    tip_frame.ends_with("_grasp_frame")) {
    return ToolModel::GRIPPER;
}
```
- `ends_with` C++20；若编译标准低于 C++20，改用 `tip_frame.size() >= 13 && tip_frame.compare(tip_frame.size()-13, 13, "_grasp_frame") == 0`

**`src/fairino_planning_ros/src/fairino_planner_manager.cpp`** — `resolveToolModelFromGroupName()`（约 25 行）
```cpp
if (group_name == "robot_arm" ||
    group_name == "left_arm" ||      // ★ 双臂支持
    group_name == "right_arm" ||     // ★ 双臂支持
    group_name == "gripper_arm" ||
    group_name.find("gripper") != std::string::npos) {
    return ToolModel::GRIPPER;
}
```

**`src/fairino_planning_ros/src/fairino_ik_plugin.cpp`** — tool/URDF check（约 258 行）
- `getLinkModel("grasp_frame")` 在双臂 URDF 里不存在 → check 跳过（WARN）。改为遍历 `left_grasp_frame` / `right_grasp_frame`（存在才 check），或保持 skip 也行（check 只是诊断，不影响求解）。**倾向：最小改动，check 保持 skip 并改日志为 info 级说明双臂跳过**。

### 构建
```bash
colcon build --packages-select fairino_planning_ros --merge-install --symlink-install
```

### 验证（V1）
- 单臂回归：重启单臂仿真，确认 `Fairino IK tool/URDF check ok` + IK 仍成功（不受 ends_with 影响）
- 双臂 IK 单测：本地 C++ 复现 `resolveToolModel("left_grasp_frame")` → GRIPTER（或直接看双臂 move_group 日志）

## 风险与回滚

| 风险 | 等级 | 应对 |

| FairinoIKPlugin 源码偏离 robotarm | 中 | 只加 ends_with/组名识别，不改算法；git diff 记录 |

| RViz 双臂面板 | 低 | 对齐单臂 .rviz 配置经验（namespaced 单路径，防振荡） |

**回滚**：git 历史；双臂 launch 一行改回单 move_group。
