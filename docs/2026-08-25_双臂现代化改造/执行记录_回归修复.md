## 回归 1：SetGripper 走 fairino 管线失败（已修复）

### 现象
BT 第一步 `<SetGripper open>` 失败 → Recovery → 整体 FAILURE。
日志：`group_name=left_hand, selected_planner=birrt*` → `BiRRT*: start configuration in collision`。

### 根因
规划管线统一后 move_group 默认管线=fairino。gripper_service 的 `moveit2_gripper` 未设 pipeline_id
→ 夹爪（2 关节 left_hand 组）走 BiRRT*（6-DOF 机械臂算法）→ 不可用。
**robotarm 标准做法**：gripper 客户端一律 `pipeline_id='ompl'`（fairino_pose_control_server.py:119 同款）。

### 修复
`gripper_service.py`：`self.moveit2_gripper.pipeline_id = 'ompl'`（单臂/双臂统一生效）

### 验证
✅ 修复后 SetGripper open 成功（日志 `Using planning pipeline 'ompl'` + `left_hand_controller Goal reached`）

## 回归 2：双臂 IK 目标 frame 错位（已修复）

### 现象
BT 推进到 MoveToPose pregrasp 失败。日志：
```
MoveToPose: sending goal xyz (-0.2740, -0.2915, 0.1600)   ← left_base_link 系
FairinoIKPlugin: target=pos=[0.6240, 0.2915, 0.1600]       ← world 系（yaw=π 镜像+偏移）
stage_survival: failure={category=GeometryUnreachable, stage=D_domain}
```

### 根因
MoveIt Humble 把 ik_pose 转到 **model root frame**（双臂 URDF root=world）再传给 IK 插件
（符号 `setToIKSolverFrame` 证实）。单臂 root=base_link 与 DH 假设一致所以一直正常；
**双臂 root=world ≠ left_base_link，DH 模型收到 world 系坐标 → 几何不可达**。
KDL 能解是因为它理解完整 URDF 链。

### 修复
`fairino_ik_plugin.cpp`：
- 新增 `robot_model_` / `root_is_base_` / `base_to_root_` 成员
- initialize：检测 `root_name != base_frame_` 时，沿 base link 固定关节链累乘
  求 `base_in_root`，存 `base_to_root_ = base_in_root.inverse()`
- solveIK：`T_target = base_to_root_.matrix() * poseToEigen(ik_pose)`（仅双臂时）
- 单臂 root==base 免转换，行为不变

### 待验证
- [ ] 重启仿真后 BT 全流程（pick_place_dual）通过
- [ ] 单臂仿真不受影响（root_is_base_=true 路径）

## 结论
两次回归都是"规划管线统一/双臂现代化"的**边界条件遗漏**，不是 BT/接口层问题：
1. 夹爪组必须 ompl（fairino 只支持机械臂 6-DOF）
2. IK 插件需处理 root≠base 的 frame 转换（双臂特有）
