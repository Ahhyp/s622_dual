### 2.3 关键代码事实（已核实）

- `move_to_pose_server.py`（C2 后）：`move_group_namespace="/move_group_fairino"` **硬编码**（第 92 行），`pipeline_id="ompl"` 也硬编码（第 94 行）→ 双臂下连不上/用错管线
- `gripper_service.py`（C2 后）：同样硬编码 `/move_group_fairino`；`group_name='robot_arm'`/`'hand'` 硬编码 → 双臂应为 `left_arm`/`left_hand` 等
- `dual_move_server.py`：自写 GetMotionPlan 调用（根级 `/plan_kinematic_path`）+ `_split_trajectory` 拆分 12→6+6 + 双 controller 并行执行；`pipeline_id='ompl'` 参数化但默认 ompl
- `dual_arm_kinematics.yaml`：left_arm/right_arm 均 KDL
- `s622_dual_arm.srdf`：已定义 left_arm/right_arm/left_hand/right_hand/dual_arm 组 + dual_home/dual_handover_ready 组态
- `FairinoIKPlugin::resolveToolModel`（fairino_ik_plugin.cpp:331）：tip_frame 精确匹配 `"grasp_frame"` → GRIPPER；双臂 `left_grasp_frame` 不匹配 → 默认 FLANGE（**工具偏移丢失**）
- `resolveToolModelFromGroupName`（fairino_planner_manager.cpp:25）：只认 `robot_arm`/含 `gripper` → `left_arm`/`right_arm` 会落到 FLANGE
- MoveItMotion `arm_clients` 是 dict（`{"fairino": ...}`），`set_ik`/`set_planner` 遍历所有 client——多臂基础在
- MoveItMotion `move_to_joints` 走 `plan_async(joint_positions)` → 对 dual_arm 组 12 关节理论上可行，但**执行**走 `moveit2.execute()`（单 controller 语义），dual 联合需要拆分——MoveItMotion 无拆分能力

## 3. 方案设计（待确认）

### 3.1 决策点 A：双臂 move_group 架构

**方案 A1：单 move_group 实例 + fairino 管线（最小改动）**
- 保持单 move_group（根级），但：
  - `pipelines=["fairino","ompl"]`，默认 fairino
  - 注入 planning_core + 4 算法 + ik_core 参数（同单臂）
  - kinematics 注入 left_arm/right_arm 用 FairinoIKPlugin（需 D8 支持）
- 优点：改动小，dual_arm 组规划照旧；缺点：无双 IK 对比（单臂有 fairino/kdl 双实例是历史产物）

**方案 A2：namespaced 双 move_group（完全对齐单臂）**
- `/move_group_fairino`（left/right 用 FairinoIKPlugin）+ `/move_group_kdl`（KDL），服务 namespaced
- arm_actions 用 `move_group_namespace` 连接（D3 参数化后天然支持）
- 优点：与单臂架构一致，可用 KDL 兜底；缺点：改动较大，dual_arm 12-DOF 组在两个实例都注册

**倾向**：**A2**（与单臂完全对齐，D3 参数化后客户端无感切换；双臂也获得 IK 兜底能力）

### 3.2 决策点 B：dual_move_server 改造

**方案 B1：保留自写 server，内部换 MoveIt2/MoveItMotion 规划**
- dual_move_server 保留"12-DOF 规划 + 拆分 + 双 controller 执行"骨架（这是 MoveItMotion 没有的能力）
- 规划段：GetMotionPlan 调用改为 namespaced（`/move_group_fairino/plan_kinematic_path`）+ pipeline=fairino
- 或内部构造 `MoveIt2(group_name='dual_arm', joint_names=12, move_group_namespace=...)` 用 `plan_async`，保留拆分执行

**方案 B2：MoveItMotion 包办**（需验证 12-DOF 执行可行性）
- MoveItMotion.move_to_joints 12 关节 + 执行 → 需要 moveit_controllers.yaml 有 dual_arm 的 controller 映射（目前没有）
- 或 MoveIt2 的 execute 走 move_group execute_trajectory（12-DOF 无 controller）→ **不可行**，除非加 dual controller

**倾向**：**B1**（保留拆分执行，规划层换 namespaced + fairino；MoveItMotion 用于单臂子动作）

### 3.3 决策点 C：FairinoIKPlugin 双臂支持（D8）

- `resolveToolModel`：精确匹配扩展为 `tip_frame == "grasp_frame" || ends_with("_grasp_frame")` → GRIPPER
- `resolveToolModelFromGroupName`：`group_name.find("arm") != npos && group_name != "dual_arm"` → GRIPPER（或显式列 left_arm/right_arm）
- 这是 fairino_planning_ros 源码小改，与 robotarm diff 会偏离（需记录在案）

### 3.4 决策点 D：arm_actions 参数化（D3）

- `move_to_pose_server.py` / `gripper_service.py` 加 `move_group_namespace` 参数（默认 `/move_group_fairino` 保持单臂兼容），group_name 从 config 读（已有）
- `arm_actions_dual.launch.py`：left/right 实例传对应 namespace；去掉根级 remap（namespaced 客户端直连）

### 3.5 决策点 E：retime / RViz（D6/D7）

- 双臂 launch 接入 retime_server（同单臂，use_sim_time=true）
- dual_arm.rviz 配 Move Group Namespace（A2 时）
