## 8. 卡点状态（2026-09-10 晚：已关闭）

> 历史两次诊断的更正轨迹：原判"pads 只夹到边缘、差 5~15mm 居中"（§8 旧文）→ 被 §7.17 推翻（几何上指板就在杆的截面位置上）
> → §7.18 重启对照证明穿透是系统行为 → **§7.19 定位根因并修复**。

**根因**：`SetGripper close` 把指关节目标设成 `close_positions=(0,0)`，位置控制器合爪后**继续往 0 压**
（指关节 effort=150N vs 杆 0.03kg）→ 指板缓慢穿入物体（30mm 杆几分钟内被压到 5mm），
"握持"退化成穿透楔持 → 46s~1min 滑脱，且 `f1` 被压到 0.0026 使判据失效。

**修法（已验证）**：合爪后追加一次 hand controller 保持轨迹，目标 = **实测停位 − 1mm**（而非 0/0）。

**修法后的完整结果（rodV7）**
```
L pick  → f1=+0.01552, 真实间隙 29.8mm        （真咬合）
L rise  → rod=(0.0404,0.0001,0.3393) flat
R→PRE   → 扰动 0.36mm / 2.54°      R→RECEIVE → 扰动 0.06mm / 0.4°
R close → 停位保持 → settled f1=+0.01474  ← 落进 [0.010,0.020]
        真实指板间隙 R=27.6mm / L=29.9mm      （真咬合, 30mm 杆）
Transfer → True        L open → R 单持 (Rgap=28.7mm)
耐久 → 400s 观测全程未脱落, 杆自行回正; 7 分钟后 Rgap=29.7mm, R f1=+0.01352
```
对照：修法前同流程 R 单持仅 46s 落桌。

**下一步（已无阻塞项，按规划推进）**
1. 把"停位保持"生产化：改 `gripper_service`（`close_positions` 语义 / force-limited close），使 BT 侧无需额外调用。

## 9. 本轮新增的关键实测结论（已归档 §7.13~§7.16）

1. **执行层**：MoveToPose 直线上升/servo lift 会掉杆 → 抬升必须 ompl 关节空间；servo descend 是拾取唯一低 z 手段。
2. **夹持**：深 descend（TCP 低于物顶）+ μ 提升 + 质量/惯量匹配是长保持的前提（惯量忘缩放会导致 rod 动力学异常）。
3. **传递零扰动三件套**：margin 盒（δ=10mm）+ LEFT-touch 分阶段 + **接近前必须开爪**。
4. **R 区 IK 不可用**：pose-goal 99999 / MoveToPose False → 关节解靠雅可比搜索或关节插值。
5. **验证纪律**：RTF≈0.25 时 close 需 ~16s 墙钟，必须 **settle 30s+ 再读 f1**，否则出现假阳性 GRASPED。
