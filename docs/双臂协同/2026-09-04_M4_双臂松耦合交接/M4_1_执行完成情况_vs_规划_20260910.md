## 8. 当前唯一技术卡点与下一步

> ⚠️ **2026-09-10 更新（见 M4_0 §7.17）：本节原诊断已被推翻。**
> 原判"pads 只夹到边缘、差 5~15mm 居中"不成立——经 `/compute_fk` 离线几何 + Gazebo link 真值核实，
> R 指板**就在杆的截面位置**上，问题是**指板-物体接触是穿透式的**（30mm 杆被夹到 5~6mm 间隙而不被顶住），
> 所以 `f1` 在本 sim 会话不是有效咬合度量，`f1∈[0.010,0.020]` 这一门控会把成功的姿态判成失败。

**已完成的链路（`tmp/m4_round/ho_verify.py`，rodV3/rodV4，2026-09-10）**
```
L pick(f1=0.0161±0.0005) → ompl rise(rod ≈ 0.0417,−0.0005,0.3398) → margin attach(LEFT-only)
→ R open → R→PRE(扰动 ≤0.35mm) → exact dual attach → R→RECEIVE(扰动 ≤0.03mm)
→ R close(settled f1≈0.0025, 真实指板间隙 4.6~5.3mm) → Transfer=True → L open
→ 杆悬空由 R 单独承托（L 指板 48mm）→ 46s~1min 后滑脱落地
```
即：**流程全部跑通且可复现（重启前后各一次对照一致），握持不成立**（穿透楔持，分钟级失效）。
详见 M4_0 §7.17 / §7.18（含重启对照表）。

**真正的卡点**：本 sim 会话的夹爪-物体接触/驱动不可信——
1. 指板可穿透 30mm 杆到 5~6mm 间隙（接触太软 / 位置控制持续压入）；
2. 同一进程内 R 的 open/close 会间歇性完全不响应（与 §7.7 finger infra bug 同源，会话性）；
3. 后果：所有"抓稳/掉不掉"的历史结论（含"L 稳定保持 >5min"）都需要在可信会话下复验。

**下一步（按优先级）**
1. **先解决夹爪可信度**（否则后续任何指标都无意义）：
   查 gz 接触刚度/`min_depth`、指关节 effort 与位置控制、finger collision 是否真参与；
   或加"可信性自检门"：抓取后命令张开，物应落 → 不落即判 sim 异常，本会话作废（必要时重启双臂仿真，§7.7c 经验）。
2. 判据替换：`f1 ∈ [0.010,0.020]` → **行为判据**（Transfer→L open→N 秒后杆是否仍由 R 承托）+ **几何判据**（link 真值算指板间隙 ≈ 30mm）。
3. receive_pose 已由 FK 反解确定：grasp=(0.0524,−0.054,0.339)，`R_RECEIVE=[0.2761,−1.3157,−1.6776,−3.3161,−1.2915,−1.5708]`（零扰动实测成立）。
4. 之后才是 BT 回填（`GenerateHandoverCandidate`、`config/m4_handover.yaml`、`pick_handover_place.xml` 改造、Retreat/Recovery）与 T4~T7 统计。

## 9. 本轮新增的关键实测结论（已归档 §7.13~§7.16）

1. **执行层**：MoveToPose 直线上升/servo lift 会掉杆 → 抬升必须 ompl 关节空间；servo descend 是拾取唯一低 z 手段。
2. **夹持**：深 descend（TCP 低于物顶）+ μ 提升 + 质量/惯量匹配是长保持的前提（惯量忘缩放会导致 rod 动力学异常）。
3. **传递零扰动三件套**：margin 盒（δ=10mm）+ LEFT-touch 分阶段 + **接近前必须开爪**。
4. **R 区 IK 不可用**：pose-goal 99999 / MoveToPose False → 关节解靠雅可比搜索或关节插值。
5. **验证纪律**：RTF≈0.25 时 close 需 ~16s 墙钟，必须 **settle 30s+ 再读 f1**，否则出现假阳性 GRASPED。
