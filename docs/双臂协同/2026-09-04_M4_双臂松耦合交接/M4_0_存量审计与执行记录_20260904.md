**D. 🚨 根因纠正：本 sim 会话的"咬合"是穿透式的，f1 不可信**
- 指板能把 30mm 杆"夹"到 **5~6mm 间隙**（穿透 ~25mm）而不被顶住 → 力/接触是软的，位置控制持续压入。
- 直接证据（诊断实验）：
  1. 命令 `left open`（实测指板张到 **43.6~48mm**，远超杆 30mm）后，杆**仍悬空不落**；
  2. 再命令 `right open`，杆 **5s 内落桌**（z 0.34→0.015）→ 证明物体确实被"咬在"R 的指板几何里（渗透楔持），不是接触；
  3. 同一进程内 R 的 open/close 有一次完全不响应（间隙停在 ~36mm），另一次响应 → 与本项目 §7.7 记录的 finger 关节 infra bug 同源（会话性）。
- 因此：`settled f1 ∈ [0.010,0.020]` 这类判据在本 sim 会话**无效**（穿透把 f1 压到 0.0026~0.0034）；
  §7.16 的"pads 已接触杆但只夹到边缘 / 差 5~15mm 居中"是**误诊**——其实指板就在杆的截面位置上，只是没被顶住。
- 可用的替代判据（本轮已验证）：
  - 行为判据：`Transfer → L open → 杆是否仍由 R 承托`（本次：成立，但不耐久）；
  - 几何判据：从 Gazebo link 真值算指板间隙（`|p_f1 − p_f2| − 20.2mm`），夹 30mm 杆应停 ~30mm。

**E. 本轮排掉的脚本/工具坑**

**F. 穿透的可能机理（供下一步排查，尚未验证）**
- 世界 SDF `dual_arm_world.sdf` **没有 `<physics>` 段**，gz-sim Fortress 默认引擎为 **dartsim**；
  场景里写的 `<friction><ode><mu>`（杆 μ=3.0、地面 100）在 DART 下由 gz-physics 的 SDF 解析器读取（可用），
  但 `<contact><ode><kp/kd/min_depth>` 一类**接触刚度参数 DART 不读** → 无法用 SDF 调接触硬度。
- 力/质量比极端：指关节 `effort=150N` 位置控制 vs 杆 `mass=0.03kg`（§7.13 原本为"保持稳定"把质量从 0.1 调低到 0.03）。
  高推力 + 轻物 + DART 默认求解器 ⇒ 指板持续压入物体会不断加深穿透，直到"楔住"。
- 可测的验证实验：① 物质量加大（0.3~0.5kg）看指板是否停在 ~30mm；② 降低指关节 effort/PID；③ 显式指定 `<physics>` 引擎并调参。

**G. 当前状态与下一步**

- 真正卡点已从"receive_pose 差几毫米"变成：**指板-物体接触是穿透式的，无法形成真实 30mm 咬合**。

### 7.19 🎯 根因确认 + 修法：穿透来自"合爪后继续压向 0"，保持停位即得真咬合（2026-09-10）

**假设**：`SetGripper close` 把指关节目标设成 `close_positions=(0,0)`（`gripper_service` 参数），
