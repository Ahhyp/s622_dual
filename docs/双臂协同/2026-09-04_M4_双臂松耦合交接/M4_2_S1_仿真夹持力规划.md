## 0. 为什么是 S1（并澄清上一轮的口径矛盾）

| 说法 | 对象 | 结论 |
|---|---|---|
| "真机没有力控接口 → 不做力控" | 把力控做成**业务层/接口层**能力（新 service 字段、BT 传力参数） | ✅ 仍然成立：会造成 sim/real 双路径 |
| "S1：仿真侧建模常值夹持力" | 把力放进**仿真被控对象模型**（plant model） | ✅ 可以做：真机的力本来就由气压硬件提供，仿真必须显式建模 |

**兼容性契约（本次实现的边界）**
1. 业务层不变：`SetGripper.srv` 仍是 `open|close`；BT/XML、MoveIt 夹爪规划语义不动。
2. 真机红线：真机启动时 close 命令恒为 `[0,0]`（`opening=0.5*(|f1|+|f2|) < 0.005`），
   绝不出现中间值（否则会被 `fairino_hardware` 判成 `OPEN`，见 §7.21）。
3. 默认零影响：所有新参数默认 `0.0`/关闭；**不传参数 = 与提交 `5f184fa` 完全一致的行为**。
4. 差异只写在仿真专用文件里；真机文件 `src/s622_moveit_config/config/s622_real_ros2_control.xacro` 不动。

## 1. 设计：真机物理 ↔ 仿真建模的对应关系

| 真机物理量 | 仿真建模 | 参数 |
|---|---|---|
| 螺丝限位（最小闭合间隙） | `close` 位置目标 = `±gap/2`（**已提交**，`close_stop_gap`） | `gripper_close_stop_gap` [m] |
| 调压阀气压 → 恒定夹持力 | 闭合期间向 finger 关节发布**常值 effort** | `gripper_clamp_effort` [N] |
| 开阀换向（张开） | `open`：effort 归零，位置目标 = `open_positions` | — |
| 无位置反馈（只有 0 / ±0.0305） | 仿真有真实 f1 反馈（**只用于仿真验证**，不能当真机判据） | — |

**数据流（仿真）**
```
SetGripper(close)
  └─ gripper_service
       (a) [现有] MoveIt 规划 hand 组 → ±gap/2  →  <arm>_hand_controller(JTC, position)
       (b) [新增] 发布常值 [−F, +F] → /<arm>/hand_effort_controller/commands (Float64MultiArray)
SetGripper(open)
  └─ (a) MoveIt → open_positions      (b) 发布 [0, 0]
```
> 符号：finger1 正方向为张开 → 夹持力为 **−F**；finger2 反号 → **+F**。最终以探针实测符号为准。

**为什么 (a)(b) 要配合**：`(a)` 保证 pads 停在螺丝限位（不爬行、不穿透）；`(b)` 提供不随位置误差消失的夹持力。
单独用 (a)：力=0（§7.21）；单独用 (b)：位置失控。

## 5. 风险与备选

| 风险 | 触发判据 | 备选 |
|---|---|---|
| **R1** position+effort 不能并存 | P0 探针第 1/3 条失败 | **Plan B**：finger 只留 `effort` 接口；仿真侧 `gripper_service` 的 close/open 直发 effort（`±F` / 反向小力），绕开 MoveIt 夹爪规划；真机仍走 MoveIt（参数默认关闭）。接口层仍不变 |
| **R2** 两个控制器时序抖动/抢占 | 探针第 3 条不稳定 | 降低 effort 发布频率（5~10Hz）、仅在闭合期间发布；必要时闭合后把 hand 组切到 effort-only |
| **R3** 夹持力把杆挤飞/穿模 | G1 或 G2 出现位移突跳 | 力值从 2N 起扫；必要时同时把 `close_stop_gap` 调到 ≈30mm（让位置伺服不参与夹持，只由力提供） |
| **R4** 后续真机接入 | — | 软件只需 open/close；力由调压阀设定。本文档记录该映射，真机代码本次不动 |

**Plan C（保底，不新增接口）**：`close_stop_gap` 停在实测停位后，按"受控压入 N mm"补偿（§7.19 已验证可撑 400s）。
不物理，仅作 R1/R2 都失败时的兜底，且必须在文档里标注为"非物理的仿真替代"。

## 9. P0 探针结果（2026-09-12）：S1-A 路线不成立，机制已定位

**探针用的注入方式**（比原规划更干净，无需装包/加控制器）：
gz 原生 `ignition-gazebo-apply-joint-force-system`（`gz::sim::systems::ApplyJointForce`），
在仿真专用 `s622_dual_arm_gazebo.urdf.xacro` 的模型级 `<gazebo>` 块挂 4 份（四个指关节），
订阅 `/model/s622_dual_arm/joint/<joint>/cmd_force`（`Double`），收到前完全惰性。
> 原规划的 `effort` 命令接口路线先被否掉：本机**没装** `ros-humble-effort-controllers`
> （`ros2_controllers` 未安装，只有 `gripper_controllers`/`joint_trajectory_controller`），
> 且该路线要动 ros2_control 描述 + 新增控制器；gz 插件路线则完全不碰 ros2_control。

**A/B 实测（每格都是独立仿真会话，`gripper_close_stop_gap:=0.029`）**

| 会话 | 插件 | 右指 f1/f2 对 open/close 的响应 | 指板间隙 |
|---|---|---|---|
| #1（插件开） | ✔ | **无响应**：f1 恒 ≈0、f2 恒 −0.0305 | 恒 30.29mm |
| #2（插件关） | ✘ | **正常**：open→f1=0.0249/f2=−0.0240；close→f1=0.0151/f2=−0.0154 | 48.8 → 30.2mm ✓ |
| #3（插件开，复现） | ✔ | **又无响应**：f1 恒 ≈0、f2 恒 −0.0305 | 恒 30.29mm |

插件本身**确实在发力**：会话 #3 里给 finger2 发 `+5N`，f2 立刻从 −0.0305 走到 **0.0**（指板闭合）✓。

**机理解释（与 gz 组件语义一致）**：gz-sim 里关节的 `JointForceCmd` 与
`JointVelocityCmd` 是**互斥**的力/速度控制二选一。gz_ros2_control 的 position 模式实际写的是
`JointVelocityCmd`（§7.21 的"速度∝误差"伺服）；一旦 `ApplyJointForce` 建立了
`JointForceCmd` 组件，该关节就变成**力控**，位置/速度伺服被旁路 → 表现为"手指冻结在限位上"。
⇒ **"位置伺服 + 关节力"不能并存**，S1-A（P1 的 position+effort 并存方案）**在机制上不成立**。

**附带发现（低置信度、待验证）**：§7.7 记录的"finger1 恒为 ≈0（下极限处）、对任何命令无响应"
与本次冻结**表征完全一致**（同样钉在下极限）。当年没有本插件，所以未必同因；但值得回看
是否存在"某个力/速度命令组件被占用"的共同根因。

## 10. 修订方案：Plan B「纯力控手指 = 气动模型」

既然关节只能二选一，就**把仿真的手指做成力控**——这其实更贴近气动夹爪的本质：
气压给恒力、螺丝给行程上限，没有位置伺服。

| 真机 | 仿真（Plan B） |
|---|---|
| 开/关阀 → 气压推动手指 | `close`：两指施加**闭合恒力** `F`；`open`：施加**张开恒力**（小） |
| 螺丝限制最小闭合间隙 | 关节**限位**（仿真专用 xacro 参数；共享描述里加参数，默认=真机无限位） |
| 无位置反馈 | 仿真有 f1/间隙，仅用于验证 |

**改动清单（在 P1 基础上调整）**
| # | 文件 | 改动 |
|---|---|---|
| 1 | `src/gz_launch/config/s622_dual_arm_gazebo.urdf.xacro` | 四个 finger 挂 `ApplyJointForce`（已写，参数 `gripper_force_plugins` 默认 **false**，Plan B 启用时置 true）；并透传"螺丝限位"xacro 参数 |
| 2 | `src/s622_moveit_descriptions/urdf/s622_moveit_descriptions.urdf.xacro` | finger 关节加 xacro 参数 `finger_stop_gap`（**默认 0 = 无限位 = 真机行为**）；仿真传 0.029 |
| 3 | `src/s622_arm_actions/s622_arm_actions/gripper_service.py` | 新增仿真分支：`finger_force_mode`（默认 false）+ `clamp_force`；true 时不走 MoveIt/JTC，直接发开/合力并等待（`SetGripper` 签名不变） |
| 4 | `src/s622_arm_actions/launch/arm_actions_dual.launch.py`、`src/gz_launch/launch/s622_dual_arm.launch.py` | 透传 `finger_force_mode` / `clamp_force`（默认 false/0） |
| 5 | 验证脚本 | 复用 `grip_force_probe.py`（改判据）、`ho_verify.py`、`carry_test.py` |

**Plan B 的验证判据（在 §4 的 G0/G4/G5 之外，G1~G3 照旧）**
- **PB1 手指可控**：`close` 后指板停在限位（≈29mm，±0.5mm）且不再继续挤入（5min 内变化 ≤0.3mm）；`open` 后回到开位。
- **PB2 力值扫描**：`F ∈ {2,5,10} N` 取满足 G1/G2 的最小值；若 10N 仍滑，回到 §5 风险表。
- **PB3 重复性**：同一力值连跑 3 次 `close→open`，指板停位重复性 ≤0.3mm。

**Plan B 的已知代价（需在文档与汇报里写清）**
1. 仿真的夹爪**内部路径**与真机不同（仿真=直发力；真机=MoveIt 计划 → JTC → 驱动阈值开阀）。
   业务接口（`SetGripper`）不变，但"仿真验证过 ≠ 真机路径验证过"。
2. 仿真里 MoveIt 的 hand 组不再驱动夹爪 → 相关规划路径在仿真中形同虚设（真机仍走）。
3. 力值/限位是**建模量**：真机的对应物是调压阀与螺丝，必须真机复验才能下结论。

**Plan C（保底）**：若 Plan B 也受阻，回到"停位 + 受控压入 N mm"（§7.19 已验证可撑 400s），
但必须标注为**非物理的仿真替代**。

**由此得到的可选解法（"对齐初始位与限位"两条路都已查证不可行）**

**（用户建议）让初始状态与螺丝位一致 —— 试了两种实现，都被否掉：**
1. **SDF 初始位置** ✗：`<joint><axis><initial_position>` 只存在于 SDF 1.7/1.8，schema 原文标注
   *"DEPRECATION WARNING: This tag has no known implementation... will be removed in SDFormat 1.9"*；
   本机世界为 SDF 1.9（`/usr/share/sdformat12/1.9/joint.sdf` 已无该元素）。
2. **关节弹簧（参考位=螺丝位，刚度=气压当量）** ✗ 作为"挡位"不成立：
   URDF→SDF 映射**可用**（已实测：`<gazebo reference="joint"><springStiffness>/<springReference>`

   其 effort 上限 150N，会把手指一路压到命令位（弹簧被压到底），**螺丝失效**。

**结论：螺丝只能做成"物理限位块"**（不与初始位冲突的硬约束）——
1. **物理限位块（S3，推荐）** —— 不改关节限位（初始位不违规 → 不会锁死），在指板行程上放一个静态挡块，

   就不会碰到杆。**这能完整保留 A'' 语义**（命令越界 + 机械挡位 = 持续夹持力）。
2. **回到 Plan C**：不限位，`close` 目标停在"实测停位 − squeeze"（§7.19 的 hold-at-stall，已验证可撑 400s；
   carry 跟随率 squeeze=1mm→45%、2.5mm→75% 量级）。无锁死风险，但夹持力来自缓慢挤压，属半物理近似。

## 12. S3（物理限位块）实测：同样被"初始状态"卡住 —— 并由此得出一条**结构性结论**（2026-09-12）

**S3 实现**（已落地，默认关闭）：sim-only xacro 给左右爪各加一个挡块 link（box：宽=`gripper_stop_gap`、
厚 0.020、高 0.016），固定于 `${prefix}wrist3_link` 的 z=0.196（= grasp 系 z≈−0.021，**在杆截面之后**，
含 13° 倾斜余量仍留 ~4mm）。已核实：URDF→SDF 转换把挡块 **lump 进 wrist3 的 collision**
（`left_wrist3_link_fixed_joint_lump__collision_collision_1`，size `0.028 0.02 0.016` ✓），即物理模型里确实有它。

**实测（`GRIPPER_STOP_BLOCK=1 GRIPPER_STOP_GAP=0.028 gripper_direct_close:=true`）**
```
控制器 5/5 active ✓; URDF 含 gripper_stop ✓
初始: 四指全 0 (gap −0.2mm) —— 物理没有把手指顶到挡块
left/right open -> False  (MoveIt 计划失败: 起始状态=手指与挡块互相穿模)
close -> True 但手指不动
```
**原因与 A''-限位**完全同源：模型"全闭合位"= 手指停在中心，而挡块必须占住这个中心区域才能挡住合拢
⇒ **起始状态落在挡块体积内**（互相穿模）→ MoveIt 判自碰撞（`open` 失败）、物理也不把它推开。

**由此得到一条结构性结论（本次三个方案都撞在同一点上）**
> 想要**稳定**的夹持力，需要二者之一：
> **(甲) 力源**（恒力，像气压）；或 **(乙) "硬限位 + 足够大的持续位置误差"**。
> 而 (乙) 要求硬限位离"模型静止位"足够远才能产生大误差；可模型的静止位就是"全闭合"，
> 限位/挡块只能落在它里面 → **必然与初始状态冲突**（限位→关节锁死；挡块→穿模+MoveIt 失败）。
> 结论：**这套"位置伺服 + 硬限位"的模型结构上无法产生稳定夹持力**，必须走 **(甲) 力源**。

**修订路线（推荐，证据最充分）—— Plan B′：纯力控手指（= 气动模型）**
- 复用**已验证可用**的 gz `ApplyJointForce`（P0 探针：给 finger2 发 +5N 立即使其从 −0.0305 走到 0 ✓）；
- 该插件会让关节变成**力控**（位置伺服被旁路）——在 S1-A 里这是"缺点"，在**纯力控模型里正是我们想要的**；
- `close` = 施加闭合恒力 `F`（每指），`open` = 施加张开力；**不需要位置伺服、不需要关节限位/挡块**
  ⇒ 初始状态问题自然消失（手指停在力平衡处，和真机一样）；
- 接口不变：仍是 `SetGripper(open|close)`；差异只在仿真侧（`finger_force_mode` + gz 插件）；
- 待实现/验证：`gripper_service` 增加力控分支（默认关闭）→ 力值扫描 `{2,5,10}N` → G1/G2/G3。

**留档**：S3 的挡块代码保留在 sim-only xacro（默认 `false`）——将来若改用"力控 + 行程上限"需要它。
