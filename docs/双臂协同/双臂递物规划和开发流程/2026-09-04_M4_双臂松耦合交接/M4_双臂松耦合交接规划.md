# M4 双臂长条物体交接详细规划

## 1. 阶段目标

M4 从 M2.7 baseline 后正式开始。目标不再定义为“左右臂到固定 `dual_handover_ready` 后交换物体”，而定义为：

> 建立 Attached-Object-Aware 的双臂递物系统，使右臂在左臂持有长条物体时能够把物体作为真实碰撞体参与规划，通过安全的 Pre-Handover → Approach → Grasp → Transfer → Separation 流程完成 Left-to-Right handover。

主流程调整为：

```text
Left Pick
→ Attach Long Object
→ Left Lift
→ Left Move To Handover Hold
→ Left Stable
→ Generate Right Receive Pose
→ Right Move To Receive Pre-Pose
→ Right Low-Speed Approach
→ Right Close
→ Verify Right Grasp
→ Transfer Object
→ Left Open
→ Left Retreat
→ Right Retreat
→ Success
```

M4 第一版不允许 Left 和 Right 同时向最终 handover 位姿运动。Left 先进入持物位姿并保持静止，Right 再接近。

最终要求：
$$
R_h=\frac{N_{\mathrm{handover\ success}}}{N_{\mathrm{valid\ handover\ attempts}}}\ge0.95,\qquad N=100
$$
同时要求：
$$
N_{\mathrm{object\ drop}}=0,\qquad N_{\mathrm{collision}}=0
$$

## 2. M4-P0：长条物体必须进入 PlanningScene

当前 M4 最优先任务不是 Right Grasp，也不是 Recovery，而是建立正确的 Attached Collision Object。

设真实长条尺寸为 $(L,W,H)$，PlanningScene 使用带安全余量的碰撞尺寸：
$$
L_c=L+2\delta,\qquad W_c=W+2\delta,\qquad H_c=H+2\delta
$$
初始建议 $\delta=5\sim10,\mathrm{mm}$，后续根据实际标定误差调整。

第一版继续使用 `SolidPrimitive.BOX`，暂时不引入 mesh。只有物体几何明显无法用 box 近似时再升级 mesh。

物体 Attach 后必须满足：
$$
{}^WT_O={}^WT_{G_L},{}^{G_L}T_O
$$
其中 $G_L$ 为 `left_grasp_frame`，$O$ 为长条物体 frame，${}^{G_L}T_O$ 必须包含完整位置和姿态，不能继续只使用 `offset_z`。

| 文件                                                        | 修改                                                                             |
| --------------------------------------------------------- | ------------------------------------------------------------------------------ |
| `s622_bt_manager/src/scene_nodes.cpp`                     | `AttachObjectNode` 支持完整 position + quaternion；`TransferObjectNode` 同样支持完整 Pose |

| `planning_scene_service.py`                               | 第一版原则上不改；继续复用已有完整 Pose Attach/Transfer                                         |

`AttachObject.srv` 和 `TransferObject.srv` 不需要修改。

### 3.1 `AttachObjectNode`

当前接口从：

```text
size_x
size_y
size_z
offset_z
```

升级为：

```text
size_x size_y size_z
pose_x pose_y pose_z
pose_qx pose_qy pose_qz pose_qw
```

即：

```xml
<AttachObject
    arm_prefix="left"
    object_name="handover_bar"
    size_x="{object_size_x}"
    size_y="{object_size_y}"
    size_z="{object_size_z}"
    pose_x="{left_object_x}"
    pose_y="{left_object_y}"
    pose_z="{left_object_z}"
    pose_qx="{left_object_qx}"
    pose_qy="{left_object_qy}"
    pose_qz="{left_object_qz}"
    pose_qw="{left_object_qw}" />
```

第一版不强求全部参数来自在线视觉。如果 Left 每次都在固定区域、固定 yaw、固定抓取点抓长条，则 ${}^{G_L}T_O$ 可以直接从 YAML 配置。若后续允许抓取点明显变化，再升级为在线计算。

### 3.2 `TransferObjectNode`

同样删除仅依赖：

```text
offset_z
```

的设计，改为完整：
$$
{}^{G_R}T_O
$$

其中：
$$
{}^{G_R}T_O=\left({}^{O}T_{G_R}\right)^{-1}
$$

因此只要 M4 定义好“Right 应该在物体什么位置、什么姿态进行抓取”，Transfer 后物体就可以保持正确姿态，不再重新变成 `z offset + identity orientation`。

## 4. M4-P0：重新设计 Handover Geometry

长条物体不能再把 Left 和 Right 的抓取点设计在同一区域。应利用长条长度，把两个抓取区域空间分离。

在 object frame $O$ 下定义：

```text
left_grasp_region
right_grasp_region
```

例如长轴定义为 $x_O$，Left 持有一侧，Right 抓取另一侧。两夹爪抓取中心距离应满足：
$$
d_g=\left|p_{G_L}^O-p_{G_R}^O\right|\ge d_{\mathrm{gripper}}+m
$$
其中 $d_{\mathrm{gripper}}$ 表示两夹爪实际碰撞包络需要的空间，$m$ 为安全余量。

目标不是让两个 TCP 尽可能靠近，而是：

```text
Left 稳定持住一端
Long Bar 中间提供传力
Right 从另一端/另一自由区域抓取
```

这样长条物体本身反而成为 handover 的优势。

## 5. M4-P0：增加 `GenerateHandoverCandidate`

不要把 Right 最终接物 Pose 固定死在 world。

Left 到达 `handover_hold` 后，根据 Left 当前真实 TF 和 Attached Object Pose 计算物体世界位姿：
$$
{}^WT_O={}^WT_{G_L},{}^{G_L}T_O
$$

配置 Right 相对于物体的目标抓取变换：
$$
{}^OT_{G_R}^{*}
$$

则 Right 最终接物 Pose：
$$
{}^WT_{G_R}^{*}={}^WT_O,{}^OT_{G_R}^{*}
$$

新增 BT 节点：

```text
GenerateHandoverCandidate
```

输入：

```text
left_grasp_frame
right_base_frame
object_pose_in_left_grasp
right_grasp_pose_in_object
approach_distance
approach_direction
```

输出：

```text
right_receive_pose
right_receive_pre_pose
object_pose_in_right_grasp
```

这样即使 Left 最终实际位置存在几毫米 tracking error，Right 接物 Pose 也会跟随实际 Left/Object 状态变化，而不是盲目运动到固定 world pose。

## 6. M4-P0：Pre-Pose + Approach

Right 不再直接规划到最终抓取位姿。

定义最终接物位置 $p_R$，Approach 单位向量为 $\hat n$，Pre-Pose 为：
$$
p_{\mathrm{pre}}=p_R-d_a\hat n
$$
初始建议：
$$
d_a=50\sim100,\mathrm{mm}
$$

Approach 方向尽量避免沿长条轴线扫入。若长条单位轴为 $\hat a$，优先选择：
$$
|\hat a\cdot\hat n|\approx0
$$
即从长条侧面接近，而不是沿长条长度方向扫过去。

流程：

```text
Right Open
→ MoveToPose(right_receive_pre_pose)
→ Low-Speed Approach(right_receive_pose)
→ Right Close
```

`right_receive_pre_pose` 必须完全 collision-free。

最终 `right_receive_pose` 应优先设计成“长条已经进入张开的两指之间，但尚未发生实体穿模”，这样第一版甚至不需要修改 Allowed Collision Matrix。

## 7. Final Approach 的实现策略

第一版先复用已有 `MoveToPose`：

```text
Right MoveToPose(receive_pre)
velocity_scale = 0.10~0.15

Right MoveToPose(receive_pose)
velocity_scale = 0.03~0.08
```

因为 Pre-Pose 已经非常接近，第二段只负责短距离 Approach。

如果实际发现最后一段轨迹出现明显绕行、Approach 方向不可控，再增加：

```text
CartesianApproach
```

实现固定方向的短距离笛卡尔运动。

当前阶段不要一开始就为此重写整个 Servo 系统。

## 8. Collision Policy

正常阶段：

```text
Right Arm ↔ Long Object
collision = forbidden
```

Right 到 `receive_pre_pose` 后，如果张开的夹爪可以无碰撞包住物体，则继续保持全部碰撞检测，不修改 ACM。

只有实际测试证明最终 Approach 因 finger collision geometry 无法到达时，才增加非常局部的 handover ACM：

```text
handover_bar ↔ right_finger1 = allowed
handover_bar ↔ right_finger2 = allowed
```

禁止放开：

```text
handover_bar ↔ right_wrist
handover_bar ↔ right_forearm
handover_bar ↔ right_arm
left_arm ↔ right_arm
```

ACM exception 仅允许存在于：

```text
RIGHT_APPROACH
→ RIGHT_CLOSE
→ TRANSFER
```

Transfer 完成后立即恢复。

因此 ACM 属于 M4 按需项，不是第一步。

## 9. M4-P1：正式运动顺序修改

删除旧流程：

```text
Left Pick
→ Lift
→ DualMove(dual_handover_ready)
→ Right Close
→ Transfer
→ Left Open
→ DualMove(dual_home)
```

改为：

```text
Left Pick
→ Attach Long Object
→ Left Lift
→ Left Move To Handover Hold
→ Left Stable
→ GenerateHandoverCandidate
→ Right Open
→ Right Move To Receive Pre-Pose
→ Right Low-Speed Approach
→ Right Close
→ VerifyRightGrasp
→ TransferObject
→ Left Open
→ Left Retreat
→ Right Retreat
→ Dual Home (optional)
```

两个关键变化：

1. Right 接近时 Left 完全静止；
2. Transfer 后先完成安全分离，再允许双臂共同运动。

## 10. M4-P1：Right Grasp Handshake

严格 invariant：

```text
VerifyRightGrasp != SUCCESS
⇒ TransferObject forbidden
⇒ LeftOpen forbidden
```

状态：

```text
LEFT
→ RightClose
→ VerifyRightGrasp SUCCESS
→ BOTH_PHYSICAL
→ TransferObject SUCCESS
→ RIGHT
→ LeftOpen
```

Right Verify 失败：

```text
Left Hold
→ Right Open
→ Right Retreat
```

## 11. M4-P1：Transfer 后的 Retreat

原来 Transfer 后直接 `DualMove(dual_home)` 对长条物体风险较高，因此删除。

Transfer 后物体已经 Attach 到 Right：

```text
Right Hold
→ Left Open
→ Left Retreat
→ Left Safe
→ Right Retreat
```

只有左右机械臂和长条物体已经形成明显安全距离后，才允许：

```text
DualMove(dual_home)
```

## 12. M4-P1：Recovery

保持四种 ownership：

```text
NONE
LEFT
BOTH_PHYSICAL
RIGHT
UNKNOWN
```

Recovery：

| State           | Recovery                       |
| --------------- | ------------------------------ |
| `LEFT`          | Left Hold，Right Open + Retreat |
| `BOTH_PHYSICAL` | Both Hold，Right Open，恢复 `LEFT` |
| `RIGHT`         | Right Hold，Left Open + Retreat |
| `UNKNOWN`       | Both Stop + Both Hold，禁止自动松手   |

要求：
$$
N_{\mathrm{recovery\ induced\ drop}}=0
$$

## 13. M4 测试顺序重新调整

| Stage | 内容                           |        次数 | Gate                 |
| ----- | ---------------------------- | --------: | -------------------- |
| T0    | RViz 长条 Attach Geometry 检查   | ≥10 poses | 模型位置/方向正确            |
| T1    | Right 路径故意穿过长条               | ≥10 cases | Planner 拒绝或绕行        |
| T2    | Left Hold，Right→Pre-Pose     |        30 | Object Contact=0     |
| T3    | Right Pre→Receive，夹爪保持打开     |        30 | Drop=0，非预期 Contact=0 |
| T4    | Right Close→Verify→Transfer  |        30 | Handover ≥28/30      |
| T5    | Failure Injection + Recovery |       ≥20 | Recovery Drop=0      |
| T6    | Pick→Handover                |        50 | 找到主要 failure mode    |
| T7    | 参数冻结后正式实验                    |       100 | $R_h\ge95%$          |

T0、T1 是新增的硬 Gate。T1 不通过，不进入真机 Right Approach。

## 14. 新增实验指标

除原 M4 指标外增加：

```text
attached_object_geometry_valid
right_prepose_plan_success
right_object_collision_during_approach
right_approach_success
right_approach_time
object_drop_before_contact
object_drop_during_contact
```

重点区分：

```text
PRECONTACT_DROP
APPROACH_COLLISION
GRASP_FAIL
TRANSFER_FAIL
POST_TRANSFER_DROP
```

这样可以判断问题到底发生在路径规划、物理碰撞、夹取还是 ownership transfer。

1. 测量并确定长条 $(L,W,H)$、Left grasp point、Right grasp point。
2. 修改 `AttachObjectNode`，支持完整 ${}^{G_L}T_O$。
3. 在 RViz 验证 Attached Long Object 跟随 Left。
4. 验证 Right planner 能避开 Attached Long Object。

6. 固定 `left_handover_hold`。
7. 实现 `GenerateHandoverCandidate`。
8. 实现 `right_receive_pre_pose` 和 `right_receive_pose`。

12. 加入 `TransferObject→LeftOpen`。

## 16. M4 Definition of Done

```text
[ ] 长条真实尺寸进入 PlanningScene
[ ] Attached Object 使用完整 position + orientation
[ ] RViz 中长条与真实抓取姿态一致
[ ] Left 带物运动时 CollisionObject 正确跟随
[ ] Right planner 会主动避让长条
[ ] Left 与 Right 使用分离的 grasp region
[ ] Left Handover Hold 稳定
[ ] Right Receive Pre-Pose collision-free
[ ] Right Approach 不产生非预期碰撞
[ ] Right Close 后执行 VerifyRightGrasp
[ ] Verify 失败 Left 不松手
[ ] Transfer 使用正确 object pose in right grasp frame
[ ] Transfer 后 PlanningScene 中物体姿态不发生明显跳变
[ ] LeftOpen 只发生在 Transfer 成功后
[ ] Transfer 后 Left 先 Retreat
[ ] Recovery 不无条件 Open Both
[ ] UNKNOWN ownership 时 Both Hold
[ ] 纯 Handover ≥30 次
[ ] Failure Injection 完成
[ ] 正式测试 100 次
[ ] $R_h\ge95\%$
[ ] Object Drop = 0
[ ] Inter-arm Collision = 0
[ ] Right→Object unintended collision = 0
```

M4 的一句话目标更新为：

> **将长条物体作为双臂系统中的 Attached Collision Body 建模，在 Left 静止持物条件下，通过 Object-relative Receive Pose、Pre-Pose 和受控 Approach 完成安全可靠的 Right grasp，并实现经过验证的 Left-to-Right ownership transfer。**
