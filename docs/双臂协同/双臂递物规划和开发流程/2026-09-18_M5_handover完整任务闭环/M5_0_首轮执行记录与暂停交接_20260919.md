## 2. 已完成并实测验证的结论

### 2.1 夹具几何（`src/gz_launch/models/regrasp_fixture/model.sdf`）

- 局部系原点在落地中心，杆长轴 = 局部 Y；世界位姿标称 **(0.10, -0.20, 0)**
- 支撑面 z=0.105 → **杆心落座 0.1200m**。两次独立放置偏差 **0.00mm**，且与滚转无关
- 两个支撑放**中段** y=±20mm（不是两端）：两个抓取区各占 20.61mm，杆长 150mm，两端各只剩 10.7mm，放不下支座
- 已接入 `s622_dual_arm.launch.py` 自动生成，参数 `spawn_regrasp_fixture` / `fixture_x` / `fixture_y` / `fixture_yaw`

**为什么否决了第一版的 90° V 槽**（重要，别再改回去）：正方截面在 90° V 槽内有**两个稳定落座高度**——角朝下时杆心在 V 尖上方 21.2mm、边朝下时 30.0mm，相差 8.8mm，取决于放入瞬间是否发生滚转。第一版实测落在 0.1288 而设计值 0.1200，验算壁面 `x+z=0.1988`、杆底角 `(0.085, cz−0.015)` 得 cz=0.1288，与实测完全吻合。而方案 B 已确认正方截面绕长轴转 90° 几何等价，V 槽对横滚的约束**没有收益**，只带来高度双值。

### 2.2 右爪抓取朝向（决定夹具能不能用，最关键的一条）

由 M4 标定的 `receive_quat` 反解：

| grasp_frame 轴 | 世界方向 | 含义 |
|---|---|---|
| x（指板张合） | **−Z** | **竖直张合**，一指向下、一指向向上 |
| y（杆长轴） | +Y | 与 `ROD_YAW=90°` 一致 |
| z（接近） | +X | 与 M4 `approach_axis=[1,0,0]` 一致 |

交叉验证：M4 手工调的 `receive_offset.x = −8.6mm`（"指板接触区前置量"）正是沿 grasp z 的量，与指板在该向长 41.5mm 相符；`落座 +15.0mm` 也等于杆心到指板中位面的偏移。

**两条推论（已写进夹具模型注释）**：

1. 下指板要伸到**杆心下方 50mm** ⟹ 重抓区下方必须净空 50mm，**固体 V 块/桌面式支撑在这个抓取下不成立**
2. 指板包络（实测自 `finger1/2.STL`）：沿杆轴 20.61mm ｜ 接近向 41.5mm ｜ 张合向 70.37mm

## 3. 已知缺口（暂停位置）

### 3.1 放置未真正达成——**根因已定位，修复方向明确**

**现象**：行为树全链路 SUCCESS，但杆落在 z=0.1300（比设计值高 10.1mm）、y 偏 12.1mm、且姿态倾斜。几何分析显示杆离夹具最近的盒体还有 44mm（悬空）。**把右臂移开后，杆立刻落到 z=0.1200 并精确稳定** —— 说明夹具本身正确，杆是**搭在右爪下指板上被带走**的。

**根因**：放置位姿是用配置里**冻结的"杆在爪内"偏置**反算的：

```
目标爪位姿 = 夹具上杆心 + receive_offset
          = (0.10, −0.20, 0.120) + (−0.0086, −0.054, +0.0030)
```

但本轮实测该偏置的 z 分量与配置值差约 10mm。杆因此悬在支撑面上方 10mm，而右爪下指板顶面恰在"杆心 −14.7mm"、支撑面在"杆心 −15mm"，于是杆落在指板上。

**这不是新问题**：M4 的 `m4_handover.yaml` 注释里已经记过同一件事（"原值的 z 少 14mm ⇒ 杆进爪时偏上 14mm"、"实测 `tcp − rod` = (−5.2, −54.0, **+15.0**) mm"），并总结为"**receive 必须运行期生成**"。M5 规划 §9/§13/§14 也预见了（关节锚点 + 局部修正 + 以物体为中心）。本轮只做了"裸锚点"，跳过了运行期测量与修正。

## 6. 本轮踩过的坑（避免重复）

1. **两个逆解服务都不能盲信**
   - `/move_group_fairino/compute_ik` 在 **M4 已知可用**的位姿上就返回 `-31`，本工作区不可用
   - `/move_group_kdl/compute_ik` 求解**正确**（回代残差 ≤0.005mm），但返回的 `solution.joint_state` 含**全部 16 个关节**（左臂 0~7、**右臂 8~13**、左右指 14~15）。直接取 `position[:6]` 拿到的是**左臂**的值，回代 FK 会差几百毫米——我因此一度误判"逆解不可用"，实际是取值错了。**必须按关节名映射**（`fixture_reach_check.py` 里已写好）
2. **关节限位别凭印象**：j2/j4 是 `[-4.6251, 1.4835]`，j1/j5/j6 是 `±3.0543`，j3 是 `±2.8274`（来源 `urdf.xacro` 的 `${prefix}j1..j6`）。我一开始把 j2 当成 ±2.094，导致解落在错误的分支、限位裕度也算错
3. **改启动参数要重新构建**：`gz_launch` 只有目录安装（无 C++ 目标），新增模型需 `colcon build --packages-select gz_launch --merge-install`；本工作区的 install 是 **merge 布局**，不带 `--merge-install` 会报错
4. **`pkill -f` 会误杀自己**：清理进程时用命令行模式匹配，匹配到了执行该命令的 shell 自身。**改用进程号**
5. **静态模型不发布位姿**：`ign topic ... /pose/info` 里 static 模型（夹具）没有 position 块，解析时不能把窗口滑到下一个模型（`fixture_seat_check.py` 已处理）
6. **`ign model` 是查询工具**，生成模型要用 `ros2 run ros_gz_sim create`，删除用 `ign service -s /world/dual_arm_world/remove`
7. **RTF≈0.2**：仿真时间是墙钟的约 1/5。单程关节运动 13.6~35.5s 墙钟，M5 单轮会比 M4 的 162s 长不少
