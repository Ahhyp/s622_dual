## 三条原则

**仿真先行,实机验证。** 逻辑、规划、BT 全在 Gazebo 里调通,实机只负责暴露物理误差。上层代码零改动切换,靠 `mock_components` → Gazebo → 真实 SystemInterface 三档。

**单臂闭环先跑通,再上双臂。** 视觉抓取的坑(YOLO 精度、反投影、点云噪声)和双臂的坑(标定、同步、碰撞)必须分开调试,混在一起你分不清故障来源。

**每个里程碑必须产出一个可量化数字。** 没有数字的阶段等于没完成——这既是工程验收标准,也是简历素材。

## 里程碑

时间是粗估,按你的实际投入调整。

### M0 建模与仿真骨架(1~2 周)

| 任务                     | 要点                                                                                                              |
| ---------------------- | --------------------------------------------------------------------------------------------------------------- |
| `dual_arm_description` | `world` → `left_base` / `right_base`,气爪、相机 link(注意 `camera_link` 与 `camera_optical_frame` 分开)                   |
| SRDF 三 group           | `left_arm(6)` / `right_arm(6)` / `dual_arm(12)`,group 到 controller 的映射                                          |
| **自碰撞矩阵人工复核**          | Setup Assistant 可能误把左右臂 link 对标为 Never in Collision 并禁用,必须打开 SRDF 搜索 `disable_collisions` 里同时含左右臂 link 名的条目全部删除 |
| Gazebo 场景              | 两臂 + 桌面 + 两个相机 plugin,物体模型                                                                                      |
| mock → Gazebo          | 先 `mock_components/GenericSystem` 跑通 MoveIt,再切 Gazebo                                                           |

**退出判据:** RViz 里三个 group 都能规划执行;**故意**规划一条穿越对方臂的路径,规划器必须失败(这是验证臂间碰撞检查真的生效,而不是被 SRDF 静默禁用了)。

**已知坑:** Gazebo 气爪夹持经常抓不住(接触摩擦不足,物体滑落或抖飞)。用 `gazebo_grasp_plugin`,或抓取瞬间动态创建 fixed joint。别在这上面耗太久,它不是你的技术重点。

### M1 硬件通道与 ServoJ 表征(1~2 周,实机)

先做表征,再写 hardware interface。SDK 是抄的,每个行为都要实测。

| 任务            | 产出                                                      |
| ------------- | ------------------------------------------------------- |
| ServoJ 五项验证   | 反馈内容与频率、**有无关节电流上报**、带宽与延迟、停发指令行为、单周期步长限幅、`write()` 阻塞性 |
| `dual_arm_hw` | 两个 SystemInterface,挂**同一个** controller_manager,250Hz    |
| 单臂正弦跟随        | 0.5/1/2/5Hz,记录幅值衰减与相位滞后 → **跟踪误差、等效延迟**                 |
| 双臂同步跟随        | 两臂跟同一条轨迹,互相关求相对延迟 → **抖动均值与 3σ**                        |

**退出判据:** 拿到跟踪误差和双臂抖动两个数字。

**这是决策门 G1**,见下。

### M2 标定(1 周)

| 任务                  | 方法                                        |
| ------------------- | ----------------------------------------- |
| 双基座 (T_{B_2}^{B_1}) | 拖动示教辅助对触,15~20 组姿态覆盖交接区,最小二乘              |
| Gazebo 真值验证         | 同一份代码在仿真跑,残差应达 1e-6 量级                    |
| 噪声注入实验              | 在真值上注入 ±0.5mm/±0.01°,画残差-组数收敛曲线,确定实机该采多少组 |
| 腕部 RGBD 手眼          | eye-in-hand,求 (T_{cam}^{flange})          |
| 全局 RGB 手眼           | eye-to-hand,求 (T_{cam}^{world})           |
| 交叉验证                | 两臂尖端指向同一物理点的偏差;视觉给出的位置与实际抓取位置的偏差          |

**退出判据:** 基座残差 ≤ 2mm、手眼重投影亚像素、交叉验证偏差 ≤ 3mm。

全局相机必须机械锁紧。**它动了之后所有标定和已采数据全部失效。**

### M3 单臂视觉抓取闭环(2 周,右臂)

| 任务         | 要点                                     |
| ---------- | -------------------------------------- |
| YOLOv8 数据集 | 自采标注,建议 300~500 张,含光照/摆放/遮挡变化          |
| 粗定位        | 像素反投影射线 ∩ 已知桌面平面 → 粗 3D 位置             |
| 精定位        | 移到物体上方,腕部 RGBD,mask 内点云 PCA 求主轴 → yaw  |
| 抓取执行       | MoveIt2 规划 + `AttachedCollisionObject` |
| 单臂 BT      | 检测 → 接近 → 精定位 → 抓取 → 放置                |

**退出判据:** 随机摆放 100 次抓取成功率 ≥ 90%。

**坑:** 腕部深度相机有最小距离(D4xx 通常 0.2~0.3m),夹爪临近闭合时物体落在盲区。精定位要在**接近阶段**完成,别指望夹取瞬间还有深度。先查你的型号最小距离。

### M4 双臂松耦合:互斥 + 交接(2 周)

| 任务                | 要点                                                                         |
| ----------------- | -------------------------------------------------------------------------- |
| 工作区互斥             | 共享区排他锁,任何时刻只允许一臂进入                                                         |
| 在线距离监控 controller | 独立线程 250Hz,FCL `distance()`,两级阈值(50mm 减速 / 20mm 双臂联动停)                     |
| 交接握手 BT           | A 到位 → 稳定确认 200ms → B 规划抓取(A 作静态障碍)→ B 闭爪 + 气压确认延时 → A 开爪 + 延时 → A 沿避让方向退出 |
| 失败回退              | 每步超时 + Fallback 分支                                                         |
| 气爪延迟实测            | 指令到实际夹紧的延迟(50~200ms 量级),写进 BT 的延时参数                                        |

**退出判据:** 连续 100 次交接成功率 ≥ 95%,并统计失败模式分布(抓空 / 位置偏 / 滑落)。

这一阶段用**顺序执行**,不碰 12 轴同时运动。

### M5 完整流程(1~2 周)

分拣 → 右臂抓取 → 交接给左臂 → 左臂换持翻面 → 右臂重抓原被遮挡面 → 装配放置。全流程 BT 编排 + 失败恢复分支。

**退出判据:** 连续 50 次成功率 ≥ 90%,记录单次循环节拍(这是 M6 的 baseline)。

**M5 结束你的简历主体就完整了。** 后面两个是加分项。

### M6 协同优化:12 轴联合规划(1 周)

把 M5 里"一臂动完另一臂再动"的段落替换为 12 轴 group 统一规划,两臂同时运动且彼此互避。

**退出判据:** 节拍对比 → 缩短百分比;记录 RRTConnect 平均/P95 规划耗时。

参数:`planning_time` 5~10s、`num_planning_attempts` 4~8 取最短解、`longest_valid_segment_fraction` 降到 0.002~0.003(防两臂高速交错时的穿透漏检)。

交接姿态附近是狭窄通道,可能超时。解法是加中间路点拆成两次简单规划,不是换规划器。

### M7 仿真闭链(可选,1~2 周,sim-only)

物体任务空间 6-DOF 轨迹 → 离散路点 → 按固定抓持关系反解双臂 (q_1, q_2) → 统一时间参数化。**只做运动学,不做内力和柔顺**(Gazebo 的接触物理不足以支撑那部分结论)。

**退出判据:** 闭链位姿一致性误差 (|\Delta T|) < 0.1mm。

## 两个决策门

**G1(M1 后)—— 双臂抖动决定 M6 的形态**

| 抖动 3σ  | 结论                         |
| ------ | -------------------------- |
| < 2ms  | M6 正常做,M7 的算法理论上可迁移实机      |
| 2~10ms | M6 只做互避(不依赖精确同步),这是主要价值,够用 |
| > 10ms | M6 收益有限,时间转投 M5 的成功率优化     |

**G2(M2 后)—— 基座残差决定交接方案**

| 残差    | 结论                       |
| ----- | ------------------------ |
| ≤ 2mm | 直接交接                     |
| 2~5mm | 交接位加锥形导向工装,或加大气爪开口余量     |
| > 5mm | 回去查 URDF 连杆参数与关节零位,别硬往下走 |

## 常见卡点

**M0**:SRDF 臂间碰撞对被误禁用——仿真实机都不报错,直到撞上。M0 的退出判据专门查这个。

**M1**:抄来的 SDK 在"停止下发指令"和"超限幅跳变"这两个边界行为上最容易出问题,直接影响安全设计,务必实测。

**M2**:坐标系约定(optical frame vs body frame 差一个固定旋转)是手眼标定第一大错误来源,靠仿真真值对比抓出来。

**M3**:YOLOv8 数据集自采标注是实际耗时最长的单项任务,提前排期,别低估。

**M4**:气爪没有力反馈,"抓到了"只能靠延时 + 气压/到位开关。这个传感器不要省。

**全程**:重新标定后采集的数据和之前的不能混用,记录标定参数版本。
