## M2.5 方案

**目的**:两个 MoveIt Servo 进程各自绑定一个 planning group,通过 namespace 隔离 topic/service,输出到各自的 controller。lifecycle_manager 和 BT 参数化留给 M2.6/M2.7。

### 关键参数变化(vs M1.7)

| 参数                       | M1.7                                   | left                                  | right                                  |
| -------------------------- | -------------------------------------- | ------------------------------------- | -------------------------------------- |
| `move_group_name`          | robot_arm                              | left_arm                              | right_arm                              |
| `planning_frame`           | base_link                              | left_base_link                        | right_base_link                        |
| `ee_frame_name`            | grasp_frame                            | left_grasp_frame                      | right_grasp_frame                      |
| `robot_link_command_frame` | base_link                              | left_base_link                        | right_base_link                        |
| `command_out_topic`        | /robot_arm_controller/joint_trajectory | /left_arm_controller/joint_trajectory | /right_arm_controller/joint_trajectory |
| `joint_topic`              | /joint_states                          | /joint_states                         | /joint_states                          |

**关键点**:`planning_frame` 用**各自的 base_link**,不用 world。理由:

* Servo 语义是"在 planning_frame 里给一个 twist,IK 求解到 joint velocity"
* 如果 planning_frame=world,左臂发 twist=(0.1, 0, 0, 0, 0, 0) 意思是"在 world 里沿 +x 移动",但左臂 base yaw=π,实际手臂沿自身 x 移动的话反而是 world -x——这跟 M1.7 VisualAlign 里 descend/lift/retreat 五种模式的语义会不一致
* 用 `left_base_link` 作为 planning_frame,left arm 的 twist 语义跟 M1.7 完全一样(twist 沿自身 base 系),VisualAlign 代码逻辑不改
* M2.6 里 visual_align_server 发 twist 时,`TwistStamped.header.frame_id` 也得对应设成 `left_base_link` / `right_base_link`

## 产出 3: 修改 `gz_launch/launch/s622_dual_arm.launch.py`

在 rviz 那节之后,`return LaunchDescription(...)` 之前,加入 servo 段:

```python
# ============ 11. MoveIt Servo (双实例, 各自 namespace) ============
left_servo_yaml_path = os.path.join(
    robot_moveit_pkg, "config", "left_servo_config.yaml"
)
right_servo_yaml_path = os.path.join(
    robot_moveit_pkg, "config", "right_servo_config.yaml"
)

with open(left_servo_yaml_path, 'r') as f:
    left_servo_params = {"moveit_servo": yaml.safe_load(f)}
with open(right_servo_yaml_path, 'r') as f:
    right_servo_params = {"moveit_servo": yaml.safe_load(f)}

left_servo_node = TimerAction(
    period=17.0,
    actions=[
        Node(
            package="moveit_servo",
            executable="servo_node_main",
            name="servo_node",
            namespace="left",
            parameters=[
                left_servo_params,
                moveit_config.robot_description,
                moveit_config.robot_description_semantic,
                moveit_config.robot_description_kinematics,
                {"use_sim_time": True},
            ],
            remappings=[
                # namespaced node 默认订阅 /left/tf, 必须 remap 回全局 TF
                ("/tf", "/tf"),
                ("/tf_static", "/tf_static"),
                # 全局 joint_states 和 planning_scene (由 move_group 单例发)
                ("/left/joint_states", "/joint_states"),
                ("/left/monitored_planning_scene", "/monitored_planning_scene"),
            ],
            output="screen",
        )
    ],
)

right_servo_node = TimerAction(
    period=17.0,
    actions=[
        Node(
            package="moveit_servo",
            executable="servo_node_main",
            name="servo_node",
            namespace="right",
            parameters=[
                right_servo_params,
                moveit_config.robot_description,
                moveit_config.robot_description_semantic,
                moveit_config.robot_description_kinematics,
                {"use_sim_time": True},
            ],
            remappings=[
                ("/tf", "/tf"),
                ("/tf_static", "/tf_static"),
                ("/right/joint_states", "/joint_states"),
                ("/right/monitored_planning_scene", "/monitored_planning_scene"),
            ],
            output="screen",
        )
    ],
)
```

然后 return 里加入:

```python
return LaunchDescription([
    set_model_path,
    gazebo, clock_bridge, camera_bridge,
    spawn_robot, spawn_box,
    robot_state_pub,
    jsb_spawner, arm_hand_spawner,
    move_group, rviz,
    planning_scene,
    left_servo_node, right_servo_node,   # ← 加这行
])
```

⚠️ 关于 remapping 里的 `("/tf", "/tf")` 
语法:namespace 生效后,节点内所有相对/绝对 topic 都会被自动加 `/left` 前缀吗?
**不会**——ROS2 里 namespace 只影响相对 topic,以 `/` 开头的绝对 topic 不受 namespace 影响。但 moveit_servo 内部有些 topic 是通过 `node->create_subscription` 传相对名的(比如 `tf`),会被 namespace 化成 `/left/tf`。所以 remap `/tf → /tf` 是**兜底**——如果实际不需要 remap,加了也无害;如果需要,少了就报错。

## 常见坑

### 1. `planning_frame` 用 base 系 vs world 系的语义差

Servo 的 twist 是**相对 planning_frame 表达的**。twist 里 header.frame_id 会被 servo 内部转换到 planning_frame。

* planning_frame=left_base_link,twist frame_id=left_base_link → 沿左臂自身 x 轴移动 EE
* planning_frame=left_base_link,twist frame_id=world → servo 内部会做 TF 变换,把 world twist 转到 left_base_link 系再计算 IK

M2.6 你在 visual_align_server 里,如果 twist 的 header.frame_id 一直用 `base_link`(M1.7 硬编码),现在得改成参数化的 `${arm_prefix}base_link`。M2.6 会处理。

### 2. namespaced 节点的 remapping 语法

ROS2 namespace 只影响相对 topic。你写 `("/left/joint_states", "/joint_states")` 是把节点内部的绝对话题 `/left/joint_states` remap 到 `/joint_states`——但绝对话题不会被 namespace 自动加前缀,这一条本来就多余。

**为什么还写**:moveit_servo 内部可能有 `node->create_subscription<...>("joint_states", ...)`(相对话题),namespace 会把它自动变成 `/left/joint_states`,此时需要 remap 回全局。

**保守做法**:写上 remap 不管有没有生效。若看到错误提示"No topic /left/joint_states"或 servo 一直等待 robot state,再检查。

### 3. `use_sim_time` 传法

servo_node 需要 `use_sim_time=True` 才能跟 Gazebo 时钟同步。我 launch 里已经在 parameters 里传了。如果漏掉,servo 内部时间戳会跟 sim 时钟差异越来越大,几秒后进入 wall time 假死状态。

### 4. `moveit_servo` 参数命名空间

servo_node 加载 YAML 时,期望参数在 `moveit_servo.xxx` 下(而不是根级)。所以 launch 里包一层:

```python
{"moveit_servo": yaml.safe_load(f)}
```

你 M1.7 launch 就是这么做的,直接照抄。

### 5. 启动顺序:controller 必须先 active

Servo 输出 JointTrajectory 到 `/left_arm_controller/joint_trajectory`——如果 controller 还没 active,消息丢弃。所以 servo 必须在 `arm_hand_spawner`(12s)之后启动。我设成 17s(在 move_group 之后),保险。

### 6. Twist 单位

`command_in_type: "speed_units"` → linear m/s, angular rad/s。V4/V5 里 `linear.x=0.05` 就是 5 cm/s。如果 M1.7 你 tune 过特定 gain,记录下来 M2.6 复用。

### 7. Servo start 后 EE 会漂移?

Servo 启动瞬间会做一次"当前状态锁定",EE 不应该漂移。如果出现 EE 上升/下降/旋转,说明:

* YAML `move_group_name` 跟 URDF 里 group 不匹配
* 或 controller 之前状态污染(比如 M2.4 里 hand controller 记录了错误的 finger position)
* 或 command_out_topic 串到了别的 controller

先 Ctrl+C 停发 twist,servo 应该稳定。稳定就没问题。

### 8. hand_controller 会不会跟 servo 冲突?

不会。servo 只发 arm 6 个 joint 的 trajectory 到 `/left_arm_controller`,`/left_hand_controller` 独立管 finger,互不干扰。
