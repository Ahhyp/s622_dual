## 2. R2：任务相位驱动（APPROACH → LIFT → TRANSPORT → LOWER）

### 2.1 契约增量（需批准，属接口变更）
`msg/TransportStatus.msg` 追加 5 个字段（**只追加，不改既有字段与顺序**）：
```
int32   phase_index        # -1 = no trajectory; else 0..phase_count-1
string  phase_name         # "" when phase_index < 0
int32   phase_count
float64 phase_elapsed_s    # t_traj - phase_start[index]
float64 phase_duration_s   # 该相位标称时长（0 = 未知）
```
控制器侧：`TransportTask` 已有 `traj_->duration()`；相位边界取自 `trajectory.hpp:63` 的边界时间数组，按 `t_traj` 二分定位（**每周期 O(log n)，无分配**），写入 `TransportSample` 新增字段。发布侧字段填充在 `publishStatus()` 内完成（RT 路径，无分配）。

### 2.2 执行器侧推进规则
- `tick()` 中新增相位推进：`if (st.phase_index != last_phase_) { advance(now, "controller phase boundary"); last_phase_ = st.phase_index; }`，**只允许 +1 递增**，跳变（>+1）或回退 → `enterProtection(Hold, "phase_desync")`。
- 四相位映射：控制器 `phase_name` ∈ {`approach`,`lift`,`transport`,`lower`} ↔ 执行器 `State::{Approach,Lift,Transport,Lower}`；名称不匹配 → `Hold("phase_name_mismatch")`。
- `phaseDone(t)` 保留，但**只用于 Grasp/Release/Retreat**（这三态没有控制器轨迹），并在实现内标注 `SIMULATED`。
- 超时：`phase_timeout_scale`（已有，1.5）× `phase_duration_s`；`phase_duration_s == 0` 时回退到全局超时。触发 → `Hold("phase_timeout")`（已有代码路径 `state_machine.cpp:396-420`）。
- HOLD/FAULT/ABORT：既有 `enterProtection` + 锁存语义不动；相位推进在非 active 态直接返回。
- 确定性时钟：`tick(now_s)` 注入时间不变；测试用固定步长（8 ms）推进，断言事件序列与时间戳。

## 3. R3：附着适配器（最小接口 + stub）
