## 10. T-H13 判据 C1–C6 逐条判定

> 来源：同上，第 236–322 行（§6，逐字；含 §6.1–§6.9）

#### 6. C1–C6 逐条判定

##### 6.1 C1 — 638 周期 & `dropped == 0`：**PASS**

- B/B2/C/C2：运输块分别 661/650/650/650 行，取前 638 行作窗口；`dropped=0`（dump 原文可见）。
- A 轮：记录器整体关闭（`dump_success=false`，无 CSV），`dropped` 在 `capacity_<=0` 时不可能自增（`src/timing_recorder.cpp:61` 早退，`++dropped_` 只存在于 `n >= capacity_` 的溢出分支），故为**结构性 0**，不是实测值 —— 本文件不把它记为实测证据。A 轮「完成 638 周期」由 `COMPLETE` + `t_traj=5.100` 证明。

##### 6.2 C2 — `p99(C) − p99(B) ≤ 100 µs`：**PASS**

冻结设计 §5.2 的原文是**有符号**不等式 `p99(C) − p99(B) ≤ 100 µs`（不含绝对值）。按字面判定：

| 配对 | `p99(C)−p99(B)` | 对字面判据 | 对本文件额外采用的对称形式 `|·|≤100` |
|---|---|---|---|
| C − B | **−76.4 µs** | −76.4 ≤ 100 ⇒ 成立 | 成立 |
| C2 − B2 | **+11.8 µs** | +11.8 ≤ 100 ⇒ 成立 | 成立 |

本文件在 §0/§5 里额外用了 `|p99(C)−p99(B)| ≤ 100`（比冻结判据更严），两配对同样成立 ⇒ **判据按字面与按加强形式都通过，没有放宽**。注意：字面判据是「C 不比 B 慢超过 100 µs」，它**不允许**把 −76.4 µs 读成「相位计时改善了实时性」——负数来自跨进程噪声（同一组态两轮之差就有 45.7 / 42.5 µs，方向不稳定，见 §6.9）。

限定：同态跨轮噪声约 ±45 µs（p99），因此该判据只能证明「没有出现 >100 µs 的系统性开销」，不能证明相位采集开销 < X µs（X 需原生 Linux + 更多轮次，见 C6）。

另据本文件 §6.9：B 轮的 p50 反而高于 C 轮（172.8/185.3 vs 147.5/151.6 µs），这一差异大于相位测量本身的成本，说明**本机 p50 的跨轮漂移已达 ±30 µs 量级**，任何小于该量级的开销都无法在此环境分辨。

##### 6.3 C3 — 每样本 `sum(P1..P6) ≤ cycle_us`：**PASS**

逐行检查（不是只查窗口）：

| 数据 | 行数 | 违例 |
|---|---|---|
| `/tmp/th13/b/timing.csv` | 674 | 0 |
| `/tmp/th13/c/timing.csv` | 663 | 0 |
| `/tmp/th13/b2/timing.csv` | 663 | 0 |
| `/tmp/th13/c2/timing.csv` | 663 | 0 |
| `/tmp/th13/c_ee/timing.csv` | 388 | 0 |

窗口内最坏 `sum/cycle`：C 0.9993、C2 0.9992、早退探针 0.9990（B/B2 因 mask=0 恒为 0）。最坏比接近 1 而非超过 1，说明相位切分覆盖了 cycle 的几乎全部时间且无自我重叠；剩余 0.07 % 是 `end()` 取时刻到下一拍 `begin()` 之间的循环尾开销（P0/P7，按设计不属任何相位）。

##### 6.4 C4 — `P6 == 0` 样本的正当性：**PASS（带空真说明）**

- C/C2 轮：`P6 == 0` 的样本数 = **0**，判据空真成立；`branch==1` 的 P6 最小值 = **0.09 µs**（非零），说明采样粒度足以覆盖 `publishStatus()`。
- B/B2 轮：`phase_mask=0` ⇒ 六相位恒 0，该判据**在这些轮不可评估**（不是放宽，而是三态定义使然：B 轮的目的就是只留 P0/P7）。
- A 轮：无记录器，判据不适用。
- 计数器有效性另有实测：hooks-OFF 回归里 `test_realtime_budget` 的 S4-T17 长跑（7102 样本、`branch{idle=13,transport=6772,early_exit=317}`）dump 出 `publish_trylock_miss=**17**`，即 E8 早退期间确有 `trylock` 失败并递增（该轮 mask=0，故只有计数器、没有 P6 列）。见 §8。
- **证据边界（不得扩写）**：本文件**不主张**「某次 `trylock` miss 与某个具体 `P6` 样本逐周期对应」已建立——两者从未同时观测到（主轮 P6 非零但计数器 0；S4-T17 计数器 17 但 mask=0 无 P6 列）。C4 的 PASS 只等于「冻结判据在本次数据上成立（空真）」，不等于「发布竞争已归因完成」。

##### 6.5 C5 — 各相位 p50/p99/max 落盘且非零：**PASS**

C/C2 两轮六相位 `recorded=638/638`，p50/p99/max 见 §5.1，CSV 原始列见 `/tmp/th13/c/timing.csv`、`/tmp/th13/c2/timing.csv`。

统计口径（`src/dual_arm_qp_controller/src/timing_recorder.cpp:159-181`，逐条可核）：

| 情形 | 记录方式 | 对统计的影响 |
|---|---|---|
| 相位**未被执行**（在其之前早退，如早退样本的 P4） | 该槽保持 `0` | 不计入该相位的 mean/p50/p99/max；`recorded` 减少 |
| 相位**执行了但读数为 0**（两次 mark 落在同一时钟粒度内） | 同样是 `0` | 与「未执行」不可区分 ⇒ `recorded` 是**下界**（代码注释已写明） |
| 相位**被执行且 > 0** | 写入 `phase_us_[p][n]` | 进入该相位的分布 |

- 因此 `recorded` 的读法：`recorded == samples` ⇒ 该相位在每个样本上都被观测到非零；`recorded < samples` ⇒ 差额是「未执行 + 亚粒度」的合计，不能一律解读为早退。
- 本文件的两组数据正好覆盖这两种情况：主轮 C/C2 六相位均 `638/638`（窗口内**没有**亚粒度坍缩）；早退探针 P4 为 `275/388`，差额 113 与 `branch=2` 样本数**逐一相等**（§7），故该差额可完整解释为「未执行」。
- 未使用任何插补：`summarize()` 不填 0、不对零值做补偿；分位数只在 `>0` 的样本上计算，所以空真不会把某相位的 p99 拉向 0。
- 溢出处理：`dropped > 0` 时该样本整体不落盘（`end()` 在 `n >= capacity_` 处只 `++dropped_`），不会出现「只写了部分相位列」的半样本；本轮所有轮次 `dropped=0`，无溢出样本。

##### 6.6 C6 — 各相位 p99 绝对阈值：**UNVERIFIED**

依赖原生 Linux（WSL2 无 RT 调度：`chrt` EPERM、`ulimit -r=0`）。本轮**不设阈值、不降标、不以外推替代**。本机数据仅可作为相对比较（C2）与形态参考（§5.1）。

##### 6.7 「`timing_phases=0` 时原有行为逐位不变」

- 代码层：掩码不含该位 ⇒ `phaseEnabled()` 为 false，`mark()` 立即返回（不读时钟、不写累加器）；`publish_trylock_miss_` 只在 `timing_.enabled()` 时自增；`setOutcome()` 只写两个 int 成员，不参与任何控制计算。
- 实测层（可测的部分）：A（off）/B（mask=0）/C（mask=63）/B2/C2 五轮最终 `q_cmd` **逐位一致**（`max|Δq| == 0`），`t_traj` 均 5.100、终态均 `COMPLETE` ⇒ 打开记录器、乃至打开全部相位，**没有改变控制序列**。
- **限定（如实）**：交接单 §4 要求的「改前 vs 改后对同一输入逐值比较 P0/P7 列」**未完成**。原因：改前的 CSV 只存在于 `/tmp/c43s4_rt/timing_s4t2.csv`，而该路径由 `test_realtime_budget` 每次运行重写；本轮回归跑过该用例后，改前 5 列格式的原始文件已被覆盖（现存文件已是 13 列，`rows=714`）。因此本条只能给上面的代码论证 + 控制输出逐位一致证据，**不能**给逐值计时对比。这不是判据 C1–C5 的一部分，但属交接要求，故显式记为缺口。

##### 6.8 零分配 / 零 syscall（RT 路径）

未新增任何堆分配：相位缓冲在 `configure()` 一次分配（`resize/assign`），`mark()`/`setOutcome()` 只碰已分配内存与标量；RSS/fd 仍在 `configure/reset/rebaseResources/summarize` 采样。本轮**未**做 heaptrack/massif 审计（与 W2-R4 的记录一致），RSS 只作量级观察：C 轮 `rss growth=112 KB`、C2 `100 KB`、B `76 KB`、B2 `3052 KB`（B2 的 3 MB 属 glibc arena/ROS 分配噪声，跨轮不可比）。

##### 6.9 噪声与可分辨度（供复核判断）

| 观测量 | 值 |
|---|---|
| p99 同态差（B vs B2 / C vs C2） | 45.7 / 42.5 µs |
| p50 同态差（B vs B2 / C vs C2） | 12.5 / 4.1 µs |
| B 组 p50 高于 C 组 | 25.3 / 33.7 µs（方向与「C 多做 22 次时钟读」相反） |
