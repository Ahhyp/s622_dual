### 3.1 W0-1 同一算法只有一份定义 —— 通过（本轮整改后）

守卫：`src/dual_arm_object_task/cmake/check_single_object_task_definition.cmake`，由
`src/dual_arm_object_task/CMakeLists.txt:46-51` 注册为 ctest 条目 `test_single_object_task_definition`。

**上一版守卫的缺陷（本轮修复）**：它只在 `dual_arm_object_task/` 内统计定义，因此把同一份
`AnchoredObjectTaskBuilder` / `AnchoredObjectTask` 复制到**任何其他包**都能通过；另外它把"禁止直调帧数学"
写死成一张包名清单，清单外的包直调也会通过。这与规划 §14.7 的原文判据（"全 `src/` 里命中数 == 1"）不符，
属于**标准被悄悄降低**，不是新提出的加严。

**本版的四条判据**：

1. `class AnchoredObjectTaskBuilder` 与 `struct AnchoredObjectTask` 的**定义**（不是声明）在规范包内各恰好 1 处；
2. **任何其他包**里出现这类定义即违规——不再依赖包名清单，这是上一版的盲区；
3. 原始帧数学（`anchoredObjectPose(` / `anchoredObjectTwistJacobian(` / `anchoredObjectErrorJacobian(` /
   `decoupledPoseError(` / `decoupledErrorRateMap(`）只允许在 `MATH_EXEMPT` 四个包里出现：
   `dual_arm_kinematics`（定义方）、`dual_arm_object_task`（唯一实现）、`dual_arm_transport`（S2 冻结的候选筛选，
   只算锚定位姿、无雅可比/无误差/无 QP 行）、`dual_arm_transport_mock`（S3 参考实现与审定测试，按设计要直测原始数学）；
4. 匹配前先剥 `//`、`/* */` 注释并把连续空白归一为单空格，因此注释、`#include`、前置声明、测试代码**不会误报**。

`dual_arm_object_task/include/dual_arm_object_task/anchored_object_task.hpp` 缺失 ⇒ 失败（缺文件不得当作通过）；
