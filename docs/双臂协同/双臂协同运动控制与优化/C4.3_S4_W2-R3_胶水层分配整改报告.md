## 4. 判定：为什么不能“最小预分配”

自有 3.08 次/solve 的两处站点指向同一对象：`QpSolution` 的返回缓冲。

```cpp
// src/dual_arm_qp_core/include/dual_arm_qp_core/qp_types.hpp:29-36
struct QpSolution {
    Eigen::VectorXd x;        // ← 唯一动态尺寸字段
    bool converged; int iterations; double primal_res, dual_res, solve_time_ms;
};
```

- `solution.x.resize(n)`（`osqp_solver.cpp:206`）每次 solve 新建 24 维堆缓冲；
- 其余站点是该对象随返回值构造/搬运的同一缓冲。

要消除它，只有三条路，全部越界：

1. `QpSolution::x` 改 `Eigen::Matrix<double, 24, 1>` ⇒ **改公共结构体类型**（`dual_arm_qp_controller`、`test_*`、S3 golden 全受影响）；
2. 增加 `solve(const QpProblem&, QpSolution*)` 输出参数重载 ⇒ **改求解器接口契约**；
3. 在 `solveImpl` 内复用私有缓冲后再拷出 ⇒ 拷贝本身仍要分配，**不减反增**。

⇒ **BLOCKED**。`git diff -- src/dual_arm_qp_core` 里**只有一行用户既有改动**（`src/dual_arm_qp_core/include/dual_arm_qp_core/dual_arm_qp.hpp` 中 `dq_center` 之后的一个空行；mtime `2026-10-23 18:42`，且已存在于本轮开工快照 `/tmp/w2r3/git_before.diff`），本轮未新增任何 qp_core 改动。
