## 3. B-3-2 控制流证明（逐路径）

### 3.1 事实基线
- `transport_active = transport_ != nullptr && transport_->active()`（`:661`），而 `active()` 的定义是 **`traj_ != nullptr`**（`transport_task.hpp:182`）⇒ **`Hold` 状态下 `transport_active == true`**。这是"拒绝也要能回执"的前提，成立。
- `applyPendingStart()` 在 `:659`（`transport_active` 之前）。
- `update()` 内所有终止点（`:704/708/709`、`:724/725/726`、`:745/750/751`、`:761/765/766`、`:777/792/793`、`:810/811/812`、`:818/830`）**每一条都调用 `publishStatus()` 与 `writeCommand()`**，唯一例外是 `:640` 的 `readState()` 失败 `return ERROR`（在该点之前）。

### 3.2 结论表

| 检查项 | 结论 | 证据 |
|---|---|---|
| 状态发布是否仍执行 | ✅ 是。drain 插在 `:661` 之后，其后**每一条**返回路径都调用 `publishStatus()`；请求在 `update()` 后段被观测到，**同一拍**即发布（受抽稀影响，见 §4） | §3.1 终止点清单 |
| 是否存在重复推进 | ❌ 不存在。`advance(true)` 唯一调用点 `transport_task.cpp:254`（提交成功后）；`Hold` 时 `step()` 在函数首部早退（`state_ != Running && != Complete`），永远到不了 `:254`；`out.committed` 默认 `false`（`transport_task.hpp:131`）⇒ `q_cmd_` 不累加 | 同上 |
| 是否存在新的状态覆盖 | ⚠️ 有一处**同拍覆盖**（非缺陷，但必须声明）：drain 位于安全层（`:696` 臂距、`:713` D7、`:736` E8）**之前**，若同拍安全层也触发，则 `hold("collision")` 等会把 `failure_code`/`hold_origin` 改为控制器自身 ⇒ 回执 `result==1` 但 `hold_origin=="controller"`。**方向安全**（执行器 L3 要求 `origin=="executor"`，会失败 ⇒ 不会假确认），但必须新增 T-H15 固化 | `:703`/`:723`/`:744`/`:760` |
| 是否改变任务终止语义 | ❌ 不改变。只调用 `hold()`，从不调用 `abort()`/`fault()`；`Hold` 仍可被 `~/resume_transport` 解除 | `:650-655` |
| 是否破坏实时线程执行边界 | ❌ 不破坏。RT 侧新增 1 次 `exchange` + 1 次 `store`，无锁、无分配、无系统调用、无阻塞 | Rev.2 §7 |

### 3.3 由核查发现的**不等价点**（已修订，不强行判过）

**B-3-2 位置条款必须精确到"`:661` 之后、安全层 `:696` 之前"**，且**不能**改成"放进 `if (transport_active)` 分支内部"：
- 若放进分支内部，`Idle` 时（`active() == false`）drain 永不发生 ⇒ 槽被永久占用 ⇒ 后续请求永远 `busy`（**死锁式饥饿**，见 §5-S4）。
- 若放在 `:640` 之前，`readState()` 失败路径会先消费请求却无 `publishStatus()`（`:640` 直接 `return ERROR`）⇒ 回执丢失。

**另一个真实边界**：`:640` 返回早于 drain ⇒ `readState()` 失败期间请求滞留槽中（不丢，但暂不回执）。此时新请求得 `busy`；执行器 300 ms 超时 → abort。这是**安全方向**，但必须写入 R1a 验收（T-H17：注入一次 `readState` 失败，确认请求未被丢弃、恢复后仍得到回执）。

## 4. B-3-5 时序预算（含真实测量依据）

### 4.1 各段时长

| 段 | 值 | 依据 |
|---|---|---|
| A. 服务到达 → RT 消费 | ≤ 1 tick = **8 ms** | 服务回调在 executor 线程（CAS 入槽），`update()` 由 `controller_manager` 驱动，125 Hz（`dt=0.008`） |
| B. RT 消费 → 回执可见 | **0 ms（同拍）** 或 **(k·13)×8 ms** | drain 在 `:661`、`publishStatus()` 在其后 ⇒ 同拍调用；但 `:836` `if (++status_tick_ < status_period_ticks_) return;` 抽稀 ⇒ `status_period_ticks_ = lround(1/(0.008·10)) = 13`（`:316-317`） |
| C. `trylock` 丢失 | 每次 **+13 tick = 104 ms**，**次数无界** | `:837` `if (!status_pub_->trylock()) return;` |
| D. DDS 传输 | ≈ 1 ms（本机） | 实测经验值，R1a 须实测 |
| E. executor 观测 | ≤ 1 tick = **8 ms** | `executor_node.cpp:91` `create_wall_timer(cfg.dt)`；`:134` `sm_->tick(...)`；状态订阅为事件驱动（`:51`） |

### 4.2 结论

| 情形 | 总延迟 | 300 ms 是否覆盖 |
|---|---|---|
| m = 0（无 `trylock` 丢失） | **≈ 121 ms** | ✅ |
| m = 1 | **≈ 225 ms** | ✅（裕量 75 ms） |
| m = 2 | **≈ 329 ms** | ❌ **超出** |
| m ≥ 3 | 更大 | ❌ |

⇒ **300 ms 不是硬上界，不能称为 worst-case。** Rev.2 §6 T-H7 的"worst ≤ 208 ms"应下调为"**期望上界**"，且**不得**据此宣称 300 ms 有充分裕量。此为**阻断 R-1**。

### 4.3 修复（Rev.2.1 P-1）
`publishStatus()` 改为"**回执变更即强制发布**"（`status_published_ack_` 仅在 `trylock()` 成功后更新）：

| 情形 | 总延迟 |
|---|---|
| m = 0 | **≈ 17 ms** |
| m = 1 | ≈ 25 ms |
| 300 ms 可覆盖 | **m ≈ 34 次连续丢失**（裕量 ≥ 12×） |

修复后 300 ms 才具备"充分裕量"的资格；**在此之前不予判定通过**。

## 5. 六项阻断闭环的一致性核查

逐场景推演（S1…S9），标 ⚠️ 者需新增规则：

| # | 场景 | 结论 |
|---|---|---|
| **S1** | 连续请求（执行器每次都换新 `seq`） | ✅ 首个入槽、后续 `busy`；槽在下一 tick 被消费；无丢失 |
| **S2** | 超时后**同 `seq` 重试**（回执曾丢失） | ⚠️ **语义歧义**：控制器此时已 `Hold` ⇒ `result=2`；若执行器把 2 读成"未冻结"会在**已冻结**时 abort。修复见 Rev.2.1 P-2（判定须同时看 `state`/`origin`/`seq`）→ **阻断 R-2** |
| **S3** | `seq` 回绕 | ✅ 控制器不受影响（只需 `0` 与非 `0`）；执行器侧 `>=` 比较需在回绕时清零（Rev.2.1 P-3） |
| **S4** | `Idle` 下发请求 | ✅ 若 drain 在 `:661` 之后 ⇒ 会计入并回 `result=2`，槽不滞留。**若**把 drain 挪进 `if (transport_active)` 内部则**永久 `busy`**（已在 §3.3 禁止） |
| **S5** | 死锁 | ✅ 无锁、无 `wait`；唯一"卡住"是 RT 线程停止 ⇒ 槽滞留 ⇒ 执行器超时 abort（非死锁） |
| **S6** | 数据竞争 | ✅ `hold_ack_` 单原子；`hold_req_seq_` 单原子；`hold_origin_` 只在 RT 线程写、`publishStatus()` 也只在 RT 线程读 |
| **S7** | 错误确认（假阳性） | ✅ 同拍安全层覆盖 origin 为 `controller`，执行器 L3 要求 `origin=="executor"` ⇒ 不会假确认（需 T-H15 固化） |
| **S8** | B-3-1 × B-3-3 | ✅ 只有"应用成功"才写 `origin`；被拒请求不改 origin（`hold()` 未被调用） |
| **S9** | `reset()` 后 origin 残留 | ✅ `reset()` 置 `None` ⇒ 状态显示 `""`；不会被误读为外部冻结 |

**新引入的竞态/死锁/竞争/静默丢弃/错误确认：0 处**；但 S2 是**规则缺失**（非竞态），必须由 Rev.2.1 P-2 补齐后才能进入实现。
