## 1. 决策变量与问题形式

```
z = [dq (12); s (6)]
min   w_rel  || J_rel dq - alpha*e - s ||^2      (相对位姿任务, alpha = kp_rel*dt)
    + w_slack|| s ||^2
    + w_center|| dq - dq_center ||^2
    + w_reg  || dq ||^2
s.t.  dq_lower <= dq <= dq_upper                  (关节限位 + 速度, 硬约束)
      C z <= d                                       (通用不等式, 预留给 CBF)
```

- `e = log( (^L T_R)^-1 · target )`，`J_rel` 取 body(R 系)，来自 Step 0 的 `dual_arm_kinematics`。
- 相对任务带 slack：冲突时 QP 仍可解，且 slack 直接量化"为可行性牺牲了多少相对约束"。

### ⚠️ 实现中发现并修正的真实 bug
初版把任务 residual 写成 `J_rel dq + alpha*e - s`，**符号反了**。
因为 `edot ≈ -J_rel dq`，要 `e→0` 必须 `J_rel dq = +alpha*e`。
修正前调节实验误差 **2.76e-2 → 3.775（发散）**；修正后 **2.76e-2 → 9.7e-16**。
这正是 Step 0 把 `J_rel`/误差速率约定用有限差分钉死的价值。

## 2. Solver backend（D6）

- 抽象接口 `QpSolver`（`QpProblem` / `QpSolution`），控制器不绑死具体求解器。
- **已实现并测试：内置 ADMM（OSQP 同款算子分裂）**，零依赖、稠密、18 变量规模。
  - 支持 **warm start**（`QpProblem::x0`），控制器跨周期复用，是 125Hz 的关键。
- **OSQP backend 暂未接入**：本环境没有 osqp，且沙箱禁用 sudo，无法 `apt install`。
  - 安装命令：`sudo apt install ros-humble-osqp-vendor`
  - 装好后实现 `src/osqp_solver.cpp`，`find_package(osqp)` 自动启用；当前 `hasOsqpBackend()==false`。
- 安全兜底：`DualArmQp` 在返回前把 `dq` **投影回硬约束盒**（solver 容差 ~1e-6，硬约束不能靠容差）。

## 3. 测试（8/8 通过）

### 3.1 Solver 单元测试
| 测试 | 结果 |
|---|---|
| 无约束最小二乘 | x = b，16 iters |
| 盒约束投影 | x = clamp(b)，46 iters |
| 线性不等式（x1+x2≥1） | x = (0.5, 0.5) |
| backend 工厂 | `admm`，`hasOsqpBackend=0` |

### 3.2 双臂 QP
| 测试 | 判据 | 实测 |
|---|---|---|
| 相对位姿调节 | 误差收敛 | **2.758e-02 → 9.747e-16**，全程硬约束满足 |
| 硬约束 | \|dq\| ≤ vmax·dt，关节不越界 | 满足（vmax=0.5 rad/s 时 \|dq\|≤0.004） |
| slack 饱和 | 不可达目标 slack 显著 | 可达 2.0e-19 / 不可达 **2.84e-02** |
| 求解耗时 | < 8ms | **0.394 ms/solve**，max 48 iters（warm start） |

> 对 125Hz（8ms）预算，求解占 **约 5%**，余量充足。
