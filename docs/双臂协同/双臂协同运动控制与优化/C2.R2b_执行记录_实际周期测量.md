# C2.R2b 执行记录：用真实时钟差分测周期（修正 C2.R2 的漏洞）

> 日期：2026-10-08
> 代码：`dual_arm_qp_controller`（`period_monitor.hpp`, `dual_arm_qp_controller.cpp`, `test_period_monitor.cpp`）
> 起因：C2.9a 实测发现 **gz_ros2_control 传给控制器的 `period` 恒为 `1/update_rate`**，
> C2.R2 的"周期超期检测"因此形同虚设。

---

## 1. 问题

C2.R2 里控制器写的是：

```cpp
const bool deadline_fault = period_monitor_.update(period.seconds());
```

而 gz_ros2_control **不传实际经过时间**，它永远给 `1/update_rate = 8.000 ms`。
→ 在 Gazebo（以及任何"合成 period"的后端）里，超期检测**永不触发**。

## 2. 修复

`PeriodMonitor` 新增**时间戳差分**入口：

```cpp
bool updateFromTime(double now_s, double fallback_s);
//  - 首拍 / 时钟回跳 / 非有限 → 用 fallback（= period 参数）
//  - 其余 → dt = now - last_time   （真实经过时间）
bool lastWasMeasured() const;   // 本拍是否来自真实差分
```

控制器改为：

```cpp
const bool deadline_fault =
    period_monitor_.updateFromTime(time.seconds(), period.seconds());
```

统计日志同时打印两者，差异一眼可见：

```
period ms: arg=8.000 measured(mean=8.000 P95=... max=..., measured_flag=1) | overruns=...
```

## 3. 单元测试（8/8 通过，新增 3 项）

| 测试 | 内容 |
|---|---|
| `DifferentiatesAbsoluteTime` | 首拍回退 → 单调时间戳给实测 → 20ms 步长被判超期 |
| `BackwardsClockFallsBackToNominal` | 时钟回跳（仿真重置）→ 回退，不误报 |
| `NonFiniteTimeFallsBack` | NaN → 回退 |

## 4. 实测验证

### mock（真实墙钟）——修复**立刻产生价值**

```
period ms: arg=7.935 measured(mean=8.000 P95=8.330 P99=8.514 max=646.748, measured_flag=1)
           | overruns=1/2501 | solver P99=0.204 ms
D7 HOLD enter @ t=13.086s: control period overrun (arm=-1)
D7 HOLD exit  @ t=13.087s
```

抓到了一个 **646 ms 的真实 stall**（旧代码完全看不到），并按设计触发**双臂 HOLD**、下一拍恢复正常。

### Gazebo —— 修正 C2.9a 的判断

```
period ms: arg=8.000 measured(mean=8.000 P95=8.000 P99=8.000 max=8.000, measured_flag=1)
```

Gazebo 里 `measured` **也是 8.000 ms**——因为 `time` 是**仿真时钟**，控制器在仿真时间里确实是 125 Hz。
**RTF ≈ 0.46 的差距（墙钟 58 Hz）控制器看不到，也不该由它负责。**

→ **结论修正**：周期监控只在**真实时钟**（mock / 真机）上有意义；
Gazebo 只能验证单拍计算量与闭环动力学，**不能**验证墙钟实时性。这一点与 C2.9a §4 一致。

## 5. 边界

- 时钟回跳按"回退"处理（不重置 window 统计），仿真 reset 后统计会有一拍名义值；
- `period` 参数在 real `controller_manager` 下本身带抖动（实测 7.5~7.9 ms），
  所以**用实测值而非参数**是正确的选择。
