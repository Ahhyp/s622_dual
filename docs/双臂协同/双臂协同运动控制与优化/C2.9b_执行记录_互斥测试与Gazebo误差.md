## 1. C2.9b：JTC ↔ QP profile 互斥

### 做法

再用 `spawner` 尝试加载两个"探针"控制器：

| 探针 | 定义 | 期望 |

| `left_arm_jtc_probe` | 与 QP **相同的左臂 6 关节 + position 命令接口** | 必须被拒绝（接口已被 QP 占用） |
| `left_arm_jtc_vel_probe` | 同样关节但 **velocity** 命令接口 | 必须被拒绝（该 profile 里不存在 velocity 接口） |

## 2. Gazebo 相对位姿误差量化

新增 `dual_arm_qp_monitor` 节点：订阅 `/joint_states`，用**同一套 `dual_arm_kinematics`**
把第一帧记为 `^L T_R` 目标，之后持续报告误差 RMS/max（位置用 mm、旋转用 deg）。

实测（Gazebo QP profile，sweep 幅值 0.06 m / 周期 4 s）：

| 指标 | 数值 |
|---|---|
| 位置 RMS | **≈ 42 mm** |
| 位置 max | **≈ 60.4 mm**（= sweep 幅值） |
| 旋转 RMS | **0.0007°**（几乎完美） |
| 旋转 max | 0.0035° |

**旋转保持完美，位置几乎完全不跟踪** —— 且 max 恰好等于 sweep 幅值，说明**实际相对位移基本没动**。

## 3. 根因：Gazebo 位置伺服增益被固定在 0.1（τ = 10 s）

gz_ros2_control 日志：

```
[gz_ros2_control]: The position_proportional_gain has been set to: 0.1
```

它是 `gz_system.cpp` 里 `declare_parameter` 的**节点参数**，默认 **0.1**，
即 `q̇ = 0.1·(q_des − q)` → **时间常数 10 s** —— 反馈回路再怎么写也追不上 4 s 周期的指令。

**尝试过三条配置途径，全部无效**（日志始终 0.1）：

| 途径 | 结果 |
|---|---|
| `<joint><param name="position_proportional_gain">` | ❌ 被忽略 |
| `<hardware><param name="position_proportional_gain">` | ❌ 被忽略 |
| 插件 yaml 里的 `gz_ros2_control: ros__parameters:` | ❌ 被忽略 |

（已把无效途径写进 xacro 注释，避免后人重复踩。代码里保留 `arm_position_gain` 参数，
但**当前版本无效**。）

### 影响与含义

- ✅ Gazebo position profile 仍可用于验证：**接口契约、profile 互斥、D7 安全层、CBF 避障、控制器生命周期**
- ❌ **不能**用于验证**跟踪精度/相对位姿精度**——误差被慢伺服主导，与 QP 无关
- 若要拿到可信的仿真精度数字，需要：
  1. 让增益真正生效（重编 gz_ros2_control 改默认值，或找到正确的参数入口）；
  2. 或加一个 **velocity 接口的 Gazebo profile**（QP 需要速度输出模式；与 D2 的 position 输出冲突，仅限仿真验证用）；
  3. 或直接用**真机**（C5）。
