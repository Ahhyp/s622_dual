## 1. "五类归属合计 27608" vs "steady 27435" 的窗口差异

同一 B′ 前（对照）运行 `driver_ctrl_moving.txt` 的阶段表：

```
init   12      78,542 B
warmup 159    152,028 B
steady 27435  23,609,184 B
done   2        4,568 B
----------------------------
合计   27608
```

| 归属类 | 次数 |
|---|---|
| OSQP | 26940 |
| OWN_core | 655 |
| libstdc++ | 1 |
| libc | 6 |
| other_module | 6 |
| **合计** | **27608** |

⇒ **27608 − 27435 = 173 = init 12 + warmup 159 + done 2**，与 steady 的差**完全由非测量阶段构成**：

- `init 12`：进程启动期（DDS/库初始化）
- `warmup 159`：首次 `solve()`（OSQP 工作区创建）——被刻意排除在 steady 口径外
- `done 2`：**账本自身写出**时的文件缓冲（`fopen`/`fprintf`）

**口径定义**：`steady` = 排除 init / warmup / done 后的 638 次 `solve()` 窗口。分母固定 638。

### 1.1 运行间抖动（必须一并记录）

`driver_prod_static.txt` 的同口径总数为 **27606**（libc 4 次），对照片为 **27608**（libc 6 次）⇒ **总数抖动 ±2，全部来自 libc 内部调用**；**两文件的 `steady` 均为 27435，完全一致**。

⇒ 结论：可比的稳定量是 `steady`（27435 / 638 = **43.002 次/solve**），总量差值不构成归属漂移。

## 3. B′ 前后计数 / 阶段 / 分母一致性

| 阶段 | B′ 前（ctrl） | B′ 后（bprime） | 差 |
|---|---|---|---|
| init | 12 | 12 | 0 |
| warmup | 159 | 158 | **1** |
| steady | 27435 | 26797 | **638** |
| done | 2 | 2 | 0 |
| **合计** | **27608** | **26969** | **639** |

- **分母一致**：两文件由同一 `l1_driver`、同一 638 次 `solve()`、同一参数（`w_center=1e-4 / kp_obj=20 / w_obj=1 / w_slack_obj=1e3`）产生。
- **639 = 638 + 1**：`steady` 减少 638（1.00/solve，即 `solution.x.resize(24)`）；`warmup` 减少 1（warmup 那次 `solve()` 同样做一次 resize）。两者相加恰为总数差。
- 归属维度：`OWN_core 655 → 16`（−639）、`OSQP 26940 → 26940`（**0**）、`UNKNOWN 0 → 0`。
- 因此 **B′ 的收益 = 1.00 次/solve，不多不少**，与"每 solve −1.000"的结论一致。
