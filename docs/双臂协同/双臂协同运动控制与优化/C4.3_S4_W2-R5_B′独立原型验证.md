```cpp
// src/dual_arm_qp_core/include/dual_arm_qp_core/qp_types.hpp（原型副本内）
using QpVec = Eigen::Matrix<double, Eigen::Dynamic, 1, 0, 24, 1>;

struct QpSolution {

    ...
};
```

**最小补丁 = 1 行类型别名 + 1 行成员类型**，其余源码零改动。

## 6. 兼容性风险（必须在正式审批时正面回答）

1. **ABI 破坏**：`QpSolution` 位于已安装的公共头（`install/include/dual_arm_qp_core/qp_types.hpp`），`sizeof` 48 → 240 且无版本化符号 ⇒ **所有下游包必须重编译**，不能只换 `.so`。
2. **容量上限成为隐式契约**：`MaxRows = 24`，与 `src/dual_arm_qp_core/src/dual_arm_qp.cpp:174` 的 `constexpr int kNumVars = 24;` 是同一个数但**分处两个文件**。任何未来把决策变量扩到 >24 的改动会踩 Eigen 断言/未定义行为 ⇒ 落地时必须把 24 提升为头文件常量（如 `kQpMaxVars`）并让两处引用同一常量，加 `static_assert` 与运行时守卫 + 明确错误码。
3. **按值返回体积增大**：`QpSolution` 由 48 B 增到 240 B，返回/拷贝成本上升；实测 `mean solve_us` 无可测差异（本候选不改变算法路径）。
4. **收益量级有限**：只消除 **1 次/solve、192 B/solve**；剩余 42 次/solve 全在冻结第三方 OSQP 内 ⇒ **B′ 不能把"控制路径零分配"作为卖点**，只能作为"自有胶水层已无每-solve 分配"的局部结论。
5. **未覆盖**：`QpProblem` 侧的 Eigen 临时对象、`Eigen::JacobiSVD`（仅在状态发布路径，10 Hz）、`t_traj` 轨迹对象均未纳入本候选。
