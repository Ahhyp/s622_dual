## 3.2 相位顺序检查（每个出口的 mark 序列）

| 出口 | mark 序列（相位号 → 行号） | 严格递增？ |

- 每个出口的 mark 行号与相位号同时单调递增 ⇒ 相位区间**互不重叠**，C3（`sum(P1..P6) ≤ cycle_us`）由构造保证（实测亦为 0 违例）。
- 相位「关闭」语义：`mark(p)` 记录的是**从上次 mark（或 `begin`）到本次 mark 的增量**，即标记的是**前一个**相位区间的结束，故函数命名与注释在每处都写明所属相位。

## 3.3 与冻结设计 §2 相位边界的逐条对照

| 相位 | 设计边界（设计文档行号） | 现盘行号 | 语句 |
|---|---|---|---|
| P1 | `readState()` 返回（`:691`→`:1019`） | 720 | `markTimingPhase(0);  // P1: readState()` |
| P2 | `applyPendingStart()` + hold drain（`:714-760`） | 778 | `markTimingPhase(1);  // P2: command dispatch + applyPendingStart() + hold drain` |
| P3 | `collision_->distance` + `health_.evaluate` + E8（`:790-841`） | 886（正常）/819,838,868（早退） | `markTimingPhase(2);` |
| P4 | `transport_->step()`（`:858`）或 IDLE `qp_->solve()`（`:894`） | 905 / 945 | `markTimingPhase(3);` |
| P5 | `clampToLimits` + `writeCommand`（`:864-867`/`:907-908`） | 915 / 963（+早退 823,847,872,895,952） | `markTimingPhase(4);` |
| P6 | `publishStatus()`（`:882`/`:920`→`:924`） | 931 / 976（+早退 828,849,878,900,954） | `markTimingPhase(5);` |

结论：六个相位的**边界语句位置与冻结设计一致**；设计行号是冻结时的行号，实施后因插入 22 处 mark 而整体下移（`begin()` 由 `:690` → 709 即 +19 行）。
