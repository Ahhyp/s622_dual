## 2. 方案 A（已批准）如何落实为代码

| W6-0 实测事实 | 代码中的处置 |
|---|---|
| 插件**不能**初始未附着（`initial_attach` 在 6.16 不存在） | `beginStartupGuard()` 无条件认为"可能已焊接"，必须先 `RequestDetach` 并**确认** `detached`；确认前 `requestAttach()` 一律拒绝（`attach_refused_before_startup_release`） |
| 启动焊接出现在 server 就绪后 **2.165–2.201 s** | 启动释放窗口 `weld_startup_release_timeout_s = 5.0`（覆盖 server 启动，而非一个控制周期）；该值标 `[待标定]` |
| 4 次运行中 **2 次瞬移 0.475 m** | 无法从"已附着"推断"没瞬移"，因此 attach 确认时**必须**有调用方给的瞬移测量；未测量 → `attach_snap_unmeasured`（**"未测量"不等于"没瞬移"**） |
| 超过 2 mm 的 attach 是失败而非"带瑕疵的成功" | `attach_snap_exceeded` 且置 `detach_required_`：不 detach 就不许重试 |
| attach/detach 是订阅方主题、`ign topic -l` 看不到 | 主题名来自插件 debug 日志的实测值，写进配置与默认值，不做自动发现 |
| 重复请求幂等（`Already attached/detached`，rc=0） | 重试沿用同一 attach；失败由"未确认"而非"命令报错"判定 |

状态机（每个控制周期由 `tick(now_s)` 给出必须执行的动作）：

```
启动 ──RequestDetach──► Wait ──(state=detached，新鲜样本)──► Confirmed(startup_released) ──┐
                          └──(窗口 5 s 用尽)──► Failed(weld_not_released / weld_state_unknown) │
                                                                                            ▼
                                     requestAttach ──► RequestAttach ──► Wait ──(state=attached)──► 2 mm 判定
                                                                                 ├─≤2 mm─► Confirmed(attached)
                                                                                 ├─>2 mm─► Failed(attach_snap_exceeded) + 需先 detach
                                                                                 └─未测──► Failed(attach_snap_unmeasured)
                                                                                 (未确认且未超次数►重发；超次数►Failed(attach_not_confirmed))
```

## 3. 失败码（**均未注册**，需 D4 批准，本轮不写入注册表）

| 码 | 触发 | 恢复 |
|---|---|---|
| `weld_state_unknown` | 窗口内没有任何新鲜的焊接状态样本 | 人工/上层重试；不得当作 detached |
| `weld_not_released` | 状态一直是 `attached`，启动焊接没被释放 | 停止，人工排查插件/桥接 |
| `attach_not_confirmed` | 有界重试后仍未收到 `attached` | HOLD，重新对位 |
| `attach_snap_exceeded` | 已附着力但瞬移 > 2 mm | **必须先 detach**，再重新接近 |
| `attach_snap_unmeasured` | 已附着力但没有瞬移测量 | 同上（证据不足即失败） |
| `attach_refused_before_startup_release` / `attach_refused_weld_state_unknown` / `attach_refused_weld_still_on` | 前置条件不满足时的拒绝 | 满足前置后重试 |

> 现状：`src/dual_arm_transport_executor/src/state_machine.cpp` 的注册表**未新增**任何码（D4 未批准）；上述码目前只存在于 `AttachClient::outcome()` 字符串中。W7 接线时必须先获批注册，否则会出现"未登记码"。

## 5. 与冻结契约的关系

- **§14.3 C3（attach 不瞬移 ≤2 mm/100 ms）**：直接被用作 `weld_max_snap_m` 默认值；本轮**只做单测**，没有在 Gazebo 里测真实瞬移，因此 **C3 本轮既未通过也未失败**——它属于 W7 的端到端测量。
- **§14.3 C5（不得用共享库字符串当行为证据）**：本轮的插件行为证据来自 W6-0 的运行时日志；xacro 展开只是静态结构检查，不被当作运行时证据。
- **D4（12 个 `registered=false` 失败码）**：本轮没有注册任何新码（见 §3），也没有修改注册表。
- **W4 台账**：`S4-T18/plugin_probe` 仍是 `[待标定]`、证据态未改；本轮不宣称 S4-T18 通过。

## 6. 未做与阻断（诚实边界）

1. **没有**在 Gazebo 里 spawn 这个新 xacro 的机器人 + `c43_sample` 并亲手 attach/detach：这需要把 `ros_gz_bridge` 的 `ignition.msgs.Empty`/`StringMsg` 映射接上、并实现位姿采样（下一项），属 **W7**。
2. **没有**实现瞬移测量源（订阅 `/world/c43_s4_world/pose/info` 或 `/model/…/pose` 并算 ‖Δp‖）：`AttachClient::setMeasuredSnap()` 目前只有测试在喂值；接线时必须有真实采样器，否则 attach 永远停在 `attach_snap_unmeasured`（这是有意的失败关闭）。
3. **没有**把 `AttachClient` 接进 `executor_node`/状态机：W6 的文件范围不含 `executor_node.cpp`（那是 W7 的 W7–W9 表首行）。
4. **原 xacro 与副本的漂移风险**：冻结要求"复制、不改原文件"，故两者会各自演化；建议 W7 加一条 `diff` 守卫（副本 = 原文件 + 已知增量），本轮未加。
5. **启动竞态仍未消除**：启动焊接本身无法关闭，只能"尽快释放 + 校验"；2.17–2.20 s 窗口内若发生 0.475 m 瞬移，依赖 detach 后的位姿校验来发现（采样器未接线，见第 2 项）。
