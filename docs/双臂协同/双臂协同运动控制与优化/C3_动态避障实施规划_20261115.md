# 动态避障实施规划（2026-11-15）

## 要实现什么

在双臂保持共同抓持关系的同时，根据障碍物的位置和运动方向调整运动；没有可行运动时停止。先在仿真中用已知障碍物做验证，再接视觉。S6 性能消融按用户安排延期，本计划中的少量正反例用于验证避障功能。

当前起点是 Git 提交 `94853d6`。C43 已完成物理搬运、暂停恢复和一批停车验证，8 mm 附加停车余量仍只适用于已测场景。主动改道会改变工况，不能直接沿用之前的停车结论。

## 分步执行

| 步骤 | 做什么 | 怎样判断通过 |
|---|---|---|
| 1 数学与代码检查 | 复跑 C2.7；加入障碍速度项，验证正负号、单位、数据过期和非法输入 | 静止障碍退化为原公式；接近的障碍要求更早避让；过期输入明确无效 |
| 2 离线双臂试验 | 在现有 QP 中加入已知运动障碍的约束，使用理想关节跟随；记录距离、相对误差和求解结果 | 有避让空间时产生有效约束并维持距离；不可行时报告失败，不能忽略约束继续走 |
| 3 静态障碍仿真 | 建立实际 URDF、手指和被搬物体的距离覆盖；先用固定障碍，选择有可行绕行空间的场景 | 通过新路径几何检查和真实物理接触检查，完成抓持、改道、落座与释放 |
| 4 移动障碍仿真 | 用原生仿真位置和已知速度作为输入，加入新鲜度检查与有限时间外推 | 接近、远离、横穿、停住及输入中断均有可追溯结果；危险或过期时受控停止 |
| 5 视觉输入 | 再接检测、坐标变换和速度估计，测延迟与误差 | 使用测得误差和延迟配置余量，不能把仿真真值结果算成视觉结果 |

本次先执行步骤 1 和步骤 2 的首个最小试验。它只证明约束在 QP 中起作用，不声称 Gazebo 动态搬运完成。后面按依赖逐步实施；本表不是每一步都要再次请求许可。

## 数学和接口约定

控制器求解的是每拍关节增量 `dq`，控制周期目前为 8 ms。设表面距离为 `d`，要求的间距为 `d_safe`，`h = d - d_safe`；`g` 是距离对 12 个关节的梯度；`n` 从障碍指向机器人，`v_obs` 为障碍最近点的世界坐标速度。

约束写为：

```text
-g · dq <= dt × (alpha × h - n · v_obs)
```

右侧的速度项使向机器人靠近的障碍收紧约束。旋转障碍需要最近点速度，不能直接拿中心速度代替。首轮仅用平移球体和一个 TCP 点做离线数学检查，明确不覆盖全机械臂与被搬物体。

障碍位置、速度、法向和关节状态必须使用一致坐标系与时间。过期、未来、非有限数据，以及无法确定法向的穿透/重合状态均不生成有效约束；接入控制器时必须进入已验证的停止流程，不能悄悄当作“无障碍”。

距离查询和梯度计算先放在非实时试验中。后续接入控制器前，需要确定计算位置、有限大小的数据传递、检查时效和失败处理，不把通用 FCL、文件操作或动态内存分配直接塞进实时更新。

多个障碍需要同时保留附近的约束，避免只看最近一对而漏掉另一侧。每拍约束、命令候选和实际执行后距离都要记录。CBF 的一阶预测不等于连续碰撞证明，位置伺服的跟随延迟也必须单独验证。

## 首批试验和记录

1. 重新运行原 C2.7 臂间 CBF 测试，保留原输出。
2. 对新速度项做静止、接近、远离、错误时间戳和非法参数测试。
3. 在同一个离线双臂 QP 中比较移动球体约束关闭/开启。关闭只在离线运行，用于确认场景确实会侵入要求间距；开启必须实际改变关节运动，并统计最小距离与相对抓持误差。
4. 记录求解失败次数和每次残差。不能把未收敛的输出当作成功避障。

日志放在 `log/c3_dynamic_20261115/`，代码、配置、简短结果和证据摘要留在仓库。正式 Gazebo 试验之前再固定物体/障碍尺寸、速度、距离阈值、重复次数和退出条件。首轮数学测试中的数值只为构造可复现例子，不批准物理停车余量。
