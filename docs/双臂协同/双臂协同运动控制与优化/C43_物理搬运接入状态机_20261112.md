# C43 物理搬运接入既有状态机（2026-11-12）

本轮将无 weld、四指固定驱动力的物理搬运接入原 `c43_s4_executor`，采用显式参数 `plant_profile=physical_contact`。默认 `ideal_weld` 保留原逻辑。复用 `TransportStateMachine`、`PhaseDriver`、`HoldRequester`、`AbortRequester` 和 `ArtifactWriter`；Python 是动作执行/观测适配器，阶段推进在 C++ 核心完成。

这是新增物理配置的集成验证，不是原 W7 全矩阵重新验收，也未完成 W8/W9 或真机安全验证。

## 状态与推进条件

`IDLE → APPROACH → GRASP → LIFT → TRANSPORT → LOWER → RELEASE → RETREAT → COMPLETE`

| 状态/边界 | 执行与观测要求 |
|---|---|
| IDLE→APPROACH | 有效关节状态、源支撑接触、无机器人接触、双臂JTC有效、QP未激活、手指JTC未激活；接触证据新鲜 |
| APPROACH | 复用已验证的张指、右臂先行、双臂分次下降接近；完成观测须对应当前命令 |
| GRASP→LIFT | 四指实际接触，完成闭合/检查；STRICT切换并核对QP独占12个臂position接口，臂JTC停用，手指JTC未激活 |
| LIFT/TRANSPORT/LOWER | 原QP负责搬运；持续检查四指接触与已核验的臂归属标志；控制器状态、心跳与既有保护继续生效 |
| LOWER→RELEASE | 目标支撑接触且物体距目标≤10 mm；有限0.2 mm落座，至少执行1 s后且仍有支撑接触才请求停止；必须收到新鲜、可解析、active、executor来源、seq=1、applied的HOLD ACK |
| RELEASE | 适配器独立再检查真实目标接触；reset QP、切回臂JTC、确认支撑后张指；必须有张指反馈 |
| RETREAT→COMPLETE | 执行原退离/回位路径；最终目标支撑持续接触、无机器人接触、目标误差≤10 mm |

QP相位使用现有PhaseDriver允许的 `lift, settle, transport, lower, settle_post`，时长分别6/5/8/6/2 s。`settle` 保持LIFT，`settle_post` 保持LOWER；不扩展冻结相位名白名单。轨迹为抬升60 mm、Y平移120 mm、下降60 mm，再有限落座。四指搬运驱动力各5 N，无FT闭环。

## 适配协议与故障语义

新增类型化 `ContactCommand` / `ContactEvidence`。命令绑定task_id、单调command_id、phase；观测另有单调evidence_seq、观测/原生接触时间戳。C++拒收其他任务、错误命令和过期序号，不接受Python直接发布“下一状态”。默认接触新鲜度0.1 s；目标支撑与四指判定要求最近5条原生接触消息连续满足。

状态机锁存HOLD/FAULT/ABORT后发STOP，取消未完成臂JTC动作；若已提交QP轨迹，走既有AbortRequester并等待权威控制器状态。没有确认则升级为故障，不把服务accepted当已停止。Abort轮询间隔50 ms，避免在控制器状态更新前耗尽有限重试。失败后保留夹持至实验清理；清理时归零驱动力仅用于销毁这一轮仿真，不是空中失持恢复策略。

本配置每个独立实验只运行一个任务。`~/reset` 明确拒绝尚未验证的物理恢复操作；需检查锁存结果后重新启动隔离实验。W9的在线恢复和重新抓取仍待做。

## 本轮问题与处理

1. ROS Humble的rclcpp回调类型推导不支持这些泛型lambda，首次编译失败；改为显式消息、服务和SharedFuture类型后通过。
2. `physical_r1` 在GRASP→LIFT后因 `executor_lost` 停止，随后停止确认失败。实验启动原来只桥接世界专用时钟，QP节点的心跳接收使用节点ROS时钟，而update使用Gazebo时钟。新增仅物理executor配置启用的世界时钟→`/clock`桥接，保留世界专用时钟和既有2 ms配置，未放宽心跳阈值。失败原始日志完整保留。
3. `physical_r2` 已完成QP抬升和横移，但下降途中接触观测新鲜度守卫触发HOLD。原生接触时间戳仍每2 ms连续；Python旧订阅缓存了50条clock、100条JointState/pose，控制守卫可能消费排队旧值。物理executor配置改为深度1获取最新观测，C++状态/证据队列也改为1；新增接收端sim、证据stamp和原生contact_stamp逐条日志，保持0.1 s新鲜度阈值。
4. 正式PhaseDriver不接受控制器诊断的 `hold/seat` 名称；使用已有 `settle/settle_post` 语义，不修改旧白名单。
5. `physical_r3` 走到LOWER并匹配HOLD ACK，但恢复JTC后样件约高于目标支撑面1 µm，原生支撑接触消失；RELEASE独立守卫拒绝张指，结果FAULT/release_failed。此前首触即HOLD缺少切换所需的落座余量。改为在原2 s/0.2 mm的有限落座轨迹至少执行1 s（smoothstep参考约0.1 mm）后，仍有支撑接触才发HOLD；停止后先等待2仿真秒稳定，再reset/切JTC。仍要求切换后真实支撑接触，不放宽松爪条件。
6. `physical_r4` 已保持目标支撑并成功松爪进入RETREAT，但JS驱动的证据发送出现约0.106仿真秒间隔，触发新鲜度HOLD。将接触观测发送从JointState回调解耦为独立20 ms墙钟定时器；原生contact时间戳仍用于0.1 s守卫，不靠重复旧接触续命。检查还发现原同步JTC helper未处理STOP：补充同时取消左右两个动作，等待两个权威动作结果终态后才确认STOP；在JTC归属阶段不再向已inactive的QP请求不可确认的ABORT。新增显式retreat-abort注入验证该路径。
7. `physical_r5` 已回位到末段，但再次出现约0.14仿真秒证据空档，HOLD后两个JTC结果均为CANCELED，停止修复得到实测。原生接触stamp仍连续2 ms，Python接触处理有约0.19墙钟秒暂停。离线重建65,138条接触/状态记录，单次全堆GC扫描耗时0.092～0.101 s，即使回收0条也有开销；这支持GC为潜在来源，但没有当时的GC trace，不能断言该次暂停的唯一根因。限定本物理实验进程在运行期间暂停自动循环GC，清理后恢复；记录 `python_gc_policy.json`。第5/6轮模型、场景、控制器、候选与任务输入归一化后相同，见 `r5_r6_input_parity.json`。这不是Python硬实时保证。
8. 下放结束不代表目标支撑已建立；沿用有限落座+原生支撑接触+精确HOLD ACK条件，禁止COMPLETE直接穿越到松爪。

## 构建与运行

在容器中构建：

```bash
source /opt/ros/humble/setup.bash
cd /workspace
colcon build --merge-install --packages-select dual_arm_transport_executor gz_launch --cmake-args -DBUILD_TESTING=ON
source install/setup.bash
colcon test --merge-install --packages-select dual_arm_transport_executor
```

宿主机无GUI运行（输出目录必须尚不存在）：

```bash
docker exec -w /tmp s622_yep bash -lc 'source /workspace/install/setup.bash; ros2 run gz_launch c43_run_contact_transport.py --backend qp-executor --out /workspace/log/c43_executor_20261112/physical_r6'
```

`qp-executor` 默认显式2 ms物理步长；其他后端默认仍为原5 ms。可用 `--physics-step-ms 2` 显式写出。入口会清除继承的C43实验环境，保留独立ROS域/IGN分区及每轮输入快照。GUI不是本轮验证的一部分。

负例入口加 `--inject-executor missing-grasp` 或 `--inject-executor missing-support`，只能用于qp-executor。前两种仅屏蔽发送给状态机的对应观测，原生接触原始记录不修改，因此是“观测缺失”测试，不能宣称是物理掉落实验。另可用 `--inject-executor retreat-abort`，在退离命令开始后1仿真秒主动ABORT，核对两个JTC动作均取消终止。
