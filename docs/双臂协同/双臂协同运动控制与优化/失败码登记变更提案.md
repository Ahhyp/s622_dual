# 失败码登记变更提案（12 项，**未批准前维持未冻结**）

> 现状：`src/dual_arm_transport_executor/src/state_machine.cpp:116-130` 有 **12** 个
> `registered == false` 的失败码。它们在生产路径上会被真实写入 `failure_code`（不是占位符），
> 但**没有**任何已批准契约定义其语义。本提案请求一次性登记（或拒绝），**未批准前不改任何冻结文档**。
>
> 一个重要的安全属性（已实现，与是否登记无关）：`protectionOf()` 对未知码返回 `Protection::Hold`
> （`state_machine.cpp:176`），因此**未登记的码绝不会退化为"无保护"**。

## 1. 登记语义的四个字段

`注册名 · 触发条件 · 保护等级 · 恢复路径`。恢复路径统一遵循既有规则：HOLD/FAULT/ABORT 都是**锁存**，
`resume` 只被 HOLD 接受；FAULT/ABORT 必须 `reset` 后重新 `start`（`state_machine.cpp:243`、`resume` 段）。

## 3. 3 个碰撞码的专项审查（要求重点）

| 问题 | 结论 |
|---|---|
| 与 S3 的 `collision` / `swept_collision` / `insufficient_clearance` 是否重名？ | **语义重叠、名字不重**。S3 三码来自 `dual_arm_collision` 的规划侧判定；新三码来自**运行期 guard**（每控制周期、双臂/物体/扫掠三种口径） |
| 是否有同一事件被两个码描述的风险？ | **有**：臂-臂距离过近时 S3 会报 `collision`，运行期会报 `collision_arm_arm`。二者触发点不同（规划 vs 运行），但下游若按名字聚合会重复计数 |
| 是否必须新增三码？ | **建议合并为已登记的三码 + 一个 `_runtime` 后缀**，或保持三码但在登记文档中写明"运行期口径，非规划口径"。**本轮不擅自合并**（会改变已交付的 R4 证据） |
| 恢复语义 | 三者均 HOLD；但 `collision_sweep` 的拒绝是"路径不可行"，resume 只会再次触发 ⇒ 实际有效恢复是 `reset + 重新规划`。**登记文档必须写明这一点**，否则会被误读为可 resume |
| 触发阈值来源 | 与 `collision_d_stop_` 同源（控制器侧参数），不是新阈值；代理球半径 `0.06 m` 是既有 `DualArmCollisionModel` 默认值 |
