## §0 结论（一句话）

W1 的接线目标达成：控制器现在**真的读取并使用**物体任务三参数，`update()` 每周期从
`dual_arm_object_task`（唯一数学定义）取 `AnchoredObjectTask`，按冻结符号契约组

W0 记录的缺陷是「三键在 `src/`+`include/` 中 0 命中」；现在它们在启动日志里被打印，
并且 `w_center` 来自 yaml（该次用的是基础 profile `0.01`，见 §4.6）。

### 3.2 库真的链接了唯一数学定义

```
$ objdump -p install/lib/libdual_arm_qp_controller.so | grep NEEDED
  NEEDED               libdual_arm_object_task.so
  NEEDED               libdual_arm_qp_core.so
  NEEDED               libdual_arm_kinematics.so
```

`transport_task.hpp:9-14` 与 `.cpp` 中没有任何锚定/前馈/误差的重新推导：位置误差、速率映射、
`adjoint` 全部来自 `dual_arm_kinematics::anchoredObject*` / `decoupled*`，任务对象来自
`dual_arm_object_task::AnchoredObjectTaskBuilder`。满足了 R24 与 W0 的「同一算法只有一份定义」。

### 3.3 符号契约在装配点是显式且被测试锁死的

`transport_task.cpp:97-101` 的 `step()` 装配点：

```cpp
row.J              = task.J;          // d(e_O)/dq
row.e              = -task.e;         // QP 槽位要的是「剩余误差」
row.body_twist_ff  = task.v_ff;       // 前馈是 +v_d，不是 -v_d
row.valid          = task.inputs_ok;  // 绝不用 anchor_ok
```

S4-T4 用「只改一处」的方式验证这三行不可拆：`2v_d` 严格翻倍（2.63e-17）、正负反称
（1.35e-17）、方向点积为负。若把 `row.e` 或 `row.body_twist_ff` 的符号单独翻掉，T4 立即失败。

### 3.4 相对任务仍用冻结闭链，不是现算

`transport_task.cpp` 在 `latch()` 里取 `builder_.leftTrightGrasp()`（= `G_L⁻¹ G_R`）作为
`solve()` 的第二参，之后永不重算。S4-T3 断言它与 builder 的值逐元相等
（`max|Δ| == 0.0`），并**记录**它与 `kin_.leftTright(q0)` 在本 fixture 上只差 2.65e-13
——这正是 S2 冻结基线的含义（在标定构型上两者重合），而两者在运动过程中会分离；
控制器只用冻结值，所以不随测量误差漂移。

### 3.5 轨迹钟只在 committed 时前进（P0-1）

`transport_task.cpp` `advance(bool committed)`：`committed` 为真才 `t_traj += dt`，并钳在
`duration()`。S4-T3 跑 40 个周期全 committed，`t_traj = 0.3200 = 40 × 0.008` 精确相符。
反方向证据：S4-T5 的拒绝周期 `committed == false`，`t_traj` 不动（拒绝路径直接 `hold()` 返回）。

### 3.6 HOLD / RESUME（P0-1 后半）

- HOLD 冻结 `t_traj` 与 `q_cmd`，不自动恢复（`state_ == Hold` 时 `step()` 直接返回冻结值）。
- `resume(q)` 三项检查（`e_O` ≤ 5 mm / 2°、越限、`row.valid`），通过则从 `t_traj` 继续；
  未通过则把**剩余轨迹整体平移** `Δ = p̂ − p_d`，只改 `T_d.translation()`，
  `v_ff` 因平移不变而**逐位不变**（§4.2.2 的要求）。
- 连续 2 次未通过 → `abort("resume_failed")`。
- 这部分的端到端测试在 W7（S4-T19），W1 只落实现（规划就是这样分的）。

### 3.7 E6：近 π 在**求解前**拒绝（P0-5 的 E6）

`transport_task.cpp` `sample()` 计算 `e_obj_rot_rad`，若 `> cfg_.obj_rot_error_refuse_rad`
则置 `refusal_code = "object_error_near_pi"`；`step()` 见 refusal 立即 `hold()` 返回，
`dq` 保持零、`iterations` 保持 0。冻结阈值 `3.0915926535897933 = π − 0.05`（S3 收口决定）。

## §4 与规划的偏差（必须披露）

### 4.1 库 target 改名（必需，非设计选择）

`rosidl_generate_interfaces(${PROJECT_NAME} ...)` 会创建一个名为 `dual_arm_qp_controller` 的
**custom target**，与同名 `add_library` 冲突：
`add_library cannot create target "dual_arm_qp_controller" because another target with the same name already exists`。

处置：库 target 改名 `dual_arm_qp_controller_lib`，并用
`set_target_properties(... OUTPUT_NAME ${PROJECT_NAME})` 保持安装出的文件仍是
`libdual_arm_qp_controller.so` —— 插件 xml 的 `<library path="dual_arm_qp_controller">` 因此
无需修改，已实测该文件存在且 pluginlib 可加载。**对外接口未变。**

### 4.2 msg/srv 的两处命名约束

- `float64`：ROS 2 IDL 没有 `double` 基本类型；写成 `double` 会得到
  `rosidl_adapter.parser.InvalidResourceName: 'double' is an invalid message name`。
- 字段名必须小写：`start_world_T_object`（srv）→ `start_world_t_object`。注意
  `TrajectorySpec::start_world_T_object`（C++ 成员，S3 定义）**未改名**，两者名字不同是刻意的。

### 4.3 E2 / E4 / E8 未在 W1 落地

规划 §4.7.1 列了 E1–E8 八条，§7.1 把对应测试（S4-T21/T22）排在 **W3**。W1 只落：
E1 越限、E3 solve_fail_streak、E5 row 非法、E6 近 π、E7 臂距。
E2（`q_state` 过期）、E4（`update()` 间隔）、E8（执行器心跳）需要额外的订阅/心跳接口，
按规划留到 W3 —— **W1 的控制器目前不能声称具备完整的本地故障保护**。

### 4.4 用的是 3 参「外置行」重载

规划文字写「调 4 参重载」，实际 `dual_arm_qp_core` 提供的是
`solve(q, left_T_right_target, const ObjectTaskRow&)`（3 参，W2 时加的）。语义与规划一致，
方案文字里的「4 参」指旧的三任务行写法。**未改 QP 核心。**

### 4.5 接口放在控制器包内

`src/s622_task_interfaces` 在仓库里不存在（W0 清点已记录）。规划 §6 的 W1 文件清单本身
就把 `srv/`、`msg/` 列在 `dual_arm_qp_controller` 内，故照此实现；若后续需要跨包共享，
再拆独立接口包。

### 4.6 基础 profile 的 `w_center` 仍为 1e-2

规划 §6 只要求改 `config/dual_arm_qp_gazebo_controllers.yaml`（已改 1e-4 + 注记）。
`config/dual_arm_qp_controllers.yaml:34` 保留 `0.01`：该 profile 在 W1 范围内
物体任务恒关（IDLE 强制 `w_obj=0`），而 S3 legacy 逐位回归（S4-T3/T5c 的祖先）就是在
`w_center=1e-2` 下建立的；此时改它只会让「相对任务」的历史对比失去基线。
Gazebo 场景（S4.2）才用 1e-4。

### 4.7 抓取变换用硬编码默认值 + 参数覆盖

`TransportTaskConfig::object_T_left_tcp/right_tcp` 默认硬编码 S2 冻结基线的 16 元数值，
并可由控制器参数（16 元 row-major）覆盖；`parseIso3()` 校验刚性。没有引入 baseline yaml
解析依赖，避免控制器反向依赖 S2 冻结包。
