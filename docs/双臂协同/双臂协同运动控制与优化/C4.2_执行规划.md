## 0. 一句话目标

把"交接位靠示教猜"变成**带硬约束的优化问题**：在 C4.1 给出的共同可达空间里，
用真实 IK + 真实碰撞几何筛出**完整位姿可行**的候选，再优化出交接位、待机位与协同区，
并以 **M4 当前交接方案（Baseline B）为唯一正式基线**做可复现的对照。

实验主线：

```
M4 Baseline B  →  V0（只优化位置）  →  V1（位置 + ≤10° 姿态）  →  Optimized Handover
```

## 1. 目标与边界

### 1.1 做什么

| #   | 内容                                                                                                                                     |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| a   | **位姿可达性分析**：把 C4.1 的 TCP 点可达逐级收紧为"双臂同时位姿可达 ∧ 满足抓握约束 ∧ 无碰撞"                                            |
| b   | **交接位优化**：在可行候选中求最优物体位姿 `T_O`（及导出的 `q_L, q_R`）                                                                  |
| c   | **待机位优化**：求不挡道、关节余量大、离协同区近的双臂待机构型                                                                           |
| d   | **协同区域筛选**：输出"双臂可同时规范操作"的空间区域（体素 + 最优子区）                                                                  |
| e   | **单基线对照**：以 **M4 Baseline B** 为唯一正式基线，报告 §7.1 定义的各项提升；<br>Baseline A 仅作**历史静态参考**，不参与正式收益百分比 |
| f   | **V0 → V1 主实验主线**：V0 只优化交接位置（姿态固定为 M4 姿态），V1 再加 ≤10° 姿态扰动                                                   |
| g   | **可视化 + 一键复现**                                                                                                                    |

### 1.2 不做什么

- ❌ 协同搬运的完整轨迹与动态过程（**C4.3**，本阶段只保留接口）；
- ❌ 抓握点优化（**独立扩展**，本阶段只固定 `T_rel`，但变量接口预留）；
- ❌ 轨迹品质 / 避障 / 前馈（**C3**）；
- ❌ 真机验证（**C5**）；
- ❌ 力控、动力学、`inertial` 相关。

### 1.3 ★ 与 C4.1 的关系（本阶段最重要的一句前提）

> **C4.1 的 CRW 是"TCP 点可达"的采样体素估计，不是位姿可行域，不能直接当作约束使用。**

C4.1 只回答了"某个点被某条臂的 TCP 走到过"，它**没有**回答：
姿态是否可达、IK 是否存在、多解里是否有不碰撞的那个、运动是否可到达。
C4.2 的**第一步就是把这件事补上**，并且这个补的过程本身就是可报告的产出（位姿可达率）。

#### 2.1.1 Baseline B 的定义与重建流程（★ 必须重建，不能直接取关节角）

M4 的交接**不是一个固定关节构型，而是一段过程**（[handover_rod.xml](../../../src/s622_bt_manager/behavior_trees/handover_rod.xml)）：

```
GenerateHandoverCandidate（由物体运行期位姿算目标）
  → 右臂到 PRE（沿 +x 退 60 mm）
  → TransferObject：线性进给 60 mm → RECEIVE
  → 左爪松开 → 右臂带物退让
```

[m4_handover.yaml](../../../src/s622_bt_manager/config/m4_handover.yaml) 里只有两个"基点"，**都不是最终 RECEIVE 构型**：

| 值                                                                              | 位置                  | 作用                                                             |
| ------------------------------------------------------------------------------- | --------------------- | ---------------------------------------------------------------- |
| `bb.left_hold_joints` = [0.3353, −1.5739, −0.9095, −2.2290, 1.5708, −1.2355]    | `m4_handover.yaml:87` | 左臂举着杆的**已验证 HOLD 构型**                                 |
| `bb.right_receive_base` = [0.2856, −1.2598, −1.7115, −3.3161, −1.2915, −1.5708] | `m4_handover.yaml:59` | 右臂接物的**反解基点**（j4..j6 固定，**j1..j3 由 IK 沿进给求**） |

**实测：`right_receive_base` 不是真实 RECEIVE。** 由杆位姿 + `receive_offset` 反推出的 M4 RECEIVE
目标，与该基点的 FK 结果相差 **9.0 mm**（TCP 位置差 [−6.5, −0.4, +6.3] mm）。

**正式 Baseline B 按下述流程重建**：

```
M4 target pose   （= rod 位姿 + receive_offset；姿态 = receive_quat）
      │
      ├─ FairinoIK::solve()          → 解集（≤8 支）
      ├─ IK branch selection         → 以 right_receive_base 为 seed 选分支（IKSelector）
      └─ q_R^{M4}

左臂：q_L^{M4} = bb.left_hold_joints  （M4 实际 HOLD 构型，无需重建）

      ▼
q_B = [ q_L^{M4} ; q_R^{M4} ]
      │
      └─ FK 重新计算：  T_L^B ,  T_R^B ,  T_O^B ,  T_rel^B
```

**硬性约定**

- **禁止**混用 `right_receive_base` 与重建后的真实 RECEIVE 构型；
- **所有 Baseline B 指标统一从 `q_B` 及由它导出的 `T_*^B` 计算**；
- rod 的世界位姿必须由 `T_O^B = T_L^B · (^G_L T_O)` **精确算出（含姿态）**，见 §8 R5；
- 重建过程本身要有单测：`‖FK(q_R^{M4}) − target‖` 必须收敛到 IK 容差内（≈1e-5 m 量级），
  且**明显小于** `right_receive_base` 的 9.0 mm 偏差。

我在 `/tmp` 写了一个一次性探针（**未入库**）实测，结论：

| 结论                                  | 实测                                                                                                                                                                  |

| 地面可用 box 代替平面                 | 已验证"手臂朝下"能判碰撞 ✅                                                                                                                                            |
| URDF 可从 xacro 确定性重生成          | `xacro src/gz_launch/config/s622_dual_arm_gazebo.urdf.xacro`；与仓库现有 fixture **结构完全一致（69 个 link+joint，366 字节数相同）** ✅                               |

**⚠️ 实测发现 3 个陷阱（必须写进代码断言，否则结论静默错误）**

1. **网格静默加载失败**：不 `source install/setup.bash`（ament index 缺 `package://` 解析）时，
   所有 mesh 报错后 collision geometry 变**空**，`isStateColliding` **恒返回 false**、查询耗时降到 0.5 µs。
   → 必须在构建后**断言碰撞几何非空**，并把"实际加载了多少 collision shape"打进日志。
2. **`distanceSelf(state)` 不带 ACM 时恒为 0**：SRDF 里 34 条相邻 link 是"设计上接触"的，
   不套 ACM 会把它们算成碰撞，最小距离永远 0.0。
   → 必须用 `distanceSelf(state, scene.getAllowedCollisionMatrix())`。实测带 ACM 后为 **0.0131 m**。
3. **全局最小距离 ≠ 臂间净空**：`distanceSelf` 返回的是"任意 link 对"的全局最小，
   可能被**单臂内部**的近距离 link 主导（实测 Baseline A 与 Baseline B 拿到**同一个** 0.0131 m，
   而两者的 capsule 臂间距离是 0.154 / 0.058 m —— 完全不是一回事）。
   → 臂间净空目标必须**把同臂 link 对全部 ACM 禁用**后再查，只留 cross-arm 对；
   或者与 C2.7 capsule 口径**双报**并说明差异。
4. **地面 box 与 base_link 接触**：floor box 顶面放在 z=0 时与底座接触，
   `distanceRobot` 直接返回 −1（判为碰撞），而 `isStateColliding` 返回 false。
   → 地面几何要留 **base 的 ACM 例外** 或把地面顶面放到 z = 0 但把 `base_link` 加入地板 ACM。

## 3. 数学建模

### 3.1 分层集合 S0–S4（D1 第一层：位姿可达性）

严格按你的区分定义**四个嵌套集合**，逐级收窄，每级都报转化率：

| 集合   | 定义                            | 判定手段                                                     |
| ------ | ------------------------------- | ------------------------------------------------------------ |
| **S0** | TCP **点**可达                  | C4.1 的 CRW 体素（采样代理）                                 |
| **S1** | **单臂指定姿态**的 TCP 位姿可达 | 该臂解析 IK 有解 ∧ 解在关节限位内 ∧ 通过 `IKSelector` 硬过滤 |
| **S2** | **双臂同时**位姿可达            | 两条臂各自满足 S1（对同一目标物体位姿）                      |
| **S3** | S2 ∧ **满足相对抓握约束**       | `‖log(T_rel^{-1} · T_rel^des)‖ ≤ ε_rel`                      |
| **S4** | S3 ∧ **无碰撞**                 | 真实网格：自碰撞 ∧ 地面 ∧ 物体（含 target/环境）             |

> （额外要求 3），本阶段作为**可选的 S5 标记**单独报告，不混入 S4 的定义。

```

### 3.2 优化变量（D1 第二层，分层启用）

**主变量**：物体世界位姿 `T_O ∈ SE(3)`（**6 DOF**）。
`q_L, q_R` **不是自由变量** —— 它们由 IK 从 `T_O` 导出（每个臂是一个**解集**，来自 8 支解析解）。

**优化全部以 Baseline B 为原点**（不是从零搜索，而是"在 M4 附近找更好的"）：

| 层级                                 | 变量                                                                                | 说明                                               |
| ------------------------------------ | ----------------------------------------------------------------------------------- | -------------------------------------------------- |
| **V0（主实验）**                     | `p_O` 位置 3 DOF；**姿态固定** `R_O = R_O^{M4}`                                     | 回答："保留 M4 交接方向、只重选位置，能改善多少？" |
| **V1（主实验）**                     | `p_O` + `δθ_O`，**旋转向量范数约束**：`R_O = R_O^{M4} · exp([δθ]_×)`，`‖δθ‖₂ ≤ 10°` | 回答："再允许小范围姿态调整，还能额外改善多少？"   |
| **V2（扩展，本阶段不做，接口预留）** | 全 6 DOF 姿态 + 抓握点沿杆轴偏移 `s` + 绕杆轴对称角 `ψ∈{0,π}`                       | 需先解决 §2.3 的 Q1–Q4                             |

**主实验主线（报告的主线叙事）**：

```
M4 Baseline B  →  V0 Position Optimized  →  V1 Position + Orientation Optimized
```

V0 与 V1 的候选池都以 `T_O^B`（Baseline B 的物体位姿）为中心生成，
半径由 C4.1 的交接候选区界定（§4.1）。**V0 与 V1 必须用同一套硬约束与同一套归一化口径**，
否则两级之间的增益不可比。

**★ 姿态扰动的唯一定义（不得与逐轴 ±10° 混用）**

```
R_O(δθ) = R_O^{M4} · exp([δθ]_×)          δθ ∈ R³
约束：    ‖δθ‖₂ ≤ θ_max      （默认 θ_max = 10°）
```

- 用**旋转向量（轴角）的欧氏范数**约束，**不是**逐轴 `|δθ_x|,|δθ_y|,|δθ_z| ≤ 10°`
  （逐轴约束的实际最大转角会到 `√3·10° ≈ 17.3°`，两者不等价）；
- 后续 **±5° / ±10° / ±15° 敏感性实验一律用同一范数定义**，只改 `θ_max`；
- 报告里必须写出实际使用的 `θ_max` 与范数定义。

**离散分支**：`|IK_L| × |IK_R| ≤ 8 × 8 = 64` 种解组合，**必须全部评估**（额外要求 2），
不是每只手取第一个解。`IKSelector` 的硬过滤先做粗筛，再对存活组合做碰撞与评分。

### 3.4 软目标与归一化（D1 第三层 + 额外要求 5）

**每个指标必须先归一化到 [0,1] 再加权**，不允许不同量纲直接相加：

| #          | 指标                                                          | 方向 | 归一化方式（事先声明）                        |
| ---------- | ------------------------------------------------------------- | ---- | --------------------------------------------- |
| J1         | `σ_min(J_L)`                                                  | ↑    | `min(σ/P95_σ, 1)`，`P95_σ` 取自候选池         |
| J2         | `σ_min(J_R)`                                                  | ↑    | 同上                                          |
| J3         | 相对任务可操作度 `w_rel`（BodyR）                             | ↑    | `min(w/P95_w, 1)`                             |
| J4         | **真实最小碰撞距离**（cross-arm，见 §2.5 陷阱 3）             | ↑    | `min(d/d_ref, 1)`，`d_ref = 0.05 m`           |
| J5         | 关节限位余量 `min_i min(q_i−q⁻_i, q⁺_i−q_i)`（双臂取小）      | ↑    | `min(m/0.5 rad, 1)`                           |
| J6         | 与 **M4 Baseline B** 的偏离 `‖q − q_B‖`（按限位区间归一化后） | ↓    | `1 − min(‖·‖/‖·‖_ref, 1)`                     |

**目标函数**：

```
max  Σ_k λ_k · J_k(x)          x = (T_O, 解组合)
s.t. H1..H8
```

**权重 `λ` 的确定方式（不允许拍脑袋）**：
1. 先跑**单目标**（每个 J 单独最优）得到 7 个"单目标极点"；
2. 再跑**等权**与 **2–3 组任务导向权重**（例：精度优先 / 安全优先）；
3. 报告 **Pareto 前沿**与最终推荐点的取舍说明；
4. **敏感性**：权重 ±50% 扰动，报告 Top-5 集合的 Jaccard 稳定性。

### 3.5 量纲与表达系口径（额外要求 5）

- **表达系固定 `BodyR`**（与 C4.1 一致），所有 `σ_min(J_rel)` 一律标注 `BodyR`；
- **C4.1 已证明**：`w_rel = ∏σ` 帧不变，`σ_min` 帧相关 → 两者分开报，不混用；
- **平移/旋转量纲**：`J` 是 `[v; ω]` 混合量纲（m/rad 与 rad/rad）。
  为证明结论不依赖尺度选择，**同时报一个无量纲化版本**：
  `J' = diag(1/L_c·I₃, I₃) · J`，特征长度 `L_c = 0.2168 m`（TCP 工具长度），
  并给出"原始口径 vs 无量纲口径"下 Top-5 候选的一致性；
- **单臂 `σ_min`** 用 `jacobianBase`（6×6，base 系，参考点 = grasp origin），与 C2.8 口径一致。

### 3.6 待机位与协同区的建模（与交接位分开，不混在一个目标里）

**待机位（standby）** —— **单点优化。A6 已定（2026-10-09）**：

> **定义**：待机位 = **"面向下一次交接的安全准备构型"**，

**主评价指标（从待机位到优化后交接构型的这一段）**：

| 优先级 | 指标                                                                                                                                                   |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 主     | ① 无碰撞规划成功率（`isMotionValid` / 规划器成功率）<br>② 路径长度<br>③ 关节运动量 `‖q_standby − q_handover‖`<br>④ 安全净空（cross-arm mesh distance） |

```
max  ν1·J_plan_success(→handover) + ν2·J_path_len + ν3·J_joint_motion + ν4·J_clear
s.t. H1,H2,H3,H5,H6 ；且末端不在协同区内（避免占位）

### 4.1 候选池生成（复用 C4.1，不重新采样）

从 C4.1 的 278 万条记录出发（`analysis/data/workspace_dual_arm.bin`），
按目标物体姿态与 `T_rel` 反推候选 `T_O`，并分层取池：

| 池            | 来源                                             | 用途                                       |
| ------------- | ------------------------------------------------ | ------------------------------------------ |

| **P2 协同池** | C4.1 全 CRW 样本                                 | 协同区体素化                               |
| **P3 网格池** | CRW bbox 内按 2 cm 网格均匀撒点                  | 覆盖性对照（防止 P1 的采样偏置漏掉可行区） |

> 所以必须配 P3 做覆盖性对照 —— 这是 C4.1 那条"占用不是体积"的诚实边界在 C4.2 的直接后果。

### 4.2 每个候选的可行判定管线（顺序 = 由便宜到贵）

```
T_O 候选
 ├─ ① 由 T_rel 反推 T_L^des, T_R^des                       (~0)
 ├─ ② 双臂解析 IK → 解集 (≤8 × ≤8)                          (~0.1 ms)
 ├─ ③ IKSelector 硬过滤 + 归一化评分（每臂，取存活解）        (~0.02 ms/解)
 ├─ ④ 解组合的 H4 相对抓握误差检查                            (~0)
 ├─ ⑤ 全网格碰撞 + 地面 + 物体（每存活组合）                  (~0.029 ms/组合)
 └─ ⑥ 软目标计算（σ_min / 距离 / 余量）→ 归一化加权            (~0.02 ms)
```

**预算估算**（含早退）：单候选 ≈ **0.5–2 ms**（取决于存活解数）。
10 万候选 ≈ **1–4 分钟**（单线程）；多线程后 < 1 分钟。
主实验用 **P1+P3 合计 ≤ 2×10⁵ 候选**，总预算上限 **30 分钟**。

### 4.3 搜索与精化

1. **粗筛**：在候选池上跑 §4.2 全管线 → 得到 S1..S4 与目标值；
2. **局部精化**：对目标值 Top-K（K=200）候选，用 **Nelder–Mead / 坐标下降**在 `T_O`
   的 3（V0）或 5（V1）维上精化，目标函数含**可行性罚项**（硬约束违反即判死）；
3. **多起点**：Top-K 分散在不同连通分量里（避免全挤在一个局部最优）；
4. **不做全局黑箱优化**（如 CMA-ES 全空间）：运动学地形不连续（IK 分支切换），
   全局搜索收益低、可解释性差；改用"网格/候选池穷举 + 局部精化"更可复现。

### 4.4 多种子与排序稳定性

- 精化阶段用 **N ≥ 20 个独立初值**，报告 `p_opt` 与最优值分布（不是只报最好的一次）；
- 权重扰动 ±50% → 报告 Top-5 的 Jaccard；
- 池采样扰动（P1 随机子集 × 5）→ 报告目标值的标准差。

## 7. 成功率定义（★ 分母逐个写死，避免混为一谈）

| 指标                            | 分子                                                          | **分母**                          |
| ------------------------------- | ------------------------------------------------------------- | --------------------------------- |
| **IK 成功率** `p_IK(arm)`       | 该臂存在 ≥1 个通过 H1–H3 的解的目标位姿数                     | **该臂被尝试的目标位姿总数**      |
| **位姿可达率** `p_pose`         | 双臂同时存在 ≥1 可行解的目标位姿数                            | **候选目标位姿总数**              |
| **抓握约束满足率** `p_rel`      | S2 中满足 H4 的目标位姿数                                     | **\|S2\|**                        |
| **无碰撞率** `p_free`           | S3 中通过 H5–H7 的**解组合**数                                | **S3 中被评估的解组合总数**       |
| **优化成功率** `p_opt`          | 收敛到"满足全部硬约束 ∧ **优于 M4 Baseline B**"的独立运行次数 | **独立运行次数**（多种子/多初值） |
| **S5 到达率** `p_reach`（可选） | S4 中通过 `isMotionValid` 的候选数                            | **\|S4\|**                        |

### 7.1 指标提升的定义（★ 统一口径，以 Baseline B 为分母）

所有"提升 X%"一律以 **M4 Baseline B** 为比较对象。**四类指标用各自的正确写法，不机械套同一个公式**：

| 指标类型                                                               | 定义                                                     | 示例                                                                              |
| ---------------------------------------------------------------------- | -------------------------------------------------------- | --------------------------------------------------------------------------------- |
| **连续量且 `M_B > 0`**：`σ_min`、`w_rel`、关节余量、臂间净空、综合评分 | `(M_opt − M_B) / M_B × 100%`                             | `σ_min 0.369 → 0.412（+11.7%）`                                                   |
| **成功率 / 比率**：`p_IK`、`p_pose`、`p_rel`、`p_free`、`p_opt`        | **百分点差（pp）**：`M_opt − M_B`                        | `p_pose 3.41% → 8.02%（+4.61 pp）`<br>❌ **禁止**写成 `+135%` —— 分母接近 0 时会爆 |
| **失败率 / 误差类**：规划失败率、相对抓握误差、偏差                    | `(M_B − M_opt) / M_B × 100%`（下降为正），**并给绝对值** | `相对误差 1.0 mm → 0.4 mm（−60%）`                                                |
| **耗时 / 时间类**                                                      | **比值或差值，不用百分比**                               | `规划耗时 1.8 s → 0.6 s（0.33×）`                                                 |

**每一条都必须同时给绝对值**（`0.369 → 0.412`），不能只报百分比 —— 避免"提升 300%"其实只有 0.03 mm。

## 8. 风险与备选方案（★ 含实测踩到的陷阱）

| #       | 风险                                                                             | 概率         | 对策                                                                                                                                                             |
| ------- | -------------------------------------------------------------------------------- | ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **R1**  | **网格静默加载失败** → 碰撞恒 false，结论全错                                    | 中           | §2.5 陷阱 1：构建后**断言 collision shape 数 > 0**，并把加载统计打进日志与 `summary.json`                                                                        |
| **R2**  | **`distanceSelf` 不带 ACM 恒为 0**                                               | 高           | §2.5 陷阱 2：强制带 `getAllowedCollisionMatrix()`；单测断言"Baseline B 的 cross-arm 距离 > 0"                                                                    |
| **R3**  | **全局最小距离被同臂 link 对主导**，臂间净空被低估                               | 高           | §2.5 陷阱 3：再建一个"禁用同臂对"的 ACM 查 cross-arm；与 C2.7 capsule 口径**双报**                                                                               |
| **R4**  | **地面 box 与 base_link 接触** → `distanceRobot` 恒判碰撞                        | 高           | §2.5 陷阱 4：把 `base_link` 加入地板 ACM 例外，或地面顶面下沉 1 mm                                                                                               |

| **R9**  | "静态可行"被误读为"能到达"                                                       | 中           | S4 与 S5 严格分离（额外要求 3）；文档与图例都显式标注                                                                                                            |
| **R10** | 权重主观 → 结论不可靠                                                            | 中           | 单目标极点 + Pareto 前沿 + 权重敏感性；不报单一"综合得分"                                                                                                        |
| **R11** | MoveIt 依赖让 C4.2 变重、构建变慢                                                | 低           | 碰撞层做成**可替换后端**（`MoveItCollisionBackend` / `CapsuleCollisionBackend`），后者作 fallback 与交叉验证                                                     |
