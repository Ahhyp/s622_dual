# C4.3 S4 — W6-0 DetachableJoint 插件实测报告（Gazebo Fortress 6.16）

- 日期：2026-10-28
- 范围：**W6-0 定向插件实测**（只做这一项）。未创建 `c43_s4_dual_arm_gazebo.urdf.xacro`、未写 `attach_client`、未改任何产品代码、未改任何阈值或 Gate。
- 依据：`C4.3_S4_W5-W9_一体化执行规划_v1.0_20261028.md` §4（W6-0 要求）、`C4.3_S4_执行规划.md` §14.3（C1–C5）；用户授权选项「只做 W6-0 插件实测」。
- 结论一句话：**插件在 6.16 可用，但「启动即附着」无法配置为关闭、且行为是竞态（4 次中 2 次把样件瞬移 0.475 m）；主题触发的 attach/detach 确定性良好且不瞬移。** 因此 W6 不能把启动物理约束当作 GRASP，须先批准局部兼容方案。

## 2. 构造是否可行

| 构造 | 结果 | 证据 |
|---|---|---|
| 插件放在 **world** 作用域 | **不可用** | `[Err] [DetachableJoint.cc:51] DetachableJoint should be attached to a model entity. Failed to initialize.`（`worldscope.log`） |
| 插件放在**模型**内 | 可用 | 三行 debug 日志确认主题解析：`Detach topic is: /probe/detach`、`Attach topic is: /probe/attach`、`Output topic is: /probe/state` |

⇒ W6 的插件必须挂在模型上（即挂到机器人/夹具模型），不能挂 world。

- `ign topic -l` **不含** `/probe/attach`、`/probe/detach`（插件只是订阅方，不广播）；
- 只含 `/probe/state`（发布方）。
- ⇒ 不能用 `ign topic -l` 证明 attach/detach 主题存在，正确证据是插件 debug 日志 + 实际投递成功。

## 4. 启动附着：发生、无法关闭、且是竞态

4 次独立运行（每次全新 server，同一 `probe_world.sdf`，child 从 z=0.5 自由落体到地面 z=0.025）：

| run | 首次 `attached` 时刻（server ready 后） | 结果 |
|---|---|---|
| 1 | 2.201 s | 空操作（child 留在地面 z=0.024999） |
| 2 | 2.178 s | 空操作（同上） |
| 3 | 2.196 s | **被拉回 SDF spawn 位姿 z=0.500（瞬移 0.475 m）** |
| 4 | 2.165 s | **同上（瞬移 0.475 m）** |

- 启动附着**一定发生**（4/4），延迟 2.165–2.201 s；
- **不可配置关闭**（无 `initial_attach` 参数）；
- **不幂等于位姿**：2/4 次把 child 从地面拉到 spawn 位姿，瞬移 **0.475001 m**。

后果：若 W6 依赖"启动即附着"，则 (a) 样件从 t=0 就焊在左夹爪上，**那不是 GRASP**（违反规划 §4 W6-0 的明令）；(b) 瞬移 0.475 m 远超冻结 §14.3 C3 的「attach 不瞬移 ≤2 mm」口径。

## 5. 主题触发的 attach / detach 语义

| 动作 | 实测 |
|---|---|
| 静止（z=0.024999）时发 `/probe/attach` | 日志 `Attaching entity: N` + `Creating detachable joint [N]`；**z 不变（Δ=0.000 m）**，即保留当前相对位姿、不瞬移 |
| 发 `/probe/detach` | `Removing entity: N` + `Detaching joint [N]`；z 由 0.025 → 0.0170（自由落体 8 mm 落地沉降，非瞬移） |
| 重复 detach ×3 | 第 2、3 次 `Already detached`（`DetachableJoint.cc:310`），命令 rc=0、无错误 |
| 重复 attach ×2 | 第 2 次 `Already attached`（`DetachableJoint.cc:167`），rc=0、无错误 |

⇒ 只要 attach 由主题触发，语义是「按当前相对位姿焊接」——这正是 GRASP 需要的行为（配合 §14.3 C3 的 2 mm 判据由相对位姿差检验）。

## 6. 对 W6 的影响与需批准的方案

**阻断点**：插件无法初始未附着 ⇒ 无论 GRASP 何时发生，启动物理约束都会先存在。

| 方案 | 内容 | 代价/风险 | 是否需批准 |
|---|---|---|---|
| **A. 启动即 detach**（推荐） | launch/执行器在 server 就绪后立刻发一次 `/…/detach`，把样件释放到支撑上；GRASP 时做**首次** attach | 启动窗口 2.17–2.20 s 存在竞态，若在该窗口内发生 teleport 需校验并报错（可门禁：detach 后校验样件位姿与期望一致，不一致 → HOLD） | 是（涉及"启动物理约束"的处理口径） |
| **B. 自定义 system plugin** | 新写一个可 `initial_attach=false` 的附着插件 | 新增包 + 构建依赖 + 需在 SDF 引用本地 `.so`；不能复用官方插件 | 是（新代码与新构建面） |
| C. 接受启动即附着 | 把启动 weld 当抓持 | **禁止**：等价于把启动物理约束冒充 GRASP，且会瞬移 | 否（明确不做） |

在 A/B 获批前，**W6 不得开始写产品代码**（xacro / attach_client / 测试）。
