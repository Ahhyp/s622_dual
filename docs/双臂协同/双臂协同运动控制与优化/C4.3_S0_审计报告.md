3. **"JTC profile 可直接用来发轨迹"** —— 实测**激活失败**，见 §4.1。

5. **"共同可达空间 = 搬运可行空间"** —— 文档自己已经提醒（§四 C4.1），
   审计进一步确认：C4.1 的可达集是**单臂 TCP 点集**，与"两爪夹住同一刚体"的约束完全不同。

### 2.4 ★★ 数值验证：物体 Jacobian 在相对旋转 = π 处是**错的**

规划的 §五 要求"所有 Jacobian 必须明确表达坐标系、twist convention"。
我按这条做了**有限差分验证**（探针 `/tmp/probe_jac.cpp`，链接已编译的
`libdual_arm_kinematics.so`，未改仓库）。

**背景**：C2 的"物体坐标系"是两抓握坐标系的 **SE(3) 中点**
（`dual_arm_kinematics.cpp:87-98`）：

```
p_O = (p_L + p_R)/2
R_O = R_L · exp( 0.5 · log(R_L^T R_R) )
```

**验证结果**

| 相对旋转 `‖log(R_L^T R_R)‖` | `objectJacobianBody` 相对误差 |
|---|---|
| 2.4890 rad | 1.3e-8 ✅ |
| 2.6599 rad | 1.5e-8 ✅ |
| 2.9927 rad | 2.9e-7 ✅ |
| **3.1416 rad (= π)** | **6.6e-1 / 8.6e-1 / 7.4e-1** ❌ |

**即：在 ξ 恰好等于 π 时，解析物体 Jacobian 与真实一阶响应偏差最高 86%。**
不是数值噪声，是**闭式 `G` 矩阵在该分支点不成立**（`logSO3` 在 π 处轴向不定，
`G = R_L J_l(ξ/2)·0.5·J_l(ξ)^{-1} R_L^T` 的导数项丢失）。

**对照：相对任务 Jacobian 在所有帧、所有角度（含 π）都精确**，最差 4.6e-8
（`/tmp/probe_rel.cpp`）。**所以相对任务是安全的，问题只在物体任务。**

**为什么这对 C4.3 特别要紧**：两只夹爪从两端夹住同一个盒子时，
两抓握坐标系的相对旋转**天然接近 180°**（左爪朝 +x、右爪朝 −x）。
我在 C4.2 的仿真里也实测到双臂镜像 home 位形的相对旋转**精确等于 π**。

**结论**：若 C4.3 直接沿用 C2 的中点物体坐标系，会**正好落在它唯一失效的点上**，
而且**没有任何错误信号** —— 这会产生"控制器莫名其妙不准"的隐蔽故障。

**可选处置（需你在规划里定）**
- (a) 自己定义 C4.3 的物体坐标系 `^W T_O`（不用中点），并**推导它自己的 Jacobian**；
- (b) 仍用中点系，但**设计抓持使 ξ 刻意远离 π**（例如两爪同向抓持），并加一条
  `|‖ξ‖ − π| > 阈值` 的运行期断言；
- (c) 修 `objectJacobian` 在 π 处的分支（工作量中等，且中点系本身在 π 处方向不唯一）。

我倾向 **(a) + (b) 的断言**：C4.3 的 `G_L`、`G_R` 是规划自己定义的固定抓持变换，
物体 Jacobian 完全可以由 `Ad(G_L)`、`Ad(G_R)` 直接拼出，不依赖中点系。

### 2.5 C2.6 文档**已经自认**另一个 π 问题（且未修）

`C2.6_执行记录_奇异与病态处理.md:53-70` 明确写着：

> B 类（`|e|→π`）失效来自我们的一阶误差映射
> `edot ≈ -Ad(T_err⁻¹) J dq`（实现里隐含 `J_r^{SE3}(e) ≈ I`）
> **正确修复**：实现 SE(3) right-Jacobian 的闭式逆（Barfoot 7.86）……**本次未做**

这条与 §2.4 是**两个不同的 π 问题**（一个是误差映射，一个是物体系定义），
但**都会在 C4.3 的近似 180° 抓持下同时出现**。规划必须把两者都列为已知风险。

- **离线**：`DualArmScene`（C4.2）—— URDF+SRDF 直接解析 + `moveit::core::RobotModel`

  （`finger1/finger2/grasp_frame`）；双臂那份只来自

  **32 条 `disable_collisions`**（`grep -c` 得 34 是因为含 2 行中文注释）。
  ⚠️ 我 C4.2 的 `src/dual_arm_pose_optimization/include/dual_arm_pose_optimization/collision_backend.hpp:7`
  头注释里写的 "34" 是错的，**已于 2026-10-15 经批准改为 32 并补上出处**
  （**只改注释，未改碰撞逻辑**）。**没有任何跨臂 disable 条目** ⇒ 臂间碰撞检查默认开启。
  `grasp_frame` **没有 `<collision>` 几何**，因此不会作为碰撞 link 出现。
- **碰撞模型**：`dual_arm_collision` 是**每臂 6 个胶囊（DH 帧 0-1…5-6）、半径 0.06 m**，
  **不含夹爪手指、不含物体**，且**只测跨臂对**（无同臂自碰、无地面、无环境）。
  `distance` 是**有符号**的（穿透为负）；`distanceGradient` 是**只在当前最近对上做中心差分**，
  最近对切换时只是近似。C4.2 实测该胶囊把臂间距**高估 7.9 倍**。
  → **C4.3 的碰撞检查必须用 C4.2 的网格后端，不能只用 C2 的胶囊。**
  另：胶囊半径 0.06 在**≥5 个文件 + 5 个控制器 YAML** 里各写一遍，**没有单一来源**。
- **`DualArmKinematics` 硬编码 `ToolModel::GRIPPER`**，所有 FK/Jacobian 都在**抓握系**；
  法兰系只能经 `dh(a)` 或 `worldTframe(...,6)` 拿。C4.3 若需要夹爪/法兰系要另开接口。
- **关节限位在 ≥5 处重复**（qp_core、3 个测试文件、`feasibility.cpp`），无单一来源。
- **`objectJacobian` 的头注释写的是 "Exact"**（`dual_arm_kinematics.hpp:98`），

  `test_object_frame.cpp` 的差分验证**没有覆盖 π 这一点**。

## A5. 对 §6.1 "极薄 adapter，而非重写优化器" 的具体回答

规划原文：「检查 C2.3/C2.4 有没有可直接消费物体轨迹的输入；没有则先设计极薄 adapter，而非重写优化器。」

**审计结论：core 有完整实现（含物体任务与 4 参数版 `solve()`），控制器侧零入口。**

**因此 adapter 的确切形状是**（**不是**重写优化器）：

1. **控制器加 4 组参数**（纯声明，不改算法）：
   `kp_obj` / `w_obj` / `w_slack_obj`；`enable_singularity` 及其 6 个子参数；
   `w_null_margin` / `w_null_manip` / `w_null_clear` / `null_step`；`d_safe` / `alpha_cbf`。
2. **加一个目标入口**（三种可选，按侵入性排序）：
   - (a) 一个 `target_csv`/`target_param` 参数 + 内部时间插值（最小、可离线复现、无需新消息）
   - (b) 订阅一个 `geometry_msgs/PoseStamped`（物体目标）+ `PoseStamped`（相对目标）
   - (c) 自定义 action（进度/取消，最完整但最重）
   → **S3/S4 建议先用 (a)**，因为它天然可离线复现，符合 §7.2 的阈值冻结要求。
3. **`update()` 里把 `qp_->solve(q, target)` 换成 `qp_->solve(q, target_rel, target_obj_body)`**
   —— 一行调用改动，核心算法零改动。
4. **物体目标的 `frame` 约定必须先冻结**（见 A7 的 π 问题）。

**代价估计**：控制器侧 ≤ 120 行（参数声明 + 一个插值器 + 调用切换），
**不触碰 `dual_arm_qp_core`**。

## A7. S1 最小单测设计（规划要求）

按 §3.4 + §6.1 S1，最小可执行单测集（建议放 `c43/tests/`）：

**T1 抓取几何合法性（`test_grasp_geometry`）**
- `GraspGeometry.ValidConfigAccepted`：合法 `size_xyz/mass/I/G_L/G_R` 通过
- `RejectsNegativeSize` / `RejectsEmptyFrame` / `RejectsNonRotationMatrix`（`R^T R ≠ I` 或 `det ≠ 1`）
- `RejectsSingularTransform`（构造不可逆的 `G`）
- `RejectsIdenticalLeftRightGrasp`（`G_L == G_R` ⇒ 闭链退化，必须拒绝）

**T2 闭环残差零性与不变性（`test_closure_consistency`）—— 对应 §3.4 三条**
- `ZeroResidualWhenExactlyOnTarget`：取任意合法 `T_WO`，令
  `T_WL = T_WO G_L`、`T_WR = T_WO G_R`，断言 `‖e_closure‖ < 1e-12`
- `InvariantUnderCommonRigidMotion`（§3.4-2）：对物体与双手施加同一 `ΔT`，
  `e_closure` 在 1e-10 内不变
- `ControlledPerturbationGivesExpectedResidual`（§3.4-3）：
  在右臂加已知 `δ ∈ R^6` 的位姿扰动，断言 `e_closure` 的**方向与幅值**符合解析预测
  （不是只断言"变大了"）
- `TranslationAndRotationReportedSeparately`：断言单位分别为 m 与 rad，且不混合
- `UsesSE3NotElementwiseMatrixDiff`：构造两个"逐元素差很大但 SE(3) 距离很小"的例子，
  断言不使用逐元素差

**T3 ★ π 分支专项（本审计新增，正式规划未预见）**
- `ObjectFrameAtExactlyPiDoesNotSilentlyLie`：
  构造 `‖log(R_L^T R_R)‖ = π` 的构型，断言 **要么** `objectJacobian` 与有限差分一致，
  **要么**显式抛错/置无效标志 —— **不允许静默返回错值**
- `RelativeJacobianIsExactAtPi`：同一构型下 `relativeJacobian` 必须与差分一致（已验证 4.6e-8）
- `GraspGeometryRejectsNearPiRelativeRotation`：若选择"禁近 π"策略，
  断言 `‖ξ‖ ∈ (π−ε, π]` 被抓取几何校验拒绝

**T4 运动学对拍（`test_kinematics_reconciliation`）**
- `ObjectJacobianMatchesFiniteDifference`（**含 ξ 扫过 π 邻域**，补上现有测试的盲点）
- `RelativeJavaobianMatchesFiniteDifferenceAllFrames`（BodyR / LeftL / WorldSpatial）
- `KnownPiSingularityIsDocumented`：断言 `dual_arm_kinematics.hpp:98` 的 "Exact" 注释
  与实测不符这件事**在 C4.3 侧有显式记录**（避免后人误信注释）

**T5 控制接口适配（`test_adapter_min`，离线即可）**
- `ThinAdapterProducesSameDqAsCoreDirectCall`：用同一组 `(q, target_rel, target_obj)`
  比较"经 adapter"与"直接调 core 4 参数版"的 `dq`，断言一致到 1e-12
  —— 证明 adapter **没有改变算法**
- `ObjectTaskDisabledWhenWObjZero`：`w_obj=0` 时等价于 2 参数版

### A14.1 ★ 优先项 (c)+(d) 的新证据（决定 S1 方案的关键）

本次审计为此**专门写了 3 个独立探针**（链接真实库 `install/lib/libdual_arm_kinematics.so`，
非复刻实现），源码 `src/dual_arm_kinematics/`。结论比原记录更严重：

**证据 1 —— 双端抓持天然落在 π 上。**
双臂镜像位形实测 `‖log(R_LᵀR_R)‖ = 3.141592653589793`，与 `π` **逐位相同**。
即 C4.3 的目标工况**正好落在奇异面上**。

**证据 2 —— 该位形下"中点"不唯一（数学退化，非数值 bug）。**
`dual_arm_kinematics.cpp:96` 定义 `R_O = R_L · expSO3(0.5·logSO3(R_LᵀR_R))`（头文件
`dual_arm_kinematics.hpp:86-89` 亦自述为 "SE(3) midpoint of the two grasp frames"）。
实测两个候选中点 `R_L·exp(±ξ/2)`：

```
‖log(Ro+ᵀ R_L)‖ = 1.570796327   ‖log(Ro+ᵀ R_R)‖ = 1.570796327
‖log(Ro-ᵀ R_L)‖ = 1.570796327   ‖log(Ro-ᵀ R_R)‖ = 1.570796327     (π/2 四位相等)
‖log(Ro+ᵀ Ro-)‖ = 3.141592654   <-- 两个"中点"彼此相差 π
```
⇒ **两个都是合法的测地中点**，中点非唯一。

**证据 3 —— `objectJacobian` 的误差随 `‖ξ‖ → π` 连续增大（不是分支跳变）。**
对 `objectJacobianWorld` / `objectJacobianBody` 做同构型有限差分对拍
（`h = 1e-7`，body/spatial twist 按各自定义计算）：

| `π − ‖ξ‖` | `objectJacobianWorld` 相对误差 | `objectJacobianBody` | `relativeJacobian` |
|---|---|---|---|---|
| ≥ 4e-1 | ~1e-8 | ~2e-8 | ~2e-9 |
| 1e-1 | 7e-8 | 1e-7 | 2e-9 |
| 1e-2 | 1.5e-5 | 3.0e-5 | 2e-9 |
| 1e-3 | 3.9e-4 | 7.7e-4 | 2e-9 |
| 2e-4 | 7.4e-4 | 1.4e-3 | 2e-9 |
| 2e-5 | **1.0** | 1.4 | 2e-9 |
| **0** | **1.0** | **4.6** | **2.0e-9** |

三点关键读数：
- 误差**平滑单调增长**，是**真实的数学病态**，不是 `logSO3` 的分支选择错误；
- 出错的只是**角速度行**，且集中在"绕 π 轴自转"的那几个关节
  （本次镜像位形下为 `q[0], q[4], q[6], q[10]`），其余关节误差为 0；
- **`relativeJacobian` 处处精确（含恰好 π 处 2e-9）**——因为它**不含中点**。

**证据 4 —— 这不是"加个容差"能救的。**
要把物体 Jacobian 的相对误差压到 `1e-4` 以下，需要 `|π − ‖ξ‖| > 1.5e-3 rad ≈ 0.086°`。
双端抓持同一刚体的相对姿态**不可能**保证离 π 有 0.086° 以上。

### A14.2b 锚定物体 Jacobian 的完整定义（用户批复第 2 项）

**这是 W2 坐标系契约表的核心内容，S1 必须先把它写成可判定的条款，再写代码。**

**(a) 基本定义与符号**

| 符号 | 含义 |
|---|---|
| `W` | world frame |
| `O` | 物体 frame（**任务给定** `T_WO,d(t)`，非中点） |
| `L` / `R` | 左／右臂 TCP（grasp frame），`T_WL(q_L)` / `T_WR(q_R)` |
| `G_L` / `G_R` | 抓持时冻结的 TCP→物体常数变换，`G_L = (T_WO*)⁻¹ T_WL*`，`G_R = (T_WO*)⁻¹ T_WR*` |
| `T̂_{O,L}` | **左锚定**物体位姿估计 `= T_WL · G_L⁻¹` |
| `T̂_{O,R}` | **右锚定**物体位姿估计 `= T_WR · G_R⁻¹` |
| `ξ̂_{O,X}` | 锚定残差 `= log( (T_WO,d)⁻¹ T̂_{O,X} )^∨ ∈ ℝ⁶`，`X ∈ {L,R}` |

**(b) twist 约定（必须二选一并写死）**

采用 **body twist**（物体自身坐标系表达）：`V^b = (T⁻¹ Ṫ)^∨ = [v^b; ω^b] ∈ ℝ⁶`。
理由：`J_rel`（`relativeJacobian`）已是 body 约定且实测处处精确，物体任务沿用同一
约定可保证 `e_rel` 与 `e_obj` 的 QP 行直接可比，无需在雅可比之间插 Adjoint。

**明确排除**：不得使用 spatial twist `(ṪT⁻¹)^∨`。本次审计中我第一版探针混用了
body/spatial，**得出过假结论**（把 body 误差当成 spatial 误差比较），已修正。
两种约定**不可混用**，且必须在测试注释中写明。

**(c) 行排列**

`V^b = [v_x, v_y, v_z, ω_x, ω_y, ω_z]ᵀ` —— **平移在前、旋转在后**，与仓库现有
`relativeJacobian` / `objectJacobianBody` 的排列一致（S1 内以下标常量固定，
并在契约表写死，不依赖"惯例"）。

**(d) TCP 与物体参考点之间的变换：参考点平移 + Adjoint**

`T̂_{O,L} = T_WL G_L⁻¹` 把**参考点从 TCP 搬到物体原点**，因此关节到物体 body twist
的映射**不是** `J_L` 本身，而是：

```
J_{O,L}(q_L) = -Ad( G_L ) · J_L(q_L)          ∈ ℝ^{6×6}
J_{O,R}(q_R) = -Ad( G_R ) · J_R(q_R)          ∈ ℝ^{6×6}
```

其中 `J_L` / `J_R` 是**TCP 的 body Jacobian**（`relativeJacobian` 内部已有的那一份，
`T_WL` / `T_WR` 的 body 约定），`Ad(·)` 是 SE(3) adjoint：

```
Ad(T) = [ R        0   ]          作用顺序 V^b_new = Ad(G⁻¹) V^b_old
        [ [p]ₓ R   R   ]
```

推导（左臂，物体侧）：`T̂_{O,L} = T_WL G_L⁻¹`，故
`V̂^b_{O,L} = (T̂_{O,L}⁻¹ · d/dt T̂_{O,L})^∨ = Ad(G_L) · (T_WL⁻¹ Ṫ_WL)^∨ = Ad(G_L) · V^b_L`。
**误差定义取 `(T_WO,d)⁻¹ T̂_{O,L}`，其变化率需要再左乘 `Ad( (T̂_{O,L})⁻¹ T_WO,d )`**；
在残差已收敛（该 Adjoint ≈ I）时退化为上式。**S1 必须实现带该修正的完整雅可比**，
`-Ad(G_L)` 只是零残差附近的形式，不得当作全局精确式（并在测试中用**大残差**工况验证
这一项确实被算进去了）。

> 说明：符号取 `-` 是因为残差定义为"期望⁻¹ × 实测"，关节正方向运动使实测前移、
> 残差减小。**符号约定在 S1 内用有限差分确认，不靠推导结论直接采信。**

**(e) 左右锚定 Jacobian 的独立有限差分验证（必做）**

- `J_{O,L}` 与 `J_{O,R}` **分别独立**对拍：扰动 `q_L` 只检验 `J_{O,L}`，
  扰动 `q_R` 只检验 `J_{O,R}`；
- 对拍对**残差映射** `ξ̂_{O,X} = log((T_WO,d)⁻¹ T̂_{O,X})^∨` 做中心差分
  （`h = 1e-7`），而不是对 `T̂` 逐元素差分；
- **覆盖**：`‖ξ_rel‖` 恰好 π、π−1e-3、π−1e-1、一般姿态（含 `‖ω‖ ≈ 0` 与 `≈ π`）、
  **纯平移扰动**、**纯旋转扰动**、**平移+旋转耦合扰动**；
- 判据：全部工况相对误差 ≤ `1e-8`（与 `J_rel` 同量级）。

**(f) ★ 左锚定 ≠ 固定左臂（用户批复明确要求澄清）**

"左锚定物体任务"只表示**用左臂推算的物体位姿 `T̂_{O,L}` 作为物体任务的反馈量**，
**不表示左臂被固定**。双臂仍然是两个独立的 6-DOF 决策变量，协同方式为：

```
主任务（相对位姿约束）   e_rel   : T_WL⁻¹T_WR → T_rel* = G_L⁻¹ G_R
物体任务（锚定）         e_obj,L : (T_WO,d)⁻¹ T_WL G_L⁻¹ → I
```

- `e_obj,L` 只约束**左臂 + 物体**这一条链，它**不会**使左臂不可动——`T_WO,d(t)`
  是时间的函数，左臂照样跟随期望轨迹运动；右臂**通过 `e_rel` 参与**，
  即"两臂要保持 `T_rel*`"这一硬约束把右臂锁定为左臂的函数；
- 若只用 `e_obj,L` 而不加 `e_rel`，则右臂完全不受约束（自由臂）；
  **这正是 C4.2 交接位优化要解决的自由度**，也是为什么两条任务必须同时进 QP；
- 反过来，若同时用 `e_obj,L` 和 `e_obj,R`，则残差 `e_closure = ξ̂_{O,L} − ξ̂_{O,R}`
  是**冗余信息**，只能作为**一致性监测/故障判据**，不得再当作独立任务叠加
  （否则 QP 行线性相关、`J Jᵀ` 奇异）。**这一条写进 S1 契约表。**
