## §0 结论摘要

三句话：

1. **S3 验证过的东西一件都不需要重写**：锚定物体任务（`AnchoredObjectTaskBuilder`）、冻结轨迹与前馈（`FrozenObjectTrajectory`）、外部物体行接口（`ObjectTaskRow` + `DualArmQp::solve(q, L_T_R, row)`）已经在 S3 里逐位验证过，S4 只做"接线 + 场景 + 状态机 + 监控"。
2. **真正的缺口在控制器和场景，而不在数学**：`dual_arm_qp_controller` 目前**没有任何对外命令接口**（`src/dual_arm_qp_controller/src/dual_arm_qp_controller.cpp` 里 `create_subscription/create_service/create_publisher/create_client` 计数为 **0**），目标位姿是 `on_activate` 时抓一次（`:134`），求解固定走 2 参数重载（`:216`）；`dual_arm_qp_gazebo_controllers.yaml` 里写的 `kp_obj: 20.0 / w_obj: 1.0 / w_slack_obj: 1000.0` **一行都没被读取**（在控制器 `src/` 与 `include/` 里 grep 这三个键 = 0 命中）。也就是说：**仿真配置里"物体任务已开"是纯装饰**。
3. **Gazebo 场景基本是空的**：QP profile 用的 `src/gz_launch/worlds/dual_arm_world.sdf` 只有 `ground_plane`（`<model name="ground_plane">`，全文仅此一个 model），**没有桌子**；`s622_dual_arm.launch.py:254` 生成的是 `target_box`（**4 cm 立方、0.0612 kg**，`src/gz_launch/models/target_box/model.sdf:7,18`），与 S2 冻结样件（0.12×0.05×0.05 m、0.35 kg、支撑面 `top_z_m = 0.25`）**不是同一个物体**。S4 必须自己搭这个场景。

因此 S4 的技术难点排序是：**场景与附着 > 控制器接口与状态机 > 碰撞与监控 > 数学**。

### 0.1 三个需要裁定的决策（其余本文按推荐方案写死）

| # | 决策 | 推荐 | 理由 | 影响 |
|---|---|---|---|---|
| **D-S4-1** | 复用 S3 的物体任务代码，是"从 mock 包里搬到一个中性包"，还是"控制器直接依赖 mock 包" | **搬**：新建 `src/dual_arm_object_task/`，把 `AnchoredObjectTaskBuilder` 与 `FrozenObjectTrajectory` 从 `dual_arm_transport_mock` 迁入，mock 与控制器同时依赖它 | 控制器依赖 `dual_arm_transport_mock` 会把 MoveIt/FCL/yaml-cpp 一起拖进实时进程（mock 的 `transport_checker` 依赖 `dual_arm_pose_optimization`），且"mock"名字进生产链路会误导后来人 | 触及 S3 已验证的文件布局（**只搬不改数学**），需以 S3 全部 49 个用例作为回归判据 |
| **D-S4-2** | Gazebo 侧理想抓持怎么实现 | **单侧 `DetachableJoint`（左臂）+ 右臂作运动学跟随**，右臂与物体之间**不加**第二个固定关节 | 双侧刚性关节会把"双臂 + 物体"变成闭链过约束，物理求解器只能靠约束冲突硬解；单侧附着 + 右侧跟随在数学上与 S3 的 `L T R* = G_L⁻¹G_R` 完全一致 | 需要独立的"右 TCP vs 物体"误差指标作为通过判据，而不是靠物理接触 |
| **D-S4-3** | 物体—静态环境的碰撞检测放在哪 | **实时层用解析判据（盒顶点 vs 桌面平面），预检层用 MoveIt FCL 扫掠，物理层用 Gazebo 接触传感器**，三层各报各的 | 实时线程里跑 MoveIt FCL（`TransportChecker` 每次重画世界 + FCL 距离查询）不可能满足 8 ms 周期；而解析判据对"长方体 vs 平面"是**精确**的，比采样扫掠更可信 | 需要在文档里明确"离散采样 ≠ 连续安全证明"，这条已在 S3 §12.2 立过 |

### 0.2 建议拆分（§10 详述）

单阶段做完 S4 会同时压上"接口迁移 + 状态机 + Gazebo 附着 + 碰撞 + 故障"五件事，无法独立验收。建议拆 **S4.1 / S4.2 / S4.3**，每段有自己的通过判据，且 **S4.1 完全不碰 Gazebo**（用已有的 `dual_arm_qp_mock.launch.py` + `mock_components/GenericSystem` 跑真实控制器）。

## §1 目标、范围与非目标

### 1.1 目标（S4 完成的定义）

把 S3 在 mock 中验证过的**锚定物体任务 + 双任务 QP 协同搬运**，接入生产控制器 `dual_arm_qp_controller` 与 Gazebo 链路，跑完一次**双臂理想固定抓持搬运**：从经过检查的双臂构型出发 → 接近 → 闭合夹爪并确认理想抓持 → 抬升 → 平移 → 下降放置 → 释放 → 完整日志与指标。

### 1.2 范围

| 项 | 是否在 S4 |
|---|---|
| `dual_arm_qp_controller` 增加物体任务接线、目标流、状态监控 | ✅ |
| 新建物体任务的中性库（`dual_arm_object_task`，见 D-S4-1） | ✅ |
| 新建/改造 Gazebo 场景（样件、支撑、世界） | ✅ |
| Gazebo 理想抓持附着（`DetachableJoint`） | ✅ |
| 任务执行器与状态机（非实时进程） | ✅ |
| 物体—环境碰撞（三层方案，见 D-S4-3） | ✅ |
| HOLD / ABORT / FAULT 的检测、归因、日志 | ✅ |
| 回归 S3 全部用例 + C2 全部用例 | ✅ |
| 力控、摩擦锥、夹爪夹持力、真实夹爪传感器 | ❌ |
| 真机 ServoJ 实机实验 | ❌（挂起） |
| S5 的完整故障注入矩阵（本 S4 只做 4 类基础注入） | 部分，S5 补齐 |
| 支撑式欠约束搬运 | ❌（延后） |

### 1.3 非目标（明确不做，防止范围蔓延）

1. **不重新设计 QP 数学**：`z = [dq(12); s_rel(6); s_obj(6)]`、外部 `ObjectTaskRow` 约定、`row.J = J_O / row.e = -e_O / row.body_twist_ff = +v_d` 的符号契约、`w_center` 权衡结论，全部沿用 S3，**一个符号都不改**。
2. **不改 S2 冻结基线**：`src/dual_arm_transport/config/transport_baseline.yaml` 只读。
3. **不重构 C2 求解器/算法**：`dual_arm_qp_core` 除已有的 `ObjectTaskRow` 重载外不再加公开接口。
4. **不追求"物理上真的夹住了"**：第一版是**理想固定抓持**（运动学刚体约束），Gazebo 里用关节约束近似，不建模摩擦力/夹持力。三层成功（运动学跟随 / 物理接触稳定 / 真实夹持）必须分开报，见 §4.7.4。
5. **不把采样碰撞检查包装成"连续碰撞安全证明"**。

### 2.5 碰撞能力的真实边界（三层，各自能做什么）

| 层 | 实现 | 能查 | 查不了 | 实时性 |
|---|---|---|---|---|
| **A. 胶囊解析** | `src/dual_arm_collision/`（`kCapsulesPerArm = 6`，`distance(q)`、`distanceGradient`） | 臂—臂最小距离 | 任何世界物体、任何自碰撞（非跨臂） | 微秒级，**可进 RT** |
| **B. MoveIt FCL** | `src/dual_arm_pose_optimization/` 的 `DualArmScene` / `MoveItCollisionBackend`；`TransportChecker::checkState/checkSweep/checkSweepTracking` | 全 URDF 网格 vs 场景物体（样件、支撑）、ACM 豁免 | 实时性（每次 `applyWorld` 要重画世界 + 重建 FCL） | 毫秒—百毫秒级，**只能离线/预检** |
| **C. Gazebo 物理** | `ignition-gazebo6 6.16.0` + `gz_ros2_control` | 真实接触、穿透、约束冲突 | 解释性（不知道"豁免"，只知道几何相交） | 仿真步长内 |

**S3 留下的洞**（S3 验收 §12.2 已自认）：`TransportChecker::checkSweepTracking` 解决的是"样件 vs 手指/臂"，**没有**"样件 vs 桌面/环境"这一层。原因很具体：`DualArmScene` 里被插入的只有样件与候选支撑，而支撑在 S2/S3 里是**被检查对象**而非地面。

**边界铁律**：

- 实时线程**不**做：MoveIt/FCL 查询、文件 IO、日志字符串拼接、yaml 解析、`DetachableJoint` 调用、夹爪 action。
- 非实时进程**不**做：直接写关节命令、绕过控制器改 `q_cmd`。
- 状态机**只**在非实时进程里；实时控制器只有一个"执行/保持"的二元本地状态（+ 故障码）。

### 4.2 目标如何进 QP（本文固定的设计选择）

**选项 A（推荐，本文采用）：轨迹句柄 + 控制器内部播放**

- 执行器调用服务 `~/start_transport`，参数是一份**轨迹规格**（沿用 `config/s3_transport_trajectory.yaml` 的 `phases` / `time_scaling` / `dt`，加一个 `start_world_T_object` 覆盖项）。
- 控制器在**非实时回调**里构造 `FrozenObjectTrajectory`（唯一一次堆分配），随后用 `realtime_tools::RealtimeBuffer`（或等价的原子指针交换）交给 `update()`。
- `update()` 内每周期用**轨迹时钟** `t_traj`（不是墙钟）：`T_d = traj.at(t_traj, &v_ff)`；`task = builder.build(q_state_, T_d, v_ff)`；`row.J = task.J; row.e = -task.e; row.body_twist_ff = task.v_ff; row.valid = task.inputs_ok`。时钟语义见 §4.2.1。

为什么不用"125 Hz 目标流"：
- 流式传输必然引入**陈旧性**问题（网络抖动、executor 卡顿），而且"目标过期就该 HOLD"这条判据本身会变成一个新的故障源；
- 前馈 `v_d` 需要与 `T_d` **严格同相位**（S3-T4d/T4e 验证的正是这件事），拆成两条消息就有相位错配风险；
- 轨迹播放让**时间基准只有一个**（控制器自己的 `time`），复跑可重复。

#### 4.2.1 轨迹时钟（P0-1，第二轮审核强制）

**不能用 `time - t_start` 当轨迹时间。** 墙钟在 HOLD 期间照样走，一旦拿它当 `t`，恢复时目标会瞬间跳到"本该到达的位置"，等于凭空产生一个阶跃目标 —— 这正是要禁止的。

采样时钟：

```
t_traj_{k+1} = t_traj_k + dt      if 本周期 committed（真的把 q_cmd 写下去了）
t_traj_{k+1} = t_traj_k           otherwise（求解失败、判据拒绝、HOLD、ABORT）
```

- `t_traj` 单调不减、只在**真的执行**时前进；轨迹结束时钳在 `duration()`，之后 `T_d` 恒为末位姿、`v_ff = 0`。
- 每个周期把 `t_traj` 写进 `cycles.csv`（新列），断言 `Δ ∈ {0, dt}`，这是可机检的。
- 墙钟仍然用，但**只**用于：新鲜度判定、超时判定、日志时间戳。两者不混。

#### 4.2.2 HOLD / RESUME（P0-1，第二轮审核强制）

| 阶段 | 行为 | 判据 |
|---|---|---|
| 进入 HOLD | 冻结 `t_traj`，冻结 `q_cmd_`（双臂同时） | 任一 HOLD 条件触发（见 §4.7.1） |
| HOLD 期间 | 不推进轨迹、不收新目标、不自动恢复 | `t_traj` 逐位不变 |
| 收到 `~/resume` | 先做三项检查再决定 | ① `e_O(t_traj)` 的 `‖e_p‖/‖e_r‖` ≤ `[待标定]` 5 mm / 2°；② 当前 `q` 不越限；③ 判据 A 层全过 |
| `resume` 通过 | 从 `t_traj` 继续，`q_cmd_` 不跳 | 首个周期 `‖T_d − T̂_{O,L}‖` 不增 |
| `resume` 未通过 | **不**强行恢复：把**剩余**轨迹整体平移 `Δ = p̂ − p_d`（只平移，不改速度剖面、不改相位时长），平移量记进 `summary.json` 的 `resume_shift` | 平移后 `‖e_O‖` 严格下降；`v_ff` 序列逐位不变 |
| `resume` 两次未通过 | 进 `ABORT` | 不许无限次平移 |

**代价（必须写进文档，不能藏）**：控制器多了一个"内部时间轴"，因此 `Abort` 语义要清楚 —— `Abort` 立即清空轨迹并冻结（不是"停在轨迹上某点"）。

**选项 B（备选，不采用）**：`~/object_target`（`PoseStamped` + 前馈四元数/向量两条消息），控制器只存最新值，超过 3 个周期判 `stale_command` → HOLD。优点是支持"手动点动"；缺点如上。**S4 只把"手动点动"作为调试工具另外做一条 `~/jog_object_target`，不进主链路。**

#### 4.3.2 为什么不是所有逻辑都进实时线程

| 逻辑 | 放实时线程？ | 理由（具体到本仓库） |
|---|---|---|
| QP 装配/求解 | ✅ 必须 | 8 ms 周期 |
| A 层便宜判据（胶囊、盒-桌面解析、陈旧） | ✅ | 微秒级，且必须"每周期都查"才叫安全层 |

### 4.4 抓持初始化与锁存语义（G7 的具体解法）

时间线（一次任务内只做一次）：

1. `GRASP` 子步③：用**测得的** `q` 算 `T̂_{O,L}(q)`、`T̂_{O,R}(q)`，并读 Gazebo 的样件真值 `T_WO^gz`（若可用）。
2. 断言 `decoupledPoseError(T̂_{O,L}, T_WO^gz)` ≤ `[待标定]`（建议 3 mm / 1°），否则 `FAULT(grasp_check_failed)` —— 这是"夹爪确实合上了"的运动学证据。
3. 断言两锚定估计一致性 `anchorGap(T̂_{O,L}, T̂_{O,R})` ≤ `[待标定]`（建议 2 mm / 0.5°）。
4. **锁存**：`G_L = object_T_left_tcp` 取冻结基线值（不测、不反算）；`G_R` 同理；`L T R* = G_L⁻¹ G_R` **由基线算出并冻结**（S3 已实测 `R = I₃, p = (0, −0.0994, 0)`）。
5. **锁存轨迹起点**：`traj.start_world_T_object := T̂_{O,L}(q_grasp)`（**实测起点**，不是基线标称 `(0,0,0.275)`）。这样即使 `APPROACH` 停位有 2 mm 偏差，轨迹也不会在 `t=0` 产生阶跃。

> 这一条是 S4 对 S3 的**语义升级**：S3 里 `T̂_{O,L}(q_grasp)` 恰好等于冻结 `T_WO*`（S3-T2 断言 ≤1e-10）；S4 里允许它偏离，**偏离量被记录为"抓持偏差"**，而不是被当成误差掩盖。

### 4.5 物体与环境碰撞（G13/G14 的具体解法）

#### 4.5.1 三层分工（不宣称连续）

| 层 | 何时 | 查什么 | 判据 | 失败动作 |
|---|---|---|---|---|
| **A 实时层** | 每周期 | ① 臂—臂胶囊距离（现有 `dual_arm_collision`）；② **盒 8 顶点 vs 桌面平面**（解析、精确）；③ 盒 8 顶点 vs 地面；④ 命令/状态陈旧；⑤ 物体行合法性 | ① ≥ `collision_d_stop`；②③ min 顶点 z ≥ `table_top_z + min_clearance_m`；④ age ≤ 3 周期；⑤ `ObjectTaskRowCheck == Ok` | ②③ → `ABORT`；①→`HOLD`（现有语义）；④⑤→`HOLD` |
| **B 预检层** | 每次相位切换前 | `TransportChecker::checkState` + `checkSweepTracking`（16 采样/段）over **上一轮验证过的关节路径**；再加盒/桌面解析判据逐采样 | `min_clearance ≥ min_clearance_m (=2 mm)` 且无 `in_collision` | 拒绝启动该相位 → `FAULT(precheck_failed)` |
| **C 物理层** | 全程 | Gazebo 接触传感器（样件 collision）、样件真值位姿、右臂跟随误差 | 非预期接触 = `object_env_contact`；右臂跟随 `anchorGap > 阈值` = `follower_divergence` | `ABORT` |

**明确不宣称的事**：

- A 层的盒-桌面判据是**精确**的（凸体 vs 平面），但它只覆盖"桌面/地面"这两类环境；
- B 层是**离散采样**，采样间可能漏（S3 §12.2 已立此口径）；
- 因此 **S4 不提供"连续碰撞安全证明"**，只提供"每拍精确的平面判据 + 预检采样 + 物理接触见证"三件证据。

#### 4.5.2 为什么"盒 vs 臂"不查

抓持期间盒与手指是**设计上的接触**（S2 已把 `grasp_contact_links` 放进 ACM：`left_finger1/2`、`right_finger1/2`）。若把盒 vs 臂放进实时判据，正常抓持会立刻"碰撞"。故：

- 盒 vs 手指：**豁免**（ACM 已有机制）；
- 盒 vs 臂的其他连杆（腕、小臂）：**不豁免**，由 B 层在预检里查（`robot_world` 层已覆盖），实时层不查（会误报）。

#### 4.5.3 有限几何与允许接触（P0-2，第二轮审核强制）

**"盒顶点 z ≥ 桌面平面"只对半空间成立，对一张有限大小的桌子是错的**：样件移出桌面边缘时，那个平面下方已经什么都没有，判据却还在拦。反过来，桌子边缘的竖直侧面也完全没被覆盖。

因此改用：

| 对象 | 几何 | 判据 | 保守方向 |
|---|---|---|---|
| 桌面 / 地面 | **有限长方体**（pose + size 从 world SDF 读） | 样件 OBB 与桌面 OBB 的 **SAT（15 轴）** 分离测试：必须分离 | **精确**（分离轴定理对凸体是充要的） |
| 支撑柱（禁止方向） | 圆柱 → **外接方盒** `2r × 2r × h` | 样件 OBB 与外接方盒必须分离 | **保守**（宁可误报：与外接盒都不碰 ⇒ 一定不碰圆柱） |
| 支撑柱（允许接触方向） | 精确：顶面平面 `z = top_z` + 圆盘 `ρ ≤ r` | `LOWER/RELEASE/COMPLETE` 相位允许底面落在该平面上 | **精确**（接触是设计意图，不能误报） |
| 夹爪指面 ↔ 样件 | 设计接触 | 豁免（ACM `grasp_contact_links`） | — |

**允许接触清单（白名单，其余一切接触都是违规）**：

1. 四个手指的指面 ↔ 样件侧面（抓持期全程）；
2. 样件底面 ↔ 支撑顶面（仅 `LOWER` 之后的相位）。

**桌面几何必须与基线对齐**：从 world SDF 读桌面 pose/size 后，断言其顶面 `z` 与 `src/dual_arm_transport/config/transport_baseline.yaml` 的 `support.top_z_m = 0.25` 相差 ≤ 1e-6，否则启动即失败（防止"场景改了、基线没改"的静默错位）。

#### 4.5.4 物体真值从哪来

| 量 | 来源 | 用途 | 注意 |
|---|---|---|---|
| `T_WO^gz` | Gazebo 样件位姿（经 `ros_gz_bridge` 或 `tf2`，`[待标定]` 选一条） | 物理真值、抓持检查、放置判据 | 附着期间它由左臂决定，**不能**当作独立证据（见 §4.7.4） |
| `T̂_{O,L}`/`T̂_{O,R}` | 控制器/执行器用 `q` 算 | 锚定估计、右臂跟随 | 独立于物理 |
| `e_follow` | `anchorGap(T̂_{O,L}, T̂_{O,R})` | **右臂是否真的跟着物体**（不受附着影响的独立见证） | S3 §2.5 已证明它就是闭链残差 |

### 4.6 Gazebo 理想附着（G11/G12 的具体解法）

#### 4.6.1 机制

- 用 Fortress 自带 `ignition-gazebo-detachable-joint-system`（已确认存在，见 §2.7），在 C4.3 专用 xacro 里给机器人模型加 `<gazebo><plugin ...>`：
  `parent_link = left_grasp_frame`、`child_model = c43_sample`、`child_link = c43_sample_link`。
- 附着 = 向默认主题 `/model/s622_dual_arm/detachable_joint/attach` 发一条空消息；分离 = `/detach`。
- 附着时机：`GRASP` 子步⑤（夹爪已闭合、抓持检查已过）。
- **分离顺序（P0-3，第二轮审核强制；统一为唯一顺序，不许有第二个版本）**：

```
① 确认样件被稳定支撑：底面距支撑顶面 ≤ 1 mm，且竖直速度 ≤ 5 mm/s（连续 3 个采样）
② detach
③ 等 100 ms，确认样件没有随夹爪上升（Δz ≤ 0.5 mm）
④ 张开手指
⑤ 两臂后退
```

任何一步失败 → `FAULT(release_failed)`，并且**不回退**到"先张手再 detach"（那会导致样件被手指弹开或卡住）。

#### 4.6.2 为什么只 attach 一侧（D-S4-2）

若左右各建一个固定关节到同一个样件，则"左臂—样件—右臂—躯干"构成**闭环**：两臂各 6 个位置伺服 + 2 条刚性约束，物理求解器只能靠约束冲突硬解，表现为抖动、穿透、甚至飞散。数学上也不必要：S3 的协同本来就由 **QP 的相对任务 + 物体任务**保证闭链，物理关节只是"让样件跟着左手走"的一个仿真装置。

**因此**：左臂 = 物理附着；右臂 = 由 QP 相对任务带到 `L T R*`；两者一致性由 `e_follow` 度量。

**并且**要做一个**对照实验**（S4-T12）：`--attach both` 跑同一轨迹，把抖动/接触力/穿透记录成"过约束的反例"，证明单侧附着不是偷懒而是必要的。这个实验**只诊断、不支持**。

#### 4.6.3 附着不能"瞬移"

`DetachableJoint` 建立的是"当前相对位姿"的固定关节（不是 snap 到某个标称位姿），但仍要防：
- 附着前记录 `T_WO^gz`，附着后 100 ms 再读一次，`‖Δp‖ ≤ [待标定] 2 mm`、`‖ΔR‖ ≤ [待标定] 0.5°`，否则 `FAULT(attach_failed)`。
- 附着前必须满足"夹爪指面与样件侧面接触"（由抓持检查的运动学误差间接保证）。

#### 4.6.4 三个层次必须分开报（用户 §三.5 要求）

| 层次 | 判据 | 证据 | 能说明什么 |
|---|---|---|---|
| **L1 运动学跟随** | 相对位姿误差、锚定物体误差、右臂跟随误差 | 控制器 12 维状态 + `T̂_{O,L/R}` | QP/闭链数学对不对 |
| **L2 Gazebo 物理接触稳定** | 样件无穿透、无非预期接触、无约束冲突抖动、附着未断 | 接触传感器 + 样件真值 | 物理世界是否"配合"了数学模型 |
| **L3 真实夹持稳定** | 摩擦锥、夹持力、滑移 | **S4 没有**（无夹爪力控/摩擦建模） | **S4 不能宣称** |

报告里这三行必须分开写，禁止用 L1 数字去暗示 L3。

#### 4.6.5 插件必须**实测**验证，不得从共享库字符串推断（P0-3）

§2.7 里"参数名/默认主题"是从 `.so` 的字符串表读出来的 —— 这只能说明**字符串存在于二进制里**，不能证明插件在这个 Fortress 版本上按这个语义工作。因此 W6 的第一步不是接线，而是 **S4-T18 插件实测**：

1. 起一个最小世界：一个静止模型 + 一个自由落体模型 + 一个带该插件的模型；
2. `ign topic -l` / `ign service -l` 记录**真实**的主题与服务名；
3. 实际发一次 attach，确认两体变成刚体（相对位姿 1 s 内不变）；再发一次 detach，确认分离；
4. 记录 attach 是否 snap、snap 距离是多少；
5. 产出 `plugin_probe.json`（真实主题名、参数名是否被接受、attach/detach 生效证据）。

**判据**：`plugin_probe.json` 里的主题名必须与 xacro 里写的一致；若不一致，以实测为准并**更新本文档**，不许"照文档实现"。

#### 4.7.1 控制器必须能**独立**保护自己（P0-5，第二轮审核强制）

执行器是普通节点，会崩溃、会被 `Ctrl-C`、会卡在服务调用里。**控制器的安全不能依赖执行器活着。** 因此控制器自带一张 HOLD 条件表，全部在实时线程内判定、不依赖任何外部消息：

| # | 条件 | 阈值 | 码 | 恢复方式 |
|---|---|---|---|---|
| E1 | `q_state` 越限 | `q_min ≤ q ≤ q_max`（含 1e-9 容差） | `joint_state_out_of_bounds` | 人工 |
| E2 | `q_state` 过期 | 距上一条 joint state > 3 周期（`[待标定]`） | `stale_state` | 过期消失 + `~/resume` |
| E3 | 求解连续失败 | `solve_fail_streak ≥ 10`（沿用） | `qp_solver_failed` | `~/resume` |
| E4 | 更新超时 | `update()` 实际间隔 > `2·dt` 连续 5 次 | `deadline_missed` | `~/resume` |
| E5 | 物体行非法 | `ObjectTaskRowCheck != Ok` | `object_task_row_invalid` | `~/resume` |
| E6 | 物体姿态误差近 π | `> π − 0.05`（冻结值 `3.0915926535897933`） | `object_error_near_pi` | 需目标改变 |
| E7 | 臂—臂过近 | `< collision_d_stop`（沿用） | `collision` | `~/resume` |
| E8 | **执行器心跳丢失** | 距最后 `~/heartbeat` > 100 ms（`[待标定]`） | `executor_lost` | 执行器回来 + `~/resume` |

**锁存与恢复权限（不许"自动恢复"）**：

| 类别 | 触发 | 恢复前提 |
|---|---|---|
| `HOLD`（可恢复） | E1–E8 中除 E1 外 | 条件消失 **且** 收到显式 `~/resume`；控制器**不**自己恢复 |
| `FAULT`（需重置） | E1、`grasp_check_failed`、`attach_failed`、`precheck_failed`、`release_failed` | 收到 `~/reset`（并重新 `~/start_transport`） |
| `ABORT`（终止本次任务） | `closure_violated`、`object_env_contact`、`object_table_clearance`、`follower_divergence` | 只能新的 `~/start_transport` |

**职责边界（写死，避免两方都以为自己负责）**：

| 职责 | 控制器（实时） | 执行器（非实时） |
|---|---|---|
| 每拍能不能走、走多少 | ✅ 唯一 | ❌ |
| 冻结与安全联锁 | ✅ 唯一（含执行器失联） | ❌ |
| 相位/状态迁移 | ❌ | ✅ 唯一 |
| 夹爪、附着、预检 | ❌ | ✅ 唯一 |
| 目标轨迹内容 | 只执行，不改 | ✅ 唯一 |
| 记录与产物 | 只出 Status | ✅ 唯一 |

### 5.1 关键实现细节（预先钉死，避免实施时再讨论）

1. **`w_center`**：控制器默认 `1e-4`（S3 实测：`1e-2` 会让 `max e_rel` 到 `1.7e-3` 并失败；`1e-4` 降到 `1.67e-05` 且步长只差 0.1%）。**不改** `DualArmQpParams` 的默认值（会让 S3 的 legacy golden 失效），只在控制器与 S4 配置里覆盖。
2. **`w_obj` / `kp_obj` / `w_slack_obj`**：`w_obj = 1.0`、`kp_obj = 20.0`（S3 `ff_1` 场景同值）、`w_slack_obj = 1e3`。控制器要**断言** `w_obj > 0 ⇒ w_slack_obj ≥ 1e2`（否则物体任务"无牙"，S3-T5h 的教训）。
3. **`w_null_*` 必须全 0**：两个 6 维任务 + 12 自由度，满秩时零空间为零；S3-T18a 实测 `rank=12`、`σ_min=7.945620e-02`、`cond=35.06`。控制器若误设非零 `w_null_*`，`N ≈ 0` 会让求解器在噪声里打转。
4. **`v_max`**：Gazebo profile 现有 `1.0` rad/s；`dt=0.008` ⇒ 单拍 8 mrad。S3 全绿用的是核心默认 `2.5`。**S4.1 先用 `2.5` 复现 S3，S4.2 再评估降到 `1.0` 是否影响跟踪**（这是两个变量，不能同时改）。
5. **`enable_singularity`**：保持 `false`（S3 从未启用；W0 已查明它在控制器里是死参数）。若要开，必须单独一轮实验。
6. **时间轴**：`t` 用 `update()` 的 `time`（`rclcpp::Time`），`t_start` 在服务回调里记录并以原子量交给 RT；`t` 单调性由 `update()` 保证。
7. **`q_state` 越限**：`update()` 进入时先查 `q_min ≤ q_state ≤ q_max`，越限直接 `HOLD(joint_state_out_of_bounds)` 并**不进 QP**（S3-T13c 的教训：越限状态送进 QP 会被误报成 `qp_solver_failed`）。

## §14 第二轮审核整改（P0×5 / P1×5）——落点、验收条款、回退条件

> 本节是对 `c43_s4_review_r2` 审核意见的逐条应答。每条都给：**裁定** → **文档落点** → **验收条款（可在测试里机检）** → **回退条件**。凡本节与正文冲突，以本节为准（正文已同步修改）。

### 14.1 P0-1 轨迹时钟与 HOLD/RESUME

**裁定**：`time - t_start` 不能代表轨迹时间；HOLD 必须冻结轨迹时间；RESUME 必须重新检查状态与剩余轨迹，避免目标跳变。

**落点**：§4.2.1（采样时钟）、§4.2.2（HOLD/RESUME 表）、§4.7.1 的 E4。

**验收条款**：

| # | 条款 | 机检方式 |
|---|---|---|
| A1 | `t_traj` 只在 `committed` 的周期推进 | `cycles.csv` 中 `Δ t_traj ∈ {0, dt}`，无第三种取值 |
| A2 | HOLD 期间 `t_traj` 与 `q_cmd` 逐位不变 | 注入 HOLD，断言 `t_traj[k] == t_traj[k-1]` 且 `q_cmd` 差为 0 |
| A3 | `resume` 前必须过三检查（误差/越限/A 层） | 三检查任一不过 ⇒ 不得进入运行态（状态序列里看不到 `RUNNING`） |
| A4 | `resume` 后不产生目标阶跃 | 首个周期的 `‖T_d − T̂_{O,L}‖` 不增，且 `‖ΔT_d‖ ≤ v_max·dt` |
| A5 | 平移分支只在"剩余轨迹整体平移"时使用 | `summary.json` 的 `resume_shift` 只含 `Δp`，`v_ff` 序列逐位不变 |
| A6 | 两次 resume 失败即 `ABORT` | 状态序列 `HOLD→ABORT`，无第三次 resume |

**回退条件**：若平移分支在转弯相位造成速度不连续（`v_ff` 相邻周期差 > `[待标定]`），**删掉平移分支**，退化为"A3 不过即 `ABORT`"。这是保守方向，允许。

### 14.2 P0-2 有限几何与支撑接触

**裁定**：盒顶点对平面只在半空间精确；必须处理桌面有限 XY、支撑柱几何、允许的目标支撑接触、禁止穿透。

**落点**：§4.5.3（几何与允许接触表）、§4.5.1（A 层判据改为 SAT）、§8 的 P0-8。

**验收条款**：

| # | 条款 | 机检方式 |
|---|---|---|
| B1 | 桌面按**有限长方体**建模，几何从 world SDF 读 | 启动断言 `top_z` 与基线 `0.25` 差 ≤ 1e-6 |
| B2 | 样件 vs 桌面/地面用 **OBB-OBB SAT（15 轴）** | S4-T11 交叉验证：与 FCL 判定不一致数 = 0 |
| B3 | 支撑柱禁止方向用**外接方盒**（保守），允许方向用**精确圆盘+顶面** | S4-T20：桌外下降不误拦；桌面穿透必报 |

| B5 | 每条判据标注保守方向 | 文档即证据；代码注释同 |

**回退条件**：若 SAT 在 RT 超预算（S4-T2 不达标），退化为"8 顶点 + 12 边中点"近似判据，**必须**在偏差登记里写明"降级为近似、桌沿附近可能漏报"，并降低对应验收等级。

### 14.3 P0-3 DetachableJoint 与 RELEASE

**裁定**：统一附着解除顺序；先确认稳定支撑，再 detach、张手、后退；插件参数/主题/状态反馈必须对实际安装的 Fortress 版本**实测验证**。

**落点**：§4.6.1（唯一顺序）、§4.6.5（实测验证）、S4-T18、S4-T16。

**验收条款**：

| # | 条款 | 机检方式 |
