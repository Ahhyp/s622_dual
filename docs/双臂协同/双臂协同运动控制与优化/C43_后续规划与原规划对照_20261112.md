## 3. 建议实施顺序与具体交付

下面N1～N6是执行批次，不是新的正式Gate编号。当前N1已有首轮工程完成证据；N2控制器验证和新物理配置的C++executor全流程已有首轮证据，原W7全矩阵仍未重签；N3仅新增了控制器/物理分列指标；N4仅有局部落座HOLD/ACK正向证据，未完成故障矩阵；N5/N6其余工作仍待实施。

### N1：整理和冻结已经成功的物理搬运配置

**目的：**让成功结果脱离个人会话与历史日志目录，避免下一次清理log后无法启动。

交付：

1. 为当前物理搬运配置建立独立任务定义：样件、两支撑、候选关节/物体抓取变换、路径、驱动力、诊断阈值及来源。
2. 将启动必需的种子URDF/world、候选和轨迹转为正式可安装资源或可从源码生成的输入；消除`c43_force_lab.py`默认读取旧log模型的依赖。
3. 无GUI与GUI共用同一任务输入；默认每轮唯一输出目录，保留失败与启动失败状态，不覆盖旧记录。
4. 完整记录源码版本/哈希、模型、Gazebo版本、物理步长、控制器、ROS域、IGN分区、随机种子、原生生效接触参数及阈值口径。
5. 把物理等待改为仿真时间，把墙钟保留为仿真停止/失联的看门狗；旧“20 s保持”仍按原采样跨度解释。
6. 将当前±25 mm/15°候选版本化；在没有重新验证前，保留原STL与实际生效接触参数，不为了整理配置就顺手改变摩擦。

验证：新输出目录无GUI完整复跑，核对四指接触、无支撑空中搬运、目标落座与退离；从独立构建/安装资源启动而不是依赖旧实验log。先做少量工程冒烟，再冻结正式重复次数，不能把少量通过写成可靠性保证。

**N1不要求增加FT闭环。** 当前固定驱动力已经是有价值的参考组。

### N2：物理支路与正式QP/W7对齐

**目的：**回到原C4.3“复用QP完成协同搬运”的控制研究问题。

先做最小接口与文本对照：原W7的左单附着/手指JTC约定，与当前无weld/原生驱动力不同。明确保留的理想附着参考配置，以及新增物理接触配置的范围与命名；对需要改变的正式约定单列差异，不擅自改验收阈值或历史状态。

实现顺序建议：

1. 保留同步JTC参考组和全部原始数据。
2. 利用新候选计算真实G_L、G_R及相对目标，不能仍给QP发送旧冻结抓取关系。
3. 接近阶段由JTC完成后受控停止/切换；只有确认QP active且资源归属正确，才进入QP搬运阶段。
4. 手指原生驱动力与手指JTC保持互斥；臂JTC与QP也保持互斥。
5. 将接触建立、物体位姿、目标支撑确认及最终退离接入已有任务状态，而不是重写第二套正式状态机。
6. 先定点持物/小幅抬升，再扩大到同一60 mm抬升、120 mm横移；接入正式日志。

验证：输入和驱动力相同的JTC参考/QP实验都记录真实物体轨迹、两手相对位姿、两侧独立推算物体的一致性和跟随误差。不能只比较节点是否COMPLETE，也不能直接以当前约1.2 mm落点误差推导整个QP控制性能。

### N3：W8度量与C4.4统一评测口径

优先补齐：

- `e_O`：物体真值对参考轨迹，分别统计平移/旋转、峰值/RMS/末态，记录采样频率与时序。
- `e_rel`：左右TCP相对位姿误差；记录两侧独立物体估计的闭合一致性，不能复制同一个估计当成两个来源。
- `e_follow`：控制器状态和实际关节跟随，区分控制器到达、腕部到达与物体跟随。
- 夹持滑移、四指接触持续率、源/目标支撑接触阶段、姿态峰值、末态误差、清距、相位用时和RTF。
- 统一首过、允许重试、启动失败、受干扰、协议已替代等分类；有限轮次报告原始n/N，不将两次成功宣传为稳定成功率。

原W8中的前馈on/off必须在正式QP分支且其他条件相同后进行；单/双附着属于理想模型的隔离对照，不能把当前无weld实验替换成这些矩阵的已完成行。三来源要按时间戳/坐标系/延迟核对。L1运动学、L2仿真物理接触、L3真实硬件夹持分列，L3当前不作已验收结论。

建议先用当前无GUI日志验证指标计算，再固定测试点、路径、重复规模与输入清单；追加实验时保持原始失败行，形成C4.4可消费的结果表。

### N4：W9新增故障、安全与恢复分支

先核对已有W3/W7的有效证据，仅补新物理任务引入或受变更影响的路径，避免全盘重做。

建议覆盖：

| 场景 | 必须观察什么 |
|---|---|
| 一臂滞后/停滞、两臂目标不同步 | 跟随/相对误差如何触发既有状态；两臂是否共同停止继续推进 |
| 控制器失联、状态过期、仿真时钟停滞 | 物理等待与通信看门狗分开；不得无状态继续运动 |
| 未形成四指接触或搬运中丢失接触 | 是否拒绝抬升、是否按正式策略处理失持，而非只等总开口塌缩 |
| 样件碰桌面/支撑侧面、非手指连杆碰样件 | 相位白名单与实际接触是否一致；保留首次触发证据 |
| 放下未接触目标支撑 | 不误报落座、不按成功路径直接松爪 |
| HOLD和恢复 | 记录命令冻结、状态/ACK、恢复入口和第一条新命令；异常退出不算恢复验证 |

物理无附着配置下的attach相关项按模型适用性标注；原理想附着配置仍依原要求保留该对照，不能删项后宣称原矩阵全覆盖。正式failure code、阈值及安全状态遵守现有契约，不因诊断脚本用了15 mm/48 mm就自动注册或批准。

本项是Gazebo故障实验，不能签发真实硬件安全结论。

### N5：C4.5消融与必要的夹持扩展

在上述输入、指标与失败定义冻结后，选择最能回答问题的少量对照：

1. 同候选同路径下的同步JTC参考与QP控制，评价真实物体跟随及相对位姿。
2. 原偏端部抓取与新抓取关系，保留其适用路径差异、失败阶段及碰撞可达性，不强行跑已知非法路径。
3. 原STL与等包络三盒碰撞的仿真敏感性；摩擦绑定正确性与数值标定分开。
4. 位置夹持、固定驱动力；若后续确有精度/扰动需求，再增加FT闭环，统一接触建立历史后才讨论单一驱动力因素。
5. 单臂横摆与中心约束专项，观察共同移动、单指开限位、横向/竖直滑移；这是尚未解决的问题，不是所有搬运工作的强制前置。
6. 物体质量、初始小偏置、速度或外扰的有限范围验证。每次扩展同时保存实际模型与输入，不拿旧单工况成功率替代。

“控制做得更复杂”不是退出条件；能回答哪项改动改善了哪个指标、付出什么代价，才是消融结果。

## 4. 暂不作为下一步必经项的内容

- **FT闭环：**可选扩展，不因历史怀疑就重写夹持；当前缺少的首先是可复现资源和正式控制链对齐。
- **M4交接从零重做：**已有历史成果，应先检查移植差异；当前C43不是M4的新100轮证据。
- **M5夹具重抓：**可以另开目标；恢复应从当轮物体抓取偏置/居中放置接上。
- **支撑式欠约束课题：**C43首版明确延期的独立方向；两个落座支撑不等于已经研究“欠约束协同搬运”。
- **真机、原生RT验收：**需要对应环境与正式流程，保留原有未验证/挂起状态，不用Gazebo代替。
