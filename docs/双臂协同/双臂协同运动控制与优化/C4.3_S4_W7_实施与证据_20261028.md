## 2. 接线的行为（逐条对应冻结/规划要求）

| 要求 | 实现位置 | 行为 |
|---|---|---|
| 启动焊接**不得**当作 GRASP | `state_machine.cpp` `start()` | 客户端未 `startupVerified()` → `start()` 拒绝，`why=weld_startup_release_pending`；启动窗口内一直 `attached` → 客户端失败 `weld_not_released` |
| GRASP 先确认附着再 LIFT | `tickWeld()` + `phaseDone()` 闸门 | 控制器相位推进与显式 `phaseDone()` **两条路径都被拦**，`why=weld_not_confirmed` |
| 未测到瞬移 = 失败（fail closed） | `AttachClient`（W6）+ 节点 `onPoses()` | 无 pose 证据 → `attach_snap_unmeasured` → HOLD `attach_failed` |
| 瞬移 > 2 mm 必须失败 | 同上（`weld_max_snap_m: 0.002` = 冻结 §14.3 C3） | `attach_snap_exceeded` → HOLD `attach_failed`，且客户端标记必须先 detach |
| RELEASE 先 detach 再后退 | `tickWeld()` + `phaseDone()` 闸门 | 未脱开 → `phaseDone()` 返回 false（`weld_not_confirmed`）；一直脱不开 → FAULT `release_failed` |
| 不重发同一请求 | `weld_attach_requested_` / `weld_detach_requested_` | 每个 attach/detach 只发一次；重试由客户端内部计时决定 |
| 状态机保持纯逻辑 | `attachWeldClient` 注入 | 只有节点碰 ROS；状态机不持有 ROS 类型 |

**一个本轮修掉的真 bug（值得记录）**：`AttachClient` 的 `Confirmed` 是粘性的（启动解除成功后会一直返回
`Confirmed`）。第一版 `tickWeld()` 直接把任意 `Confirmed` 当成“attach 成功”，于是**启动解除被误读成
一次成功附着**，GRASP 立刻放行。现在用 `weld_attach_requested_` 区分“我们请求的 attach”与“启动解除的
残留 Confirmed”，并有专门用例覆盖。

## §10 2026-10-29 真跑结果：T1 定位 + 一次 weld-only GRASP→LIFT

> 证据目录：`docs/双臂协同/双臂协同运动控制与优化/T1_QP满速定位_20261029/`（`README.md` 是总入口）。
> 本节只记录**实际跑过**的东西；没有把 weld 当真实夹爪，也没有把 `COMPLETE` 当 W7-C 全部指标 PASS。

### 10.1 T1：QP 满速的根因与修复

**现象**：`start_transport` 后 `approach` 段 200 ms 内 `active_limit_count=10–12`，
`min_limit_margin_rad≈1.6 rad`（离位置限位很远），`max|dq|=v_max·dt=0.008`，执行器
`joint_limit_saturation` HOLD，attach 从未发生。

**根因链**（实测定量 + 离线 FK 复核）：

1. launch 用 `ros_gz_sim create -J q_grasp12` 企图让机器人出生在抓取位姿；
2. `gz_ros2_control` 用 URDF `<state_interface><param name="initial_value">` 覆盖关节初值，
   `-J` 实际无效（§8 B-1/B-4）；实测 q0 是 `s622_moveit_config/config/initial_positions.yaml`
   的 `[0.5, −1.05, 1.05, −1.05, −0.8, 0]`；
3. W7-B1 为让起点门通过，把控制器 `home_q` 覆盖成这个出生位姿；
4. 但 `TransportTask` 的相对目标 `left_T_right_` 是**冻结的 grasp 链**（`q_grasp12` 处 FK）：
   - `q_grasp12` 处 `e_rel = 0.000000 m / 0.000000 rad`
   - `[0.5, −1.05, …]` 处 `e_rel = 2.342792 m / π rad`
5. 控制器每拍要 `alpha·e = 0.16 × 2.34 m ≈ 0.375 m` / `0.50 rad`，而每关节上限只有
   `1.0 × 0.008 = 0.008 rad`；`w_center=1e-4 ≪ w_slack=1e3`，QP 只能顶满 `dq` 并牺牲物体任务。

**实测对比**（同一台 Gazebo、同一条 5/6 相位轨迹）：

| 阶段 | q0 | `e_rel` | `active_limit_count` | `max|dq|` | `e_obj_pos` |
|---|---|---|---|---|---|
| 修复前 | `[0.500 −1.050 …]` | 2.196 m / 2.927 rad | 11 → 12 | 恒 0.00800 | 0 → 0.55 m |
| 修复后 | `q_grasp12` | 0.0003 m / 0.0011 rad | **0** | ≤5.2e-4 | ~1e-4 |

**修复**（不改任何冻结判据/阈值）：

- 新增 `src/gz_launch/config/c43_s4_gazebo_initial_left.yaml` / `…_right.yaml`，分别写左右臂
  `q_grasp12`；`c43_s4_dual_arm_gazebo.urdf.xacro` 让左右 `ros2_control` 各读对应文件；
- `c43_s4_qp_home_override.yaml` 的 `home_q` 改回 `q_grasp12`；
- 结果：出生位姿 = `home_q` = 冻结 grasp 链。
