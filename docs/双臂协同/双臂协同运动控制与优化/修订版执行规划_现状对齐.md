### 1.2 已建成的控制基础设施（不要重做）

1. **双臂统一模型**：`world → left_base/right_base`，`prefix` 参数化，气爪、全局/腕部相机；SRDF 五组 `left_arm(6)` / `right_arm(6)` / `left_hand` / `right_hand` / `dual_arm(12)`，含 `dual_home`、`dual_handover_ready`。
2. **仿真**：单 `controller_manager` + 5 controllers（left/right arm+hand + JSB），`gz_ros2_control`；两个 namespaced move_group（`/move_group_fairino`、`/move_group_kdl`）；左右 MoveIt Servo 节点；`trajectory_retime_server`（MoveIt TOTG）；`planning_scene_service`（双臂 touch_links）；全局 + 腕部相机 bridge。
3. **真机 hardware**：`fairino_hardware` 已参数化 `ip/prefix/servoj_cmd_t`，分层架构（ros2_control 主线程只做锁内拷贝，独立 `io_loop` 线程调 SDK）；58.3 单臂 20mm 微动验证通过。**真机双臂同 CM 未联调。**
4. **自研规划**：`FairinoPlannerManager`（BiRRT* / Tube-BiRRT* / RRT* / AAPF）+ DH 解析 IK + 多解选择器；left_arm / right_arm 已从 OMPL 切到该管线；`dual_arm(12)` 因 fairino 只支持 6-DOF，**仍走 OMPL**。
5. **12 轴执行**：`dual_move_server` —— 调 `/move_group_fairino/plan_kinematic_path`（group=dual_arm）规划 12-DOF，再拆成 6+6 分别发 `left/right_arm_controller` 的 FollowJointTrajectory 并行执行。
6. **任务层**：BehaviorTree.CPP，已有单臂 pick-place、双臂 handover（`handover_rod.xml`）、M5 夹具重抓等树。

### 1.3 完全没有的东西（本规划要补的空白）

- Pinocchio / OSQP / Ruckig / TOPP-RA / CBF / FCL 距离监控 / 工作空间-可操作度分析；
- **任何自研的速度级 / 雅可比 / QP 运动控制器**（MoveIt Servo 是第三方库、按单臂使用；没有 12 轴统一的层级 QP）；
- 前馈补偿、输入整形、零空间优化、奇异点处理（自研层面）。

### 1.4 关键现实约束（会改变原规划的数字前提）

- **ServoJ 最终定 125Hz（cmdT=0.008），250Hz 已决定不跑。** 原因：SDK/上位机**每 ~100 次 ServoJ 一次 ~1030ms 固有阻塞**（rc=0），500Hz/250Hz 试验被拒；125Hz 是当前稳定配置。
- **Humble 的 JTC 不会因 hardware ERROR 中止**：hardware `read()/write()` 返回 ERROR 后 JTC 仍会跑完并报 success（机械臂可能没动）。安全逻辑必须自己写，不能依赖 JTC。
- Gazebo 与真机是两条链：Gazebo 测的是 JTC 正弦跟踪链；真机测的是插件内 ServoJ 调用链。

## 7. 决策门（修正版）

- **G1 双臂相对抖动**（真机；当前只有 Gazebo 0.00ms）：
  - < 2ms：12 轴同时运动协同可做；
  - 2–10ms：只做互避，不做精确同步；
  - > 10ms：放弃同时运动，转 QP + 避障深度。
  - ⚠️ 补充：即使瞬态抖动合格，ServoJ 的 ~1s 周期性阻塞仍可能让"精确同步"在长任务里周期性失效，需要专门的 stall 恢复策略。
- **G2 标定残差**：仿真 `T_LR_cam` 未稳定 ≤3mm；真机重测后再定协同精度目标。
- **G3 QP 性能**：125Hz → 周期预算 **8ms**。P95 < 1ms 正常；1–3ms 需简化约束集；> 3ms 降频或分层。
