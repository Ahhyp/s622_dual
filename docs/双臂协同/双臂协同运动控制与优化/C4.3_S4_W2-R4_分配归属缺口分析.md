## 2. 为什么不能把这 4501 次推给第三方

1. 探针 `record()` 只在 `malloc()` 里调用；`calloc/realloc/posix_memalign` 只递增计数、**不取栈**；
2. 因此“没有栈”≠“栈里有 libosqp”；
3. 更关键：**Eigen 的对齐分配可能根本不经过 `malloc`**。这是一个必须先澄清的技术事实，见下。

## 3. 一个被忽略的可能性：Eigen 可能走 `posix_memalign`

Eigen 的 `Eigen::internal::aligned_malloc` 在 Linux 上按 `EIGEN_MALLOC_ALREADY_ALIGNED` 选择
`posix_memalign` 或 `malloc`。若走 `posix_memalign`：

- 它**不会**被 `LD_PRELOAD` 的 `malloc` 钩子看到；
- 则 `:210` `solution.x.resize(n)` 的那 2.00 次/solve 分配在探针里**不一定**能对上一一对应。

R3 报告中把 1276 次 malloc 直接钉在 `:210`，**这一点需要复核**（栈帧确实指向该行，但“该行唯一使用 malloc”这一推断缺证据）。

**为了不让归属结论依赖于这个不确定性，本轮改用不受 libc 符号影响的判据**（§4）。

## 4. 决定性补强方法（已实测）：`EIGEN_RUNTIME_NO_MALLOC`

Eigen 提供编译期开关：定义 `EIGEN_RUNTIME_NO_MALLOC` 后，任何 Eigen 侧堆分配都会在
`check_that_malloc_is_allowed()` 处触发断言（`/usr/include/eigen3/Eigen/src/Core/util/Memory.h:164`），
**与走 malloc 还是 posix_memalign 无关**。

本轮实测（`/tmp/w2r4/bounded_vec.cpp`，`-DEIGEN_RUNTIME_NO_MALLOC`）：

| 用例 | 代码 | 结果 |
| --- | --- | --- |
| A | `Eigen::VectorXd v; v.resize(24);` | **SIGABRT（退出码 134）** ⇒ 确实分配 |
| B | `Matrix<double,Dynamic,1,0,24,1> a; a.resize(24); a.resize(12); a.resize(24);` | **退出码 0** ⇒ 容量内 resize **零分配**；`sizeof = 208` |

⇒ 两个结论：

1. `QpSolution::x` 的每次 `resize(n)` **是**一次真实的 Eigen 分配（与 libc 符号无关地证明）；
2. 评审推荐方案 B′（有界动态向量）**能**把它变成零分配 —— 由实测而非推断支持。

## 5. 归属补强方法（建议采纳，本轮未改工具）

### 5.1 类型化拦截（闭合 4501 的必需项）

| 项 | 做法 |
| --- | --- |
| 拦截点 | `malloc`, `calloc`, `realloc`, `reallocarray`, `posix_memalign`, `aligned_alloc`, `memalign`, `valloc`, `pvalloc`, `strdup`, `strndup`, `operator new/new[]` |
| 记录内容 | `kind`（枚举）+ 请求字节 + 返回指针 + 5 帧栈 |
| 闭合判据 | `sum(entries) == total`（相对误差 ≤ 0.1%），否则**报 FAIL 而不是猜** |
| 栈符号化 | 现有 `dladdr` 方案可复用；`-fno-omit-frame-pointer` 保证帧链完整 |

### 5.2 `mallinfo2` / `smaps` 交叉核对（数量级）

每次 solve 前后读 `mallinfo2().uordblks` 与 `/proc/self/smaps` 的 `Heap`；
只用于“数量级是否对得上”，**不作判据**（会受 glibc arena 缓存影响）。

### 5.3 全路径零分配断言（终态）

在测试里用 `EIGEN_RUNTIME_NO_MALLOC` 包住整段 `qp.solve()`：
- 现状预期：**失败**（证明 `solution.x` 分配）；
- 方案 B′ 落地后预期：**通过**；
- 这比“数 3.04 次”更强：它把“零分配”变成可判定命题。

> 局限：该开关只覆盖 Eigen 侧；OSQP 的 `malloc`（33/solve）仍需 5.1 的类型化拦截来归属。
