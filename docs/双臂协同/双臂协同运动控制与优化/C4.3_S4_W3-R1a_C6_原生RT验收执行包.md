性质：执行包 + 本轮实测。**未**伪造、未模拟、未手工构造 PASS；**未**改任何冻结阈值。

## 0. 一句话结论

C6 需要**原生 Linux + 实时能力**的真实测量。本机是 WSL2，门禁按设计拒绝出结论（`ENV_REFUSED`，exit 2）。
本轮把"拒绝"做成了**可比对、可拒绝伪造**的证据链：机器事实 JSON + 门禁自身判定 + 回传审计程序，
目标机跑完后把产物回传，本机可一键判定 C6 证据是否成立。

## 1. 本机环境判定（多信号，不只看 `uname`）

`/tmp/rt_gate_check/machine_facts.json`（本轮新产，门禁自动生成）：

| 信号 | 值 | 含义 |
|---|---|---|
| `kernel` | `6.18.54.1-microsoft-standard-WSL2 … PREEMPT_DYNAMIC` | Microsoft 内核 ⇒ 虚拟化 WSL2 |
| `cmdline` | `… WSL_ROOT_INIT=1 …` | 独立于 `uname` 的第二信号 |
| `preempt_rt_flag` | `false`（`/sys/kernel/realtime` 不存在） | 无 PREEMPT_RT |
| `chrt_fifo_ok` | **false**（`chrt -f 80` 失败） | 无法请求 SCHED_FIFO（agent 无 CAP_SYS_NICE） |
| `governor_cpu0` | 空 | 虚拟 CPU，无 cpufreq |
| `nproc` | 16 | 核数充足，但不足以补偿前四项 |
| `cgroup_cpu_max` | `max 100000` | 未限核，但仍是虚拟化 |

判定：**不合格**。理由不是"名字里有 WSL"，而是"FIFO 调度不可用 + 无 RT 抢占 + 虚拟化时钟"三者同时成立。

## 2. 门禁升级（本轮改动）

`src/dual_arm_qp_controller/scripts/run_native_rt_acceptance.sh`：

1. **新增 `collect_facts()`**：在拒绝前先生成 `machine_facts.json`（schema `c43s4.native_rt.machine_facts.v1`），
   并把 `eligible` 判定写成 `(not wsl) and chrt_fifo_ok and nproc>=4`。
2. 环境不合格时明确写成 `ENV_REFUSED: machine_facts says ...`（exit 2），**不**再只给一句 WSL 提示。
3. `verdict.json` 内嵌 `machine_facts`，使"数字"与"机器"永远一起流转，防止"把别处的日志当本机证据"。
4. 冻结阈值仍由脚本自己用常量判（`p99≤6400 µs`、`interval≤12000 µs`、`overruns=0`、`RSS≤1024 KB`、`fd=0`、`cycles≥638/6380`），不信任被测程序打印的 PASS。

本轮实测：`bash …/run_native_rt_acceptance.sh --out-dir /tmp/rt_gate_check` → `ENV_REFUSED … exit 2`，
产物 `machine_facts.json` + `verdict.txt`（见 §1）。

## 3. 回传审计程序（本轮新增，防伪造）

`src/dual_arm_qp_controller/scripts/audit_native_rt_verdict.py`：

| 输入 | 作用 |
|---|---|
| `verdict.json` | 目标机门禁产物（含内嵌 machine_facts） |
| `machine_facts.json` | 独立机器事实（用于资格判定） |
| `realtime_budget.log` | 原始 gtest 输出（本程序**自己重解析**并重算阈值） |

判定顺序与出口码：

| 码 | 决策 | 含义 |
|---|---|---|
| 0 | `PASS` | 机器合格 + 原始日志重算达标 + 远端不自相矛盾 ⇒ **C6 证据成立**（仍需人工签字，不等于 Gate 放行） |
| 2 | `ENV_REFUSED` | 机器不合格（WSL / FIFO 不可用 / 核数不足）——**即使远端自称 pass 也拒绝** |
| 3 | `FAIL` | 机器合格但数字未达冻结阈值 |
| 4 | `INCONSISTENT` | 缺原始日志、或远端 verdict 与日志矛盾 |
| 5 | `NOT_RUN` | 没有 `verdict.json`（本机现状） |

本轮自检（在本机）：缺产物 → `NOT_RUN`；伪造 `{"pass": true}` + 本机 facts → `ENV_REFUSED`，
并追加理由 `verdict.json claims pass although the machine was ineligible -- refused`。

## 4. 目标机执行步骤（可直接复制）

假设目标机已装 ROS 2 Humble 并有本仓库（`$REPO=/path/to/my_S622`）。

### 4.1 前置条件（缺一不可，门禁会逐条拒绝）

```bash
# 1) 原生内核（非 WSL / 非容器）
grep -qiE 'microsoft|wsl' /proc/version && echo "WSL -> 不能作为 C6 证据" || echo "native ok"

# 2) PREEMPT_RT（推荐；主线 6.12+ 的 PREEMPT_RT 也可，门禁只告警不拒绝）
cat /sys/kernel/realtime 2>/dev/null || echo "no /sys/kernel/realtime (warn only)"

# 3) FIFO 调度可用（必须）
sudo chrt -f 80 true && echo "FIFO ok"

# 4) governor = performance（建议）
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_governor

# 5) 核数 >= 4
nproc

# 6) 依赖
source /opt/ros/humble/setup.bash && ros2 pkg prefix dual_arm_qp_controller
```

### 4.2 构建与执行（内存安全配方，避免 OOM）

```bash
cd "$REPO"
eval "$(conda shell.bash hook)" && conda activate yolov8     # 需要 empy
PKGS="dual_arm_qp_core dual_arm_qp_controller dual_arm_object_task dual_arm_transport_mock" \
JOBS=2 bash scripts/build_mem_safe.sh

# 关掉无关负载（浏览器/编译/其它 ROS），然后：
sudo bash src/dual_arm_qp_controller/scripts/run_native_rt_acceptance.sh --out-dir /tmp/c43s4_native_rt
echo "gate exit=$?"      # 0=PASS 2=ENV_REFUSED 3=数字未达标
```

> 注意：脚本内部已用 `chrt -f 80` 启动测试；若 `sudo` 不可用，需先给 `CAP_SYS_NICE`
> 或写 `/etc/security/limits.d/` 的 `rtprio` 条目，再以普通用户执行。

### 4.3 需要回传的三件产物

```
/tmp/c43s4_native_rt/verdict.json          # 门禁判定（内嵌 machine_facts）
/tmp/c43s4_native_rt/machine_facts.json    # 机器事实
/tmp/c43s4_native_rt/realtime_budget.log   # 原始 gtest 输出（审计程序要重解析）
```

回传后在本机执行：

```bash
python3 src/dual_arm_qp_controller/scripts/audit_native_rt_verdict.py \
  --verdict /path/verdict.json --facts /path/machine_facts.json \
  --log /path/realtime_budget.log --json /tmp/c6_audit.json
echo "audit exit=$?"    # 0 才算 C6 证据成立
```
