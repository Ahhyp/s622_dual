## 2. 测量装置

- 探针：`/tmp/w2r5/alloc_typed.c` → `liballoctyped.so`（`LD_PRELOAD`）
- 拦截入口（9 类）：`malloc`、`calloc`、`realloc`、`free`、`posix_memalign`、`aligned_alloc`、`memalign`、`valloc`、`pvalloc`、`operator new` / `new[]` / aligned `new`
- 计数语义（按要求区分）：
  - `alloc` / `free` / `fail` **三个独立计数器**，`free` 不计入分配次数
  - `realloc` 区分 `in-place` 与 `moved`（本轮实测 `inplace=1, moved=0`）
  - 失败调用（返回 `nullptr`/非 0）单独计入 `fail`（本轮 `fail=0`）
- 每条记录：**6 帧调用栈** + 入口类型 + 字节数 + 测量阶段（`warmup` / `steady`）
- 模块归属：`dladdr` 解析到 `libosqp.so` / `libdual_arm_qp_core.so` / `libstdc++` / `libc` / 测试仪表；**跳过探针自身的栈帧**（否则归属会全部落到探针上）
- 重入守卫：`busy` 标志把探针自身（`backtrace`/`dladdr`/`fopen`）的分配排除在外

## 3.1 关键适用性发现（必须记录，不能当成"已完全覆盖"）

1. **`-O2/-O3` 下 C++ `new` 被内联或被识别为版本化符号**（`_Znwm@GLIBCXX_3.4`），未加 version script 的 `LD_PRELOAD` 定义无法稳定胜出 ⇒ 生产构建下 `new` 由底层 `malloc` 承担，**总数不丢，但入口标签由 `new` 变为 `malloc`**。
2. **Eigen 在本目标走普通 `malloc`**：`/usr/include/eigen3/Eigen/src/Core/util/Memory.h:52-58` 的 `EIGEN_MALLOC_ALREADY_ALIGNED` 命中（glibc 已 16 字节对齐）⇒ `posix_memalign` 计数为 **0 是预期**，不是漏拦。这一条直接否定了 R4 的"Eigen 可能走 posix_memalign"担忧。

## 5. R3 的 4501 次未归属：解释与证明

R3 的原始 dump（`/tmp/mw2/l1.txt`）：`total_alloc=32623`，entries 求和 **28122**，差 **4501**。

**原因**：R3 的探针**只对 `malloc()` 取栈**；`calloc`/`realloc`/`posix_memalign` 计入总数但不入 entries。

**同一 gtest L1 负载上的类型化测量**：

```
total=32666   malloc=23056   calloc=4502   realloc=1   new=5105   new[]=2
```

`calloc = 4502 ≈ 4501`（±1 为运行间差异）⇒ **4501 次即 calloc 路径**，不是"来源不明的第三方"。

## 6. R3→R4 的 95 次差额：逐项闭合

R4 表：`21075 + 1964 + 4988 + 4501 = 32528`，而 R3 总数 `32623`，差 **95**。

| 项 | R3 原值 | R4 表值 | 差额 |
|---|---|---|---|
| `libstdcxx` | 27 | **未列** | 27 |
| `libc` | 3 | **未列** | 3 |
| `OWN_core` | 1980 | 1964 | 16 |
| `INSTRUMENT` | 5037 | 4988 | 49 |

`27 + 3 + 16 + 49 = 95` —— **与差额完全相等，闭合**。

（分类依据：R3 dump 的"首模块"字段；R4 表的 OWN/INSTR 两项在人工转录时发生了 16/49 的口径漂移，不是新的分配来源。）

另写**仅计数探针**（`/tmp/w2r5/countonly.c`，无 `backtrace`、无 `dladdr`、不做符号解析）：

```
malloc=23100 calloc=4504 realloc=1 free=29531 posix_memalign=0 total_alloc=27605
```

⇒ **两种独立实现在 27606 次上相差 1 次（0.004%）**：证明"取栈 + 符号解析"本身没有显著扰动计数。`mallinfo2` 未用于计数（只可作为字节辅助），符合"不视为完整调用计数器"的要求。

## 9. 本账本的限制（不得当成完备性证明）

1. 只覆盖**动态链接**的堆分配；栈上对象与 `alloca` 不在统计内。
2. `operator new` 在生产构建下并入 `malloc` 桶，故"自有代码调用 `new`"会显示为 `libdual_arm_qp_core.so` 的 `malloc` 站点。
3. 6 帧栈深之外的调用者不可见（若能捕获的帧全部在探针内部则记 `UNKNOWN`，本轮为 0）。
4. `warmup` 阶段单独标记，未计入 `steady` 口径。
5. 字节数随目标运动状态变化（`static` 33.78 KB/solve vs `moving` 37.01 KB/solve），**次数不变**。
