## 0. 一句话目标与变更记录

**目标：**在左右 S622 机械臂的开关式二指夹爪分别抓住同一刚性物体两端的假设下，复用既有 12 轴位置型 QP 协同控制链路，实现可重复的「接近—闭合—抬升—平移—下降—释放—撤离」仿真任务，并量化物体轨迹、双手相对位姿、抓取闭环一致性、碰撞安全、实时性与故障响应。

## 2. 系统架构、分层和数据合同

建议逻辑分层（实际 ROS 包落点在 S0 审计后确认）：

```text
C4.3 task runner / state machine
      ├── task spec: object, grasp transforms, path, timeouts
      ├── C4.2 candidate loader + C4.3 dual-grasp feasibility
      ├── ideal grasp / object-state observer
      ├── supervisory stop / error manager
      └── measurement and experiment recorder
                   ↓ desired object SE(3) path
C2 trajectory tracking + relative-pose QP (reuse current backend)
                   ↓ qdot or qcmd adapter, confirmed by repository
ros2_control command-mode (single owner for each commanded joint)
                   ↓
mock / Gazebo position-compatible profile
```

**控制资源独占**：同一组关节不得由左右 JTC 与 QP 并发下发冲突命令；切换应在受控暂停下完成，严格检查控制器状态及资源占用。ROS 2 Humble 的 `controller_manager` 支持控制器切换，但具体 profile 必须实测。

**物体在三个系统中的身份要分清：**
- 可视化/状态估计：物体的 `T_WO`；
- 规划场景：作为碰撞物体管理，被抓后需要正确维护允许接触集合；
- 动力学场景：第一版可用 kinematic/ideal 物体代理，不把它当作真实接触稳定实验。

不得把“MoveIt 物体 attach 到一个 link”解释成两端闭链的物理求解。不得默认把物体同时以两个 fixed joint 焊在两条独立控制链上。

## 3. 刚性双抓取数学模型

### 3.1 位姿与固定抓取变换

令 `W` 世界系、`O` 物体系、`L/R` 左/右抓取 TCP；齐次变换记 `^A T_B`。

抓取时刻冻结：
- `G_L = ^O T_L*`
- `G_R = ^O T_R*`

理想固定抓取要求：

$$
{}^W T_L(q_L) = {}^W T_O\,G_L,\qquad
{}^W T_R(q_R) = {}^W T_O\,G_R.
$$

从而目标双手相对位姿固定：

$$
{}^L T_R^* = G_L^{-1}G_R.
$$

**两侧均为完整六维固定抓取时，理想模型一般构成闭链约束。** 在实际有微小机械误差的系统中，这并不代表两侧内部力为零。

### 3.2 抓取一致性残差

由左右 FK 分别推算物体：

$$
{}^W \hat T_{O,L} = {}^W T_L G_L^{-1},\qquad
{}^W \hat T_{O,R} = {}^W T_R G_R^{-1}.
$$

记录 SE(3) 残差：

$$
e_{closure} = \log\!\left[( {}^W\hat T_{O,L})^{-1} {}^W\hat T_{O,R}\right]^\vee.
$$

记录分量而非仅一个混合标量：平移误差 `[m]`，旋转误差 `[rad]`。`Log`、左右误差方向和 frame 选择必须用有限差分/构造例测试。

**关键防作弊规则：**可以用一个明确标记的 `T_WO,display` 显示物体，但左、右独立推算的 `T_WO` 必须分别入日志；不能只看显示物体跟踪误差就判成功。

### 3.3 物体跟踪与双手相对保持

物体参考路径为 `T_WO,d(t)`，期望左右 TCP：

$$
T_{WL,d}(t)=T_{WO,d}(t)G_L,\qquad
T_{WR,d}(t)=T_{WO,d}(t)G_R.
$$

在 C2 现有约定下使用：
- 主任务：相对位姿残差或等效约束 `e_rel`；
- 运动任务：物体/协调框架跟踪误差 `e_O`；
- 限制：位置、速度、加速度（如存在）、碰撞安全；
- 次目标：关节居中、可操作度等。

建议数学表达（**设计目标，不宣称与仓库现有实现相同**）：

$$
\min_{\dot q,s}\ w_O\|J_O\dot q-v_{O,d}\|^2
  + w_s\|s\|^2+w_q\|\dot q\|^2
$$

使得

$$
J_{rel}\dot q+K_{rel}e_{rel}=s,
\quad
q_{\min}\le q+\dot q\Delta t\le q_{\max},
\quad |\dot q|\le \dot q_{\max},
$$

并加入当前已有且验证过的安全不等式。实际 C2 的任务优先级和符号口径必须在 S0 对账，禁止机械照抄上式。

**Jacobian 约束**：所有 `J` 的 twist 次序、参考点、表达坐标系必须相同，必要时使用 SE(3) adjoint；不得把各自基坐标下 Jacobian 直接当作 `[-J_L, J_R]`。

### 3.4 三个必须先过的单元性质

1. 当两手恰好符合 `T_WO G_L/G_R` 时，闭环残差为零。
2. 对物体和两只手施加同一刚体变换后，闭环残差不变（数值容差内）。
3. 故意在一侧增加已知微小位置/旋转扰动，残差方向与幅值正确；从独立 FK 推算的物体位姿不再一致。

## 4. 物体、夹爪与碰撞建模

### 4.1 测试对象

采用参数化长方体：`size_xyz`、质量 `mass`、惯量 `I`、物体 frame、左右抓取 frame、是否允许接触的碰撞 link 列表；每个试验必须保存实际配置值。首版不硬编码真实 M4/M5 物体尺寸；未核实的尺寸均为**仿真样件**。

### 4.2 开关式夹爪行为

状态至少含 `OPEN / CLOSING / CLOSED / OPENING / FAULT`（真实接口可能仅有开关命令；内部仿真状态与硬件反馈严格区分）。

- 只有在双手已到抓取预位、物体几何符合要求时才允许闭合。
- 无传感器时不能因发出 `CLOSE` 即认定真实抓持成功；仿真 `GRASP_CONFIRMED` 是由理想约束条件定义的事件。
- 释放前应满足物体已稳定到达放置支撑面、机器人进入静止/低速条件。
- 释放后恢复物体为独立碰撞物体，撤离时继续碰撞检查。

### 4.3 规划场景

物体抓取前位于 world collision scene；抓取后维持一个统一物体的几何表示，处理 grasp links 的合法接触，避免“物体隐身”“全部碰撞禁用”。放置后恢复世界物体。所有阶段应记录场景对象数量、ACM 变化与关键碰撞结果。

### 4.4 Gazebo 第一版实现策略

按优先级：
1. **离线/kinematic mock：**采用双端抓取约束和两侧 FK 独立推算，不做物理接触。
2. **Gazebo 理想抓持 profile：**使用单一明确归属的物体运动学代理或经验证的约束策略；两臂对同一目标运动，额外监控闭环残差。
3. **后续真实接触实验：**才单独研究摩擦、夹持、接触力与掉落。

不得通过物体“视觉跟随”替代位姿残差、碰撞安全或同步故障验收。

## 5. C4.2 → C4.3 的精确接口边界

**不可混淆两个基线：**

- **C4.2 的唯一正式基线：**M4 Baseline B，是**交接位优化**的历史口径；不得恢复 Baseline A 为同级正式基线。
- **C4.3 的任务基线：**为**两端同时抓取同一物体并完成运输轨迹**单独建立 `transport_baseline`；和 C4.2 的改善百分比不直接互换。

建议读入（最终以实际 schema 为准）：
- C4.2 `baseline`、`handover.v0`、`handover.v1`、相关候选构型、碰撞筛选方法；
- C4.1 CRW 作为粗筛；
- 既有 IK 多分支枚举、FCL/PlanningScene 和轨迹规划器。

转换到搬运任务时必须重新做：
1. 物体双端抓持几何；
2. 左右 IK **组合**可行性；
3. 全机器人、物体与环境的碰撞；
4. 起点到抓取预位及搬运路径的动态/离散有效性；
5. 相对位姿约束与轨迹的贯通可行性。

不能因为 C4.2 V1 指标好，就称它直接是 C4.3 的有效双抓持构型。

### 6.1 阶段工作细则

**S0（先做，不得跳）：**
- 搜索实际 QP solver/controller、ROS 2 控制模式、`position` / `velocity` interfaces、125 Hz 调度、时钟/时间戳来源。
- 检查 C2.3/C2.4 有没有可直接消费物体轨迹的输入；没有则先设计极薄 adapter，而非重写优化器。
- 检查物体碰撞是否已进入 FCL/MoveIt 和 Gazebo；识别已有抓取服务与状态机。
- 验证旧工作区是否存在未提交修改；不得覆盖。
- 冻结 `S0_artifact_inventory`：源路径、commit、测试命令、实测结果、接口负责人。

**S1：**
- 独立测试物体 frame、左/右 grasp frame 的方向与偏移；负尺寸、空 frame、相同左右抓持位、不可逆变换、非法旋转矩阵均要拒绝。
- 物体和夹爪的姿态误差采用 SE(3) 而非简单逐元素矩阵差。
- 平移与旋转误差独立汇报，避免单位混合。

**S2：**
- 先枚举 IK 分支，再对左右笛卡尔积组合做综合筛选和轨迹验证。
- 选出一个保守的 `transport_baseline` 和至少两个可行备选（如存在）；不凭空保证备选数。
- 把抓取点、物体尺寸、左右 TCP 偏置写入基线结果，作为后续全流程输入。
- 起始变换只允许经过验证的抓取几何，不直接套 M4 交接偏移。

**S3/S4：**
- 任务阶段：`IDLE → APPROACH → ALIGN → CLOSE_BOTH → GRASP_CHECK → LIFT → TRANSFER → LOWER → RELEASE → RETREAT → DONE`；任一不满足条件进入 `FAULT/HOLD/ABORT`。
- 开合命令通过现有夹爪适配层；仿真状态估计不可伪装成真机传感器。
- 记录每拍 `q, q_cmd, qdot, T_WL, T_WR, T_WO,L, T_WO,R, T_WO,d, e_rel, e_closure, solver status, collision result, timestamps`。
- 在 Gazebo 中进行「物体抓取前/抓取中/释放后」场景一致性断言。

**S5：**
- 注入左/右单独冻结与双侧冻结、反馈延时、反馈不一致、求解不可行、超时。
- 监控双臂状态时效、命令进度和相对位姿偏差；超阈值停止发布新的运输进度，并使用已验证的受控 HOLD/ABORT 策略。
- 必须说明：软件 coordinated hold **不是**独立的硬件级安全停止；真机机械/电气安全机制尚未验证。
- `resume` 不应自动执行；须校验双方已稳定、抓取几何仍合理、物体状态可信，否则 `ABORT`。

**S6：**
- 优先用相同工况做“QP 相对任务启用 vs 合法消融”“使用优化构型 vs transport baseline”；失稳或非法情况在 mock/offline 中终止，不能强行持续到碰撞。
- 使用固定随机种子和可重复工况，记录每次成功/失败原因与完整配置。

## 7. 指标、阈值冻结与测试矩阵

### 7.1 指标定义

| 指标 | 定义 / 记录口径 |
|---|---|
| 双手相对位置误差 | `trans(Log(T_LR,d^-1 T_LR))` 的范数或经核实的等价定义，单位 mm |
| 双手相对姿态误差 | 旋转 Log 范数，单位 deg |
| 闭环一致性 | `T_WO,L` 与 `T_WO,R` 之间的平移/旋转误差，分开统计 |
| 物体轨迹误差 | 有真实仿真物体状态时使用物理/代理真值；并另列 FK 推算值，不能混为一谈 |
| 成功率 | 完成所有阶段且无非法碰撞、无故障超时、误差满足阈值的次数 / **所有有效启动次数** |
| 实时性 | 求解/控制 P50/P95/P99/max，超时次数，状态新鲜度 |
| 安全性 | 最小碰撞净空、碰撞次数、最大关节位置/速度越界、异常响应时延 |
| 轨迹平滑性 | 关节速度、加速度和 jerk（若可可信计算）；必须说明滤波和采样方式 |

统计时要区分 `planner failure`、`grasp geometry failure`、`controller fault`、`collision` 和 `timeout`。

### 7.2 验收数值如何设定

**不预填“已实现”的数字。** 在 S0/S3 取得现有 C2 基线后，冻结一张 `acceptance_thresholds.yaml`，列出：
- 相对平移/姿态误差的最大值、RMS 阈值；
- 物体轨迹误差阈值；
- 无非法碰撞和无越限（硬判据）；
- 解算器超时上限与调度容差；
- 故障检测、停止命令与实际停止的分离时延；
- 试验次数、有效启动定义和种子。

要求所有阈值先于正式对照实验冻结，禁止根据结果事后调阈值。125 Hz（8 ms）仅是历史控制节拍参考，实际系统在 S0 核实；不可把 500 Hz controller_manager 误当 ServoJ 执行能力。

### 7.3 最低场景矩阵

- 静止双抓持：验证不漂移；
- 垂直抬升：验证起始负载搬运路径；
- 水平平移：验证整体移动与姿态保持；
- 组合路径：抬升—平移—下降；
- 物体尺寸变化与抓持位置偏置；
- 左右不同 IK 分支/接近关节限位的合法构型；
- 故障：左 stall、右 stall、QP 失败、传感状态老化；
- 负例：抓取几何不可达、场景碰撞、任务超时。

每项至少给出配置、日志、预期和实测通过/失败，不依赖单张录屏判定。

## 8. 风险与应对

| 风险 | 机制 | 应对 |
|---|---|---|
| R1 C4.2 交接位误用 | 交接 ≠ 双端抓持 | 独立 transport baseline + 双端 IK / 碰撞重验 |
| R2 物体视觉跟随掩盖误差 | 显示正确、两手不一致 | 由左右 FK 独立重建物体；残差硬验收 |
| R3 双侧刚焊闭链冲突 | 约束求解器不稳定 | 第一版单物体代理+闭环监控；闭链物理仅单独研究 |
| R4 未知抓持反馈 | CLOSE 不等于夹牢 | 仿真确认标签；真机不可推断 |
| R5 内部作用力 | 位置误差可引起未知高内力 | 首版不宣称力安全；真机需力学和设备负载审查 |
| R6 仿真/真机控制不一致 | velocity vs position，时钟不同 | S0 profiles 对账；仿真建立 position-compatible 方案 |
| R7 单臂 stall | 健康臂继续拖动 | 双臂状态 supervision、coordinated HOLD/ABORT |
| R8 碰撞场景错误 | attach/ACM 误配置 | 对象生命周期/合法接触/非法碰撞自动断言 |
| R9 比较不公平 | 不同样件/路径/起点 | 相同场景和指标；不可行结果单列 |
| R10 可复现性差 | 依赖人工操作/硬编码 | 清晰配置、脚本、种子、commit、版本、输出 |
