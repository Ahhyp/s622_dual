## 2. W5 原冻结范围与明确非目标

### 2.1 冻结核心交付

1. 复用既有桌面模型：`src/gz_launch/models/table`。
2. 新建支撑模型 `c43_support`：圆柱半径 `0.04 m`、高度 `0.25 m`，目标支撑顶面 `world z = 0.25 m`。
3. 新建标准样件模型 `c43_sample`：长宽高 `0.12 × 0.05 × 0.05 m`，质量 `0.35 kg`，与 S2 冻结几何一致。
4. 新建 C4.3 专用世界 `c43_s4_world.sdf`。
5. 新建 C4.3 专用启动入口 `c43_s4_transport.launch.py`，与旧仿真入口隔离。
6. 在没有控制/附着命令的情况下，验证标准样件在支撑上静置 **5 秒仿真时间**，不滑动，并记录相对冻结名义位姿 `(0, 0, 0.275 m)` 的误差。

**W5 名义几何校核：** 样件高度 `0.05 m`，半高 `0.025 m`；其底面放在 `z=0.25 m` 支撑顶面时，中心应为 `z=0.275 m`。支撑若立于 `world z=0`，圆柱中心为 `z=0.125 m`。实际世界坐标和桌面摆放必须以 S2 基线及现行冻结规划为依据，避免穿模或虚假稳定。

原始 W5 对位姿误差列出 **`≤ [待标定] 2 mm`**。其中 `2 mm` 是 *未批准建议值*，**不是已经正式批准的 Gate 阈值**；不得在没有批准来源时将其写为正式 PASS 判据。

### 2.2 本次不实施

- W6 的 `detachable-joint`、xacro 注入、attach/detach 客户端或 `--attach both`。
- W7 的控制器协同搬运、夹爪 JTC 动作、完整状态机实联调或 `success=true` 流程。
- W8 的单/双附着对照、前馈对比或全套指标报告。
- W9 的三层碰撞/故障注入工程。
- 真实机器人控制、实时性认证、力控/夹持力、摩擦锥真实夹持结论。
- 修改 S2 冻结几何、QP 算法、W2 数值契约、D3/D4/D5 审批状态及安全门禁。

### 3.2 场景设计要求

- 优先直接复用 S2 冻结基线与 `gz_launch` 既有模型资源；不得通过调整尺寸、质量或坐标系“做出”好看的结果。
- 样件须是**可受重力作用的动态刚体**（不可用 `<static>true</static>` 假装稳定），具备有效碰撞几何与物理惯量。
- 支撑可按实际模型要求作为静态物体，但须有有效碰撞几何；样件—支撑应产生真实接触。
- 支撑顶面 `z=0.25 m`、样件名义中心 `z=0.275 m`；桌面放置不得与支撑/样件发生非预期初始穿模。
- 样件几何、惯量、质心、坐标系与物理接口要明确；不能通过隐式偏移掩盖基线误差。
- 不通过暂停物理、关掉重力、移除碰撞或极端摩擦参数“通过”静置测试。
- 使用现有仓库 Gazebo 分支/发行版与 `gz_launch` 习惯；初版材料提及 Fortress/`ignition-gazebo6`，实施时以仓库和机器实际兼容版本为准，不私自进行大规模系统升级。
- 保持 W5 场景的可重复启动、确定的资源路径、非冲突名称，并给后续 W6 提供稳定的 `c43_sample` 与 link 名称（不在 W5 实施附着机制）。

## 4. 分批实施安排

### W5-A｜基线核对与模型资源

**目标：** 完成可供 Gazebo 加载的标准样件、支撑模型，确认冻结几何与现有资源兼容。

**工作：**
1. 只读核对现行 W5 冻结条款、S2 `transport_baseline.yaml`、既有 `gz_launch` 模型目录和依赖。
2. 检查 Gazebo/ROS 运行能力；明确是否支持无界面/headless 启动，但**不将 native RT 检测作为前置条件**。
3. 新建或最小补全两套 `model.config`/`model.sdf`。
4. 检查尺寸、质量、惯量合法性、碰撞/视觉几何、初始 z 坐标关系和资源 URI。
5. 只做轻量 XML/SDF/模型资源检查，不启动机械臂、不修改旧 world。

**交付：** 两套模型、几何/物理参数对照、资源校验结果、环境能力记录。

**完成条件：** 模型结构有效、尺寸/质量与冻结要求一致、未破坏旧模型、差异可追溯。不要求实际运行 5 秒 Gazebo；不能称 W5 整体完成。

### W5-B｜专用 world 与独立 launch

**目标：** 完成与旧场景隔离的 C4.3 专用场景启动入口。

**工作：**
1. 新建 `c43_s4_world.sdf`，引入 ground/table/support/sample；谨慎校核几何相对位姿和初始碰撞。
2. 新建 `c43_s4_transport.launch.py`，优先沿用 `gz_launch` 既有启动约定，支持 W5 无控制的静置启动。
3. 完成路径与资源加载验证；若 Gazebo 可用，可做短时间 smoke test。
4. 不向 launch 添加 W6 detachable-joint、夹爪运动命令、控制器执行或 `--attach both`。
5. 验证独立启动入口没有改动原有 `s622_dual_arm.launch.py` 的行为。

**交付：** world、launch、可复现命令及加载结果；若不能运行 Gazebo，给出具体环境阻断与静态检查结果。

**完成条件：** 所有 W5 文件完整、静态验证通过，兼容环境下能正常加载场景；Gazebo 不可用时可判 `W5 SOFTWARE IMPLEMENTATION COMPLETE / GAZEBO_VALIDATION_HOLD`，不可称物理验收 PASS。

### W5-C｜静置验证与 W5 软件范围收口

**目标：** 验证实际场景物理行为，或如实登记尚缺的仿真证据，并形成独立关闭记录。

**工作：**
1. 在可运行的 Gazebo 环境中，**不发控制命令、不使用附着、不移动夹爪**，运行至少 `5.0 s` 仿真时间（不是仅墙钟时间）。
2. 持久化记录场景版本、SDF/模型哈希、Gazebo 版本、启动命令、退出码、开始/结束时刻、样件位姿和必要速度/接触信息。
3. 检查样件未下落、未从支撑滑走、没有不合理穿透或物理爆炸；给出初末水平漂移、位姿误差、姿态误差及可复核原始观测。
4. 与冻结 `world_T_object=(0,0,0.275)` 对照，**原样报告**测得误差；`[待标定] 2 mm` 只能作为建议参考，未批准前不得写入正式 Gate PASS。
5. 如果 Gazebo 可运行：如实区分“5 秒静置行为已有仿真证据”“误差指标观察结果”“正式阈值仍待批准”。
6. 如果 Gazebo 不能运行：保持 `GAZEBO_VALIDATION_HOLD / UNVERIFIED`，只归档已经做完的软件实施，不伪造日志或截图。
7. 只执行新增/实际受影响测试，不重跑 W2/W3/W4 全部历史回归。
8. 形成 W5 独立软件范围归档/关闭记录，列清未达到的外部依赖和对 W6 的真实可复用接口。

**交付：** 原始仿真证据（若可得）、轻量核查结果、W5 范围关闭/阻断记录与 W6 交接清单。

**完成条件：** 静置场景运行与证据完整、未突破未批准阈值时，可申请 `W5 SOFTWARE_ONLY COMPLETE`；但正式数值 Gate 是否通过必须依赖批准判据及对应证据。如果仅完成资源与启动代码但缺少 Gazebo 动态验证，应采用 `SOFTWARE_IMPLEMENTATION_COMPLETE / GAZEBO_VALIDATION_HOLD`，不能虚构 W5 验收完成。

## 9. 状态与关闭口径（必须准确）

| 层次 | 可以怎样认定 | 不可误述 |
|---|---|---|
| 模型与启动文件写完 | `W5 SOFTWARE IMPLEMENTATION COMPLETE`（需实际检查） | 不能代替 5 s 物理仿真 |
| 已完成全部 W5 软件与适用仿真验证 | 可申请 `W5 SOFTWARE_ONLY COMPLETE`，附准确证据范围 | 不等于未批准的数值阈值已获批准 |
| 仿真无法运行 | `GAZEBO_VALIDATION_HOLD / UNVERIFIED` | 不允许虚构 W5 动态 PASS |
| W5 冻结数值验收 | 由实际仿真证据 + **正式批准的**阈值共同支撑 | `[待标定] 2 mm` 不能自动充当正式 Gate |
| S4.2 整体 Gate | 需后续 W6/W7/W8 和独立判定 | W5 完成不等于 S4.2 PASS |
| S4.1 / RT / B-4 / 真机 | 维持各自的 `HOLD` / `UNVERIFIED` / `OPEN` | 不由 W5 自动解除 |

W5 的“场景成功加载”和“样件在物理引擎中确实稳定”是不同结论；W5 的仿真验证与 Gazebo 运行环境的机器实时性也是不同结论。

## 10. 每批次交付报告格式

每批提交：

1. 批次结果：`COMPLETE` / `PARTIAL` / `BLOCKED`，附可核验证据。
2. 本批创建/修改文件及必要 diff。
3. 本批实际测试命令、退出码、通过/失败/未运行。
4. 冻结数值、已批准阈值、`[待标定]` 值各自来源；任何需审批的冲突。
5. 实际运行环境与限制：Gazebo 是否可用、是否 headless、是否只做静态检查。
6. 未完成事项、对下一批的接口与最小建议（不自行启动下一批）。
7. 安全不变量：旧 Gate 未放行、未触碰真实硬件、未修改未批准契约、未提交推送。

**W5-C 额外要求：** 提供独立 W5 收尾记录，列明 5 秒静置的原始观测（如运行过）、样件实际误差、模型哈希、待标定问题，以及 W6 可以复用的正式模型名、link 名、启动路径和仍需验证的部分。

## 11. 执行节奏与下一阶段

| 批次 | 主要交付 | 下一步触发 |
|---|---|---|
| W5-A | `c43_sample` + `c43_support` 及结构校核 | A 报告由 ChatGPT 技术顾问窗口判断后下发 B |
| W5-B | `c43_s4_world.sdf` + `c43_s4_transport.launch.py`、加载/启动证据 | B 报告由 ChatGPT 技术顾问窗口判断后下发 C |
| W5-C | 静置 5 秒的仿真证据（若可执行）、归档与阻断记录 | C 报告用于 W5 收尾判定和后续 W6 规划 |

如某批次常规软件缺陷可以在授权文件内解决，执行方应主动修复，不为每个小问题重复申请审批；但不自动跨批推进、不擅自实施 W6。

**本计划书的终点：** 在现有资源条件下尽可能完成 W5 的场景软件实现；Gazebo 可运行则完成可验证的静置仿真；Gazebo 不可运行则明确挂起实际仿真验收。全过程不降低安全要求、不借用 W4 的软件完成状态冒充全阶段 Gate PASS。
