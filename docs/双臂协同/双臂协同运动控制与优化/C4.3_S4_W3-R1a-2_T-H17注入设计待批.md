## §1 被测缺陷与现有代码事实

| 事实 | 位置 |
|---|---|
| `readState()` 失败直接 `return return_type::ERROR`，**早于** drain、也不 `publishStatus()` | `src/dual_arm_qp_controller/src/dual_arm_qp_controller.cpp:640` |
| 该路径上不存在任何“回执写入”代码 | `:640` 之后才有 `hold_ack_.store`（drain 块，`:67x`） |
| 因而不可能在该路径上伪造 `hold_request_result=1` | 由控制流保证，非注释 |

⇒ T-H17 要验证的是**“失败时不冒充已冻结”**，而不是“失败时也要回执”。

## §2 注入点设计（最小缝隙，方案 A）

沿用控制器已在用的 `C43_ENABLE_TEST_HOOKS` 编译期开关（R3 任务 2 已获批并实测 OFF 时零符号），新增：

```cpp
// dual_arm_qp_controller.cpp, update() 内，紧跟 readState() 之后
#ifdef C43_ENABLE_TEST_HOOKS
  if (test_fail_readstate_budget_.load(std::memory_order_relaxed) > 0) {
    test_fail_readstate_budget_.fetch_sub(1, std::memory_order_relaxed);
    return return_type::ERROR;          // 与真实读取失败完全同一条返回路径
  }
#endif
```

`on_configure` 内（同样 `#ifdef`）：`declareIfNeeded<int>("test_fail_readstate_cycles", 0)`，
`on_activate` 时 `test_fail_readstate_budget_.store(...)`。

**改动规模**：`#ifdef` 内约 **10 行** + 1 个 `std::atomic<int>` 成员 + 1 个参数声明。

## §4 验证用例与判据

| 用例 | 注入 | 判据（必须全部成立） |
|---|---|---|
| **T-H17a** 控制器侧 | 先起搬运，`test_fail_readstate_cycles=5` | ① `update()` 连续返回 `ERROR`；② 期间 `~/transport_status` 无新的 `hold_request_seq` 回执；③ 已排队的 hold 请求**不被消费**（seq 仍非 0）；④ 不出现 `hold_request_result==1` |
| **T-H17b** 执行器侧 | 控制器进入失败态后，执行器仍在 `Hold` 等待 | ① 重试 3 次耗尽 ⇒ `Abort("hold_ack_timeout")`；② 最终状态 `ABORT`/`FAULT`，**永不为 `Done`**；③ 事件日志含 `hold_not_confirmed:` 前缀 |

## §5 与 T-H13 / T-H15 / T-H16 的关系

- T-H17a 的“不消费请求”是 T-H13（RT 路径无阻塞/无伪造）的互补证据，但**不替代** T-H13 的耗时测量。
- T-H17b 复用 T-H16 端到端的执行器侧链路；若 T-H16 台架先建成，T-H17b 直接在其上注入。
