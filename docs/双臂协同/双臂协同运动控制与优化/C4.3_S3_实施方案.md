> ⇒ 这两条把「S3 为什么必须换掉 legacy 物体任务」从「听说它 π 处不准」升级为**可闭式验算、在当前构型就已发生的事实**。

## §2 S3 数学模型

### 2.1 符号约定

| 符号 | 含义 |
|---|---|
| `q = [q_L; q_R] ∈ R¹²` | 12 个臂关节（**不含手指**） |
| `T_WL(q_L) = worldTgrasp(Left, q_L)` | 左 TCP 世界位姿（帧 `left_grasp_frame`）；`T_WR` 同理 |
| `G_L = ^O T_L`，`G_R = ^O T_R` | 冻结抓持变换（**常量**，来自 §1.1） |
| `T̂_{O,L}` / `T̂_{O,R}` | **两个互相独立**的锚定物体估计 |
| `V^b` | body twist `[v; w]`，线性在前，body 轴 |
| `Ad(T)` | SE(3) 伴随（`se3.hpp` 提供，S1 已测） |
| `J_body(q_arm)` | `DualArmKinematics::jacobianBody(Arm, q_arm)`（6×6） |
| `J_{(6×12)}` | 前 6 列属左臂、后 6 列属右臂 |

### 2.2 冻结抓持关系（第 3 问）

两爪与样件的相对位姿在**整段搬运中视为刚性**：

```
T_WL(t) = T_WO(t) · G_L        (1a)
T_WR(t) = T_WO(t) · G_R        (1b)
⇒  T_WL⁻¹ T_WR = G_L⁻¹ G_R = L T R*   （常量，与 T_WO(t) 无关）      (1c)
```

`L T R*` 在 S3 开始时**计算一次并冻结**；**绝不**从测量到的 `T_WL, T_WR` 反算（那会把跟踪误差当成目标，造成漂移）。
相对任务目标 = `L T R*`，由 C2 既有的 `relativeError(q, L T R*)` / `relativeJacobian(q, BodyR)` 承担，S3 不改其实现。

**"保持"的判定**：`‖e_rel‖` 是**控制误差**，`‖closureResidual(T̂_{O,L}, T̂_{O,R})‖` 是**独立观测量**。二者都记录，且**不得互相冒充**（第 4 问与第 6 问）。

### 2.3 左锚定物体任务（S3 的核心）

**位姿估计**（无 log、无平均）：

```
T̂_{O,L}(q_L) = T_WL(q_L) · G_L⁻¹        ∈ SE(3)                    (2)
```

**解耦位姿误差**（米 / 弧度）：

```
e_O(q_L, T_d) = [ R_dᵀ (p̂_L − p_d) ; logSO3(R_dᵀ R̂_L) ]   ∈ R⁶      (3)
```

**精确速率映射**（这是 QP 需要的雅可比）：

```
V^b_{T̂}         = Ad(G_L) · J_body(q_L)                             (4)
ė_O             = A(e) · V^b_{T̂},   A(e) = diag(R_dᵀR̂_L, JrSO3(φ)⁻¹)  (5)
J_{O,L}(q_L)    = A(e) · Ad(G_L) · J_body(q_L)         (6×6)         (6)
J_O(q, T_d)     = [ J_{O,L}(q_L) | 0_{6×6} ]           (6×12)        (7)
```

一行实现调用：

```cpp
const dual_arm::Iso3 T_hat = dual_arm::anchoredObjectPose(kin.worldTgrasp(Arm::Left, q_L), G_L);
const dual_arm::Vec6 e_O   = dual_arm::decoupledPoseError(T_hat, T_d);
const dual_arm::Mat6 J6    = dual_arm::anchoredObjectErrorJacobian(
                                 kin.jacobianBody(Arm::Left, q_L), G_L, T_hat, T_d);
dual_arm::Mat6x12 J_O = dual_arm::Mat6x12::Zero();
J_O.leftCols<6>() = J6;
```

**为什么用误差速率映射 `A(e)` 而不是裸 `Ad(G_L)J_body`**：`(3)` 是非线性误差，只有 `(5)` 才是它**严格**的时间导数（§1.3 第 7 行）。用裸雅可比就退化成小误差近似，而 C2 自己的注释（`dual_arm_qp.cpp:145-150`）恰好把「缺 SE(3) 右雅可比逆」列为 future work——锚定形式**正好补上这一项**，且不做任何近似。

**为什么只锚在左臂**（第 4 问）：见 §2.5 的恒等式与 §2.6 的取舍。

### 2.4 期望物体轨迹与速度前馈（第 1 问）

S3 的轨迹是**冻结的分段 SE(3) 轨迹** `T_d(t)`，由 S2 基线起点 + 一组航点定义（配置文件，非代码硬编码）：

```
config/s3_transport_trajectory.yaml
  dt: 0.008                       # = DualArmQpParams::dt，125 Hz
  start: from_baseline            # T_WO_star, q_grasp12
  time_scaling: smoothstep        # 速度在两个相位边界处连续且为 0
  phases:
    - {name: settle,    duration: 0.30, dz:  0.000, dx:  0.000}
    - {name: lift,      duration: 1.50, dz: +0.050, dx:  0.000}
    - {name: translate, duration: 1.50, dz:  0.000, dx: -0.060}
    - {name: lower,     duration: 1.50, dz: -0.050, dx:  0.000}
    - {name: settle2,   duration: 0.30, dz:  0.000, dx:  0.000}
  yaw_sweep_deg: [0.0, 8.0]       # 第二遍可选，用于激励旋转通道（默认 0）
```

- **平移插值**：`p_d(t) = p_phase_start + s(τ)·Δp`，`R_d(t)` 由 `yaw_sweep_deg` 决定（`0` 时恒为 `I₃`）；`s(τ)` 为 smoothstep，`ṡ(0)=ṡ(1)=0`。
- **速度前馈**（body twist，物体系）：

```
v_d = R_dᵀ · ṗ_d        (线性部分，body 轴)
w_d = 0                 (纯平移；启用 yaw_sweep 时 = R_dᵀ · (ẏ·ẑ_world))
v_ff(t) = [v_d ; w_d]                                                (8)
```

  `v_ff` 的作用：C2 的物体任务偏置为 `bias_obj = −(α_obj·e_obj + dt·v_ff)`（`dual_arm_qp.cpp:170-172`），纯比例跟踪会有 `v/kp` 稳态滞后，前馈把它消掉。S3 **同时跑 `v_ff` 开/关两组**并给出滞后对比（这是"可判定的增量证据"，而不是"看起来更顺"）。

- **轨迹是否可行不由本文件假定**：`T_d(t)` 只是**参考**。`e_O` 的终值与 `‖e_O‖` 的峰值、`s_obj` 的范数才是判据（§11）。

### 2.5 闭链恒等式（免费且强力的独立检查）

由 `(2)`：

```
T̂_{O,L}⁻¹ T̂_{O,R} = G_L · T_WL⁻¹ T_WR · G_R⁻¹
```

若 `T_WL⁻¹T_WR = G_L⁻¹G_R`（即闭链精确成立）则右端 `= I`。因此

```
‖log(T̂_{O,L}⁻¹ T̂_{O,R})‖  ≡  Φ( T_WL⁻¹T_WR · (G_L⁻¹G_R)⁻¹ )        (9)
```

即 **"两个独立锚定估计的差" 与 "闭链残差" 是同一个量**（相差一个常量共轭）。
S3 用途：
- 作为**第 6 问的观测定义**：`anchor_pos_gap_m` / `anchor_rot_gap_rad` 每周期记录；
- 作为**测试**（S3-T8）：对随机 `q` 严格验证 `(9)` 到 `1e-12`；
- 作为**控制器之外的裁判**：`e_rel` 变小但 `(9)` 不变大，才证明闭链真的被保持，而不是 QP 把误差藏进了 slack。

### 2.6 为什么必须换掉 legacy 物体任务（两条独立理由，均可当场验算）

**理由 A —— 坐标系约定不同（在当前构型就已发生，非奇异问题）**
`dual_arm_kinematics.cpp:87-98` 的 legacy 物体帧是**对称中点帧**：

```
p_O = ½(p_L + p_R)                                  (:94)
R_O = R_L · expSO3( ½ logSO3(R_LᵀR_R) )             (:96)
```

它与 S1/S2 冻结的物体帧（`(2)`）**不是同一个帧**：前者是"两爪之间的中点帧"，后者是"由 `G_L` 定义的物体帧"。在 S2 冻结构型上实测（`C4.3_S2_验收记录.md`，且 S3 §1.2 已闭式验算）：

```
Δp = 0.025 m      ΔR = π rad      (ξ_rel = 0，即与 π 奇异无关)
```

⇒ 若把 `objectJacobianBody` 接进 `J_obj`，会把**所有**冻结数字（`world_T_object`、`G_L`、`G_R`）按另一套约定重新解释，`e_obj` 会立刻包含一个 0.025 m / π 的常量偏置，控制器会把机械臂往错误的物体位姿上推。这不是精度问题，是**语义错误**。

**理由 B —— 误差约定不同（与 S1 §3.2 冲突）**
legacy：`objectError = logSE3(worldTobject⁻¹·target)`（**耦合** twist，`dual_arm_kinematics.cpp:131-134`），`objectErrorJacobian = −Ad(T_err⁻¹)·J_obj`（小误差近似，`:136-141`）。
S1：`decoupledPoseError`（**米/弧度解耦**）+ `anchoredObjectErrorJacobian`（**精确**速率映射）。
⇒ 混用会让"物体位置误差 3 mm"和"姿态误差 0.1 rad"以不可解释的方式相加，破坏 S3 §11 的验收判据（分量阈值）。

**理由 C —— π 稳健性（S3 的鲁棒性储备，不是主因）**
`ξ_rel` 在标称搬运中恒为 0（`(1c)` ⇒ 常量），所以 legacy 的 π 奇异在标称轨迹上**不活跃**。但：
- 任何使闭链短暂破裂的瞬态都会让 `ξ_rel` 远离 0；若趋近 π，legacy 的偏差实测可达 195.28 % / 4.6×（S0 §A14.1）；
- F-S1-1 已实测 `logSO3` 近 π 分支的数值缺陷（δ=1e-6 时误差 4.9e-4 rad，δ≤1e-7 时返回恰为 π）。锚定形式**完全不含旋转 log 的平均**，其唯一 log 是 `logSO3(R_dᵀR̂)`（`R_dᵀR̂ ≈ I`，远离 π），因此构造上规避。
⇒ S3 采用锚定形式，理由 A/B 是**决定性**的，C 是**附带收益**。

### 2.7 QP 装配（S3 调用 C2 的真实形态）

```
决策变量  z = [ dq(12) ; s_rel(6) ; s_obj(6) ]      ∈ R²⁴
代价      w_rel ‖J_rel dq + α_rel e_rel − s_rel‖²
        + w_obj ‖J_O  dq + α_obj e_O  − s_obj‖²
        + w_slack‖s_rel‖² + w_slack_obj‖s_obj‖²
        + w_center‖dq − dq_center‖² + w_reg‖dq‖²
约束      dq 箱式：lo = max(−v_max·vel_scale·dt, q_min−q)
                  hi = min( v_max·vel_scale·dt, q_max−q)      (按 C2 原样)
          （S3 默认不追加 C z ≤ d 行）
```

- `α_rel = kp_rel·dt`，`α_obj = kp_obj·dt`（C2 原样）。
- **12 自由度 vs 两个 6 维任务 ⇒ 恰好定解、无冗余**。因此 `w_null_*` 必须**全部为 0**（C2 自己在 `dual_arm_qp.cpp:200-204` 说明此时 `N ≈ 0`）；`dq_center` 保持 0。S3 把这条写成**显式前置断言**（若 12×12 任务的 `σ_min < 1e-6` 则报 `task_stack_singular`）。
- `w_rel` / `w_obj` 的取值：S3 扫 `w_obj ∈ {1, 10, 100}`（`w_rel = 1`）并报告 `max‖s_obj‖`、`max‖s_rel‖`、终值 `‖e_O‖` 的权衡曲线；冻结一组进验收记录。**不做自适应增益**。
- 求解器：`makeDefaultSolver()`，不改。

### 3.3 一次控制周期的时序（严格顺序，含失败短路）

```
 1. t = k·dt                          （k = 0 … steps−1）
 2. (T_d, v_ff) ← trajectory.at(t)                     // 式 (8)
 3. row ← AnchoredObjectTaskBuilder.build(q, T_d, v_ff) // 式 (2)(3)(6)(7)
 4. [独立检查] checker.applyWorld(object_source 选定的物体位姿)
 5. [独立检查] st ← checker.checkState(q)
      若 st.in_collision            → failure_code = collision；**abort**（不写命令）
      若 st.whole_robot < min_clear → failure_code = insufficient_clearance；**abort**
 6. res ← qp_->solve(q, left_T_right_target_, row{...})  // §4.1 新重载
 7. 若 !res.converged → ++solver_fail_streak；**hold（dq=0）**；超阈值 → abort(qp_solver_failed)
 8. 越限归因：统计激活的箱式约束数 active_limit_count、最小裕度 min_limit_margin_rad
      若连续 > limit_saturation_streak_max 周期被激活 → failure_code = joint_limit_saturation；abort
 9. 闭链裁判：若 ‖res.slack‖ > s_rel_max → failure_code = closure_violated；**abort**
      若 ‖res.slack_object‖ > s_obj_max → 计数（object_task_infeasible），超阈值 abort
10. 记录 CycleRecord（§8）
11. q ← q + res.dq                     （plant: ideal）
12. [独立检查] checker.checkSweep(q_prev, q)   // 用更新后的物体位置
      失败 → failure_code = swept_collision；abort
13. 轨迹结束 → 终值判据（terminal_pos_err_m / terminal_rot_err_rad）→ success / terminal_pose_error
```

**关键点**：第 5、12 步的碰撞判定**不进入 QP**（不作为 CBF/软约束），因此它是**独立裁判**；控制器不知道碰撞阈值，也就不可能"优化掉"这个判据。

### 4.1 `dual_arm_qp_core`：新增 `ObjectTaskRow` + 一个重载（**纯新增，不改既有语义**）

**动因**：R24（`C4.3_S0_审计报告.md:1141-1143`）要求 S3 适配器不得把 `kin_.objectJacobianBody(q)`（`dual_arm_qp.cpp:161`）接到 QP 的 `J_obj`。当前 QP **没有任何入口**可以传入外部计算的物体任务行，因此这条约束在现有接口下**无法满足**——必须新增接口。这是本方案唯一涉及 C2 包的改动，仅限**声明与装配点**，不触碰任何 C2 算法。

**`src/dual_arm_qp_core/include/dual_arm_qp_core/dual_arm_qp.hpp` 新增（追加在 `DualArmQpResult` 之后）**：

```cpp
/// 外部提供的物体任务行（C4.3 S3, R24）。
/// 传入 solve() 时，core **不会**调用 kin_.objectError()/objectJacobianBody()
/// —— 物体帧的约定由调用方拥有；core 只做 QP 装配。
struct ObjectTaskRow {
    dual_arm::Mat6x12 J = dual_arm::Mat6x12::Zero();  // d(e_obj)/dq
    Vec6              e = Vec6::Zero();               // 解耦误差 [m; rad]
    Vec6              body_twist_ff = Vec6::Zero();   // 物体 body twist 前馈
    bool              valid = false;                  // false ⇒ 回退到 legacy 目标路径
};
```

**`DualArmQp` 新增公开重载**：

```cpp
    /// 外部物体任务行（C4.3 S3）。当 row.valid == true 时：
    ///   - e_obj 取 row.e，J_obj 取 row.J，前馈取 row.body_twist_ff；
    ///   - 不构造/不访问 legacy 对称中点物体帧。
    DualArmQpResult solve(const Q12& q, const Iso3& left_T_right_target,
                          const ObjectTaskRow& object_task);
```

**`DualArmQp` 新增私有实现（既有 2/3/4 参重载改为委派，传 `nullptr`）**：

```cpp
private:
    DualArmQpResult solveImpl(const Q12& q, const Iso3& left_T_right_target,
                              const Iso3& world_T_object_target,
                              const Vec6& object_body_twist_ff,
                              const ObjectTaskRow* object_task_row);
```

**`src/dual_arm_qp_core/src/dual_arm_qp.cpp` 的装配点改动（仅 2 行实质改动）**：

```cpp
// 原 :117

// 新
const bool use_row = (object_task_row != nullptr) && object_task_row->valid;
const Vec6 e_obj = use_row ? object_task_row->e
                           : kin_.objectError(q, world_T_object_target);

// 原 :161

// 新

                                        : kin_.objectJacobianBody(q);

// 原 :172

// 新：前馈优先取行内

```


## §5 用户八问逐条回答

### 问 1：如何把冻结物体轨迹转换成 C2 QP 的期望任务？

**答**：不"转换"，而是**每周期实时合成**——`FrozenObjectTrajectory::at(t)` 给出 `(T_d(t), v_ff(t))`（§2.4），`AnchoredObjectTaskBuilder::build(q, T_d, v_ff)` 给出 `{J_O (6×12), e_O (6), v_ff (6)}`（§2.3 式 (2)(3)(6)(7)），交给 §4.1 的新重载。轨迹是**配置驱动**的（`config/s3_transport_trajectory.yaml`），起点的 `T_WO_star` 与 `q_grasp12` 直接取自 S2 冻结基线，**不硬编码**。
判据：`e_O` 的**解耦**分量（米/弧度）与 `v_ff` 的滞后对比（开/关两组）。

### 问 2：如何启用当前尚未接入控制器的物体任务？

**分两层回答，只有第一层属于 S3**：
- **S3（离线）**：物体任务通过 §4.1 的**新重载**启用。它绕开了两个"没接通"的根源：(a) 控制器只调 2-arg `solve`（`dual_arm_qp_controller.cpp:216`）——S3 不经过控制器；(b) 2-arg 路径把物体目标设为 `kin_.worldTobject(q)`，`e_obj ≡ 0`，物体任务即便打开也不提供运动参考——S3 显式提供 `T_d(t)`。
- **S4（ros2_control，明确不在 S3）**：声明 `kp_obj/w_obj/w_slack_obj` 三个参数 + 增加目标入口（审计推荐的 `target_csv`/`target_param` + 内部时间插值，因其天然可离线复现）+ 把 `solve(q, target_)` 换成 `solve(q, target_rel_, row)`。**这会改变 Gazebo 行为**（现有 YAML 中的同名键将从死配置变为生效），必须先单独评估。
**S3 交付的正是 S4 需要的那个已验证的 `row` 生产者。**

### 问 3：如何保持左右固定抓取关系？

**答**：`L T R* = G_L⁻¹ G_R` 在开始处**计算一次并冻结**（§1.2），作为 C2 相对任务的常量目标（`relativeError` / `relativeJacobian(q, BodyR)`，C2 原样复用，不改）。**绝不**从测量到的 `T_WL, T_WR` 反算目标（否则跟踪误差会被当成目标而自洽漂移）。
**"保持"的独立裁判**：每周期记录 `‖closureResidual(T̂_{O,L}, T̂_{O,R})‖` 与式 (9) 的双锚差异；它们与 `e_rel`（控制误差）**分开汇报**。验收要求两者同时达标（§11），不允许用 `e_rel` 小来替代闭链检查。

### 问 4：如何处理左锚定物体任务与双臂相对任务的配合？

**答**：三个层次说清楚。
- **结构层**：相对任务是**闭链约束的角色**（两臂不许相对漂移），物体任务是**运动参考的角色**（把整条闭链搬到哪去）。两者在 QP 里都是软任务（各有独立 slack），但**权重语义不同**：`w_rel` 是"不许破链"的刚度，`w_obj` 是"跟多紧"的刚度。S3 扫 `w_obj ∈ {1,10,100}`（`w_rel=1`）并给出权衡曲线，冻结一组。
- **自由度层**：12 自由度 vs 两个 6 维任务 ⇒ **恰好定解、无冗余**。因此 `w_null_margin/w_null_manip/w_null_clear = 0`、`dq_center = 0`，并加显式前置断言（`σ_min(J_stack) < 1e-6` → `task_stack_singular`）。这条直接回到 C2 自己的注释（`dual_arm_qp.cpp:200-204`）。
- **冲突层**：左锚定意味着物体任务**只驱动左臂**（`J_O` 的右 6 列为零），右臂靠相对任务跟随。若两者冲突（物体任务要求的左臂运动与目标 `L T R*` 不相容），slack 吸收，**这正是 S3 要测量的**：`‖s_obj‖` 与 `‖s_rel‖` 的大小与持续时间（§9 状态机据此归因）。**S3 不做权重自适应、不做任务优先级重排**——先把冲突量化出来，再谈策略。
- **备选（S3 不采用，列为后续）**：双锚平均（把 `T̂_{O,L}`、`T̂_{O,R}` 在切空间里平均成一条 6×12 任务行）。它在数学上**不是**对称中点，但会让物体任务同时驱动两臂，与相对任务的耦合更复杂；S3 先用最简的单锚形式把链路跑通。

### 问 5：如何验证新 adapter 的 T5 等价性？

**T5 的原始定义**（S2 遗留到 S3）：`ThinAdapterProducesSameDqAsCoreDirectCall`（1e-12）+ `ObjectTaskDisabledWhenWObjZero`。把 `row` 从适配器搬到 QP 的这条路**必须薄到可验证**。

**S3-T5a —— 薄适配等价性（`≤ 1e-12`）**
同一个 `q`、同一个 `T_d`、同一组 `DualArmQpParams`：
- **A 路**：`MockTransportLoop::cycle(q, T_d, v_ff)`（适配器 + 内部调 QP）
- **B 路**：手工构造 `row` 然后直接 `qp.solve(q, LTR_star, row)`
断言 `‖dq_A − dq_B‖_∞ ≤ 1e-12`。⇒ 证明适配层不含任何隐藏调参、没有偷偷改 `e`/`J`/前馈。

**S3-T5b —— 关闭时逐位不变（`== 0`，不是 `≤ tol`）**
`w_obj = 0` 时：新重载 vs 2-arg 旧重载，`dq` 逐位相同（`mismatches == 0`）。⇒ 证明"纯新增"。

**S3-T5c —— 旧路径行为不变**
`w_obj > 0` + 旧 3-arg 重载，在固定输入下的 `dq` 与 `HEAD` 版本逐位相同（先把 `HEAD` 的 `libdual_arm_qp_core.so` 复制到 `/tmp` 作为参照编入测试）。⇒ 证明未触碰 C2 既有语义。

**S3-T5d —— C2 既有测试全绿**（`src/dual_arm_qp_core/test/` 与 `src/dual_arm_qp_controller/test/`）。

**S3-T5e —— 适配器 vs 独立 oracle（不是自证）**
- **有限差分（远离 π）**：对随机 `q`，`J_O` 的每一列与 `decoupledPoseError(T̂_{O,L}(q+h e_j), T_d)` 的中心差分比对，容差 `1e-6`（复用 S1 的 T4/T6 手法）；
- **前向一致性（近 π，δ ≤ 1e-4 时 FD 不可用）**：检验 `‖e_O(q + h·J_O⁻¹Δ) − (e_O(q) + hΔ)‖ ≤ 1e-5`（S1 的 T4 模式）；
- **恒等式 oracle**：式 (9) 的两个独立锚差异 ≡ 闭链残差，容差 `1e-12`。

### 问 6：如何记录物体位置、姿态、相对位姿及闭环残差？

**答**：每周期一条结构化记录（`CycleRecord`，§3.2），三种落盘格式：`.csv`（人看）、`.jsonl`（机读）、`summary.json`。字段分组：

| 关节 | `q[12]` |
| 物体位姿（期望） | `world_T_object_desired`（行优先 16 数） |
| 物体位姿（**两个独立估计**） | `T_hat_left`、`T_hat_right`（各 16 数） |
| 锚一致度（= 闭链裁判） | `anchor_pos_gap_m`、`anchor_rot_gap_rad` |
| 相对位姿 | `T_WL`、`T_WR`（各 16 数）、`L T R`（16 数）、`e_rel[6]`、`‖e_rel‖` |
| 闭链残差 | `closure_pos_m`、`closure_rot_rad`、`closure_position_gap_m`、`closure_dir_ambiguous` |
| 物体任务 | `e_obj[6]`（米/弧度**分列**）、`‖e_obj‖`、`s_rel[6]`、`s_obj[6]`、`‖s_rel‖`、`‖s_obj‖` |
| QP | `converged`、`iterations`、`solve_time_ms`、`sigma_min_rel` |

`RunSummary` 给最大/最小值的**位置**（哪个周期、哪对连杆），而不只是数值——否则"最小净空 1.9 mm"无法定位。
**明确要求**：`‖e_obj‖` 在汇总里**只作为辅助**（它把米和弧度混在一个范数里，是 C2 既有口径的遗留）。主判据一律用 `e_obj` 的**前三位（米）**与**后三位（弧度）**分开的阈值。

### 问 7：如何对待 QP 求解失败、不可行任务和限位？

**答**：一张**闭合的失败码字典 + 确定性动作表**（§9），每个周期按 §3.3 的顺序短路，**任何一类都不允许静默继续**。

| 情形 | 检测 | 动作 |
|---|---|---|
| QP 不收敛 | `!res.converged` | **hold**（`dq = 0`，不写命令），`++solver_fail_streak`；连续 > 10 → `qp_solver_failed` **中止** |
| 物体任务不可行 | `‖s_obj‖ > s_obj_max` | 计数 `object_task_infeasible`；超时 → 中止 |
| 闭链被破坏 | `‖s_rel‖ > s_rel_max` | `closure_violated` **立即中止**（安全关键） |
| 关节限位饱和 | 箱式约束激活数 + 最小裕度 | 连续 > 25 周期仍饱和 → `joint_limit_saturation` 中止 |
| 任务栈奇异 | `σ_min([J_rel; J_O]) < 1e-6` | `task_stack_singular` 中止（12×12 无冗余 ⇒ 奇异即无解） |
| 碰撞 | 第 5 / 12 步独立检查 | `collision` / `swept_collision` / `insufficient_clearance` **立即中止** |
| 终值不达标 | 终点的米/弧度分量 | `terminal_pose_error` 中止 |

**"hold 而非继续"的理由**：`dual_arm_qp_controller.cpp:217-221` 就是 `if (!converged) { ++solve_fail_streak_; writeCommand(q_cmd_); return; }`——S3 与本项目既有处置一致。
**"中止而非降级"的理由**：S3 是离线验证，宁可**红**也不可**静默绿**；降级策略（松弛 `w_rel` 保链 vs 保物体）需要单独设计，属后续。

### 问 8：如何对搬运路径进行碰撞检测？

**答**：**双层、控制器外、与 QP 无关**（§3.2 `TransportChecker`，复用 S2 的 `MoveItCollisionBackend` 与注入范式）。

1. **逐周期状态检查**（第 5 步）：由**已执行的** `q` 构造 `RobotState`，**手指关节设为抓持开度 `±grip_thickness_m/2`**（搬运中样件被夹住，不是张开），样件与支架注入到**当前**位姿；查 `isStateColliding` 与 `distances`。判据：`!in_collision` 且 `whole_robot ≥ 2e-3 m`（沿用 S2 阈值）。
2. **逐段扫掠检查**（第 12 步）：`isSegmentValid(state_k, state_{k+1}, samples=16)`。这是**唯一**能抓住"穿过薄几何"的检查——125 Hz 的步长很小，但下降段速度低、离支架近，逐点检查有可能整段跳过。
3. **样件位置用哪一个**（必须明确，否则检查是假的）：搬运过程中样件**不是**世界固定物，它随机械臂走。每周期把注入位姿 `MOVE` 到三种来源之一并**分别跑**，报告差异：
   - `object_source = "left_anchor"`（**默认/保守**）：用 `T̂_{O,L}`——即"机械臂认为样件在哪"，误差在最坏方向上被暴露；
   - `"right_anchor"`：用 `T̂_{O,R}`，用于交叉验证（式 (9) 保证两者差 = 闭链残差）；
   - `"desired"`：用 `T_d(t)`，用于量化"假设完美跟踪"与"实际"的净空差。
   三种来源的净空差本身就是一条**有意义的结论**（它量化了"跟踪误差会吃掉多少净空"）。
4. **臂间净空用两套模型交叉验证**：`MoveItCollisionBackend::distances()` 同时给出 `arm_arm`（mesh/FCL）与 `capsule_arm_arm`（胶囊模型），S2 已同时记录；S3 保留两者并报告一致性。
5. **报告内容**：全程最小净空及其**周期号与连杆对**、低于阈值的周期数、首次碰撞周期、扫掠失败次数、三种 `object_source` 下的最小净空对照表。
6. **与 §1.1 的关系**：S2 的 13.117 mm 是**一个静态构型**的净空。S3 的检查覆盖"待机 → 接近 → 停下"之外**整段搬运**（用户 m03080 第 3 条的要求），且是**逐周期**而非抽样 33 点。

## §10 风险

| 风险 | 机制 | 应对 |
|---|---|---|
| **B1** 左锚定单侧驱动 ⇒ 左臂负担全部物体运动，可能撞限位或撞支架 | 物体任务只驱动左臂，右臂只跟随 | W8 扫 `w_obj`；若左臂限位，改双锚形式（§5 问 4 的备选）；先把事实量化 |

| **B3** 手指关节在搬运中是**夹持开度**而非张开，碰撞检查口径与 S2 的接近段不同 | S2 用张开（`±gripper_max_opening/2`），S3 用 `±grip_thickness/2` | `TransportChecker` 显式参数化；S3-T9 用注入碰撞证明口径真的生效 |
| **B4** 样件位姿在碰撞查询里"该用哪个"有歧义 | 三种来源确有差异 | 三种都跑、都报（§5 问 8 第 3 点）；默认取保守的 `left_anchor` |
| **B5** `‖e_obj‖` 混合米/弧度，汇总口径有误导性 | C2 遗留口径 | 主判据一律用解耦分量；汇总里 `‖e_obj‖` 只作辅助并标注 |
| **B6** §4.1 的接口新增被误读成"改了 C2" | 涉及 C2 包 | 3 条逐位回归（T5b/c/d）+ 约 30 行零删除的 diff 供审查 |
| **B7** mock 理想被控对象过于乐观 ⇒ 结论外推到 Gazebo 会失真 | `q += dq` 无滞后 | 报告显式标注模型；附一阶滞后灵敏度跑；**不**据此声称 Gazebo 也可行 |
