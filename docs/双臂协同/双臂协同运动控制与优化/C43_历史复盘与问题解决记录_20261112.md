## 3. 关键问题一：把动作成功当成抓取成功

### 现象与误判风险

- 早期流程可以COMPLETE，但手指仍约±0.0305 m张开，样件由weld带走。
- JTC能到目标；物体宽50 mm时，±0.0251 m的命令仍可能留下间隙。
- 首次触碰后立即cancel，会在单指或极轻微双指接触处停止，尚未形成持续夹持。
- 样件短暂升高、detach后没掉，可能是仍搭在夹爪或支撑上。

### 本轮怎样解决“证据不够”

1. 明确无weld场景，实际生成SDF中核验没有DetachableJoint。
2. 检查真实关节值、所有机器人—样件碰撞对；不仅看手指动作返回值。
3. 搬运前确认同一完整Contacts消息含四指，分档加载至每指5 N。
4. 保持与横移阶段确认没有源支撑/目标支撑接触。
5. 放下后确认目标支撑接触，松爪退回后确认机器人不再接触样件。
6. 把`physical_transport_complete`事件与独立的`transport_audit.json`分开；当前GUI轮只有完成日志，尚未保存与r1/r2同级的审计文件。

**解决状态：**本轮受测搬运的物体级证据已补齐；正式executor尚需接入同等检查。不能把上述诊断阈值直接提升为正式验收标准。

## 4. 关键问题二：位置夹持、驱动力和力反馈混为一谈

### 实验排除了什么

真正单臂模型删除右侧link/joint及right硬件后，两轮0.35 kg样件峰值分别升高46.184/25.006 mm，随后回落。说明同一C43左爪在单臂条件下也会失败。双臂模型中另有三轮样件撞到静止右腕，已标记为受干扰，未拿来作纯左爪能力或质量因果结论。

这不是对用户最初“旧单臂无effort也能夹起”工况的逐项复现：历史物体尺寸、质量、姿态、接触余量及驱动实现未全部统一。旧M4报告也存在固定60 N的另一套配方，不应移植成当前C43的默认值。现有证据能够纠正“接口没有effort就一定没有夹紧作用”的解释，但不能声称已找到所有旧单臂成功/当前失败之间的唯一差别。

位置预紧组中，去手指重力的轴向关节反力估计常接近模型150 N上限；进一步把位置目标从±0.0249改到±0.0248没有展示稳定改善。**位置控制没有effort命令接口，不等于没有实际夹紧作用。** 动态反力还含惯性贡献，这个150 N估计也不等同指面真实法向力。

### 成功方案到底是什么

- 接近阶段：使用关节速度反馈低速闭合，接触消息决定阶段推进。
- 持物阶段：四指各固定5 N原生关节驱动力，手指位置JTC不加载，避免同一手指被两种命令竞争控制。
- 手臂阶段：两份同步JTC轨迹；不是QP实时闭链控制。
- FT：采集、分析和检查流是否新鲜，不参与夹持力闭环调节。

因此本轮可以说“当前工况不必先引入FT闭环也能搬运”，不能说“纯固定位置配方已经成功”“完全没有反馈”或“以后不需要力反馈”。

证据：[位置A/B报告](C43_POSITION_GRIP_AB_20261111.md)、[标定与驱动对照](C43_FORCE_CALIBRATION_AND_GRIP_20261111.md)。

## 5. 关键问题三：FT恒定不是传感器必然失效

早期force.x约-0.0864948 N、torque.z约0.00306797 N·m，与手指质量0.008826 kg的重力及COM_y=0.03547 m产生的力矩吻合。

处理步骤：

1. 在ros2_control中声明传感器状态接口；转换到SDF后再注入joint FT sensor，防止转换丢失。
2. world加载ForceTorque和ApplyLinkWrench系统。
3. 通过`/world/c43_s4_world/wrench/persistent`施加world X/Y/Z的+2/-2/+5 N，各工况之间clear，避免载荷累加。
4. 保存加载前、加载后、撤载后的原始流，按当时link姿态比较RᵀF，去掉自重基线。

共27个左侧加载工况：finger1 home 9点、finger1 grasp 9点、finger2 grasp 9点。抓取姿态近似映射为child≈[-worldY,-worldZ,+worldX]；精确分析使用四元数，不能把该近似矩阵套用到所有姿态。

**边界：**这是理想仿真力通道的一致性验证；未完成独立已知力矩六轴标定，也未完成右侧及所有倾斜姿态的标定，不能签发真机精度结论。部分5 N点触及行程边界，原报告已单列。

## 6. 关键问题四：偏心抓取、翻转与后期深重叠

原抓取接触靠近样件+X端，距重心约50 mm，且主要覆盖侧面上部约10.5 mm高度。原生同时间戳重建发现：先绕Y翻起，再相对下滑，最后出现开口塌缩与毫米级几何重叠；最大STL顶点深入盒体见证约6.57 mm。该值不是Gazebo的penetration depth，也不能把后出现的重叠当作最初失稳原因。

| 对照 | 结果 | 学到了什么 |
|---|---|---|
| 原位置、原STL、5 N | 翻转、未正常离开支撑，后期开口塌缩 | 单纯固定力不能救原抓取关系 |
| 原位置、等包络三盒碰撞、5 N | 深重叠见证降到约0.019 mm，但样件末升高仅26.876 mm，仍倾斜 | 碰撞表示影响后期异常，但不是几何失稳的完整解法 |
| 原位置、修正摩擦参数引用、5 N | 参数进入SDF，但仍失稳 | 不能把“参数生效”当作“物理问题解决” |
| 原STL、样件/支撑一起X+50 mm、5 N | 三轮抬升49.999/49.992/49.992 mm，后两轮保持指令20 s | 改善相对抓取关系+固定驱动力获得成功组合 |
| 同样平移、固定位置±0.0249 | 一轮峰值43.059 mm，保持后回落 | 本次几何调整并未证明原位置配方也稳定 |

平移同时改变了偏心力臂与端边余量，未单独解耦两者；没有改变接触高度，不能宣称靠“更深插入”解决。网格存在非二流形特征，也不足以单独判定模型损坏或唯一根因。

证据：[失稳路径与几何对照](C43_ESCAPE_DIAGNOSIS_20261111.md)，含原生重建图、事件时序和所有对照日志。

## 7. 关键问题五：把成功几何迁移回机器人，而非继续移动场景

临时平移样件只是一种诊断。后续保持源样件/支撑在原位置，把左TCP沿world X减50 mm，完成IK/FK/碰撞筛选。

- 左臂居中、右臂home：完整路径311个检查状态通过，实跑两轮抬升49.975/49.977 mm，保持采样跨度19.97/19.90 s。
- 左臂居中、右臂留旧抓取位：腕部互碰。
- 两爪都移到同一重心位置：手指/腕部互碰。
- 抓取点X=±15/25/35 mm、无倾角：所测端点组合碰撞。
- X=±25 mm、各向外倾15°：获得无碰撞候选，接近路径622状态通过；实测3831状态复查无碰撞，最小臂间距23.971 mm。

**保留问题：**左臂单独持物两轮都出现约5.42 mm横摆峰值，一指靠近开限位，总开口仍约50.16 mm。此前建议过增加夹爪中心约束；之后按用户指示优先验证双臂固定力完整流程，并没有实现该中心闭环。后来的双臂成功不能反向抹去这项单臂问题，也不能把横摆归因于右臂存在。

碰撞检查使用实际URDF/SRDF和18个mesh形状，不新增两臂互碰豁免；绝对mesh路径在离线副本中加`file://`，修复MoveIt资源检索失败。离散检查不能替代连续碰撞证明，保守平板也不等于逐个建模有限桌面及桌腿。

证据：[候选迁移报告](C43_CANDIDATE_TRANSFER_20261111.md)。其中“尚未双臂夹持”的表述属于该报告当时的阶段状态，后续进展见搬运报告，历史原文不回写。
