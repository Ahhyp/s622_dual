在现有环境能完成的 W5–W9 软件实现与 Gazebo 验证应继续推进；C6、S4-T2、S4-T17 维持既有 `ENV_REFUSED / HOLD / UNVERIFIED` 或 `BLOCKED_EXTERNAL_ENV`，不重复在已拒绝的 WSL2 上索取 RT PASS。

## 2. 所有阶段共同遵守的冻结技术边界

### 2.1 架构与物理模型

- `D-S4-1`：沿用中性物体任务库 `dual_arm_object_task`，不把完整 mock 包引入生产实时依赖。

- `D-S4-3`：实时解析碰撞 / 非实时 FCL 预检 / Gazebo 接触监控**三层分工**；不得声称离散采样证明连续安全。
- 保留 S2 冻结：样件 `0.12 × 0.05 × 0.05 m`、`0.35 kg`，支撑圆柱 `r=0.04 m`、`h=0.25 m`，名义样件中心 `world_T_object=(0,0,0.275 m)`。
- 保留 C4.3 的理想抓持语义；不引入摩擦锥、力控、真实夹持力证明。

### 2.2 已获批准 CR 的重要勘误（不能只看旧初版）

仓库最新冻结文本及正式批准 CR 优先。尤其定向核对如下已在历史记录中出现的后续条款：

- **轨迹采样时钟（§14 / S4-T19）：** 仅 committed 周期推进；HOLD 冻结；RESUME 守卫不满足时不得跳时钟。
- **有限几何碰撞（§14 / S4-T20）：** 有限桌面 OBB-SAT；支撑柱禁止用外接盒作精确允许接触证明；接触白名单必须严格匹配相位和部位。
- **释放顺序（§14 / S4-T18）：** 支撑确认 → detach → 确认样件不随手上升 → 张手 → 后退，不可反序。
- **控制器本地保护（§14 / S4-T21/T22）：** E1–E8 保护与 HOLD/FAULT/ABORT 锁存、ACK 等既定语义不可削弱。
- **S4-T12 双附着：** 采集实际对照结果，**不预设“双附着必定劣化”作为必须观测到的事实**；无论对照结果怎样，正常链路仍不得启用双附着。
- **S4-T17：** 长时间实时性仍归原生 RT 外部验收；不得用 WSL2 伪造。
- **S4-B13：** 既有历史标记为尚未完成的正式需求，不可借 W7 单条轨迹假称整个姿势集合已完成。
- **CR-W3-R1A-001：** `S4-T8` 的责任归属 W9；T-H15/T-H16/S4-T21 等历史依赖以正式修订为准，不重新审计已有有效 PASS。

以上是**需要读取最新文本确认的条款主题**，不是授权 Agent 自行修订上位标准。

**输入：** W5-A 的两个模型、`check_c43_models.py`、现有 `s622_world.sdf`、`s622_gazebo.launch.py` 的可复用配置。

**主要交付：**

```text
src/gz_launch/worlds/c43_s4_world.sdf
src/gz_launch/launch/c43_s4_transport.launch.py
```

**实施：**

1. 仅做 W5 相关的定向基线核对，复用物理配置、ground、sun、插件、模型安装与资源路径；旧 world/launch 不改。
2. **桌面是初版 §5/§6 明示的 W5 场景组成部分，默认按必需项处理。** W5-A 没有将旧 `table` 直接引入，是合理的避免干涉动作，**但不等于批准删除桌面需求**。

**B 检查点：**

- SDF/XML 合法；模型资源与命名真实解析；world 中桌面/支撑/样件互不意外穿透。
- 专用 launch 可启动；Gazebo headless 实际加载且仿真时钟推进；旧场景未被改动。
- 如果冻结文本对桌面位置存在实质冲突，只暂停有冲突项并留下精确引用，不把有问题的 world 标 PASS。

### 3.2 W5-C：受控 5 s 静置与软件收尾

**前提：** W5-B 实际可加载且无已知结构冲突。

**实施：**

1. 保留真实重力、碰撞和动态样件；不运行臂控制、不附着、不强行设置每帧位置。
2. 用 Gazebo **仿真时间**而不是墙钟覆盖至少 5.0 s 的受控观测区间。
3. 持久化 pose/time 原始采样、world/model 哈希、环境/命令、日志；计算中心偏移、姿态漂移、接触/穿透与滑落情况。
4. 样件名义高度 `0.275 m`；`2 mm` 若仍是 `[待标定]`，只报告测量差值，不自动签发数值 Gate PASS。
5. 对普通 world/接触配置缺陷做小范围修复并重测，保留失败前后证据；不得通过极端参数或禁用物理掩盖异常。

**结束口径：**

- 软件文件、加载与适用仿真证据完备，可登记 `W5 SOFTWARE_ONLY COMPLETE`，并列出未批准的数值判据。
- 软件文件完备而物理仿真无法可靠运行：`W5 SOFTWARE IMPLEMENTATION COMPLETE / GAZEBO_VALIDATION_HOLD`。
- 有结构缺陷或冻结冲突：`W5 PARTIAL / BLOCKED`。

### 4.1 目标与交付

按冻结初版 §5/§6，W6 只实现理想抓持的**可分离附着机制、客户端、瞬移防护、诊断开关与最小测试**；不代替 W7 完整流程。

### 4.2 W6-0：Fortress 插件行为小型验证（必须先做，不单开大审计）

**关键兼容风险：** Gazebo Sim 6 的 `DetachableJoint` 官方接口描述包括“默认初始附着、可通过主题 detach/reattach”；较新文档出现可配置的 `<initial_attach>`。**当前运行环境为 Fortress 6.16.0，不能仅凭较新 6.x/其他版本文档认定它支持某个参数。**

只针对当前安装版做一个短小可复现的最小模型试验，记录：

- 实际插件文件名、插件加载成功与失败日志。
- `parent_link` / `child_model` / `child_link` 的实际解析。
- `attach_topic`、`detach_topic`、`output_topic` 和消息类型的实测值。
- **启动时是否已附着**，以及在本机版本能否显式配置为初始未附着。
- detach、重新 attach 的观测、超时和重复请求语义。
- 如果插件在启动时默认附着且无法可靠关闭，**禁止把启动时已有的物理约束当作 GRASP 成功**；提交局部兼容方案供审批，不擅自切换到另一种物理契约。

### 4.3 W6-1：隔离式单侧附着实现

1. 新建专用 xacro，保留原机器人模型行为，增加**仅左侧**真实关节附着链。
2. 校验 Gazebo 真正加载该专用 xacro，而不是仍载入旧机器人模型。
3. 不把 attach 仅理解为“消息发送成功”；成功要有**插件状态/关节实体/相对位姿**等实际反馈。
4. 只有满足 GRASP 前置条件时才允许 attach；失败或超时进入受控的既有 FAULT/HOLD 行为，不可继续抬升。
5. attach 前后位姿变化、100 ms 后相对稳定性做量化采样；`2 mm / 0.5°` 及其他待标定值必须查询最新台账状态，不能擅自转为正式批准阈值。
6. 对重复 attach、漏确认、无效 child_link、Gazebo 退出、ROS–Gazebo 桥断开和超时进行阴性测试。

### 4.4 W6-2：释放安全顺序与诊断隔离

遵守后续 §14/S4-T18 的唯一释放顺序：

**确认支撑稳定（既定阈值与连续采样） → detach → 观察约定时间确认物体未随夹爪上升 → 张手 → 后退。**

- 不允许“先张手再 detach”。
- detach 失败时不得继续假装释放完成。
- `--attach both` 为**显式诊断开关**，默认关闭，和正常启动入口隔离；应提供保护使正常业务配置无法误启用。
- 不通过修改样件质量/冻结几何、永久锁定 pose 或关闭碰撞达成“附着稳定”。

### 4.5 W6 完成判据

- 当前 Fortress 的插件行为有实际证据；专用 xacro/客户端可加载且可调用。
- 单侧 attach/detach 的正向、异常和重复请求均有可复核结果。
- 前后瞬移、相对位姿、释放次序均留原始测量与状态记录。
- S4-T16 抓持失败时**不得调用 attach**；S4-T18 释放顺序获得针对性证据。
- 对阈值/接口审批仍未落实的项目单独 HOLD；**软件功能完成 ≠ 正式附着 Gate PASS**。

## 5. W7：双臂完整搬运流程与产物

### 5.1 目标

在已稳定的 W6 仿真链路上，完成：

`IDLE → APPROACH → GRASP → LIFT → TRANSPORT → LOWER → RELEASE → COMPLETE`

同时保留 HOLD/ABORT/FAULT 的既定锁存与恢复语义。W7 是 **S4.2 的端到端集成**，不应重新发明 W3 状态机或 QP 数学。

### 5.2 主要改动与接口

主要在 `dual_arm_transport_executor` 的 `state_machine.cpp`、`executor_node.cpp`、必要配置、C4.3 专用启动接线和定向测试中集成：

- 等待 `dual_arm_qp_controller: active` 才允许执行搬运。
- 12 关节命令由 QP 控制器独占；执行器**不得**同时对臂 JTC 下发目标，启动时复用既有互斥守卫。
- 夹爪仅通过左/右 `hand_controller` 的 JTC 驱动。
- `GRASP`：先检查夹爪完成与抓持误差，再 W6 attach；不允许跳过反馈直接进入 LIFT。
- `LIFT/TRANSPORT/LOWER`：继承已完成的相位驱动、目标流、控制器 Status 和 ACK；不得把 W3 模拟适配器结果当作实际 Gazebo 末端行为。
- `RELEASE`：严格调用 W6 的安全释放顺序。
- 异常：对控制器失联、跟随超限、过期状态、ACK 不匹配等按已有软件安全契约处理，禁止无状态继续运动。
- 整个 W7 **只在 Gazebo/simulated mode 下执行**，不得以该集成放行真实硬件。

### 5.3 分段实施方式

**W7-A 接线**：模型/控制器/执行器/夹爪 JTC 的启动与互斥，日志与状态可观测；先做服务和状态联通 smoke。

**W7-B 流程**：按上述阶段逐段打通，从安全的定点 GRASP/LIFT/RELEASE 到完整冻结轨迹，复用既有相位框架，不以临时手动设置物体位置代替实际动作。

**W7-C 集中验证**：完整模拟任务至少有一次 `success=true` 的原始 run；若尚未满足标定阈值，只能认定成功路径功能证据，不能称全部正式指标 PASS。

## 7. W9：碰撞三层、故障注入和安全收尾

`PASS / FAIL / NOT_RUN / HOLD / UNVERIFIED / ENV_REFUSED / APPROVAL_BLOCKED`

某项尚未执行时，不能将“计划有检查器”视为已测；某项阈值未批准时，可有真实测量结果但不得误标正式指标 PASS。
