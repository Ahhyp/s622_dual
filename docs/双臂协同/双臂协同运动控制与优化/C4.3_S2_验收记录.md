source /opt/ros/humble/setup.bash
eval "$(conda shell.bash hook)" && conda activate yolov8

  --urdf   src/dual_arm_kinematics/test/fixtures/s622_dual_arm.urdf \

### §5.2 抓取目标与 IK 分支

- `world_T_object`：单位旋转，平移 `(0, 0, 0.275)`。
- `object_T_left_tcp` 平移 `(+0.0497, 0, +0.025)`，`object_T_right_tcp` 平移 `(−0.0497, 0, +0.025)`；两者旋转相同。
  - **TCP 内缩 10.3 mm**：TCP 不在端面中心（0.06），而在 `0.060 − 0.0103 = 0.0497`，因为垫面本体半宽 10.3 mm，不能跨在端面上。两 TCP 间距 = `2 × 0.0497 = 0.0994 m`。
  - 自上而下姿态：`x_tcp = +y_obj`（合拢轴）、`y_tcp = +x_obj`、`z_tcp = −z_obj`（指向样件内部，即向下）。
- 每臂 IK 分支：`total_branches = 8` → 通过本包**独立 FK 复核**（不采信求解器自带 `fk_verify`）后左右各 3 支（`ik=(3,3)`）。

## §8 缺陷与发现

### §8.1 缺陷 1（崩溃根因）：`getVariableBounds(0)` 静默空指针

- 现象：`c43_s2_baseline: no feasible baseline: basic_string::_M_construct null not valid`。
- 根因：`moveit::core::JointModel::getVariableBounds()` **按变量名（`std::string`）重载**；字面量 `0` 是空指针常量，可隐式转 `const char*`，构造 `std::string(nullptr)` 抛 `std::logic_error`。**编译通过，运行必崩。**
- 修复（`src/path_check.cpp`）：改用无歧义形式
  ```cpp
  const std::vector<std::string>& var_names = jm->getVariableNames();
  if (var_names.size() != 1) continue;
  const moveit::core::VariableBounds& bounds = jm->getVariableBounds(var_names.front());
  ```
- 教训：凡是 `getVariableBounds(<整数字面量>)` 的写法都要怀疑。

### §8.2 缺陷 2：路径检查时手指是闭合的

- 现象：修好 §8.1 后**所有**摆位都报 `standby_segment_collision`。
- 根因：`DualArmScene::makeStateQ12()` 把四个 prismatic 手指关节留在默认 `0.0` = **闭合位**；样件已在场景中，于是每个状态都与样件碰撞。
- 修复（`src/path_check.cpp::stateOf`）：显式把四指设为张开位
  ```cpp
  const double open = cfg_.gripper_max_opening_m / 2.0;
  st.setVariablePosition("left_finger1_joint", +open);  // 其余三指同
  st.update();
  ```
- 理由：待机运动与接近运动**都在手指张开时发生**，只有最后的闭合把垫面压到样件上。
- 教训：`makeStateQ12` 不设置手指；任何带样件的碰撞查询都必须显式设置手指位置。

### §8.3 缺陷 3：把「关节插值走不出直线」当成硬失败

- 现象：修好 §8.2 后主导失败变为 `approach_segment_approach_not_straight`（`line_dev` > 1 mm）。
- 根因：关节空间线性插值**不可能**在笛卡尔意义上走出直线。用户 m02331 D7 要求的是**碰撞可行性**，不是直线性。
- 修复：`PathCheckOptions` 新增 `bool require_straight_approach = false;`；`max_line_dev_m` **始终测量并写入验收记录**，默认只报告不否决。
- 证据：`test_path_check.StraightnessIsReportedEvenWhenItIsNotEnforced` 同时验证「默认通过但 `line_dev=0.005842`」与「打开开关即被否决」，证明该指标真的接入判决。

### §8.4 缺陷 4：待机解与抓取解不在同一 IK 分支

- 现象：待机与抓取各自无碰撞，但关节插值扫过碰撞区。
- 根因：待机搜索取 `res.solutions.front()`，可能落在肘翻转分支上。
- 修复：`searchStandbyFor(cfg, const dual_arm::Q12* seed = nullptr)`，给 seed 时逐臂取 `argmin |s − seed.segment<6>(side*6)|`；并把待机搜索**从「每摆位一次」移进「每候选一次」**，使二者共享分支。

### §8.5 ★ 发现 5（F-S1-1 实证）：`logSO3` 近 π 数值缺陷

源：`src/dual_arm_kinematics/include/dual_arm_kinematics/se3.hpp:51-68`。令 `δ = π − θ`。实测（两个轴，`expSO3 → logSO3`）：

| δ | 误差 \|‖logSO3‖ − θ\| | 所处分支 |
|---|---|---|
| ≥ 1e-4 | ≤ 8e-8 | 一般分支，可用 |
| 1e-5 | 1.3e-7 ~ 3.6e-6 | 一般分支，退化 |
| 2e-6 | 3.5e-5 ~ **2.1e-4** | 一般分支，不可用 |
| 1e-6 | 1.0e-6 ~ **4.9e-4** | 边界，由噪声决定 |
| ≤ 1e-7 | == δ | 近 π 分支，角度被**强制为 π** |

两个真实缺陷：
1. `se3.hpp:58` 用 `(M_PI − th) < 1e-6` 选分支，而 `th` 由 `acos` 反解、自身带 1e-8~1e-10 噪声 ⇒ **δ 恰好为 1e-6 时会随机落到任一侧**。落在一般分支时，代码除以 `2·sin(th) ≈ 2e-6`，把 `R − Rᵀ` 的相消误差放大，误差达 **4.9e-4 rad**——反而比该分支想避开的窗口差 500 倍。
2. 落在近 π 分支时返回 `M_PI * axis`，**丢弃 δ**。

对 S2 的结论：
- `kMidpointSafeMinMarginRad = 1.5e-3 rad` **可判定**：δ ≥ 1e-4 时误差 ≤ 8e-8，比阈值低 4 个数量级以上。**S1 的不改决定仍然成立。**
- `closure_residual.hpp` 中 `rotation_direction_ambiguous = (M_PI − rotation_rad) < 1e-9` **不可判定**：其真实分辨率约 **5e-4 rad**。该标志在窗口内**过度触发（偏安全侧）**，且 S2 从不在 π 附近求值它（有效闭链下该残差 ≈ 0）。
- **修正措辞**：不能因为「只用范数」就宣称不受数值误差影响；正确理由是「所用阈值远大于实测误差」。

### §8.6 ★ 发现 6：水平沿棒轴的双端抓取对本双臂几何不可行

该臂 TCP 距腕 **0.2168 m**。若沿棒轴水平内伸（`z_tcp = ∓x_obj`）：左腕在 `x_obj + 0.06 + 0.217 = x_obj + 0.277`，右腕在 `x_obj − 0.277`；左基座在 `x = +0.35`、右在 `x = −0.35`。要求两腕离各自基座轴 ≥ 0.15 m 则需 `x_obj ≤ −0.077` **且** `x_obj ≥ +0.077`，矛盾。
**→ 正面证实用户 D1 的警告「夹爪最大开合 0.061 m 不意味着整个双端抓取一定可行」，并据此转向自上而下抓取**（不违反 D2：±X 端仍是抓取区域，只是接近方向由 `object_T_*_tcp` 决定）。

### §8.7 发现 7：失败归因把单臂自碰撞误报为世界碰撞

- 现象：`screen()` 原逻辑「`arm_arm ≤ 0 || arm_proximal ≤ 0` 才算臂间/近端，否则归 world」，而 5 个被拒对的 `right_upperarm_link<->right_finger1` 等**同臂两连杆**对 `arm_arm = arm_proximal = 0.56` 而 `whole_robot = 0`，于是被误归 `collision_world`。
- 修复：新增同臂判定，同前缀（`left_`/`right_`）两连杆 → `collision_self`，跨到样件/支架/地面 → `collision_world`。
- 结果：`reject_histogram` 由 `{collision_world: 5}` 变为 `{collision_self: 5}`，归因正确。

### §8.8 发现 8：`isMidpointSafe` 用 `>=` 而非 `>`

首次测试在 `margin == threshold` 处失败，实测证明三个函数（`isMidpointSafe`/`midpointUnsafeReason`/`midpointMargin`）均为**闭区间**：margin 恰等于阈值算**安全**。已按实测修正测试期望。

### §8.9 发现 9：`provenance` 只写成注释，回读丢失

`toYaml()` 原把 `provenance` 写成 `#` 注释，`fromYaml()` 无法回读（测试报 `b.provenance == ""`）。已改为**同时**写出真正的 `provenance:` 键与人类可读注释；并把 `placement_log` 也序列化。

## §12 结论与建议

1. **S2 目标达成**：产出一条独立于 C4.2 A6、经全几何碰撞验证、经独立可达性检查的 `transport_baseline`，并具备完整的失败原因归类。
2. **D1 的警告是实质性的**：水平沿棒轴的双端抓取对本双臂几何**不可行**；最终方案是自上而下，这属于筛选结果而非预设。
3. **F-S1-1 有真实发现**：`logSO3` 在近 π 处的分支边界由噪声决定，误差最高 4.9e-4 rad。S2 的 1.5e-3 阈值安全，但 `closure_residual` 的 1e-9 歧义带不可判定（真实分辨率 ~5e-4 rad，且偏安全侧）。
4. **建议（不属 S2，供 S3/后续参考）**：
   - `se3.hpp` 的近 π 分支建议改为按 `R` 的对称部分特征分解求轴，或把窗口放宽并做一次牛顿精修，以消除 4.9e-4 的放大。
   - `closure_residual` 的 `1e-9` 阈值宜改为与实测分辨率一致的量级，或在文档中标注其真实分辨率。
   - `searchStandbyFor` 的退距上限 0.28 m 在左臂 `D_domain` 全失败，可考虑改扫方向而非仅改距离。
