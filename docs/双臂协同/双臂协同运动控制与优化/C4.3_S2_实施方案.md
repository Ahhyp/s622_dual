### §1.2 缺陷的精确边界（决定分类标准）

`src/dual_arm_kinematics/include/dual_arm_kinematics/se3.hpp:57` 的近 π 分支在
`M_PI - θ < 1e-6` 的带内可能返回**被取反**的轴。因此按**消费方式**分类：

| 类别 | 含义 | 危害 |
|---|---|---|
| **N1 `NORM_ONLY`** | 只取 `.norm()` / `.squaredNorm()` / 标量幅值 | **无害**：该分支返回的幅值恒为 π，而真值在 `[π−1e-6, π)`，幅值误差 ≤ 1e-6 rad |
| **N2 `VECTOR_ONLY_OUTSIDE_BAND`** | 用了向量分量/方向，但输入**在结构上不可能**进入 π 带 | 无害（需给出为何不可能的构造性理由） |
| **N3 `VECTOR_USED_IN_BAND`** | 用了向量分量/方向，且输入**可以**进入 π 带 | **有害**：可能出现 2π 级误差 |

**必须与数学固有性质区分**（用户 m01856 明确要求）：
旋转对数主值在 θ = π 处的不连续是**数学固有**的，任何实现都无法消除；
但本缺陷发生在 **θ < π 一侧**，是**实现引入的伪跳变**，必须修。

#### §1.3.1 缺陷本体（已复现，数值确定）

`se3.hpp:57` 的近 π 分支用 **`sign(axis[best])`** 定向，通用分支（`se3.hpp:67`）用 **`R − Rᵀ`** 定向。
两个分支的**符号约定不同**。实测（`/tmp/fs11c_probe.cpp` 段 (iii)，真实轴 `(-0.808122, +0.505076, +0.303046)`，
最大分量为**负**）：

| π−θ | ‖logSO3‖ | 与参考轴夹角 | 翻转？ |
|---|---|---|---|
| 3.0e-6 | 3.141566272 | 0.000001° | no |
| 2.0e-6 | 3.141625403 | 0.000000° | no |
| 1.5e-6 | 3.141451519 | 0.000000° | no |
| 1.1e-6 | 3.141405805 | 0.000000° | no |
| **1.0e-6** | 3.141592654 | **179.999979°** | **YES** |
| 9.9e-7 | 3.141592654 | 179.999979° | **YES** |
| 0.0 | 3.141592654 | 180.000000° | **YES** |

**必须与数学固有性质区分（用户 m01856 明确要求）**：
恰好 `θ = π` 时主值轴的符号**本就不确定**——200 个精确 π 旋转中 **84 个（42%）**
返回了与生成轴相反的符号（探针段 (v)）。**这不是缺陷**。
缺陷是 **`π − θ > 0` 一侧的伪跳变**：跨过 `1e-6` 阈值后返回轴被整体取反，与通用分支相差 **2π**。

#### §1.3.2 与缺陷并列的第二个实现问题：**近 π 角度精度**（比符号问题更基础）

`θ = acos(0.5·(trace(R)−1))` 在 `θ → π` 时条件数退化。实测**绝对角度误差**与**重构误差**
（探针 (i)(ii)，`expSO3(logSO3(R))` 与 `R` 的测地角差）：

| π−θ | 恢复出的 π−θ | 角度误差 | `expSO3(logSO3(R))` 重构误差 |
|---|---|---|---|
| 1e-4 | 1.000266e-4 | 2.7e-8 | 2.1e-8 |
| 1e-5 | 1.012989e-5 | 1.3e-7 | 1.3e-7 |
| **1.1e-6** | **1.868491e-4** | **1.87e-4** | **1.86e-4** |
| 1e-6（走分支） | 0 | ≈0 | 1.2e-6 |
| 5e-7（走分支） | 0 | ≈0 | 6.2e-7 |
| 0（走分支） | 0 | ≈0 | 2.1e-8 |

**结论：`1e-6` 这个带宽阈值与实现实际能达到的角度分辨率不匹配**
（带边缘可达 **1e-4 量级**误差）。
全部取值**有限、无 NaN**（对合法旋转矩阵）。

**另一个必须记住的事实**：**恰好 π 时通用分支本身不可用**——`sin(π) ≈ 1.2e-16`，
实测返回范数 **3.488** 而非 π。所以**近 π 分支的存在是必要的**，不能简单删除。
同时实测表明**近 π 分支比通用分支在 π 附近更精确**
（`objectJacobianBody` 范数：带内恒为 `2.345944850`；带外最后一点 `2.345714520`，
偏差 **−2.3e-4**，即通用分支在带边缘失准）。

#### §1.3.4 ★ 我方的独立复核：审计一的"3.05 幻影误差"结论**被证伪**

审计一（headline finding #1）声称：在 `q12 = 0`、目标取自同一姿态时，
`relativeError` 返回 `(+1.600759, +1.320183, +0.783824 | -1.209200, +1.209200, -1.209200)`，`‖e‖ = 3.050604`，
而真值为 0，且该值经 `dual_arm_qp.cpp:112-113,169,174-175` 直接进入 QP 代价。

**我方探针 `/tmp/fs11d_probe.cpp` 证伪了它**：

```
[1] q=0, target=achieved : |relativeError| = 4.591690e-49   (pi-|xi| = 0.000e+00)
    objectError(target=achieved) = 0.000000e+00
```

真值就是 0，与理论一致。原因：`relativeError` 计算的是 `logSE3(leftTright(q)⁻¹ · target)`，
即 **`T_err` 是"当前相对位姿"与"目标相对位姿"之间的误差**——这是**小旋转**。
π 存在于 `leftTright(q)` 本身，而**不在 `T_err` 里**。所以 `logSE3` 内部的 `logSO3` 看不到 π。

进一步扫过带边缘（目标由 `exactlyPiPose` 捕获，扫右臂 `dq1`）：

| dq1 | π−‖ξ(q)‖ | ‖relativeError‖ | ‖objectError‖ |
|---|---|---|---|
| 1.0e-4 | 9.999e-5 | 1.119610e-4 | 5.597683e-5 |
| 1.0e-5 | 1.362e-5 | 1.119610e-5 | 7.259403e-6 |
| 3.0e-6 | 6.513e-5 | 3.358830e-6 | 3.257595e-5 |
| 1.1e-6 | 1.868e-4 | 1.231571e-6 | 9.342497e-5 |
| 1.0e-6 | 4.893e-4 | 1.119610e-6 | 2.446585e-4 |
| 9.9e-7 | −4.441e-16 | 1.108414e-6 | 8.628541e-7 |
| 0.0 | −4.441e-16 | 6.938894e-18 | 6.179798e-18 |

`‖relativeError‖` 随 `dq1` **单调平滑**，跨过带边缘**无跳变**（旋转块同理：
`dq1=1.5e-6 → e_rot = (+1e-6, −1e-6, +1e-6)`，`‖e_rot‖ = 1.5e-6`，与 `dq1` 一致）。
`objectError` 的扰动来自 `worldTobject` 本身（`:96`），属上表已列的暴露点。

⇒ **`relativeError` / `objectError` 判定为安全。审计一的该条结论不采用。**

#### §1.3.5 对审计三"控制器暴露"结论的定量修正

审计三把 `worldTobject` / `objectJacobian*` 列为**可达控制路径的暴露点**。方向正确，但需要两处定量修正
（均已核对源码与探针）：

**(a) C2 QP 的物体任务是"零误差"任务。**
`src/dual_arm_qp_core/src/dual_arm_qp.cpp:91-93`：

```cpp
DualArmQpResult DualArmQp::solve(const Q12& q, const Iso3& left_T_right_target) {
    return solve(q, left_T_right_target, kin_.worldTobject(q));   // 目标 = 当前中点估计
}
```

于是 `e_obj = objectError(q, worldTobject(q)) = logSE3(worldTobject(q)⁻¹ · worldTobject(q)) ≡ 0`。
`src/dual_arm_qp_controller/src/dual_arm_qp_controller.cpp:216` 调用的正是这个两参重载
⇒ **物体误差恒为 0，不会产生"幻影物体误差"驱动的运动**。

**(b) 真实影响只经由 `J_obj` 进入权重矩阵，且是条件性的。**
`dual_arm_qp.cpp:161` 的 `J_obj = kin_.objectJacobianBody(q)` 进入 `A_task_obj_`，
再进入 `P_ += w_obj · A_task_obj_ᵀ A_task_obj_`（`:177-181`）。所以 `ξ` 的符号只改变**代价矩阵的
物体任务块**，不改变任何误差项。而 `ξ` 是否真的被取反，取决于**真实近 π 轴的最大分量是否为负**。

**实测（§1.3.6）：两个真实家位的 argmax 分量均为正（`axis[2] = +0.622251`），
审计三自己的合成扫描也给出 `dot = +1.000000`、误差 ≤ 1.5e-5 ⇒ 在家位上 `logSO3` 输出正确。**
我方的 `objectJacobianBody` 扫描（`/tmp/fs11d_probe.cpp` 段 [4]，
姿态 `exactlyPiPose`，其 argmax 分量同样为正、**未发生翻转**）显示带边缘 `‖J_body‖`
有 **2.3e-4**（相对 1e-4）的不连续——但该偏差是**通用分支在 π 附近自身失准**造成的
（带内恒为 `2.345944850`；带外最后一点 `2.345714520`），**不是符号翻转**。

⇒ **修正后的结论**：暴露点确实存在于 C2 运行期，但**当前没有任何已观测到的运行姿态会触发翻转**；
其后果将是**代价矩阵中物体任务块的结构变化**，而非误差项突变。
这是一个**必须记录、但尚未被触发**的风险。

### §1.5 F-S1-1 最小修复方案（**供审查，属独立立项，不在 S2 实施**）

依据 §1.3.1/§1.3.2，修复必须**同时**处理两件事，缺一不可：

1. **符号约定统一**：让近 π 分支的取向与通用分支在 `θ → π⁻` 的极限一致。
   可用的判据是 `sign( vee(R − Rᵀ) · axis )`（在 `‖vee(R−Rᵀ)‖` 仍具数值意义时）。
2. **阈值与可达分辨率匹配**：`1e-6` 的带宽与实测 1e-4 量级的角度误差不匹配。
   需要按 `‖R − Rᵀ‖`（或 `trace` 与 −1 的差）而非仅按 `acos` 结果来决定是否切换分支。
3. **恰好在 π 上**：符号本就不可判定（实测 42% 相反），此时**任何约定都可接受**，
   但必须**显式记录为一个有意的、已文档化的约定**，而不是看起来像 bug 的隐式选择。

**验收要求（用户 m01856 指定）**：Exp/Log 重构精度、数值有限性、分支一致性，
并配独立测试；**不得只按旋转向量符号判对错**（因为 π 处符号本就不确定）。
因 `se3.hpp` 被 C2/C4.2 共用，改生产代码前必须先提交本方案供审查，
并跑 `dual_arm_kinematics`、`dual_arm_qp_core`、`dual_arm_qp_controller`、

### §3.3 ★ 对置安装的直接后果：`ξ_rel ≈ π` 是**标称工况**

设两臂构型在各自基座系下「相同」（镜像安装下最常见的对称解），则

```
R_L = R_z(π) · R_ref ,  R_R = R_ref
ξ_rel = log( R_Lᵀ R_R ) = log( R_refᵀ R_z(π) R_ref ) = log( R_z'(π) ) ,  ‖ξ_rel‖ = π
```

**对置安装使「双臂相对姿态 ≈ π」成为双端夹持的自然解，而不是边角情形。**

这有两个独立后果，**必须在 S2 中分开处理**：

1. **数学固有**：`T_WL,d = T_WO,d G_L` 与 `T_WR,d = T_WO,d G_R` 互相约束，
   `T_Lᵀ T_R` 的主值旋转向量在 π 处**不连续**（越过后轴翻转）。
2. **实现缺陷 F-S1-1**：在 `π − θ < 1e-6` 带内，`logSO3` 的**两个分支符号约定不一致**（§1.2）。

**S2 的设计结论**：
C4.2 的物体位姿估计 `DualArmKinematics::worldTobject()` 采用

```
R_O = R_L · expSO3( 0.5 · logSO3( R_Lᵀ R_R ) )
```

即**对两个相差 π 的抓持旋转取平均**。在 `‖ξ_rel‖ → π` 时 `expSO3(±ξ/2)` 给出**两个相差约 π 的
不同「中点」**，故该定义在本机器人的标称双端夹持工况下**正坐在不连续点上**。
C4.2 的 `objectJacobianBody()` 又建立在这个中点上。

⇒ **S2 不用 `worldTobject` 作为物体参考**，改用 S1 的**左右独立锚定估计**
（`anchoredObjectPose` / `closureResidual`），它把「同一个物体位姿」当作两个独立估计来比较，
不取平均，因而**在 π 处天然良态**（§A14.1 实测：π 处两个锚定估计精确相等，
`‖log(T̂_L⁻¹T̂_R)‖ = 0`）。

### §4.2 左右固定抓持变换 `G_L` / `G_R`

沿用 S1 的 `GraspGeometry`（`src/dual_arm_kinematics/include/dual_arm_kinematics/grasp_geometry.hpp:42`）：

```cpp
struct GraspGeometry {
  Iso3 object_T_left_tcp  = Iso3::Identity();   // G_L = ^O T_L*
  Iso3 object_T_right_tcp = Iso3::Identity();   // G_R = ^O T_R*
  std::string object_frame      = "object_frame";
  std::string left_tcp_frame    = "left_grasp_frame";
  std::string right_tcp_frame   = "right_grasp_frame";
  // ...
  Iso3 leftTrightStar() const;   // ^L T_R* = G_L^-1 G_R
  std::string validate() const;  // 返回空串表示通过
};
```

**构造规则（显式、可审计，禁止从 M4 偏移反算）**：

1. 在两臂相向的对置安装下，取样件的 **±x 两个相对面**作为夹持面（世界 x 是两臂连线方向）。
2. 夹持点取该面中心，物体系到 TCP 的平移 = `(∓(size_x/2 + t_tcp_offset), 0, 0)`。
3. 夹爪接近方向沿该面外法线；手指闭合方向沿样件的另一轴。
4. 左右**严格对称**（关于世界 x = 0 平面镜像）。
5. 必须过 `GraspGeometry::validate()`，并记录 `leftTrightStar()` 与 `‖ξ_rel‖`。

#### ★ 物体局部坐标 vs 世界坐标（用户 m02331 D2 明确要求区分）

- `G_L` / `G_R`、抓取区域、接触面、接近方向**全部定义在物体局部坐标 `object_frame` 下**，
  **不随物体姿态变化**。
- 物体旋转后，**抓取区域仍由物体局部坐标定义**；只有在把 TCP 目标送到世界系时才做
  `T_WO,d · G_*` 的变换。
- **禁止**把抓取区域写成世界系常量——对置安装下，世界系写死会随物体任意姿态立即失效。
- **可判定判据**：对物体施加任意刚体变换 `T`，`G_L`/`G_R` 的**数值必须逐位不变**。
  测例：S2-T3（残差不变）+ S2-T14（`G_*` 局部不变）。

S1 已证明锚定残差在标称位姿下为 **0**（机器精度），IK 残差约 **1e-10**，
故取 `1e-6 m / 1e-6 rad`——比数值噪声高 4 个数量级，比任何真实机械误差低 2 个数量级。
**这属于「由数值能力推出」，不属于「由结果事后调阈值」。**
