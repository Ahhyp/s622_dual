# C4.3 S4 / W3-R1a — T-H13 RT 相位计时点设计

> 依据：m09161「T-H13 设计授权令」。**本轮只出设计，未改任何生产/测试代码、未新增 hook、未改构建选项。**
> 基线工作树：`HEAD = bb36fe2`（`master`），63 项未提交改动全部保留。
> 冻结状态不变：`W3-R1a Gate = HOLD`、`W2 = BLOCKED`、`B-4 = P0 OPEN`、`S4-T17 = BLOCKED_EXTERNAL_ENV`、`T-H17 = PARTIAL/OPEN`。

## 0. 设计前提（先约束再设计）

1. **不新增 hook、不改构建选项**（授权令明确）。因此相位计时只能挂在**已存在的运行时开关** `timing_enable` 上，不得引入新的 `#ifdef`。
2. **不得侵入 `TransportTask` 内部**。跨类拆分相位需要改接口，列为「需单独审批」（§7.2）。
3. **单一样本机制**。现有 `TimingRecorder` 已是 RT 安全（`configure()` 一次分配、per-cycle 零分配零 syscall），相位计时应**扩展它**，而不是再写第二个记录器——否则两套时间基准不可比，且违反“单一真源”。
4. **每个退出路径都必须收尾**。`update()` 有 7 个提前 `return`，相位计时必须由 RAII 保证 `end()` 一定执行。

## 2. 计时点清单

相位编号固定写入 CSV 列名，便于跨轮比较。**P0 与 P7 已由现有 `begin()`/`end()` 提供，本轮只需补 P1–P6。**

| 相位 | 起止边界（代码位置） | 测量目的 | 归因于 |
|---|---|---|---|
| **P0** 周期起点 | `begin()`（`:690`） | `cycle_us` 总时长、`interval_us` 间隔 | 已有 |
| **P1** 状态读取 | `readState()` 返回（`:691` → `:1019`） | 12 个 state interface 拷贝的代价；是否出现非有限值 | 本项目 |
| **P2** 命令分派 | `applyPendingStart()` + hold drain（`:714-760`） | 原子 CAS/exchange 与轨迹锁存的代价；**drain 是否在预算内** | 本项目 |
| **P3** 安全检查 | `collision_->distance` + `health_.evaluate` + E8（`:790-841`） | 三层安全判据的合并代价；`collision_` 是否内含锁/缓存重建 | 混合（`dual_arm_collision`） |
| **P4** 任务与求解 | `transport_->step()`（`:858`）**或** IDLE 的 `qp_->solve()`（`:894`） | 行装配 + QP 的合计代价 | 混合（本类 + `dual_arm_object_task` + `dual_arm_qp_core` + OSQP） |
| **P5** 命令写出 | `clampToLimits` + `writeCommand`（`:864-867` / `:907-908`） | 12 个 command interface 写入的代价 | 本项目 |

| **P7** 周期终点 | `end()`（RAII） | `cycle_us` 收尾、样本落盘 | 已有 |

补充约定：
- **P4 内部的“行装配 vs QP 求解”本轮不拆**。现有 `DualArmQpResult.solve_time_ms` 已能给出 QP 份额（10 项浮点，`solve_us` 列已在用），因此 P4 − `solve_us` 就是行装配+advance 的近似；要精确拆必须在 `TransportTask` 内埋点 ⇒ 需改接口 ⇒ 列入 §7.2 待审批。
- **IDLE 与 transport 两条分支共用 P4/P5/P6 编号**，CSV 增一列 `branch`（`0=idle`、`1=transport`、`2=early_exit`），否则两条路径的 P4 会被混在一起统计。
- **提前返回的归属**：7 个提前 `return`（`:799/816/841/856/883/902` 与 T-H17 的 `:709`）都在 `publishStatus()`/`writeCommand()` 之后或注入点处；这些样本的 P5/P6 允许为 0，但必须 `branch=2` 并记录 `exit_code`，不得直接丢弃（否则会系统性地剔掉最慢的周期）。

## 3. 单调时钟与 RT 安全记录机制

### 3.1 时钟

- 唯一时间源：`clock_gettime(CLOCK_MONOTONIC)`（当前 `nowNs()` 的实现，`dual_arm_qp_controller.hpp:104-113`）。
- **不使用** `rclcpp::Time`（可被仿真时间 / `use_sim_time` 改变）、**不使用** `gettimeofday`（可被 NTP 阶跃）。
- 已有 `interval_us` 用 `t_begin - t_prev_begin` 计算，并带 `have_prev_ && t_begin > t_prev_begin` 守卫（`timing_recorder.cpp:62-65`），对时钟回退安全——相位差沿用同一守卫。

### 3.2 数据结构（扩展现有 `TimingRecorder`）

```cpp
static constexpr int kPhases = 6;     // P1..P6
std::vector<float> phase_us_[kPhases]; // 与 wall_ns_ 同长度，configure() 一次性分配
float phase_acc_[kPhases];             // 当前周期累计（不参与落盘）
uint64_t t_mark_ns_;                   // 最近一次 mark()
```

- **容量**：与 `capacity_` 同（默认 `timing_capacity=8000`，见 `config/c43_s4_realtime_params.yaml`），按 8 ms 周期 ≈ 64 s；超出即 `dropped`（沿用现有 `capacity_` 语义）。
- **溢出处理**：`n >= capacity_` 时**不扩不覆盖**，仅 `++dropped`（现有行为 `timing_recorder.cpp:68`），并且只统计前 `capacity_` 个样本——即“多次运行拼接”由外部脚本负责，控制器绝不 realloc。
- **精度**：`float` 存微秒，8 ms 量级下有效位约 0.5 µs，足够区分相位；聚合（`summarize()`）用 `double` 重算分位数，避免浮点累加误差。
- **单次写入**：`mark()` 只做 `t_mark_ns_ = nowNs(); phase_acc_[i] += ns→us`；`end()` 里一次性把 6 个 `phase_acc_` 写进当前样本槽并把 `phase_acc_` 清零。⇒ 每相位 1 次 `clock_gettime` + 1 次 `float` 累加，**不触碰缓存行之外的内存**。

### 3.3 非 RT 数据导出

- 现有 `~/timing_dump`（`std_srvs/Trigger`，`onTimingDump` `:619`，executor 线程）继续用：`dumpCsv(timing_csv_path_)`。
- CSV 新增列：`branch,exit_code,p1_read_us,p2_dispatch_us,p3_safety_us,p4_task_solve_us,p5_write_us,p6_publish_us`。
- **导出期间 RT 侧只读**：`count_` 是 release-store（`timing_recorder.cpp` 已有），dump 只读 `[0, n)` 的已完成样本 ⇒ dump 不会看到半样本，也不会阻塞 RT。
- 落盘在 executor 线程，`fprintf` 不在 RT 内发生。

## 4. 测量开销控制与 ON/OFF 对照

### 4.1 开销预算

| 操作 | 估计代价 | 每周期次数 |
|---|---|---|
| `clock_gettime(MONOTONIC)`（vDSO） | 20–30 ns | 6（P1–P6）+ 2 已有 |
| `float` 累加 + 清 | < 5 ns | 6 |
| `end()` 写 6 个槽位 | ~50 ns | 1 |
| **合计** | **≈ 350–450 ns** | 相对 8 ms 周期 ≈ **0.004–0.006%** |

理论上可忽略，但**必须实测**（“理论上很小”不是证据）。

### 4.2 ON/OFF 与相位开关的三态对照

不新增构建选项，改用**运行时参数** `timing_phases`（`0` = 关；`0x3F` = 全开）：

| 轮次 | `timing_enable` | `timing_phases` | 目的 |
|---|---|---|---|
| A（基准） | `false` | — | 无记录器的基准 `cycle_us`（外部用 `/proc` 或 `ros2 topic` 观测不足，故 A 轮只作为“控制器无额外分支”的对照） |
| B（仅总量） | `true` | `0` | 只有 P0/P7：分离“记录器本身”的开销 |
| C（全相位） | `true` | `0x3F` | 全量相位：C − B = 6 个 mark 的净开销 |

判据：`|p99(C) − p99(B)| ≤ 100 µs`（≈ 记录器总开销上限 2 倍余量）；若超出，先怀疑 `mark()` 实现而非采样噪声（因为 350 ns × 638 周期不可能聚成 100 µs）。

### 4.3 扰动隔离

- 每轮 638 周期、独立进程、`timing_csv_path` 指向 `/tmp`。
- 三轮交替跑 2 次（B、C、B、C），用轮间差异估计噪声底，避免单次结果。

## 5. 阻塞 / 锁争用 / 超预算的验证方法与判据

### 5.1 阻塞与锁争用的观测手段

| 嫌疑点 | 观测方式 | 说明 |
|---|---|---|
| `publishStatus` 的 `trylock` 失败 | 统计 `branch=1/2` 样本中 `P6 == 0` 的比例，并新增计数器 `publish_trylock_miss_` 放入 `summary`；P6 的 p99.9 与 max | `trylock` 失败是**丢拍**而非阻塞，但会让状态延迟一个抽稀周期（≈104 ms），是 T-H6/T-H7 的输入 |
| `collision_->distance` 内锁/缓存重建 | P3 的 max 与 p99.9；对照“无碰撞几何变化”时是否出现离群 | 若 max 周期性出现，怀疑 FCL broadphase 重建 |
| OSQP 求解阻塞 | 已有 `solve_us` 与 P4 的差；`solve_fail_streak`、`iterations` 分布 | 第三方内核不在本项目控制内，只做归因 |
| 调度唤醒延迟 | `interval_us`（已有） | **不可归因到相位**，见 §7.1 |
| 超预算 | `cycle_us > period_us` 的计数（已有 `overruns`） | 注意：`update_rate == 125 Hz` 使标称周期**等于** `dt`，任何正抖动都越线 ⇒ 该判据按构造不可达，S4-T2 已登记为 `SPEC_GAP`，本轮不重复主张 |

| C2 | `p99(C) − p99(B) ≤ 100 µs` | PASS/FAIL |

## 6. `C43_ENABLE_TEST_HOOKS` 隔离与恢复 OFF

### 6.1 隔离原则

- 相位计时**不是**测试 hook：它由运行时参数 `timing_enable`/`timing_phases` 控制，与 `C43_ENABLE_TEST_HOOKS` 正交。
- 唯一需要 `#ifdef` 的地方是 T-H17 的注入点（已存在），本设计不新增。
- ON 构建下相位计时同样默认关闭；OFF 构建下相位代码仍存在但零开销（`timing_enable=false` 时 `mark()` 不被调用，因为 `TimingScope`/相位块由 `if (timing_.enabled())` 守卫）。
- 若实施时发现必须在 `#ifdef` 内才能零开销，需**单独审批**（授权令禁止新增 hook）。

## 7. 不可观测部分、实现风险、需单独审批的范围

### 7.1 不可观测（本设计明确不声称覆盖）

1. `update()` **之前**的调度唤醒延迟（`ros2_control` 主循环、内核唤醒、CPU 迁移）——只能由 `interval_us` 间接反映。
2. `update()` **之后**到执行器真正生效的时间（mock 台架是位置接口，无时间戳语义）。
3. 系统调用内部行为（`writeCommand` 只写内存；若将来走真实驱动的 IO，需重新设计）。
4. 第三方库内部细分（OSQP polish、FCL broadphase）——只能从 P3/P4 的离群值推断，不能分解。
5. 相位内的**内存分配**：计时只测时间，不测分配。T-H13（分配/阻塞探针）与 S4-T2 的分配口径是**两件不同的事**，不得互相替代。
6. 真实 CPU 竞争（同机其他进程）——WSL2 无 CPU 隔离，已登记 `BLOCKED_EXTERNAL_ENV`。

### 7.2 需要单独审批的修改（本轮不做）

| 编号 | 内容 | 为什么要单独批 |
|---|---|---|
| A1 | 在 `TransportTask::step()` 内埋点，把 P4 拆成「行装配 / QP / advance」 | 需要改 `transport_task.hpp` 接口或在类内加成员 ⇒ 触碰已验收的 S4.1 组件 |

### 7.3 实现风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| R1 相位自我重叠 | 提前返回路径漏掉 `end()` 或漏 `mark()` ⇒ C3 失败 | 用 RAII `PhaseScope` 串联，按进入顺序 mark；C3 逐样本校验 |
| R2 CSV 列变更破坏产物测试 | `test_artifacts` 的列名/列数断言会失败 | 实施时同步更新 schema 与断言（属测试改动，需在实施授权内） |
| R3 `float` 精度不足 | 若某相位 < 1 µs，`float` 累加会丢有效位 | 聚合用 `double`；单样本保留 `float`；必要时改 `double`（容量 ×2 内存，8 列 × 8000 × 8 B ≈ 512 KB，可接受） |
| R4 记录器容量不足 | 长跑（> 64 s）会 `dropped` | 已知行为；需要长跑时提高 `timing_capacity`（运行时参数，非重建） |
| R5 观测本身改变调度 | 6 次 `clock_gettime` 虽小，但可能改变 cache 命中 | 用 §4.2 的 B/C 对照量化，而不是假设 |
