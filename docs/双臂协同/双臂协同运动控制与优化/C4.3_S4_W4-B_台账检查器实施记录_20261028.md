## 2. 关键设计：必需集合不来自被检查的 YAML

B1 第 4 条要求"必需项目集合不能只从当前 YAML 本身推导"。实现方式：

1. 权威集合写在检查器内的 `REQUIRED_METRICS`（22 个用例 × 26 个指标，逐条注释对应冻结 §7 的"量化指标"列）。
2. 运行时解析冻结规划 §7 表格（`^\|\s*\*\*S4-T\d+\*\*\s*\|`），确认权威集合的每个编号在规划中存在，且规划中的编号都在权威集合中；不一致 → `REQUIREMENTS_DRIFT`（非零退出）。
3. YAML 顶层 `required_test_ids` 只作为**被检查字段**：与权威集合不一致即报 `REQUIRED_IDS_DRIFT`，不用它决定检查范围。

因此"删掉台账里的一条"不会被忽略，而会先被权威集合发现。

## 3. 检查项与退出码

| 退出码 | 含义 | 触发示例 |
|---|---|---|
| 0 | `LEDGER_OK`：结构合规、覆盖完整 | 正常台账 |
| 2 | `INPUT_ERROR`：文件缺失/YAML 不可解析/关键结构类型非法/冻结规划不可用 | 台账不存在、`entries` 非列表、规划缺失 |
| 3 | `LEDGER_RULE_ERROR`：覆盖或规则违规 | 缺必需用例/指标、重复、批准无来源、状态越权、历史 FAIL 丢失 |

规则清单（`check_ledger`）：

- 字段齐全：条目 8 项、指标 9 项；
- 受控词表：`threshold_status` / `software_state` / `evidence_state` / `gate_state`；
- `[待标定]` ⇔ `PENDING_CALIBRATION`；
- `APPROVED` 必须有非空 `source`；
- `PASS` 必须有 `evidence_ref`，且 **不得**出现在 `gate_state ∈ {HOLD, BLOCKED_EXTERNAL_ENV}` 的条目上；
- 同一测试内 `metric` 键唯一（允许一测多指标）；
- `test_id` 全局唯一；
- 权威覆盖：22 用例 × 26 指标逐项存在；
- `required_test_ids` 与权威集合一致；
- `supplementary.historical_failures` 必须存在且至少一条保持 `FAIL`（W2-C3 的 `7656/7656`）；
- `ledger_state.acceptance_pass_claimed` 不得为 true。

输出永远包含两行显式标记，防止把"结构检查通过"读成验收通过：

```
VERDICT: LEDGER_OK — structure/coverage only; this is NOT an S4.1 acceptance PASS
ACCEPTANCE_PASS_CLAIMED: false
GATE_STATUS_CHANGED: false
```
