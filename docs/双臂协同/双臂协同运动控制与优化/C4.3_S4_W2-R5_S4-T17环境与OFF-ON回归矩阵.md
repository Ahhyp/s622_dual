## 3. OFF / ON 构建与回归矩阵

| 配置 | 构建基座 | 安装布局 | 库路径 | 钩子符号 | 结果 | 耗时 |
|---|---|---|---|---|---|---|
| **OFF**（生产） | `build/` + `install/`（merge） | 平铺 `install/lib/` | `install/lib/libdual_arm_qp_controller.so` | **0** | **8/8 测试、35 用例、0 失败** | 72.05 s |
| **ON**（钩子） | `/tmp/w2r4_on/{build,install}`（独立） | 非 merge，`<pkg>/lib/` | `/tmp/w2r4_on/install/dual_arm_qp_controller/lib/…` | **1** | **8/8 测试、35 用例、0 失败** | 69.36 s |

### 3.1 加载路径校验（本轮强制步骤）

```
ldd build/dual_arm_qp_controller/test_mock_closure          -> install/lib/libdual_arm_qp_controller.so        (OFF)
ldd build/dual_arm_qp_controller/test_realtime_budget       -> install/lib/libdual_arm_qp_controller.so        (OFF)
ldd build/dual_arm_qp_controller/test_frozen_baseline_compat-> install/lib/libdual_arm_qp_controller.so        (OFF)
ldd build/dual_arm_qp_controller/test_mock_closure (ON 会话) -> /tmp/w2r4_on/install/dual_arm_qp_controller/lib/…  (ON)
strings <loaded lib> | grep -c test_force_deadline_fault_cycles  = 0 / 1
```

> **踩坑记录**：非 merge 安装的库在 `<pkg>/lib/`，若 `LD_LIBRARY_PATH` 指向 `install/lib`（空目录），测试会**静默加载主安装的 OFF 库**并全绿 —— 这正是 R4 发现的问题。本轮每次回归前都用 `ldd` + `strings` 双重确认。

### 3.2 ctest 产物判读陷阱

`build/dual_arm_qp_controller/Testing/Temporary/LastTestsFailed.log` 可能是**上一次失败运行的残留**（其 mtime 19:08:04 属于更早的日期），本次 ON 运行的 `LastTest.log`（mtime 15:06:22）显示 `Test Passed` × 8、`Test Failed` × 0。
⇒ 判读必须以 `LastTest.log` 的当次结果为准，不能只看 `LastTestsFailed.log` 是否存在。
