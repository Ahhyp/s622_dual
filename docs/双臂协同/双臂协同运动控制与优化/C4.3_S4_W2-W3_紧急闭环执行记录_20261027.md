### 1.3 C3 根因（不可满足性证据，本轮再次确认）

| 观测量 | 值 |
|---|---|
| 与冻结 S3 fixture 的 max \|Δdq\| | **9.024e-14 rad**（cycle 0 joint 6） |
| > 1 ULP 的对数 | **7 656 / 7 656（100 %）** |
| 仅换时钟（累积 vs `k*dt`） | 7.18e-16 rad |
| 仅换 warm start（开/关） | **0**（7 656/7 656 逐位相同） |
| 仅换工作区复用（常驻 vs 每周期新建） | 5.27e-16 rad |
| 近零 dq 对（\|dq\|<1e-9 双侧） | 570（7.45 %） |

机制：`≤1 ULP` 是**相对**判据。两套独立 harness 的输入只能对齐到 ~1e-16，而 QP 在"不要动"（dq≈1e-13）附近的解会把 1e-16 的输入差放大到 ~1e-14；在 1e-12 量级的条目上，1 ULP ≈ 1.6e-28，于是同一点会报出 1e10 以上的 ULP。要满足原判据必须让 S4 与 S3 的 QP 装配**逐操作位相同**——那是重写 S4 的装配路径，属产品语义变更，不是本工作包授权范围内的修复。

**结论：C3 不是"还没修好的 bug"，而是"按字面无法满足的验收判据"。** 本轮不降低判据、不把它写成 PASS。

### 1.4 本轮对 W2 的实际代码修复

接受的缺陷：**验收测试在判据失败的情况下仍然显示绿色**——`test_mock_closure.cpp:269` 用 `1e-12` 断言（比 1 ULP 宽约 1.1e6 倍），而冻结判据是 ≤1 ULP；ULP 结论只出现在 `printf` 里，任何 CI 都看不见。

修复（`src/dual_arm_qp_controller/test/test_mock_closure.cpp`）：

1. 新增 `long pairs_over_1ulp` 计数器，在每对 `(cycle, joint)` 上按项目自己的 `ulpDistance()` 统计；
2. 验收行打印 `S4-T2: CONTRACT criterion (<=1 ULP, C4.3_S4_执行规划.md:533): FAIL (7656/7656 …)`；
3. 新增 `EXPECT_GT(pairs_over_1ulp, 0)`：**把"判据当前不满足"变成机器可检的断言**。若将来真的修好，这条断言会失败并强制更新契约记录，而不是让替代阈值继续假绿。

