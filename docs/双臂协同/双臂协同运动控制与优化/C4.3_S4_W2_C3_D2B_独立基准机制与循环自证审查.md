# D2-B 独立基准机制与「循环自证」审查

> 目的：回答"同构建冻结基准是否自我循环论证"，并给出**不依赖被测二进制**的独立数值正确性证据。
> 本轮**未修改任何判据、未重新冻结 fixture**；`test/fixtures/s3_ff_1_dq.csv` 保持原样，
> 原跨构建 `≤1 ULP` 的 **FAIL 证据完整保留**（`C3_ULP超限归因.md` §1–§7，7656/7656 超限）。

## 1. 循环自证风险：真实存在，且必须承认边界

同构建冻结的做法是"用构建 B 的输出做基线，再用构建 B 去比对"。它**不能**证明：

| 不能证明的事 | 举例 |
|---|---|
| 冻结时刻已存在的错误 | 若装配把 `e` 的符号写反，冻结后仍然 0 ULP 通过 |
| 物理正确性 | 0 ULP 只说明"和上一次一样"，不说明"对" |
| 求解精度 | 只要求解器确定性不变，精度退化也会被冻结进基线 |

因此 D2-B **只能**被定义为**回归判据**（"行为未漂移"，检测装配/求解器/配置的任何改动），
**不能**被表述为"数值正确性证明"。任何把它写成 `PASS = 数值正确` 的表述都应被否决。

## 2. 消除循环依赖的四条独立证据链（本轮实测）

| # | 证据链 | 与被测对象的关系 | 本轮结果 |
|---|---|---|---|
| O1 | **跨求解器交叉验证**：同一装配下用 `AdmmSolver`（完全不同的算法）重解 638 个 QP | 只共享装配代码，不共享求解路径 | `dq` 最大绝对差 **3.766e-08**（cycle 142, joint 8），7656 对中 171 对 > 1e-8；cycle 0 两解的零空间噪声分别为 1e-14 量级但**互不相同**（如 joint 1：OSQP `1.205e-14` vs ADMM `4.797e-15`） |
| O2 | **装配逐位精确性**（既有 S4-T3）：`test_object_row_wiring.cpp:190` `EXPECT_EQ(worst_dq, 0.0)` | 与冻结基线无关，对手算行做**精确**比较 | 通过（`== 0`，不是容差） |
| O3 | **物理不变量**：关节限位、`|dq| ≤ v_max·dt`、commit/veto 决策、终点 `e_obj` | 由任务语义定义，非基线定义 | 638/638 决策一致；终点 `e_obj = 2.97e-8 m`（S3：`3.54e-8 m`） |
| O4 | **重建可复现**：同一源码在**另一套构建配方**（隔离 `-O3`）下重建 | 独立于 colcon 构建 | 与 `install/lib` 构建的 `dq` **逐位相同**（md5 `787ee417…`）；隔离重建两次 `.so` sha256 相同（`42066056f6dc33d3…`） |

O1 是本轮新增的关键证据：**两个不同算法对同一装配的解只到 1e-8 量级一致**，这直接说明
"1 ULP 输出等价"对这类问题没有工程含义；而 O1+O2+O3 共同覆盖了"装配错/语义错/精度退化"三类风险，
O4 覆盖了"构建不可复现"风险。D2-B 剩下的不可覆盖项只有"冻结时刻已存在的、且不被 O1–O3 捕捉的错误"。

## 3. fixture 生成 / 冻结 / 复验协议（提案，待批准后执行）

```
1) 生成者必须来自干净检出，不能是开发树
   git worktree add /tmp/c43s4_fixture_gen <TAG 或 commit>
2) 独立构建前缀（不污染 install/）
   colcon build --merge-install --symlink-install \
     --packages-select dual_arm_qp_controller dual_arm_qp_core dual_arm_object_task \
     --build-base /tmp/c43s4_fixture_gen/build --install-base /tmp/c43s4_fixture_gen/install \
     --cmake-args "-DPython3_EXECUTABLE=$(which python3)"
3) 逐行落盘（与现有 fixture 同列：k,t,q_prev0..11,dq0..11,e_obj_pos_m,e_obj_rot_rad,committed）
   生成器 = src/dual_arm_qp_controller/test/generate_s3_fixture.cpp（新增，见 §4）
4) 生成两次 → 必须**逐字节相同**（sha256 相等）；否则拒绝冻结
5) 复验：对新 fixture 跑 638 周期，要求 0 ULP；同时跑 O1（ADMM 交叉）与 O3（不变量）
6) PROVENANCE.txt **追加**一段（旧段保留）：
   generator commit / build recipe / generator binary sha256 / fixture sha256 / 生成日期 / 复验命令
7) 任何 qp_core 源或编译参数变更 ⇒ 必须重新冻结并重新走 4)–6)
```

## 4. 仍需补充的一个文件（未创建，属 D2-B 批准后的实施项）

`test/generate_s3_fixture.cpp`：把 §3 的生成逻辑固化成可重复的二进制（读 `c43_s4_transport.yaml`，
按 638 周期逐步 `task.step()` 并写 CSV）。本轮**没有**创建它，因为一旦提交它就意味着冻结基准的
来源发生变更——那正是 D2-B 要批准的事情。审批通过后的实现工作量：约 80 行 + 1 个 CMake 目标。

## 5. 结论

| 问题 | 结论 |
|---|---|
| D2-B 是否循环自证？ | **部分是**：它对"冻结时刻已有缺陷"无辨识力，因此**只能当回归判据** |
| 是否有独立证据？ | 有，O1–O4 四条，且 O1 为本轮新增（跨算法 1e-8） |
| 原 FAIL 证据是否保留？ | 保留，未改动（`C3_ULP超限归因.md`，`7656/7656`） |
| 是否需要改验收语义？ | **是**（基准来源由"S3 历史运行"变为"本构建冻结"）⇒ `APPROVAL_REQUIRED`，本轮不签字 |
| 0–1 ULP 复现性 | 已验证：同源码两种构建配方 `dq` 逐位相同；同配方重建 `.so` sha256 相同 |

## 6. 独立 fixture 生成器：已实现并验证（本轮新增，**隔离工具，不进构建**）

§4 当时说"未创建"。本轮按要求实现了**独立于 QP 库**的生成器，用于证明"冻结 fixture 是从 S3 运行

| 产物 | 路径 | 说明 |

| 检查 | 结果 |
|---|---|
| 两次独立生成逐字节一致 | `fixture_a.csv == fixture_b.csv`（sha256 `6a0b876260a24808c61c067989460fa860e7f022dc3b060d10111ed50711d07c`） |

   两个事实并列，不得只留后者。
