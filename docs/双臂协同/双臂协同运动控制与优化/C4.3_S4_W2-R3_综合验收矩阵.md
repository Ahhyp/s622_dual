## 7. 原生 Linux 复测说明（任务5 交付：仅说明，不改标准）

**现状**：本轮在 WSL2（`6.18.54.1-microsoft-standard-WSL2`）+ AMD Ryzen 7 4800H 上获得的最大周期间隔为
15769 / 16009 / 16571 / 21291 µs（四组各 6380 周期），全部大于 12 ms；`ulimit -r = 0` 无法设 `SCHED_FIFO`，
无 `isolcpus`，`taskset` 绑核反而更差。因此 S4-T17 维持 `BLOCKED_EXTERNAL_ENV`，**标准不放宽、结论不外推**。

**原生 Linux 复测步骤（可复制）**

```bash
# 0) 内核侧（需 root，示例：把 CPU 2-7 留给实时、CPU 0-1 给系统）
#    GRUB_CMDLINE_LINUX 追加：  isolcpus=2-7 nohz_full=2-7 rcu_nocbs=2-7
#    update-grub && reboot
cat /proc/cmdline            # 确认 isolcpus 生效
chrt -f 1 true && echo "SCHED_FIFO 可用" || echo "SCHED_FIFO 不可用"

# 1) 授权实时优先级（非 root 运行）
sudo tee /etc/security/limits.d/99-realtime.conf >/dev/null <<'EOF'
*  -  rtprio      99
*  -  memlock     unlimited
EOF
# 重新登录后：ulimit -r 应 ≥ 1

# 2) 构建（与 WSL2 同一套命令，默认 OFF 构建）
colcon build --merge-install --symlink-install --packages-select dual_arm_qp_core dual_arm_qp_controller \
  --cmake-args "-DPython3_EXECUTABLE=$(which python3)"

# 3) 跑 S4-T2 / S4-T17，并把控制线程绑到隔离核
. install/setup.bash
taskset -c 4 ./build/dual_arm_qp_controller/test_realtime_budget \
  --gtest_filter='*S4T17*'

# 4) 原始数据（同 WSL2 的列序，便于逐列对比）
#    /tmp/c43s4_rt/timing_s4t17.csv   k,wall_ns,cycle_us,solve_us,interval_us
#    汇总行由测试打印：interval_max_us / overruns(>dt) / overruns(>1.5dt) / rss / fd
```

**判定（与规划一致，不因平台而变）**

| 指标 | 阈值 |
| --- | --- |
| `cycle_p99_us` | ≤ 6400（`[待标定]`） |
| `interval_max_us` | ≤ 12000（1.5·dt） |
| RSS 增长 | ≤ 1024 KB（`rebaseResources()` 之后） |
| fd 增长 | == 0 |
| 周期数 | 6380（`t_traj` 跑到 51.04 s） |

**目的**：把“WSL2 达不到”与“控制器做不到”区分开。只有在原生 Linux + `SCHED_FIFO` + 隔离核上复现出
`interval_max ≤ 12 ms`，S4-T17 才可判 PASS；在此之前任何平台的结果都不得替代。
