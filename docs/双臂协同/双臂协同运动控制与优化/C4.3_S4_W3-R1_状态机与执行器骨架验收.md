## 4. 接口与迁移表

**控制器侧（只读复用，未修改）**：`~/transport_status`（`TransportStatus`）、`~/start_transport`（`StartTransport`）、`~/abort_transport`（`AbortTransport`）、`~/resume_transport`（`Trigger`）、`~/reset_transport`（`Trigger`）、`~/heartbeat`（`Empty`）。

**执行器侧（本包）**：`~/start`、`~/abort`、`~/resume`、`~/reset`（均 `std_srvs/Trigger`）、`~/heartbeat`（`Empty`，100 ms）。

### 4.1 新增的五个契约缺口码（不是新增故障类别，而是 W1 契约没给执行器留的路）

| 码 | 触发 | 判定层 |
|---|---|---|
| `status_never_received` | 启动后 3 个周期仍无 `~/transport_status` | 执行器 |
| `status_unparseable` | 状态帧不可解析 | 执行器 |
| `hold_invariant_violated` | HOLD 期间冻结不变量被控制器打破 | 执行器（**升级 FAULT**） |
| `phase_timeout` | 单相位超 `phase_timeout_s` | 执行器 |
| `abort_requested` | 操作员 `~/abort` | 执行器 |

## 5. 偏差：执行器无法"冻结控制器轨迹"（T05）

W1 的 `TransportTask` 只暴露 `hold(code)`/`resume`/`abort`，**HOLD 冻结的是 `t_traj` 与 `q_cmd_`**，也就是说控制器一旦进入 HOLD 就不再前进——这一点是满足的。
缺的是**反方向**：执行器判定"该协同 HOLD"时，除了 `~/abort_transport` 没有别的通道让控制器停下来（没有 `~/hold_transport` 服务、`TransportStatus` 也无 "hold request" 字段）。
本轮处置（**不扩接口、不改控制器**）：
1. 执行器自身立即 `HOLD`（不再下发相位推进、冻结快照）；
2. 对控制器只做**观测**（继续读状态、继续心跳）；
3. 若控制器在 HOLD 期间继续前进 → `hold_invariant_violated` → `FAULT`（`T04` 覆盖）；
4. 超时兜底用 `~/abort_transport`（单向、终止性，不会与 resume 冲突）。

**这是 W3-R1 的已知能力缺口**，已登记为待裁决项（见门禁矩阵 P0-3）。补法是"加一个 `HoldTransport.srv` 或在 `TransportStatus` 加 `hold_requested` 字段"，两者都属于**改 W1 契约**，需单独批准。

## 8. 环境问题与代码缺陷（分开记）

**环境（不是代码缺陷）**
1. `ROS_LOG_DIR` 必须可写：默认 `~/.ros/log` 在本沙箱不可创建，节点会 `Aborted`（`Failed to create log directory`）。
2. `RTPS_TRANSPORT_SHM ... Permission denied`：共享内存段受限，回落到 UDP，功能不受影响。
3. 本机仍为 WSL2（`W2` 的 `S4-T17` 依旧 `BLOCKED_EXTERNAL_ENV`，本轮未改）。

**代码缺陷（本轮已修）**
1. `package.xml` 里 `<depend>` 等**不接受 `condition` 属性**（`colcon build --packages-select` 不报，`--packages-up-to` 才暴露）→ 已全部移除。
2. `rosidl_get_typesupport_target` 对**外部包**返回空 → 改为直接链 `dual_arm_qp_controller::dual_arm_qp_controller_lib`。
3. `toString(State)` 与 `toString(Protection)` 签名冲突（同参数类型不同返回枚举）→ 合并为 `protectionName`。
4. 事件 `now` 参数遮蔽成员函数 `now()` → 改 `nowSeconds()`。
5. `Clock::now()` 在 `const` 成员里不可调用 → `process()` 改非 const。
6. **`_core` 库缺 `install(TARGETS)`/`ament_export_targets`** → 安装后 `install/lib/libdual_arm_transport_executor_core.so` 不存在（`ldd` 直接报错才发现）→ 已补。
7. `precheck.cpp` 初稿误留 `st.trace_active_guard()` → 改为真正的 `st.transport_active`。

**测试自身缺陷（由测试跑出来，已修，属"发现"而非"放水"）**
1. `start()` 复核用的是**缓存的上一帧状态**，所以替身改了状态却不 `tick` 时，前置检查看到的是旧值 → 用例补 `tick`/`sync`。这同时说明：**执行器的决策永远基于"已观测到的"状态**，这是设计而非缺陷，但必须在文档里说清。
2. `T05` 的"回到被中断状态"原本写成 `Grasp`，实际被中断在 `Approach` → 断言改正。
3. `T07` 的"状态过期"用例让替身刷新了自己的时间戳 → `stale_state` 永不触发 → 改为直接 `sm.tick()`（不刷新替身）。
