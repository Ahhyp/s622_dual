## 2. 三个池的特征差异（这是刻意设计的，不是冗余）

| 池 | 构造 | S0 左半 | S0 右半 | 说明 |
|---|---|---|---|---|
| **P1a** | `p_O = FK(q_L)·(^G_L T_O)`，用 C4.1 样本**自己的 `q_L`** | **98.67%** | 55.7% | 左臂**可证**能摆出该物位姿；S0 被右半过滤 |
| **P1b** | C4.1 样本记录的两 TCP 中点 | 93.0% | 94.6% | 空间先验，不绑定具体 `q_L` |
| **P3** | CRW bbox 内 3 cm 均匀网格，**不按掩码过滤** | 37.3% | 37.8% | 覆盖性对照 |

**P1a 的 S0 左半 = 98.67%** 被写成自检：它必须≈100%（因为 `p_L` 就是 C4.1 采样过的点），
差的那 1.3% 来自我这套 C++ 体素原点与 C4.1 Python 侧 bbox 定义的微小差异 ——
**这条自检的价值是把"掩码读对了"和"FK 池造对了"一次性验证掉。**

P1b 的 S0 明显高于 P1a，P3 只有 13.3% —— 说明**CRW 的外接盒里绝大部分不是点可达的**，
这正好解释了为什么必须有 P3 作对照（否则会以为"共同可达空间"是个实心块）。

## 3. ★ 关键发现：S4 的"臂间净空"在 V0 下几乎没有区分度

S4 解的跨臂净空分布**几乎是一个常数**：

```
P1 = 27.2 mm   P5..P95 = 33.7 mm   max = 33.7 mm   min = 0.1 mm
< 30 mm 的只占 1.4%
```

按最近 link 对拆开后原因清楚了：

| 最近跨臂对 | 占 S4 | 距离范围 |
|---|---|---|
| **`right_finger1 ↔ left_finger1`** | **97.72%** | **33.6 – 33.7 mm（几乎恒定）** |
| `right_forearm_link ↔ left_wrist3_link` | 1.08% | 22.1 – 30.8 mm |
| `right_wrist3_link ↔ left_upperarm_link` | 0.33% | **4.9 – 16.6 mm** |
| 其余臂杆对 | ~0.9% | 最紧 **1.1 mm** |

**原因**：刚性抓握模型固定了 `T_rel`，**两只爪的相对位姿是常数** ——
所以"爪-爪"距离**被几何锁死**，完全不携带候选的信息。
只有 2.3% 的候选是**臂杆之间**更近，而**紧的恰好就是这些**（最紧 0.1 mm）。

**这条对 S4 的设计有直接后果**：

- J4（臂间净空）在 V0 下**不是一个细粒度判别项**，而是一个**几乎恒定的地板**，
  外加对少数危险姿态的惩罚；
- 要让它有梯度，必须**显式区分**"被锁死的爪-爪距离"与"随构型变化的臂-臂距离"，
  否则优化器在 97.7% 的解上看到的是同一个数；
- **S4 是二值的（碰/不碰），而净空的长尾一直延伸到 0.1 mm** ——
  这正是必须保留连续净空指标、不能只报 S4 通过率的原因。

## 4. 其余发现

1. **S2 / S0 ≈ 29%**：点可达里只有不到三成是"双臂都能以指定姿态抓到"。
   点可达 ≠ 位姿可达，这条第一次有了数字（额外要求 1 的量化）。
2. **右臂比左臂更容易满足姿态**（68.2% vs 39.2%）。
   两个目标姿态在 V0 下都是固定的，差异来自几何：左臂必须把爪摆成"举着杆"的朝向。
3. **S4/S3 ≈ 97.7%**：碰撞只砍掉 2.25%。也就是说**约束的瓶颈在 IK/选择器的硬过滤，
   不在碰撞**（拒绝归因里 `sigma`（可操作度）、`wrist_fold`、`low_arm_height` 是大头）。
4. **S4 的物心可行区**只有 x∈[−0.20, 0.39]、y∈[−0.47, 0.52]、z∈[0.055, 0.42]，
   比 CRW bbox 小得多 —— 这是 C4.2 后续优化的真实搜索空间。

## 5. S3 的"结构性恒等"，以及为什么它仍然值得固化

规划把 S3 定义为 `S2 ∧ ‖log(T_rel^{-1}·T_rel^des)‖ ≤ ε_rel`。
在本阶段采用的**刚性抓握模型**下：

```
T_R^des = T_L^des · T_rel^B          （T_rel 由两侧抓握几何固定）
⇒ FK(q_L)^{-1} FK(q_R) 与 T_rel^B 的偏差 = 纯 IK 残差
```

所以 **|S3|/|S2| 恒为 100%**，且 H4 残差 ~1e-10。

处理方式（不是掩盖，而是固化成可检验的事实）：

- 三个池全部实测 **S3 == S2**，写成 CLI 自检；
- 单测 `C42Feasibility.S3ResidualCarriesOnlyTheIkError` 断言残差 < 1e-9，
  `RelativeGraspIsInvariantUnderPureTranslation` 断言纯平移下 `T_rel` 不变；
- `summary.json` 里写明 `s3_is_structural: true` 与原因。

**S3 真正会开始咬人是在 V1/V2**：一旦物体姿态被扰动、或放开抓握点，
`T_rel` 就不再是常数，H4 才会成为有效约束。本阶段如实标注，不假装它做了事。

### 顺带修掉的一个建模陷阱

规划早期把"右爪目标"写成"固定 `receive_quat` + 世界轴偏移"（**模型 A**，M4 BT 的字面做法），
但那只在标称姿态下成立。本阶段改用**刚性抓握（模型 B）**：
`T_R = T_L · T_rel^B`。两者在标称位姿与 V0 下**完全一致**，
但一旦扰动姿态，模型 A 会**静默破坏刚性抓握**。已在 `feasibility.hpp` 头部写明取舍。

## 6b. 后续修正（2026-10-14，S5 期间发现）

S3 当时的嵌套自检是**计数比较**（`s4 <= s3 && s3 <= s2 && s2 <= s0`），
这**不等价于**逐候选的 `S4⇒S3⇒S2⇒S1`。S5 检查候选表时发现 `S4 but not S0` 有 171 个，
才把这个弱点暴露出来。

**已改成逐候选检查并重跑**：

```
per-candidate nesting S4 => S3 => S2 => (S1_L and S1_R); violations = 0 / 233,288   PASS
S4 but outside S0 (proxy): 171   <- C4.1 采样覆盖缺口，不是嵌套违反
```

即：规划要求的 `S4⊆S3⊆S2⊆S1` **现在是被真正验证的**；
而 `S4 ∖ S0` 的 0.6% 是 **S0 作为采样代理的覆盖缺口**（IK 比掩码更强），已单独量化。

## 7. S3 的边界

1. **未做"可到达"验证**：S4 是**静态可行**，不宣称"能从当前构型无碰撞到达"。
   这条已在规划里分离（S5 标记），做法仍是待决项（`isSegmentValid` vs 真规划器）。
2. **S3 恒等**（见 §5），其内容推迟到 V1/V2。
3. **V0 姿态固定**：仅优化物心位置，姿态 = M4 标称姿态。
4. **Q1–Q4 未确认**，物体是参数化盒、基线是 `provisional_rebuilt`，
   结论不得宣称适用于真实 M4 杆。
5. **候选池是采样/网格，非连续**：漏斗比率依赖池的选取，三个池的差异（§2）已如实给出。
