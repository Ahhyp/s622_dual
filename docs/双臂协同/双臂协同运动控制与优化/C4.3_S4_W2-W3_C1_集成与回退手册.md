## 6. ABI 兼容性证据的真实覆盖范围

**已被实测证明：**

1. `sizeof(QpSolution)` = 48、`alignof` = 8、`offsetof(x/converged/iterations)` = 0/16/20 **全部不变**；
   `sizeof(QpProblem)` = 112 不变。
2. 动态符号 **133 → 143**：新增 10 个（两个 `solveInto` + 8 个 Eigen/析构模板实例），**移除 0 个**。
3. `solveInto` 在基类有默认实现（委托 `solve`），因此"只实现 `solve` 的既有子类"仍然可链接、可调用。
4. **旧二进制 + 新库**：用基线库链接出来的 driver，`LD_DEBUG` 确认加载的是候选 `libdual_arm_qp_core.so`，
   运行正常，`dq` 与基线**逐位相同**（md5 `23f6db1ad3d619ab3ee6e009a4ca6246`）。
5. 全仓重编清单：`dual_arm_qp_core`(11 目标) + `dual_arm_qp_controller`(11) + `dual_arm_transport_mock`(12) = **34**，
   其中 `gen_legacy_golden.cpp` 包含该头文件 ⇒ golden 需重生成比对。

**未被证明（不得当作已验证）：**

1. 未运行 `abi-compliance-checker` / `abi-dumper` 一类的正式 ABI 差分；上述结论来自符号表与结构体度量。
2. 未验证**仓库之外**的第三方 `QpSolver` 子类（`vtable` 末尾追加槽对该类安全，但本仓无样本可测）。
3. 未验证"旧头 + 新库"之外的混合配比（例如只用新头编译部分 TU、其余旧头且跨 `.so` 边界内联）；
   当前结论仅覆盖"旧二进制（旧头编译）+ 新库"。
4. 未做 32 位/其它 ABI（`-m32`、不同 `_GLIBCXX_USE_CXX11_ABI`）组合。
