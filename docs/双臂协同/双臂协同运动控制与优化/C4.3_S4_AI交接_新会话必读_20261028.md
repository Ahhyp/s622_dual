- **此刻的硬阻断**：QP 控制器从第一拍起就把 10–12 个关节压到速度上限（`v_max=2.5 rad/s`），

## 1. 这个项目是什么（最小地图）

六个关键包（其余是感知/视觉伺服的旧链路，本轮不碰）：

| 包 | 作用 |
|---|---|
| `dual_arm_qp_core` | QP 求解器（OSQP / ADMM），`QpProblem`/`QpSolution`，物体行装配 |
| `dual_arm_qp_controller` | 实时控制器：`update()` 每周期读状态→安全层→`TransportTask::step()`→写命令→发 `TransportStatus` |
| `dual_arm_transport_executor` | 执行器：状态机 `IDLE→APPROACH→GRASP→LIFT→TRANSPORT→LOWER→RELEASE→…`，HOLD/ABORT/FAULT 链、焊接、干跑 |
| `dual_arm_collision` | 臂-臂 capsule 距离（只有距离与梯度，没有环境/物体） |
| `gz_launch` | Gazebo world / 模型 / 组合 launch（`c43_s4_full_flow.launch.py`） |
| `dual_arm_transport_mock` | 无 Gazebo 的台架（S3 的冻结基线来源） |

数据流：控制器每 8 ms 发一条 `TransportStatus`（含 `phase_index/phase_name/t_traj/q_state/q_cmd/
active_limit_count/min_limit_margin_rad/…`）→ 执行器据此推进状态机 → 需要冻结时调
`~/hold_transport`（seq + ack 三字段回执）→ 需要终止时调 `~/abort_transport`。
焊接走 Gazebo 的 `DetachableJoint` 插件，ROS 侧由 `attach_client` 管（`/c43/attach`、`/c43/detach`、
`/c43/weld_state`）。

## 3. 正在进行、尚未完成的任务

### T1（P0，W7 的唯一硬阻断）：QP 为什么让 10–12 个关节持续满速

**现象**（`W7-B_集成实测_20261028/driver_limit_rule_20261028.log`）：14 s 的 5 相位轨迹，
`approach` 段 200 ms 内 `active_limit_count` 就是 10–12；同时 `min_limit_margin_rad ≈ 1.6 rad`，
说明离位置限位很远，**饱和的是速度上限**（`v_max × dt = 2.5 × 0.008 = 0.02 rad/周期`）。

**已经排除**：

- 不是物体锚定在世界原点——显式传 `start_world_t_object=[I|(0,0,0.275)]` 后现象不变；
- 不是探针 bug——`drive_probe.py` 曾因 `js_end` 自减恒为 0 误判「关节完全不动」，已重写并自测
  （静止 0.000 / 单关节 0.400 / 往返 0.200），实测关节真实位移 **2.30 rad**；
- 不是执行器规则——规则已按裁决改成「位置裕度 + 连续 25 拍」，实测第 26 拍才 HOLD（旧版第 1 拍）；
- 不是 `home_q` 错位——`c43_s4_qp_home_override.yaml` 已把 `home_q` 覆盖成生成位姿。

**下一步实验（按顺序，都不改语义）**：

1. 读 `src/dual_arm_qp_core/src/dual_arm_qp.cpp` 的目标构造：posture/relaxed 项、`kp_rel`、`w_rel`
   各占多少权重；打印单周期 `dq` 与各约束残差，看是哪一项在推。
2. 区分实验：把 `v_max` 减半再跑同一轨迹——若 `dq` 跟着减半，是「目标要这么大速度」；
   若 `dq` 不变（只是被限幅），是「限幅器/权重」问题。
3. 对比 mock 台架：`src/dual_arm_qp_controller/config/c43_s4_mock_params.yaml` 同一轨迹下
   `active_limit_count` 是多少。若 mock 正常而 Gazebo 满速，重点查状态反馈（`q_state` 是否有噪声/延迟）。

**验收**：一次 14 s 轨迹里 `active_limit_count` 大部分周期为 0，或至少不再让执行器 HOLD。

## 6. 会浪费你半天的坑

- 跑 gtest 必须 `source install/setup.bash` **且** `export LD_LIBRARY_PATH=$PWD/install/lib:$LD_LIBRARY_PATH`
  （**不能覆盖**，否则缺 `libfairino_planning_core.so`）。
- `pkill -f "c43_s4…"` 会匹配自己的 shell 并自杀；用 `kill -TERM $(pgrep -f "^ign gazebo" | head -1)`。
- Gazebo 插件日志默认被吞：launch 要 `-v 4`；`ros_gz_sim create -J` 对关节初值**无效**。
- URDF→SDF 会合并掉 `left_grasp_frame`：插件 `parent_link` 只能填 `left_wrist3_link`，
  `child_link` 必须写模型内名 `base_link`（不能写 `c43_sample::base_link`）。
- YAML 给 `ros__parameters` 追加键必须缩进 4 空格，否则执行器 `Failed to parse params file`。
- `hooks=ON` 必须在**独立 build/install** 里，且测试前 `source install_hooks_on/setup.bash`；
  否则 `ros2 launch` 仍加载 OFF 库，注入静默不触发（假失败）。
