## 5. 过程中的两个真实故障（已修复，记录以免复现）

1. **`ModuleNotFoundError: No module named 'em'`** —— 集成脚本首跑时未激活 conda 环境，`rosidl_generate_interfaces`
   找不到 `empy`，`dual_arm_qp_controller` 构建失败（日志 `/tmp/c43s4_c1_integration/build_core_controller.log`）。
   修复：脚本开头 `conda activate yolov8`，并在 `python3 -c "import em"` 失败时 **abort**（退出码 4）而不是带病构建。
   随后用 `--resume` 从第 2 步续跑（`--resume` 会核对四文件是否仍等于 `post_patch_sha256.txt`，不重复 apply）。
2. **首跑耗时 12 min 的 `transport_mock`**：与缺陷无关，是冷构建；`--resume` 会跳过已完成的包。

## 8. 构建内存安全（本机 OOM 事故，与本集成同因）

本机是 WSL2：**总内存 7.6 GiB、swap 2 GiB，却报 16 个 CPU** ⇒ colcon/make 默认 `-j16`。
实测单个 Eigen 重 TU（`dual_arm_qp.cpp`，`-O3`）峰值 RSS **1.16 GiB / 32 s CPU**，
16 路并发需求约 **18 GiB**。内核 OOM killer 按 RSS 选择受害者，取到的常驻大户是代理进程
（700 MB–1.3 GB），因此出现 "dsh 反复被 killed"：

```
13:37:51 Killed process 2235  (MainThread) anon-rss 1.29 GB
14:14:26 Killed process 23040 (MainThread) anon-rss 944 MB   (cc1plus 触发)
17:22:42 Killed process 8416  (MainThread) anon-rss 769 MB   (node 触发)
cgroup memory.peak = 7.47 GB
```

对策已固化为 `scripts/build_mem_safe.sh`：默认 `JOBS=2`，同时设置 `MAKEFLAGS=-j2`、
`CMAKE_BUILD_PARALLEL_LEVEL=2`、`--parallel-workers 2`，并处理 conda/`empy` 前置。
实测（重编 `dual_arm_qp_core`）：并发 `cc1plus` 峰值 **1**，`MemAvailable` 最低 **3.8 GiB**，构建 34 s 完成。

```bash
JOBS=2 PKGS=dual_arm_qp_core bash scripts/build_mem_safe.sh
```
