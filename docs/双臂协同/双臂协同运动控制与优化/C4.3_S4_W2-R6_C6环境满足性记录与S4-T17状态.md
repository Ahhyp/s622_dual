# C4.3 S4.1 W2-R6 — C6 目标环境满足性记录与 S4-T17 状态

- 阶段：C4.3 / S4.1 / **W2-R6**
- 结论：**S4-T17 维持 `BLOCKED_EXTERNAL_ENV`，本轮未执行正式测试**
- 阈值：`max interval ≤ 12 ms` **未修改**；采样量 6380 周期**未修改**；未剔除样本；未替换指标

---

## 1. 为什么本轮仍未执行

正式 S4-T17 的前提是"原生 Linux + 可设实时调度策略 + CPU 隔离"。本轮对**三处可用计算环境**逐一实测，**均不满足**，且不满足的原因不是"跑得慢"，而是**能力缺失**（无法设 `SCHED_FIFO` / 无隔离 / 无原生内核）。

---

## 2. 环境一：本机（WSL2，R5/R6 主力环境）

| 项 | 实测 | 命令 | 满足 |
|---|---|---|---|
| 内核 | `6.18.54.1-microsoft-standard-WSL2` | `uname -r` | ❌ 非原生 |
| CPU | AMD Ryzen 7 4800H / 16 逻辑核 | `nproc` | ✅ |
| RT 权限 | `ulimit -r = 0`；`chrt -f 1 true` → `Operation not permitted` | 直接执行 | ❌ |
| 实际策略 | `chrt -p $$` → `priority 0`（`SCHED_OTHER`） | `chrt -p` | ❌ |
| CPU 隔离 | `/proc/cmdline` 无 `isolcpus`/`nohz_full`/`rcu_nocbs` | `cat /proc/cmdline` | ❌ |
| 负载 | `loadavg 1.16~1.35` | `cat /proc/loadavg` | ⚠️ |
| cgroup | `cpu.max = max 100000`（未限流） | `cat /sys/fs/cgroup/cpu.max` | ✅ |
| 构建/加载 | merge-install：`install/lib/libdual_arm_qp_controller.so`（`ldd` 确认） | `ldd` | ✅ |

**判定**：非原生内核 + 无 RT 权限 + 无隔离 ⇒ **不可作为目标平台**。

## 3. 环境二：局域网原生主机 `172.23.203.131`（`kouzheng_2`）

| 项 | 实测 | 满足 |
|---|---|---|
| 内核 | `4.18.0-513.5.1.el8_9.x86_64`（RHEL/CentOS 8.9） | ✅ **原生 Linux** |
| 架构 / 核数 | `x86_64` / **40** 逻辑核 | ✅ |
| 负载 | `loadavg 1.32 0.70 0.61`，已连续运行 92 天 | ⚠️ 非空载 |
| RT 权限 | `ulimit -r = 0`；`chrt -f 1 true` → **`Operation not permitted`** | ❌ |
| 实际策略 | `chrt -p $$` → `SCHED_OTHER` / priority 0 | ❌ |
| sudo | `sudo -n true` → **`SUDO_DENIED`** | ❌ 无法改 `limits.conf` |
| CPU 隔离 | `/proc/cmdline`：`ro root=… rhgb quiet selinux=0 …`，**无 `isolcpus`** | ❌ |
| `sched_rt_runtime_us` | `950000`（未设 −1） | ⚠️ |
| ROS 2 | `/opt/ros` **不存在** ⇒ `NO_ROS` | ❌ 需从源码构建 ROS 2 + ros2_control（RHEL 8 无官方 Humble 二进制） |

**判定**：原生 Linux 与核数满足，但 **RT 权限被 `RLIMIT_RTPRIO=0` 且无 sudo + 无 CPU 隔离 + 无 ROS** ⇒ 三项关键前提不满足，且其中两项需要 root/OS 级改动，**本轮无权做出**。

## 4. 环境三：注册表中的 AutoDL 机器（`m-mui3dpp7-kxpp`）

- 为共享 GPU 云主机（root 认证），**不是**目标平台的实时性参照：虚拟化层与邻居负载不可控，无法提供 `isolcpus`/`nohz_full` 级隔离保证。
- 本轮**未在其上执行**任何测量（仅登记为"不适用"）。若后续要用，必须先验证：内核是否 RT、`chrt -f` 是否可用、ROS 2 Humble 是否已装、以及是否接受"共享云主机"作为目标平台证据 —— **均未验证**。

## 5. 若要解除阻断，需要谁做什么

| # | 需求 | 说明 |
|---|---|---|
| E-1 | 一台**原生 Linux** 目标机（或与目标机同规格的裸金属） | 不能是 WSL2 / 容器 / 共享云主机 |
| E-2 | 允许设置实时策略：`RLIMIT_RTPRIO` ≥ 1 或具备 `CAP_SYS_NICE`（或 root） | 需 OS 管理员配合（`limits.conf` / systemd `LimitRTPRIO`） |
| E-3 | CPU 隔离：`isolcpus=` / `nohz_full=` | 需改内核启动参数并重启 |
| E-4 | 已安装 ROS 2 Humble + `ros2_control` + `mock_components` | 或允许在该机构建本工作区（需 `colcon` 与依赖） |
| E-5 | 空载窗口（`loadavg` 接近 0） | 需协调使用时段 |
| E-6 | 允许保存原始 CSV 与执行日志到指定路径 | 用于可复核 |

满足 E-1…E-6 后，按既有流程执行：6380 周期（17×(lift 1.50 + lower 1.50) + settle 0.04 = 51.04 s），阈值 `max interval ≤ 12 ms`、`P99 ≤ 6.4 ms [待标定]`、RSS 增长 ≤ 1 MB、fd 不增长；**不剔除异常样本**。

## 6. 本轮明确**没有**做的事

- 没有在 WSL2 上重跑 S4-T17 并当作目标平台结论。
- 没有把 R3 的四组数据（最大间隔 15.7–21.3 ms）当作"通过"。
- 没有放宽 12 ms 阈值、没有改采样量、没有换指标、没有剔除离群点。
- 没有在无授权的情况下改动任何主机的系统配置（`limits.conf`、内核参数）。

## 7. 结论

**S4-T17 = `BLOCKED_EXTERNAL_ENV`（未解除）。** 本轮可交付的是"环境不满足性"的完整实测记录与解除清单，而不是实时性结论。
