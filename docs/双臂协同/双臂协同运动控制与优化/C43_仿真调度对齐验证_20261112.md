# C43 仿真调度对齐验证：5 ms → 2 ms（2026-11-12）

背景见[N1与QP接入记录](C43_N1基线固化与QP接入_20261112.md)§5。目标是在隔离配置中验证物理步长能整除QP周期后，轨迹时钟是否与Gazebo仿真时钟一致，并重新检查物理搬运。GUI保持关闭。

## 1. 问题与此次变更

原配置：Gazebo步长5 ms，controller_manager名义125 Hz，QP dt=8 ms。已保存的QP运行中，t_traj/仿真时间斜率约0.8000，对应按dt推算约100次更新/仿真秒；轨迹6 s实际约需7.5 s仿真时间。

本次新增明确的实验参数：

```text
--physics-step-ms 2
```

它只修改生成的world副本中的physics.max_step_size和physics名称。打包的5 ms参考资源与默认入口保留，QP dt、名义控制频率、求解器、deadline保护及其他控制参数不变，没有通过放宽超时或保护阈值掩盖问题。

启动时核对新旧输入：`task.json`、`qp_task.json`、`controllers.yaml`、`approach.json`、`transport.json`的哈希均相同；把新world的physics名称/步长恢复后，其XML与旧world一致。实际2 ms步长与显式变体标记写入metadata.json。

## 2. 验证方法与边界

1. 先跑既有QP的10 mm抬升/放回测试。
2. 小幅测试通过后，再跑60 mm抬升、保持、Y+120 mm横移、下降、接触落座/HOLD ACK、释放和退回。
3. 只对QP状态为RUNNING的记录拟合`t_traj = a × sim_time + b`。
4. 用`a / configured_dt`推算每仿真秒有效更新次数；同时报告a本身和相对1的偏差。
5. 完整搬运另外做原生同戳接触/几何审计，不能只看时钟对齐就算物理任务成功。

TransportStatus为降采样状态消息，不是逐周期实时测量。这里的125 Hz结论须写明是仿真频率推算，不是状态topic发布频率，也不构成Linux实时性或真机实时验收。物理步长改变也会影响接触积分，因此即使输入仅有步长变化，仍必须重新检查夹持和落座。

## 4. 结果

旧5 ms参考采用`log/c43_n1_20261112/qp_carry_r3/`，不覆盖或重新标记其原始数据。

| 运行 | 物理步长 | t_traj/仿真时间拟合斜率 | 推算更新频率（每仿真秒） | 物理结果 |
|---|---:|---:|---:|---|
| 原qp_carry_r3 | 5 ms | 0.800004 | 100.000 Hz | 原协议完整搬运通过 |
| qp_smoke_2ms_r1 | 2 ms | 1.000067 | 125.008 Hz | 抬升10.014 mm、放回和退离完成 |
| qp_carry_2ms_r1 | 2 ms | 1.000033 | 125.004 Hz | 完整QP搬运、接触落座和退回通过 |

小幅验证正常结束，无HOLD/FAULT/ABORT失败，控制器互斥及恢复检查通过。完整搬运也通过原生物理审计：

- 实际峰值抬升约60.041 mm；最终样件中心约`(0.000021,0.122930,0.275000)` m，目标位置误差2.930 mm。
- 抬升/保持/横移/下降共13888/13888条完整消息同时包含四指；保持与横移期间无源/目标支撑接触。
- 落座的连续支撑接触已触发原有HOLD服务，匹配ACK后reset切回JTC，再释放和退回。末态持续由目标支撑承托，无机器人接触。
- 12562个同戳原生帧；搬运最大姿态偏转约0.076°，四指STL顶点深入盒体的最大见证约0.0027 mm。它仍是几何见证，不是引擎penetration depth。
- 没有修改QP周期、求解器和已有保护判据，没有重跑后覆盖失败记录或替换旧基线。

这次消除了约20%的仿真轨迹时钟缩放误差。但旧5 ms参考落点误差约1.080 mm，新2 ms为2.930 mm，**不能把时钟对齐解释成物理放置精度提升**。物理积分步长和实际动作节拍均发生变化；需同物理步长的JTC/QP对照及重复实验才能归因，当前不作总体优劣或成功率保证。

### 墙钟与仿真频率分别报告

完整2 ms运行的RUNNING段拟合RTF约0.484（仿真秒/墙钟秒），按墙钟推算仅约60.47次控制更新/秒。小幅运行对应约0.452、56.53次/墙钟秒。因此这里修正的是仿真内8 ms调度与轨迹时钟，不是实现了当前主机墙钟125 Hz硬实时。

原5 ms默认输入保留用于复现。后续QP调度对齐实验应显式带`--physics-step-ms 2`，不把本次隔离试验自动写成正式world或W7完成。

日志根目录：`log/c43_timing_20261112/`。保留每轮真实world/model、条件、metadata、源码快照、QP状态、原生接触/位姿、FT、归属及HOLD ACK。

`input_comparison.json`保存仅步长变化的核对；`comparison.json`分列旧5 ms参考、小幅和完整2 ms结果；`source_snapshots/`及`source_sha256.json`保存本轮最终分析/入口源码。Python编译、资源哈希检查、git diff --check与实际小幅/完整物理运行通过。本轮未修改QP核心，未声称原生RT测试通过。所有本轮仿真均已清理，GUI没有重新打开。

## 5. 不自动推出的结论

本轮不修改正式executor/W7的完成状态；不能由一次时钟对齐推导全部故障恢复、保护或真机性能已通过。QP和JTC性能消融还应在相同物理步长与实际时间口径下进行。
