好的，下面是按你最新设计重新整理后的**阶段 1 计划**。这一版核心原则是：

> **用 BehaviorTree.CPP 从头到尾重构单臂抓取-放置闭环；抓取算法暂时保持 2.5D top-down + IBVS，但接口全部按 6D-compatible grasp 设计，为后续双臂 handover / transport 预留扩展空间。**

# 阶段 1：基于 BT.CPP 的单臂抓取-放置闭环重构

## 1. 阶段目标

当前已有系统可以完成：

```text
YOLOv8 OBB 检测
MoveIt2 粗定位
MoveIt Servo 视觉伺服
2D 图像空间对齐
盲降抓取
抬升验证
```

但原系统的问题是：

```text
任务逻辑集中在 visual_servo_node.py 的 Python FSM 中
状态切换复杂
后续加入放置、失败恢复、双臂任务会越来越难维护
```

因此阶段 1 的目标是：

```text
用 BehaviorTree.CPP 重构单臂 pick-and-place 任务层
保留原有 2D/2.5D 抓取的稳定性
新增放置、撤离、回 home
使用 6D-compatible grasp interface
为后续双臂任务预留 GraspCandidate / PoseStamped / object_frame 抽象
```

最终效果：

```text
Detect cube
Generate grasp candidate
Move to pregrasp
Visual align XY
Visual align yaw
Blind descend
Close gripper
Lift
Verify grasp
Move to pre-place
Move to place
Open gripper
Retreat
Go home
```

---

# 2. 本阶段技术路线

## 核心设计

本阶段不做完整 6D grasp pose estimation，而采用：

```text
6D-compatible grasp interface
+
2.5D top-down grasp implementation
```

也就是说：

| 层级     | 本阶段做法                                           |
| -------- | ---------------------------------------------------- |
| 感知     | YOLOv8 OBB + RGB-D，输出目标像素、yaw、粗位姿        |
| 抓取策略 | top-down grasp，roll/pitch 固定，yaw 来自 OBB 或固定 |
| 精对齐   | 保留原来的 2D IBVS                                   |
| 下降     | 保留 blind descend                                   |
| 运动目标 | 全部使用 `geometry_msgs/PoseStamped`                 |
| 数据抽象 | 使用 `GraspCandidate` 为未来 6D 抓取预留接口         |

一句话：

> **算法先不升级成完整 6D，但系统接口从一开始就按 6D 抓取系统设计。**

# 3. 原 visual_servo 的处理方式

不建议完全弃用原 `visual_servo` 包。

正确处理方式是：

## 弃用的部分

```text
visual_servo_node.py 中的大型 Python 状态机
```

也就是不再用它作为主任务入口。

## 保留的部分

```text
MoveIt 粗定位逻辑
error_estimator.py 深度 / 像素误差估计
j_img_to_base fallback
adaptive jacobian
lock_target_during_alignment
pregrasp_camera_offset
VISUAL_ALIGN_XY 逻辑
VISUAL_ALIGN_YAW 逻辑
BLIND_DESCEND 逻辑
LIFTING 逻辑
table_z / grasp_height_above_table 参数体系
```

推荐改造为：

```text
visual_servo_node.py
    ↓
拆成若干 ROS 2 Action / Service 能力节点
    ↓
由 BT.CPP 调用
```

也就是说：

> **原来的 FSM 废弃，原来的能力保留并封装。**

# 6. GraspCandidate 抽象设计

这是阶段 1 的关键升级点。

本阶段虽然还是 2.5D 抓取，但输出统一的抓取候选：

```text
GraspCandidate
├── object_name
├── object_pose
├── tcp_grasp_pose
├── tcp_pregrasp_pose
├── approach_vector
├── retreat_vector
├── grasp_width
├── grasp_type
├── score
└── source
```

本阶段实际内容可以是：

```text
object_name: cube
object_pose: coarse pose from YOLO/RGB-D
tcp_grasp_pose: top-down grasp pose
tcp_pregrasp_pose: top-down pregrasp pose with camera offset
approach_vector: [0, 0, -1]
retreat_vector: [0, 0, 1]
grasp_width: 0.04
grasp_type: top_down_2p5d
score: 1.0
source: yolo_obb_ibvs
```

这样后续升级 6D 抓取时，只需要替换：

```text
GenerateGraspCandidate
```

BT 主流程不用大改。

# 7. 单臂 Pick-and-Place 行为树设计

建议主树命名：

```text
single_arm_pick_place.xml
```

整体逻辑：

```text
Fallback
├── MainTask
└── Recovery
```

推荐行为树结构：

```xml
<root BTCPP_format="4">
  <BehaviorTree ID="SingleArmPickPlace">

    <Fallback name="PickPlaceWithRecovery">

      <Sequence name="MainTask">

        <CheckSystemReady/>
        <OpenGripper/>

        <RetryUntilSuccessful num_attempts="3">
          <Sequence name="DetectAndGenerateGrasp">
            <DetectObject object_name="cube"
                          min_confidence="0.05"
                          output_pose="{object_pose}"
                          output_uv="{target_uv}"
                          output_yaw="{object_yaw}"
                          output_confidence="{confidence}"/>

            <GenerateGraspCandidate object_name="cube"
                                    object_pose="{object_pose}"
                                    target_uv="{target_uv}"
                                    object_yaw="{object_yaw}"
                                    output_grasp="{grasp_candidate}"/>

            <MoveToPregrasp grasp_candidate="{grasp_candidate}"
                            velocity_scale="0.20"
                            acceleration_scale="0.20"/>
          </Sequence>
        </RetryUntilSuccessful>

        <Sequence name="ServoGrasp">
          <LockTargetPixel input_uv="{target_uv}"
                           output_uv="{locked_target_uv}"/>

          <VisualAlignXY target_uv="{locked_target_uv}"
                         tolerance_px="12.0"
                         timeout_sec="25.0"/>

          <VisualAlignYaw target_yaw="{object_yaw}"
                          timeout_sec="10.0"/>

          <AlignLockCheck tolerance_px="12.0"/>

          <BlindDescend descend_speed="0.04"
                        target_height="0.030"
                        timeout_sec="30.0"/>

          <CloseGripper/>

          <Lift lift_height="0.10"
                timeout_sec="30.0"/>

          <VerifyGrasp/>

          <AttachObject object_name="cube"
                        grasp_candidate="{grasp_candidate}"/>
        </Sequence>

        <Sequence name="PlaceObject">
          <GeneratePlaceCandidate output_place_pose="{place_pose}"
                                  output_pre_place_pose="{pre_place_pose}"/>

          <MoveToPose target_pose="{pre_place_pose}"
                      velocity_scale="0.20"
                      acceleration_scale="0.20"/>

          <MoveToPose target_pose="{place_pose}"
                      velocity_scale="0.10"
                      acceleration_scale="0.10"/>

          <OpenGripper/>

          <DetachObject object_name="cube"/>

          <Retreat distance="0.10"/>

          <GoHome/>
        </Sequence>

      </Sequence>

      <Sequence name="Recovery">
        <StopServo/>
        <OpenGripper/>
        <GoSafePose/>
      </Sequence>

    </Fallback>

  </BehaviorTree>
</root>
```


---

## 8.2 Perception 节点

```text
DetectObject
LockTargetPixel
```

### DetectObject

订阅：

```text
/yolov8/obb_detections
```

输出：

```text
object_pose
target_uv
object_yaw
confidence
```

注意：

```text
YOLO 仍然单独在 conda yolov8 环境启动
BT 节点不负责运行 YOLO 模型
```

---

## 8.3 Grasp 节点

```text
GenerateGraspCandidate
SelectBestGrasp
MoveToPregrasp
```

本阶段 `SelectBestGrasp` 可以是空实现或永远选择唯一候选。

### GenerateGraspCandidate 本阶段逻辑

输入：

```text
object_pose
target_uv
object_yaw
```

输出：

```text
grasp_candidate
```

内部生成：

```text
tcp_grasp_pose:
  frame_id: base_link
  z = table_z + grasp_height_above_table
  roll = pi
  pitch = 0
  yaw = object_yaw 或固定 yaw

tcp_pregrasp_pose:
  z = table_z + pregrasp_height_above_table
  xy = coarse xy + pregrasp_camera_offset
  orientation 同 grasp_pose
```

关键约束：

```text
最终抓取定位不能完全依赖 YOLO 像素反投影
仍然依赖 IBVS 做精对齐
```

---

## 8.4 Motion 节点

```text
MoveToPose
MoveToPregrasp
GoHome
GoSafePose
```

第一版推荐做法：

```text
BT.CPP 节点作为 Action Client
MoveIt 规划执行封装成 Action Server
```

也可以先临时让 C++ BT 节点调用已有 Python MoveIt 封装服务，以降低重构风险。

---

## 8.5 Servo 节点

```text
VisualAlignXY
VisualAlignYaw
BlindDescend
Lift
Retreat
StopServo
```

这些节点建议作为 ROS 2 Action 调用。

本阶段重点保留原先成熟设计：

```text
lock_target_during_alignment
VISUAL_ALIGN_XY 后续不再读 YOLO
BLIND_DESCEND 不读 YOLO
pregrasp_camera_offset 减少遮挡
use_adaptive_jacobian=true
j_img_to_base fallback
```

---

## 8.6 Gripper 节点

```text
OpenGripper
CloseGripper
```

推荐封装成：

```text
/gripper/open
/gripper/close
```

或：

```text
SetGripper.srv
```

不要让 BT 节点直接写死 ros2_control controller 细节。

---

## 8.7 Scene 节点

```text
AttachObject
DetachObject
```

第一版可以只做逻辑 attach/detach：

```text
AttachObject:
  标记 cube 已被抓取

DetachObject:
  标记 cube 已放置
```

后续再升级为 MoveIt Planning Scene 中的 attached collision object。

# 16. 阶段 1 简历表达

完成后简历可以写：

> 基于 BehaviorTree.CPP 重构 S622 六轴机械臂单臂抓取-放置任务层，将 YOLOv8 OBB 检测、6D-compatible 抓取候选生成、MoveIt2 粗定位、MoveIt Servo 图像空间视觉伺服、盲降抓取、夹爪控制、放置、撤离与失败恢复封装为可复用行为节点，实现完整 pick-and-place 闭环。系统采用 2.5D top-down grasp 实现并保留标准 PoseStamped / GraspCandidate 接口，为后续双臂递物与协同搬运扩展提供统一任务抽象。

英文版：

> Refactored the S622 robotic arm pick-and-place pipeline using BehaviorTree.CPP. Encapsulated YOLOv8 OBB detection, 6D-compatible grasp candidate generation, MoveIt2 pregrasp planning, MoveIt Servo-based IBVS alignment, blind descent, gripper control, placing, retreating, and recovery into reusable behavior nodes. The system uses a 2.5D top-down grasp implementation while preserving PoseStamped and GraspCandidate abstractions for future dual-arm handover and cooperative transport.

# 17. 最终执行顺序

建议你严格按这个顺序做：

```text
1. 新建 s622_bt_manager
2. 跑通 Dummy Behavior Tree
3. 写 single_arm_pick_place.xml
4. 接入 DetectObject
5. 实现 GenerateGraspCandidate
6. RViz 可视化 grasp / pregrasp pose
7. 接入 MoveToPregrasp
8. 拆出原 visual_servo 的 VisualAlignXY / VisualAlignYaw / BlindDescend / Lift
9. BT 调用 Servo Action 完成抓取
10. 新增放置流程
11. 新增 Recovery
12. 连续测试 10 次并记录 CSV
```

这一阶段的核心不是“做一个更复杂的抓取算法”，而是：

> **把原来能抓取的系统升级成结构清晰、可复用、可扩展的 BT.CPP pick-and-place 闭环。**
