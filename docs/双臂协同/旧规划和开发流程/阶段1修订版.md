# 阶段 1（修订版）：基于 BT.CPP 的单臂抓取-放置闭环重构
[阶段1开发流程](./阶段1开发流程.md)
## 1. 阶段目标

将现有单臂抓取系统升级为结构清晰、可复用、可扩展的 pick-and-place 闭环。具体落点：

* 任务层从 `visual_servo_node.py` 的 Python FSM 迁移到 **BehaviorTree.CPP v4**
* 能力层保留现有 Python 实现（IBVS、深度反投影、MoveIt 规划），只做最小封装
* 数据接口统一为 `PoseStamped` + 自定义 `GraspCandidate`，为双臂阶段预留扩展点
* 算法上仍是 2.5D top-down grasp，不做完整 6D 估计
* PlanningScene 真实 attach/detach 从一开始就接入
* 命名空间从一开始按 `arm_name` 参数化，将来直接变 `left`/`right`

## 2. 关键设计决策（相对原计划的变更）

| 变更项               | 原计划                                        | 修订版                                          | 理由                                    |
| -------------------- | --------------------------------------------- | ----------------------------------------------- | --------------------------------------- |
| Action 数量          | 5 个（Detect/Move/VisualAlign/Servo/Gripper） | 2 个 Action + 1 个 Service                      | 减少 boilerplate，Detect 直接订阅 topic |
| Detect 实现          | DetectObject.action                           | BT Sync Node 内部缓存最新 detections            | YOLO 是连续话题，Action 三段式过重      |
| 接口包               | 独立 `s622_task_interfaces`                   | 接口先放 `s622_bt_manager`，双臂阶段再抽出      | 少一个包，少一份编译开销                |
| 能力层语言           | 混合                                          | 全部 Python Action server                       | 保留经过验证的现有代码                  |
| MoveIt 调用          | 模糊                                          | 统一走 `MoveToPose` Action（Python 实现）       | 避免在 BT 节点里重写 MoveIt 调用        |
| Servo 生命周期       | 仅在 Recovery 做 StopServo                    | Action server 内部幂等管理 start/stop           | 历史已知坑：Servo 不释放导致 RViz 失控  |
| PlanningScene attach | 第一版只做逻辑标记                            | 第一版就用 `PlanningSceneInterface` 真实 attach | 双臂阶段必须有，提前 5-10 行代码        |
| 命名空间             | `/gripper/...`                                | `/${arm_name}/...`，默认 `arm`                  | 双臂阶段零成本切换                      |
| VerifyGrasp 判据     | 未定义                                        | finger 关节位置阈值（需标定）                   | 避免空抓继续往下走                      |
| Yaw 选择             | 固定或 OBB yaw                                | 在 4 个等价 yaw 中选离当前 EE yaw 最近的        | 避免无意义大转角                        |
| BT 版本              | BTCPP_format=4 但未确认                       | 明确依赖 `behaviortree_cpp` v4 + Groot2         | API 差异大，先确认安装                  |

## 5. 接口定义

### 5.1 `MoveToPose.action`

```
# Goal
geometry_msgs/PoseStamped target_pose
string planner_id           # ""=default, "OMPL", "Pilz_LIN" 等
float32 velocity_scale      # 0.0~1.0
float32 acceleration_scale  # 0.0~1.0
float32 timeout_sec
bool ensure_servo_stopped   # 进入前自动 stop servo
---
# Result
bool success
int32 error_code            # MoveItErrorCode
string error_msg
---
# Feedback
float32 progress            # 0.0~1.0
```

### 5.2 `VisualAlign.action`

合并原计划的 VisualAlign / CartesianServoMove / BlindDescend / Lift / Retreat 为一个 Action，用 `mode` 区分：

```
# Goal
string mode                 # "xy" | "yaw" | "descend" | "lift" | "retreat"

# 通用
float32 timeout_sec
bool ensure_servo_started   # 进入前自动 start servo

# mode=xy 时使用
float32 target_u
float32 target_v
float32 tolerance_px

# mode=yaw 时使用
float32 target_yaw
float32 tolerance_rad

# mode=descend/lift/retreat 时使用
float32 distance            # 米
float32 speed               # m/s
---
# Result
bool success
float32 final_error_px      # mode=xy/yaw 有效
float32 actual_distance     # mode=descend/lift/retreat 有效
string error_msg
---
# Feedback
float32 current_error
float32 elapsed_sec
```

**优点**：所有 Servo 操作共享同一份生命周期管理代码（start_servo / stop_servo / 异常超时回退）。BT 节点对外有 5 个不同节点，但 Action server 只有一个。

### 5.3 Service

```
# SetGripper.srv
string command              # "open" | "close"
---
bool success
float32 finger_position     # 实际反馈位置
string error_msg
```

```
# StopServo.srv
---
bool success
string error_msg
```

`StopServo` 单独成 Service 是为了 Recovery 路径能强制释放控制权。

### 5.4 `GraspCandidate.msg`

```
std_msgs/Header header
string object_name
geometry_msgs/PoseStamped object_pose
geometry_msgs/PoseStamped tcp_grasp_pose
geometry_msgs/PoseStamped tcp_pregrasp_pose
geometry_msgs/Vector3 approach_vector      # 单位向量
geometry_msgs/Vector3 retreat_vector       # 单位向量
float32 grasp_width                        # 米
string grasp_type                          # "top_down_2p5d" | "side" | "6d_free"
float32 score
string source                              # "yolo_obb_ibvs" | ...
```

## 6. GraspCandidate 生成策略（本阶段）

`GenerateGraspCandidate` 内部逻辑（同步 BT node，无 Action）：

```
输入：
  object_pose（从 YOLO + 深度反投影得到的粗位姿，仅用于 XY/yaw，Z 不可信）
  object_yaw（OBB 长边角度）
  current_ee_yaw（从 TF 查询）

输出 tcp_grasp_pose：
  frame_id = base_link
  position.x = object_pose.x
  position.y = object_pose.y
  position.z = table_z + grasp_height_above_table
  orientation: roll=π, pitch=0
  yaw = SelectBestYaw(object_yaw, current_ee_yaw)
    # cube 是对称的，4 个等价解中选 |Δyaw| 最小的

输出 tcp_pregrasp_pose：
  同 grasp_pose，但：
  z = table_z + pregrasp_height_above_table
  在 XY 上沿"远离相机水平投影"方向偏移 pregrasp_camera_offset
    # 相机 XY = (0.3825, 0.4838), 偏移方向 = normalize(grasp_xy - cam_xy)

approach_vector = [0, 0, -1]
retreat_vector  = [0, 0, +1]
grasp_width = 0.045
grasp_type = "top_down_2p5d"
source = "yolo_obb_ibvs"
score = confidence
```

**关键约束**：`object_pose.z` 不参与计算，避免 YOLO 像素反投影的 25mm 误差污染抓取高度。

## 7. 行为树设计

```xml
<root BTCPP_format="4">
  <BehaviorTree ID="SingleArmPickPlace">

    <Fallback name="PickPlaceWithRecovery">

      <Sequence name="MainTask">

        <CheckSystemReady joint_states_max_age="1.0"
                          tf_check_frame="grasp_frame"
                          yolo_max_age="2.0"/>

        <SetGripper command="open"/>
        <GoHome velocity_scale="0.30"/>

        <!-- 检测 + 抓取候选生成（带重试） -->
        <RetryUntilSuccessful num_attempts="5">
          <Sequence>
            <DetectObject object_name="cube"
                          min_confidence="0.05"
                          max_age_sec="1.0"
                          output_pose="{object_pose}"
                          output_uv="{target_uv}"
                          output_yaw="{object_yaw}"
                          output_confidence="{confidence}"/>
            <GenerateGraspCandidate object_pose="{object_pose}"
                                    target_uv="{target_uv}"
                                    object_yaw="{object_yaw}"
                                    output_grasp="{grasp}"/>
          </Sequence>
        </RetryUntilSuccessful>

        <!-- 粗定位：MoveIt 到 pregrasp -->
        <MoveToPose target_pose="{grasp.tcp_pregrasp_pose}"
                    velocity_scale="0.20"
                    acceleration_scale="0.20"
                    ensure_servo_stopped="true"
                    timeout_sec="15.0"/>

        <!-- IBVS 精对齐 + 盲降抓取 -->
        <Sequence name="ServoGrasp">
          <LockTargetPixel input_uv="{target_uv}"
                           output_uv="{locked_uv}"/>

          <VisualAlign mode="xy"
                       target_u="{locked_uv.u}"
                       target_v="{locked_uv.v}"
                       tolerance_px="12.0"
                       ensure_servo_started="true"
                       timeout_sec="25.0"/>

          <VisualAlign mode="yaw"
                       target_yaw="{grasp.tcp_grasp_pose.yaw}"
                       tolerance_rad="0.05"
                       timeout_sec="10.0"/>

          <AlignLockCheck target_uv="{locked_uv}"
                          tolerance_px="12.0"/>

          <VisualAlign mode="descend"
                       distance="0.13"
                       speed="0.04"
                       timeout_sec="30.0"/>

          <SetGripper command="close"/>

          <VerifyGrasp finger_min_position="0.005"
                       output_grasped="{is_grasped}"/>

          <VisualAlign mode="lift"
                       distance="0.10"
                       speed="0.05"
                       timeout_sec="30.0"/>

          <AttachObject object_name="cube"
                        grasp="{grasp}"/>
        </Sequence>

        <!-- 放置 -->
        <Sequence name="Place">
          <GeneratePlaceCandidate output_place_pose="{place_pose}"
                                  output_pre_place_pose="{pre_place_pose}"/>

          <MoveToPose target_pose="{pre_place_pose}"
                      velocity_scale="0.20"
                      acceleration_scale="0.20"
                      ensure_servo_stopped="true"
                      timeout_sec="15.0"/>

          <MoveToPose target_pose="{place_pose}"
                      velocity_scale="0.10"
                      acceleration_scale="0.10"
                      timeout_sec="10.0"/>

          <SetGripper command="open"/>
          <DetachObject object_name="cube"/>

          <VisualAlign mode="retreat"
                       distance="0.10"
                       speed="0.05"
                       ensure_servo_started="true"
                       timeout_sec="15.0"/>

          <GoHome velocity_scale="0.30"
                  ensure_servo_stopped="true"/>
        </Sequence>

      </Sequence>

      <!-- 失败恢复 -->
      <Sequence name="Recovery">
        <StopServo/>
        <SetGripper command="open"/>
        <DetachObjectIfAttached/>
        <GoSafePose velocity_scale="0.20"/>
        <AlwaysFailure/>
      </Sequence>

    </Fallback>

  </BehaviorTree>
</root>
```

注意几个细节：

* `MoveToPose` 通过 `ensure_servo_stopped` 进入前自动停 servo；`VisualAlign` 通过 `ensure_servo_started` 自动启动 servo。两边幂等。
* Recovery 末尾用 `AlwaysFailure` 让整个 Fallback 返回失败，方便外层重试或停止。
* `DetachObjectIfAttached` 比无脑 detach 安全（attach 状态从 blackboard 读）。

## 8. Servo 生命周期管理

由 `s622_arm_actions/servo_lifecycle.py` 单点管理：

```
ServoLifecycleManager:
  state: STOPPED | STARTING | RUNNING | STOPPING
  
  start_servo():
    if state == RUNNING: return success
    call /servo_node/start_servo
    wait for state RUNNING（监控 /servo_node/status 或超时 2s）
  
  stop_servo():
    if state == STOPPED: return success
    call /servo_node/stop_servo
    wait for state STOPPED

VisualAlign Action server 内部：
  on goal:
    if ensure_servo_started:
      ServoLifecycleManager.start_servo()
    执行对齐/下降/抬升逻辑
    （goal 结束不自动停，下次 MoveToPose 会停）

MoveToPose Action server 内部：
  on goal:
    if ensure_servo_stopped:
      ServoLifecycleManager.stop_servo()
    调用 MoveIt 规划执行

StopServo Service:
  强制 ServoLifecycleManager.stop_servo()
  Recovery 路径专用
```

这样 BT 节点不用管 servo 状态，只声明"我需要 servo 运行"或"我需要 servo 停止"。

## 9. PlanningScene attach 策略（第一版就做）

`AttachObject` BT node 内部：

```python
# 在 MoveIt PlanningScene 中添加 attached collision object
- shape: box, size [0.04, 0.04, 0.04]
- pose: 相对 grasp_frame，z 偏移 ≈ 0.01
- link: grasp_frame
- touch_links: [finger1, finger2, grasp_frame]
```

`DetachObject` 内部：把 attached object 转回 world frame 的 collision object，位置 = 当前 grasp_frame 位置投影到 table_z 上。

这样 MoveToPrePlace 时 MoveIt 知道末端挂着方块，会自动避免方块撞 base 或自碰撞。

**双臂阶段必须有这个**，所以早做不亏。

## 10. VerifyGrasp 判据

**Milestone 1.5 前需要一次标定**：

```bash
# 跑两次空抓和有方块抓，记录 finger 关节位置
ros2 topic echo /joint_states --field position
```

预期：

* 空抓闭合后：finger 位置 ≈ 0.0 ± 0.001m
* 抓到 4cm 方块（指尖间距≈20mm，单指 10mm）：finger 位置 ≈ 0.010m

VerifyGrasp 阈值取中间值，例如 `finger_min_position: 0.005m`。低于此值判定为空抓 → FAILURE。

## 17. 风险点与对策

| 风险                                        | 概率 | 对策                                                 |
| ------------------------------------------- | ---- | ---------------------------------------------------- |
| BT.CPP v4 与 Humble 默认 v3 冲突            | 中   | Milestone 1.0 先确认版本，必要时源码装               |
| Python Action server 调度延迟拖慢 IBVS      | 中   | Milestone 1.5 用 MultiThreadedExecutor，对比对齐时长 |
| PlanningScene attach 影响 MoveIt 规划成功率 | 低   | 第一次失败时 fallback 回逻辑 attach                  |
| Yaw 等价解择优选错导致夹爪撞方块            | 低   | 加入"yaw 误差 < 45°"硬约束                           |
| Recovery 中 servo stop 与 MoveIt 启动冲突   | 中   | ServoLifecycleManager 串行化，调用之间加 200ms 间隔  |
| YOLO 在 conda 环境，BT 在系统 Python        | 低   | 两者通过 ROS topic 通讯，无 Python 进程共享          |

## 总结：和原计划相比的核心变化

1. **接口数量减半**：5 个 Action → 2 个 Action + 2 个 Service。VisualAlign 一个 Action 用 mode 字段统一管理 xy/yaw/descend/lift/retreat。
2. **不建独立 interfaces 包**：消息和接口都先放 `s622_bt_manager`，双臂阶段再抽。
3. **PlanningScene attach 第一版就上**：Milestone 1.6 完成。
4. **Servo 生命周期单点管理**：用 `ServoLifecycleManager` + `ensure_servo_started/stopped` 字段，BT 节点不用感知 servo 状态。
5. **明确 BT.CPP v4 + Groot2**：Milestone 1.0 就锁定。
6. **VerifyGrasp 判据明确**：finger 关节位置阈值，1.5 前标定。
7. **Yaw 4 等价解择优**：避免无意义大转角。
8. **命名空间 `arm_name` 参数化**：双臂阶段零成本切换。
9. **Recovery 路径完整**：StopServo + Detach + GoSafe + AlwaysFailure。
10. **里程碑总工期**：约 11-12 个工作日（原计划没估时）。
