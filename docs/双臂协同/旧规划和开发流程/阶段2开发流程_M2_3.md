**目的**:MoveIt 加载双臂 URDF+SRDF+双 group kinematics,能在 RViz MotionPlanning 里分别对 `left_arm`/`right_arm` Plan 出轨迹。不依赖 Gazebo/controller_manager,M2.4 时再补执行链路。

**关键设计**:

1. **主 URDF 转 macro 保 arg 兼容**:文件顶层保留 `xacro:arg prefix/attach_world`,新增 `instantiate` arg。macro 定义放中间。默认 `instantiate:=true` 让 M1.7/M2.1 用户"include 即用",双臂顶层传 `instantiate:=false` 避免多余实例。
2. **双臂顶层 URDF 只放运动学**:纯 world + 两侧 arm macro + 两个 mount joint。不含 ros2_control(M2.4 会另建 gazebo 顶层)。这样 M2.3 完全解耦硬件。
3. **无 virtual_joint**:URDF 里 `world → *_base_link` 是真 fixed joint,SRDF 不需要重复声明。
4. **IK 双 group 都用 KDL**,与 M1.7 完全对齐,`fairino_ik` 不动。
5. **group_state 只保 `home`**(verticalpos 语义):M1.7 的 `pos1/pos2` 是任务姿态,左臂 yaw=π 后语义变了,M2.7 再按需重定义。
6. **demo launch 不起 controller_manager**:用 `joint_state_publisher` 发 zeros,`move_group`+`rviz2` 就够验证运动学。Execute 会失败但 Plan 成功即达标。

### 2. `s622_moveit_config/config/s622_dual_arm.urdf.xacro`(新建)

```xml
<?xml version="1.0"?>
<robot xmlns:xacro="http://www.ros.org/wiki/xacro" name="s622_dual_arm">

  <xacro:property name="M_PI" value="3.14159265358979323846"/>

  <!-- world 作为根 link, MoveIt 的规划坐标系 -->
  <link name="world"/>

  <!-- 引入主 URDF, 抑制其顶层自动实例化 -->
  <xacro:include filename="$(find s622_moveit_descriptions)/urdf/s622_moveit_descriptions.urdf.xacro"/>

  <!-- ============ 左臂: base_link 在 (0.35, 0, 0), yaw=π ============ -->
  <xacro:s622_arm prefix="left_" attach_world="false"/>
  <joint name="left_mount_joint" type="fixed">
    <parent link="world"/>
    <child link="left_base_link"/>
    <origin xyz="0.35 0 0" rpy="0 0 ${M_PI}"/>
  </joint>

  <!-- ============ 右臂: base_link 在 (-0.35, 0, 0), yaw=0 ============ -->
  <xacro:s622_arm prefix="right_" attach_world="false"/>
  <joint name="right_mount_joint" type="fixed">
    <parent link="world"/>
    <child link="right_base_link"/>
    <origin xyz="-0.35 0 0" rpy="0 0 0"/>
  </joint>

</robot>
```

⚠️ 这里 include 主 URDF 时,主 URDF 的 `<xacro:if value="$(arg instantiate)">` 会读全局 arg `instantiate`(默认 true)。我们 xacro 命令行不传 `instantiate:=false`,双臂顶层 URDF 会**多出一个空 prefix 的实例**——冲突。有两种处理方式:

**方式 A(推荐)**:xacro 命令行传 `instantiate:=false`

```bash
xacro s622_dual_arm.urdf.xacro instantiate:=false -o /tmp/dual.urdf
```

demo launch 里 mappings 传 `instantiate=false`。

**方式 B**:在双臂顶层 xacro 里覆盖 arg。但 xacro `<xacro:arg>` 覆盖行为不总一致。方式 A 更稳。

M1.7/M2.1 单臂启动不用传 `instantiate`(默认 true),行为不变。

### 6. `s622_moveit_config/launch/dual_arm_demo.launch.py`(新建)

自定义 launch,不用 MoveIt 的 `generate_demo_launch`(它默认会起 mock ros2_control,会跟我们双臂 URDF 里没有 ros2_control 段冲突)。

```python
# src/s622_moveit_config/launch/dual_arm_demo.launch.py
"""
M2.3 独立验收 launch: 仅 URDF+SRDF+kinematics 层面的验证.
不起 controller_manager, 用 joint_state_publisher 发 zeros.
Plan 可行, Execute 会失败(M2.4 再补).
"""
import os
from launch import LaunchDescription
from launch_ros.actions import Node
from launch.substitutions import PathJoinSubstitution
from launch_ros.substitutions import FindPackageShare
from moveit_configs_utils import MoveItConfigsBuilder


def generate_launch_description():
    moveit_config = (
        MoveItConfigsBuilder("s622_dual_arm", package_name="s622_moveit_config")
        .robot_description(
            file_path="config/s622_dual_arm.urdf.xacro",
            mappings={"instantiate": "false"},  # 抑制主 URDF 顶层自动实例化
        )
        .robot_description_semantic(file_path="config/s622_dual_arm.srdf")
        .robot_description_kinematics(file_path="config/dual_arm_kinematics.yaml")
        .trajectory_execution(file_path="config/dual_arm_moveit_controllers.yaml")
        .planning_pipelines(pipelines=["ompl"])
        .planning_scene_monitor(
            publish_robot_description=True,
            publish_robot_description_semantic=True,
        )
        .to_moveit_configs()
    )

    # robot_state_publisher
    rsp = Node(
        package="robot_state_publisher",
        executable="robot_state_publisher",
        output="screen",
        parameters=[moveit_config.robot_description],
    )

    # joint_state_publisher(发 zeros)
    jsp = Node(
        package="joint_state_publisher",
        executable="joint_state_publisher",
        output="screen",
        parameters=[{
            "rate": 30,
            "use_gui": False,
        }],
    )

    # move_group
    move_group = Node(
        package="moveit_ros_move_group",
        executable="move_group",
        output="screen",
        parameters=[moveit_config.to_dict()],
    )

    # rviz(用 MoveIt 默认 rviz config, 也可以先跳过)
    rviz_config = PathJoinSubstitution([
        FindPackageShare("moveit_configs_utils"),
        "launch", "moveit.rviz",
    ])
    rviz = Node(
        package="rviz2",
        executable="rviz2",
        output="screen",
        arguments=["-d", rviz_config],
        parameters=[
            moveit_config.robot_description,
            moveit_config.robot_description_semantic,
            moveit_config.robot_description_kinematics,
        ],
    )

    return LaunchDescription([rsp, jsp, move_group, rviz])
```

## 常见坑

1. **主 URDF include 时 `instantiate` 默认 true 的连锁反应**
   `s622_dual_arm.urdf.xacro` include 主 URDF,主 URDF 的 `<xacro:if value="$(arg instantiate)">` 会拿全局 arg `instantiate`——如果双臂顶层 xacro 里没自己声明这个 arg 也不传,默认 true 生效,主 URDF 会多实例化一次(空 prefix)。**必须命令行传 `instantiate:=false`**。demo launch 里 `mappings={"instantiate": "false"}` 已处理。手动 xacro 命令也要加。若忘了,`check_urdf` 会报 duplicate link `world`(空 prefix 版又建了一个 world) 或 duplicate link `base_link`。

2. **`attach_world` 的 xacro:if 判断**
   macro 内改用了 `<xacro:if value="${attach_world}">`(不再是 `$(arg ...)`)。xacro 里 macro param 传字符串 "true"/"false",xacro:if 会走字面 truthy 判断。如果你 M2.1 现有的 `robot_gazebo.urdf.xacro` 里传的是空 arg,兼容层默认 `attach_world="true"` 会生效——行为不变。如果传的是纯 Python bool(True/False),可能会失败,改成字符串 "true"/"false" 即可。测试见 V1 的 M2.1 兼容渲染。

3. **`MoveItConfigsBuilder("s622_dual_arm", ...)` 首参必须与 URDF `<robot name="...">` 一致**
   我 URDF 里 `<robot name="s622_dual_arm">`,Builder 传 `"s622_dual_arm"`。名字对不上时 Builder 会静默去找错误目录的 config,你以为改了实际没生效。**验证**:launch 起来后 `ros2 param get /move_group robot_description_semantic` 输出的 SRDF 里 group 名应是 `left_arm/right_arm`,不是 `robot_arm`。

4. **KDL 对反向 mount 的左臂**
   左臂 base yaw=π,在 world 里"倒着装"。KDL IK 计算相对 base_link,与安装朝向无关——所以左臂 IK 数学上没问题。但 `chain base_link="left_base_link"` 里的 base_link 是**左臂的 base**(不是 world),这是 SRDF 明确规定的,已正确配置。RViz 里目标 pose 如果用 `frame_id: 'world'`,MoveIt 会自动做 TF 变换到 left_base_link 系再送 IK,透明。

5. **URDF 里 `${prefix}base_link` 与 mount joint 顺序**
   `xacro:s622_arm prefix="left_"` 在双臂顶层生成 left_base_link 等,然后紧接着 `left_mount_joint` 引用 left_base_link——顺序上 `left_base_link` 已定义,OK。**若把顺序颠倒**(mount joint 写在 macro 调用前),URDF spec 允许(joint 可引用后声明的 link),但 `check_urdf` 有的实现要求先 link 后 joint,谨慎。

6. **`joint_state_publisher` 需要 `robot_description`**
   我 launch 里没显式给 JSP 传 `robot_description`。**JSP 会从话题拿**——`rsp` 已经把 `/robot_description` 参数广播了(通过 latching 参数),JSP 起来时能拿到。若日志里 JSP 报 "Waiting for robot_description",等 1-2s 应恢复;若不恢复,给 JSP 加 `parameters=[moveit_config.robot_description]`。

7. **RViz config**
   `moveit_configs_utils` 包里带的 `moveit.rviz` 是单 group 默认布局。双 group 打开后 MotionPlanning 里 `Planning Group` 下拉有 4 项,可能默认选到不存在的 `robot_arm` 导致空白。手动选一次即可。M2.7 可以专门存一个 `dual_arm.rviz` 到 s622_moveit_config/config/。

8. **`open_max` 值方向问题**
   URDF 里 `finger2_joint` 的 limit 是 `lower="-0.0305" upper="1e-6"`(负向张开),M1.7 SRDF 里 `open_max` 给 `finger2_joint=-0.0305`,双臂前缀化后保持同数值——**mimic 关系在 SRDF 层没有**(M1.7 就没有),靠 hand_controller 双 joint 同时命令。所以 `open_max` 里两根 finger 各自的值是**独立**的,确保 finger1=+0.0305 finger2=-0.0305(方向相反,张开一致)。这里 SRDF 已按 M1.7 复制。
