## 先讲 TF 观测

**这不是"误差",是双臂 base 实际位置的真实观测。** 用观测值,不要用理论值。

推算:相机在 world (0, 0.5, 0.9),左 base 世界位姿 yaw=π,右 base yaw=0。

* **相机在 left_base 系**: `(0.318, -0.511, 0.888)` ← M2.7.4 XML 左臂用这个
* **相机在 right_base 系**: `(0.382, 0.511, 0.888)` ← 右臂用这个

X 方向左右差 0.064m,说明双臂 base 实际不完全对称摆在 (±0.35, 0, 0)——可能是 URDF 里 arm mount 有 offset 或 xacro 里两侧 xyz 不完全对称。**不用管**,以 TF 实测为准。

Z 方向 0.888 vs 之前记忆的 0.9,差 0.012m,可能相机在 world 系实际是 0.888 高度,或者受相机模型 offset 影响。**同样以实测为准**。

**主路径**(table-plane 交线)完全走 TF live lookup,自动对。这些参数只有**深度 fallback 分支**用。所以稍有偏差也不致命,fallback 时 pregrasp 位置会偏几 mm,不影响主流程。

### 2. 新建 `s622_bt_manager/config/bt_dual_config.yaml`

```yaml
/bt_executor:
  ros__parameters:
    # ==================== Left arm place poses ====================
    # 左臂 place 在自己 base 系里
    left_place_frame_id: "left_base_link"
    left_place_position:  [-0.15,  0.35, 0.03]   # base_link 里的坐标
    left_place_rpy:       [3.14159, 0.0, 0.0]     # roll=pi, pitch=0, yaw=0

    left_pre_place_frame_id: "left_base_link"
    left_pre_place_position: [-0.15,  0.35, 0.20]
    left_pre_place_rpy:      [3.14159, 0.0, 0.0]

    # ==================== Right arm place poses ====================
    right_place_frame_id: "right_base_link"
    right_place_position:  [-0.15, -0.35, 0.03]
    right_place_rpy:       [3.14159, 0.0, 0.0]

    right_pre_place_frame_id: "right_base_link"
    right_pre_place_position: [-0.15, -0.35, 0.20]
    right_pre_place_rpy:      [3.14159, 0.0, 0.0]

    # ==================== M1.7 兼容(可留可删) ====================
    # 若某天 arm="" 单臂跑, 走这个 fallback
    place_frame_id: "base_link"
    place_position:  [0.0, -0.35, 0.03]
    place_rpy:       [3.14159, 0.0, 0.0]

    pre_place_frame_id: "base_link"
    pre_place_position: [0.0, -0.35, 0.20]
    pre_place_rpy:      [3.14159, 0.0, 0.0]
```

**关于 place 位置**:上面数值是**占位**——你要根据双臂实际可达空间调。快速指南:

* 左臂 base 在 world (0.35, 0, 0),yaw=π。左臂 base 系的 x 轴指向 world -x 方向。`left_place_position: (-0.15, 0.35, 0.03)` = world 系里 (0.35+0.15, 0-0.35, 0.03) = **(0.5, -0.35, 0.03)**,在桌面左手侧
* 右臂 base 在 world (-0.35, 0, 0),yaw=0。右臂 base 系的 x 轴指向 world +x 方向。`right_place_position: (-0.15, -0.35, 0.03)` = world (**-0.5**, -0.35, 0.03),桌面右手侧但**在左桌沿外**——**可能不可达**

我给的值只是示例。**M2.7.5 跑前请手动 teach 一下双臂能到的 place 点位**,通过 RViz Motion Planning 面板拖到目标点,读出 base 系坐标写进 yaml。

### 3. 新建 `s622_bt_manager/behavior_trees/pick_place_dual.xml`

**保持 M1.7 结构完全一致**,只加 `arm_prefix="{arm}"` 到所有相关 node。**Feedback**:blackboard key 里 `{u}`/`{v}`/`{grasp_pose}` 等左右**共享 root blackboard**——但同一时间只有一只手在跑一份 XML(串行),不冲突。

```xml
<root BTCPP_format="4">
  <BehaviorTree ID="PickPlaceDual">
    <Fallback name="MainWithRecovery">

      <!-- ============ 主任务 ============ -->
      <Sequence name="MainTask">
        <CheckSystemReady />

        <!-- ===== Pick ===== -->
        <SetGripper arm_prefix="{arm}" command="open" timeout_sec="5.0" />

        <MoveToPose arm_prefix="{arm}" named_pose="home"
            velocity_scale="0.3" acceleration_scale="0.2"
            ensure_servo_stopped="true"
            timeout_sec="30.0" />

        <RetryUntilSuccessful num_attempts="5">
          <Sequence>
            <DetectObject object_name="cube" min_confidence="0.10" max_age_sec="1.0"
                output_u="{u}" output_v="{v}"
                output_yaw="{obj_yaw}" output_confidence="{conf}" />
            <GenerateGraspCandidate arm_prefix="{arm}"
                u="{u}" v="{v}" object_yaw="{obj_yaw}"
                tcp_grasp_pose="{grasp_pose}"
                tcp_pregrasp_pose="{pregrasp_pose}"
                grasp_yaw="{grasp_yaw}"
                grasp_pose_x="{grasp_x}"
                grasp_pose_y="{grasp_y}" />
          </Sequence>
        </RetryUntilSuccessful>

        <LockTargetPixel input_u="{u}" input_v="{v}"
            locked_u="{lu}" locked_v="{lv}" />

        <MoveToPose arm_prefix="{arm}" target_pose="{pregrasp_pose}"
            velocity_scale="0.2" acceleration_scale="0.2"
            ensure_servo_stopped="true"
            timeout_sec="25.0" />

        <VisualAlign arm_prefix="{arm}" mode="xy"
            target_x_base="{grasp_x}" target_y_base="{grasp_y}"
            tolerance_m="0.005"
            ensure_servo_started="true"
            timeout_sec="25.0" />

        <VisualAlign arm_prefix="{arm}" mode="yaw"
            target_yaw="{grasp_yaw}"
            tolerance_rad="0.10"
            ensure_servo_started="true"
            timeout_sec="5.0" />

        <AlignLockCheck locked_u="{lu}" locked_v="{lv}"
            object_name="cube"
            min_confidence="0.05"
            tolerance_px="25.0" />

        <VisualAlign arm_prefix="{arm}" mode="descend"
            distance="0.13"
            speed="0.04"
            ensure_servo_started="true"
            timeout_sec="30.0" />

        <SetGripper arm_prefix="{arm}" command="close"
            timeout_sec="5.0" finger_position="{finger_pos}" />

        <VerifyGrasp arm_prefix="{arm}"
            finger_min_position="0.005" timeout_sec="5.0"
            finger_position="{finger_pos}" />

        <AttachObject arm_prefix="{arm}" object_name="cube"
            size_x="0.04" size_y="0.04" size_z="0.04"
            offset_z="0.02" />

        <VisualAlign arm_prefix="{arm}" mode="lift"
            distance="0.10"
            speed="0.05"
            ensure_servo_started="false"
            timeout_sec="20.0" />

        <MoveToPose arm_prefix="{arm}" named_pose="safe"
            velocity_scale="0.30" acceleration_scale="0.30"
            timeout_sec="20.0"
            ensure_servo_stopped="true" />

        <!-- ===== Place ===== -->
        <GeneratePlaceCandidate arm_prefix="{arm}"
            place_pose="{place_pose}"
            pre_place_pose="{pre_place_pose}" />

        <MoveToPose arm_prefix="{arm}" target_pose="{pre_place_pose}"
            velocity_scale="0.20" acceleration_scale="0.20"
            timeout_sec="20.0"
            ensure_servo_stopped="true" />

        <MoveToPose arm_prefix="{arm}" target_pose="{place_pose}"
            velocity_scale="0.10" acceleration_scale="0.10"
            timeout_sec="15.0"
            ensure_servo_stopped="true" />

        <SetGripper arm_prefix="{arm}" command="open" timeout_sec="5.0" />

        <DetachObject arm_prefix="{arm}" object_name="cube"
            put_back_in_world="true"
            drop_pose="{place_pose}" />

        <VisualAlign arm_prefix="{arm}" mode="lift"
            distance="0.10" speed="0.05"
            timeout_sec="20.0" />

        <MoveToPose arm_prefix="{arm}" named_pose="home"
            velocity_scale="0.30" acceleration_scale="0.30"
            timeout_sec="20.0"
            ensure_servo_stopped="true" />
      </Sequence>

      <!-- ============ Recovery ============ -->
      <Sequence name="Recovery">
        <PrintMessage msg="=== ENTERING RECOVERY ==="/>

        <ForceSuccess>
          <StopServo arm_prefix="{arm}" />
        </ForceSuccess>

        <ForceSuccess>
          <SetGripper arm_prefix="{arm}" command="open" timeout_sec="3.0" />
        </ForceSuccess>

        <ForceSuccess>
          <DetachObject arm_prefix="{arm}" object_name="cube"
              put_back_in_world="false"
              timeout_sec="3.0" />
        </ForceSuccess>

        <ForceSuccess>
          <MoveToPose arm_prefix="{arm}" named_pose="safe"
              velocity_scale="0.20" acceleration_scale="0.20"
              timeout_sec="15.0"
              ensure_servo_stopped="true" />
        </ForceSuccess>

        <ForceSuccess>
          <MoveToPose arm_prefix="{arm}" named_pose="home"
              velocity_scale="0.20" acceleration_scale="0.20"
              timeout_sec="15.0" />
        </ForceSuccess>

        <PrintMessage msg="=== RECOVERY DONE ==="/>
        <AlwaysFailure />
      </Sequence>

    </Fallback>
  </BehaviorTree>
</root>
```

**改动小结**:

* 每个 MoveToPose/SetGripper/VerifyGrasp/AttachObject/DetachObject/VisualAlign/StopServo/GenerateGraspCandidate/GeneratePlaceCandidate 都加了 `arm_prefix="{arm}"`
* AttachObject 删掉了 `link_name="grasp_frame"` —— 让节点内部按 arm_prefix 派生 `{arm}_grasp_frame`
* 其余(Detect/LockTargetPixel/AlignLockCheck)不加 arm_prefix,perception 全局

## 已知/待处理坑

### 坑 1: `AttachObject` 的 planning_scene 服务坐标

Attached collision object 在 planning_scene 里挂到 `{arm}_grasp_frame` 上,内部 pose 是 link 系(相对)—— 不受 base 系差异影响,应该正常。

但 `DetachObject` 里 `drop_pose` 是 `{arm}_base_link` 系。planning_scene_service.py 里若假设 base_link,detach 后 cube 会**放错位置**(视觉上不影响 pick-place,只影响 planning_scene 内部碰撞检测)。M2.7.5 跑通后可能会看到 RViz 里 cube 位置飘移,单独修 planning_scene_service.py 里的 frame transform。

### 坑 2: `named_pose="grasp_cube"` 缺失

M1.7 pick-place 里没用 grasp_cube,但你 M2.6 arm_config 里有 `named_pose_names: ['home', 'safe', 'grasp_cube']`。M2.7 里也没有实际调用,不影响。M2.8 可能用到。

### 坑 3: `left_place` 参数 declare 时机

`GeneratePlaceCandidate` 构造函数不 load,在 tick 中调 `ensure_loaded(arm_prefix)`,内部 `declare_parameter`。yaml 里 params 都是**预置**的——`declare_parameter` 会读到 yaml 值。**没问题**。

### 坑 4: bt_trigger 后卡在 CheckSystemReady

CheckSystemReady 是 dummy_nodes 里的一个 node,检查某些依赖 topic。**可能**需要看这个 node 检查了什么、双臂环境下是否满足。如果直接 fail,可以先临时**删掉这行**跑通再补。
