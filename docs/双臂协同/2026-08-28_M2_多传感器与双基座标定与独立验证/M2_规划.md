## M2.0：先冻结坐标系约定和数据格式

**坐标变换约定**（全项目统一，代码里禁止模糊命名如 `camera_to_tool`/`handeye_tf`）：

> {}^{A}T_{B} 表示：把 B 坐标系中的坐标转换到 A 坐标系，即 p_A = {}^{A}T_{B} · p_B

示例命名：
```text
left_base_T_right_base
tool0_T_wrist_camera_color_optical
left_base_T_global_camera_color_optical
```

**每次标定保存的元数据**：
```text
calibration_id
timestamp
git_commit
URDF hash/version
robot serial/side
camera serial
CameraInfo/intrinsics
dataset
solver
sample count
result transform
RMSE / P95 / MAX
```

**退出判据**：所有 calibration 模块只采用这一种 convention，并有 synthetic composition 单元测试。

## M2.2：先修"独立标定评估器"（真机标定之前）✅ 已完成（2026-08-31）

**⚠️ robotarm 现有缺陷**：`scripts/evaluate_calibration.py` 的 eye-in-hand 分支把 `T_base_mrk_pred` 直接赋成 `T_base_mrk_obs`——**误差被构造成 0，不能作为独立验收指标**。而 `solver.py` 内部的 fixed-marker consistency（`marker_metrics()`）思路是对的：每组样本反推固定 marker pose，算位置/旋转 RMS。

**统一成 constant-frame evaluator**（不假设 marker frame 与 tool0 重合）：

- **Eye-in-hand**（标定板固定环境中）：每个 hold-out pose 计算
  {}^{B}T_{M,i} = {}^{B}T_{E,i} · {}^{E}T_{C} · {}^{C}T_{M,i}，理论上 {}^{B}T_{M,1} = {}^{B}T_{M,2} = … → 报 marker position RMS/P95、rotation RMS/P95
- **Eye-to-hand**（marker 固定在末端）：{}^{E}T_{M,i} = {}^{E}T_{B,i} · {}^{B}T_{C} · {}^{C}T_{M,i} 同样应恒定

**必须分开**：求解 samples 与 validation samples（如 15~20 求解 + 5~10 hold-out），不能用参与求解的数据自己给自己打分。

**实现（2026-08-31，commit 见 git log）**：
- 新建 `hand_eye_calibration/evaluator.py`：纯 Python 评估模块（constant-frame 指标 + hold-out 切分 + .samples/.calib 加载 + 求解包装），不依赖 ROS 节点
- 重写 `scripts/evaluate_calibration.py`：TF 实时采集 + hold-out 评估（去掉 easy_handeye2 依赖与 placeholder）
- 新建 `scripts/evaluate_calibration_offline.py`：纯 Python 离线 CLI（无需 ROS），可对已存 .samples 直接跑 hold-out
- 新增 `test/test_evaluator.py` 21 个单测：无噪声 synthetic 数据（EIH/EOB）constant-frame 残差 ~0、噪声敏感性、hold-out 切分覆盖、YAML round-trip

**GPT 代码审查后修复（2026-08-31，第二轮）**：
- 🐛 **ROS TF quaternion 顺序**：`evaluate_calibration.py` 曾按 transforms3d 的 `[w,x,y,z]` 组装数组，但
  scipy `R.from_quat` 默认 `[x,y,z,w]`（与 geometry_msgs/Quaternion 一致）→ 在线评估旋转全错。
  已改为 `evaluator.quat_xyzw_to_matrix(x,y,z,w)`（新增公共函数 + 已知 Z+90° 单测）
- 🐛 **采集失败仍 +1 index**：`_collect_sample()` 改返回 bool，TF 获取失败不再推进 `_sample_idx`
- **求解质量门控复用**：evaluator 改为调用 `solver.solve_handeye_dataset()`（公共入口，完整生产门控：
  安装范数校验、Park/Horaud 一致性、finite 检查、internal RMS），`EvaluationResult.solver_valid`
  纳入总 PASS（solver gate AND hold-out gate），不再只信 hold-out
- **saved-calib 类型一致性**：`.calib` 加载返回 `CalibrationFile(calibration_type, transform)`，
  EIH/EOB 不匹配直接报错；`save_calibration_yaml` 不再写死 eye_in_hand
- **空输入防护**：`reference_pose`/`constant_frame_metrics` 空列表抛 ValueError
- **离线 CLI 文案**：`translation delta` typo → `rotation delta`；saved-calib 模式明确标注
  "fresh-data self-consistency（非严格 hold-out）"
- **测试扩充**：reference-leakage 对抗测试（hold-out marker 偏移 10mm，严格 reference 保持 ~10mm、
  leaky reference 塌缩到 ~0）、wrong-direction 测试（手眼方向反了必须显著变差）、
  已知 quaternion fixture、空输入、solve_count=total 越界

**验证**（对 2026-08-30 sim 已存 19 样本，solve=15/hold-out=4）：

```text
SOLVE-SET  position RMS/P95/MAX = 0.78 / 1.13 / 1.29 mm  rotation 1.206°
HOLD-OUT   position RMS/P95/MAX = 0.45 / 0.57 / 0.58 mm  rotation 1.047°
solver quality gate = PASS
OVERALL PASS = False（hold-out rotation 1.047° 微超 1° 门控）
```

hold-out 位置 RMS 0.45mm 达标；旋转 1.047° 微超 1° 门控——与手册记录的仿真
PnP 噪声（0.85°）同量级，属检测噪声而非算法缺陷。**按 GPT 建议：不为这 0.047°
放宽门控，待真机 fresh 8~10 个 hold-out 点再定工程门限（可能 1.2°）**。

## M2.4：腕部 RGB-D 单独做 Depth Validation（原规划缺失）

robotarm 手眼求解**只用 RGB + CameraInfo + ArUco PnP，没读深度图**。M3 要 YOLO mask → depth → point cloud → PCA，进 M3 前必须验证 **RGB 像素对应的 depth 准不准**。

平面标定板，距离 0.25 / 0.35 / 0.50 / 0.70 m，每距离多帧：
```text
z_depth - z_PnP
点云拟合平面: plane RMS / median depth bias / P95 depth error / invalid depth ratio
```
否则抓偏 8mm 无法区分是 hand-eye 3mm + depth bias 5mm 还是 YOLO 错。

## M2.5：双基座标定——机械法为主（不依赖视觉）

若依赖两台腕部相机求 base-to-base，会把两边手眼误差带进去。**双基座主标定独立于相机**。

### 第一步：先校准两个测量 TCP

- 尖头 probe：left_tool0_T_probe、right_tool0_T_probe（固定球心/尖点多姿态 pivot TCP calibration）
- 输出 TCP repeatability；否则"基座误差"混入 TCP offset error

### 然后采共同物理点

- 3D fixture（20 correspondences，覆盖双臂交接区，有一定 Z 高度变化，不要共线/共面，
  **按 M2.6 farthest-point 设计铺满交接区**）
- 每点左臂测 p_i^{B_L}、右臂测 p_i^{B_R}，Kabsch/SVD rigid alignment 求 {}^{B_L}T_{B_R}
- **15 fit + 5 hold-out**（hold-out 空间分布，不全用）

**⚠️ 验收分层（M2.6 v2 GPT review 结论）**：
```text
① 内部一致性（touch 数据自身）:
   fit RMS ≤ 1.5~2 mm / holdout RMS ≤ 2 mm / holdout MAX ≤ 3 mm
   —— 只能证明"一个刚体变换一致解释这些触点"；
      系统性 TCP bias 会被质心化消掉、被 Kabsch 平移吸收，
      因此 **检测不到绝对平移偏差**（可能 fit 1.3mm 但真实 base 偏 4mm）

② 绝对精度验证（独立模态，M2.7/M2.8 global camera）:
   {}^{B_L}T_{B_R}^{camera} vs {}^{B_L}T_{B_R}^{touch}
   ΔT: translation < 2~3mm, rotation < 0.2~0.5°
   —— 专门抓系统性 TCP/FK bias，是真正的外部验收
```
① 达不到就先查 TCP calibration / joint zero / URDF geometry / fixture rigidity /
touch repeatability，**不要把误差塞进软件 offset**；①过了还要②，缺一不可。

## M2.6：双基座仿真 + Monte Carlo（先做）✅ 已完成（2026-08-31）

Gazebo 中 {}^{B_L}T_{B_R}^{GT} 已知，模拟 contact noise / TCP error / joint FK noise，恢复估计。
采样数 N = 4/6/10/15/20/30，每个 N 跑 500~1000 trials，输出：
```text
sample count → translation P95
sample count → rotation P95
```
并对比"小范围点云 vs 覆盖整个交接区"——**空间覆盖往往比点数更重要**，据此决定真机采 15 还是 20。

**实现**：`src/dual_arm_calibration/`（base_alignment.py Kabsch + monte_carlo.py + scripts/mc_base_alignment.py），
GT 从 URDF 纯数学推导（left base yaw=π @ (0.35,0,0) / right yaw=0 @ (-0.35,0,0) → Rz(180°)+t=(0.7,0,0)），
无需 Gazebo 渲染。**v2（GPT 审查后）24 个单测全过**。结果见 `M2.6_双基座MonteCarlo仿真.md`。

**v2 关键结论（GPT review 修正版）**：
1. **系统性 TCP 误差封顶，加 N 无法突破**：TCP 3D RMS 1.0mm 时 WIDE N=20 封顶 2.92mm；
   TCP 3D RMS 0.5mm → 2.21mm；无 TCP → 1.92mm。真机瓶颈在 TCP probe 标定（目标 3D RMS ≤0.5mm）
2. **nested/paired 设计**（同一 20 点 fixture 的 farthest-point 子集 + 共享噪声 realization）：
   N 曲线平滑单调（4.05→2.92mm），隔离"点数效应"与"点集运气"
3. **handover-workspace 点误差是最现实指标**：默认噪声 N=20 → 3.53mm（旋转放大可见）
4. **WIDE 20 点方案确认**（15 fit + 5 hold-out）；rotation 非瓶颈（<0.3°）
5. ⚠️ **验收必须分层**：fit/hold-out residual 只验内部一致性（检测不到系统性 TCP bias），
   绝对精度必须由 M2.7/M2.8 global camera 交叉验证（见 §M2.5）
6. **tool-frame TCP 对比（补充）**：探针姿态随点变化 vs 固定姿态对精度影响 <15%
   （trans 2.68 vs 2.92mm / rot 0.208 vs 0.161°），**真机不必强制固定探针姿态**

## M2.8：双基座最终"两种方法互证"

```text
方法 A（机械触碰）:  {}^{B_L}T_{B_R}^{touch}
方法 B（全局相机）:  {}^{B_L}T_{B_R}^{camera}
ΔT = ({}^{B_L}T_{B_R}^{touch})^{-1} · {}^{B_L}T_{B_R}^{camera}
```

**验收**：translation difference < 2~3 mm、rotation difference < 0.2~0.5 deg。
若 camera 与 touch 差 8mm 而 touch 自身 1mm RMS → 问题大概率在 global hand-eye / camera optical frame / marker geometry / intrinsics，**误差可定位性**是本设计核心价值。
