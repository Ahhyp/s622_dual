## 场景 B：双臂仿真启动报错排查（2026-08-27 20:2x，用户报告）

**现象**：双臂仿真（s622_dual_arm.launch.py）启动报错 + RViz plan & execute 失败。
gz_ros2_control 报：
```
The plugin failed to load ... the class fairino_hardware/FairinoHardwareInterface
with base class type gz_ros2_control::GazeboSimSystemInterface does not exist
```
→ 硬件接口未创建 → joint_state_broadcaster/left_arm_controller 激活失败（spawner exit 1）→ RViz 无控制器可用。

**根因（环境陷阱，非代码问题）**：上午（13:34/13:43）真机/mock launch 被 Ctrl+C 后，
**两个 robot_state_publisher 孤儿进程残留**（pid 782293 真机 URDF fairino_hardware；pid 785825 mock URDF）。
20:16 双臂仿真启动时 graph 里有 3 个同名 `/robot_state_publisher`（真机残留 + mock 残留 + 双臂新启动），
gz_ros2_control 调 `/robot_state_publisher/get_parameters` 拿 URDF 时**被随机路由到残留的真机 RSP**
→ 拿到 fairino_hardware 单臂 URDF → 插件加载失败。
20:06 第一次双臂仿真成功 = 随机路由恰好命中新 RSP（同一 launch 两次不同结果）。

**证据**：
- 20:06-20:13 双臂仿真正常（gz_ros2_control `Loading joint: left_j1 ... Command: velocity`）
- 20:16 第二次失败（fairino_hardware 插件）
- 两次之间 git 干净、无代码改动
- 残留进程：`/opt/ros/humble/lib/robot_state_publisher/robot_state_publisher --ros-args --params-file /tmp/launch_params_2nkii7n4`（含 fairino_hardware），父进程为 /init（孤儿）

**处置**：kill 782293 785825，确认 ROS 进程全部清理。

**⚠️ 环境陷阱记录**：Ctrl+C 关 launch 后子进程可能残留（尤其 RSP），同名节点服务冲突会导致
gz_ros2_control 拿到错误 URDF。排查"仿真启动插件加载错误"时应先 `ps -eo pid,cmd | grep robot_state_publisher` 检查残留。

## 场景 B 续：FastDDS SHM 并发竞争故障（2026-08-27 20:47，用户报告）

**现象**：双臂仿真启动时多个节点同时报：
```
[RTPS_TRANSPORT_SHM Error] Failed init_port fastrtps_port7431: open_and_lock_file failed
```
随后 gazebo 内 gz_ros2_control 卡死（`connected to service!!` 后 19s 无 `Received URDF`），
ros2_control 未初始化，全栈异常（move_group 无 joint_states、RViz 无模型、plan & execute 失败）。

**根因**：WSL2 下 FastDDS SharedMem 传输不稳定。
- 20:47:57.25x 四个节点（dual_move_server/gripper_service×2/move_to_pose_server）**同一毫秒**并发
  创建共享内存端口文件 `fastrtps_port7431` → open+flock 竞争失败 → 这些 participant SHM 通道异常
- service（rclcpp 同步 get_parameters）请求/响应丢包 → gz_ros2_control 拿不到 URDF → 无限等待卡死
- /dev/shm 空间充足（3.8G 用 1.6M），非空间问题；非权限问题（owner=yep）

**证据**：
- 除 gazebo 外全部正常：RSP 加载双臂 URDF ✅、create spawn OK ✅、gripper_service/dual_move_server ready ✅
- gz_ros2_control 日志仅 `connected to service!!` + SIGINT，中间无输出（请求无响应）
- /dev/shm 残留 26 个 fastrtps 文件，且 **fastrtps_port7431 文件缺失**（创建失败的直接证据）
- 20:06 成功 / 20:47 失败：偶发竞争

**处置**：
1. 清理 /dev/shm 全部 fastrtps 残留文件（26 个 → 0）
2. 无残留进程

**防复发（可选）**：禁用 FastDDS SHM 传输（WSL2 下一直有 Permission denied 问题，本次升级为故障）：
FASTRTPS_DEFAULT_PROFILES_FILE 指向禁 SHM 的 XML（仅 UDPv4）→ 本机回环 UDP 无延迟损失，真机同样适用。
