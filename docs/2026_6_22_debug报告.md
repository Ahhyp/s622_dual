# 2026-06-22 坐标转换链 Debug 报告

## 背景

本报告记录对 S622 机械臂视觉伺服系统中 **pixel → 3D → base_link** 坐标转换链的系统性诊断过程。

核心目标：确认在当前相机位姿 `(0.35, 0.5, 0.9, rpy=0, 58°, -90°)` 下，YOLO OBB 检测像素 + depth 图反投影到 base_link 坐标的精度，并排查误差来源。

---

## 1. 实验 E1/E2/E2b 设计与代码修改

### 1.1 实验 E1：理论深度闭环

**目的**：验证内参 + TF + 投影/反投影公式的数学正确性。不读 depth 图，只用 GT 正向投影的理论深度 Z_gt。

**流程**：
```
GT 3D 中心 → base_to_camera → P_cam_gt → 取 Z_gt → 反投影 → 与 GT 比较
```

**修改文件**：[verify_coordinate_chain.py](../src/visual_servo/visual_servo/scripts/verify_coordinate_chain.py)

### 1.2 实验 E2：可见表面点

**目的**：GT 投影像素 + 真实 depth 图 → 反投影，检查表面点是否在方块体积内。

**关键修改**：
- 深度采样像素与反投影像素一致（都用整数像素 ui, vi）
- 方块体积判断加 3mm tolerance（深度图离散 + 5×5 patch 边缘 + Gazebo 采样误差）

### 1.3 实验 E2b：Ray-box 理论表面点验证

**目的**：对 GT 中心像素射线计算与方块 AABB 的理论入射交点，对比 depth 图实际返回的表面点。直接回答 "depth 图在这个像素返回的是不是理论上方块应该出现的表面点"。

**核心方法**：`ray_box_intersection_depth_z()`
```
P_cam(Z) = Z * [(u-cx)/fx, (v-cy)/fy, 1]    ← 不归一化，Z 即 optical Z
P_base(Z) = cam_t + cam_R @ P_cam(Z)          ← 转入 base 系
标准 slab 方法求 P_base(Z) 与方块 AABB 的交点
```

**判定标准**：|ΔZ| < 10mm 且 surface_err < 10mm。

### 1.4 E2b 移入 collect 脚本

**原因**：原 verify 脚本读取 live depth 图，但 collect 结尾 `remove_box()` 后场景无方块，E2/E2b 验证的是"无方块时的 depth"。

**修改**：在 [collect_calib_data.py](../src/visual_servo/visual_servo/scripts/collect_calib_data.py) 中，每位置 spawn 方块后当场执行 E2b，结果写入 CSV。确保 depth 数据与场景状态同步。

### 1.5 其他 collect 脚本修改

| 修改项 | 说明 |
|--------|------|
| CSV 路径 | 统一为 `calib_data_current_camera.csv` |
| spawn yaw | 从 0.5 改为 0（标定阶段轴对齐） |
| DEPTH_WINDOW | 从 9 改为 5（减少边缘/背景混合） |
| 检测选择 | 从 `results[0]` 改为 `max(confidence)` |
| TF 记录 | 每位置记录 camera TF（tx,ty,tz,qx,qy,qz,qw） |
| 时间戳 | 新增 rgb_stamp, depth_stamp, detection_stamp |
| CSV E2b 列 | gt_u, gt_v, z_depth_at_gt, z_expected, depth_minus_expected_mm, surface_err_mm, surface_inside_box, ray_hit_box |
| transform 时间戳 | 用 depth_header_stamp 替代 `rclpy.time.Time()` |

## 3. 两个嫌疑排查

### 3.1 嫌疑一：5×5 median patch 混入背景

**排查方法**：在 E2b 中打印 GT 像素处 5×5 patch 的 depth 分布（center / min / p10 / median / p90 / n_valid）。

**结果**：

| 位置 | GT pixel | min | p10 | median | p90 | n_valid |
|------|----------|-----|-----|--------|-----|---------|
| 中心 | (336,258) | 0.9268 | 0.9268 | 0.9293 | 0.9317 | 25/25 |
| 近臂左 | (364,351) | 0.9186 | 0.9186 | 0.9207 | 0.9229 | 25/25 |
| 远臂右 | (300,385) | 0.8836 | 0.8836 | 0.8856 | 0.8875 | 25/25 |
| 近臂右 | (356,157) | 1.1867 | 1.1867 | 1.1903 | 1.1939 | 25/25 |
| 远臂左 | (312,180) | 1.0320 | 1.0320 | 1.0350 | 1.1537 | 25/25 |
| 中左 | (321,306) | 0.9063 | 0.9063 | 0.9143 | 0.9706 | 25/25 |
| 中右 | (321,215) | 0.9820 | 0.9820 | 0.9847 | 0.9875 | 25/25 |

所有位置 n_valid=25/25。除远臂左和中左外，p10–p90 spread ≤ 5mm。

**结论**：5×5 patch 未混入背景，median 是纯净的 depth。p10 与 median 几乎一致，patch mixing 嫌疑排除。

### 3.2 嫌疑二：Gazebo 内部 model pose ≠ spawn 坐标

**排查方法**：每位置 spawn 后调 `ign model -m target_box --pose`，读 Gazebo 记录的实际 model origin。

**Gazebo 原始输出**：

7/7 位置 Gazebo pose 精确等于 spawn 请求值，偏差 0.000mm。rpy 全为零。

**结论**：Gazebo model pose 嫌疑排除。SDF 模型几何（link pose=0.02, box size=0.10×0.06×0.04）与 `compute_actual()` 的 `(spawn_x, spawn_y, spawn_z+0.02)` 完全一致。

## 5. 总体结论

### 5.1 已确认的事实

| # | 事实 | 证据 |
|---|------|------|
| 1 | **内参 + TF + 投影/反投影 数学链无 bug** | 实验 E1：全部 0μm；实验 A：全部 0.000px |
| 2 | **GT 投影与 YOLO 检测基本一致** | 实验 B：Δ = (0.3±1, 6.7±20)px |
| 3 | **5×5 median depth 纯净，未混入背景** | 全部 n_valid=25/25, spread ≤ 5mm |
| 4 | **Gazebo model pose 精确等于 spawn 坐标** | 7/7 偏差 0mm |
| 5 | **SDF 模型几何与代码假设一致** | link pose=0.02, size=0.10×0.06×0.04 |
| 6 | **YOLO 像素 + depth → base 水平偏差：X 方向 1.6mm, Y 方向 25.1mm** | 7 位置统计 |
| 7 | **中心位置 E2b 通过（ΔZ=−5.8mm），corner 位置 E2b 失败** | 2/7 通过 |
| 8 | **GT 中心投影像素在 corner 位置对应的是地面（z≈0.03），不是方块表面（z≈0.07–0.09）** | E2b-patch depth vs Z_expected |

### 5.2 误差来源分析

当前 pixel→base 的 39mm 平均偏差**不是代码 bug**，而是**方法本身的限制**：

1. **YOLO OBB 中心 ≠ 3D 几何中心投影**（已知）：OBB 框的是可见轮廓，不是 3D 体积。这导致 Y 方向偏差 25.1mm。
2. **GT 中心投影像素在斜视角度下不落在方块可见表面上**：相机从右侧俯视（58° tilt + 90° yaw），GT 中心投影在 corner 位置落在地面上而非方块上。这说明"GT 中心像素"本身就不适合作为 depth 采样点。
3. **Δz 的主要成分是方块上表面距离中心的偏移（约 20mm）**：YOLO 中心通常打在方块上表面附近（z≈0.09），而非中心（z=0.07）。

### 5.3 对后续工作的影响

- **不能用 YOLO 像素 + 单点 depth 做盲降抓取定位**：水平偏差 2-4cm 无法满足抓取精度要求。
- **2D 图像空间视觉伺服是正确方向**：伺服在图像空间闭环，不需要精确的 3D 坐标转换。
- **GT 像素不适合做 depth 验证**：斜视角度下 GT 中心射线的第一个可见表面不是方块。只有 YOLO 像素（落在可见表面上的像素）才适合 depth 验证。
- **降策略需要补偿**：盲降过程中 EE 在图像上会漂移，需要持续 2D 伺服补偿，或用 "YOLO 像素射线 ∩ z=目标高度平面" 求交替代单点 depth 反投影。
