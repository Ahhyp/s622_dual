## 6. 遗留问题：gazebo NaN 速度报错（本次修复）

用户终端出现：
```
[ign gazebo-1] [Err] [JointFeatures.cc:157] Invalid joint velocity value [nan]
commanded on joint [left_finger2_joint DOF 0]. The command will be ignored
```

**根因（2026-08-26 实测确认）**：双臂 `s622_gazebo_ros2_control.xacro` 中
**finger 关节缺 `<state_interface name="velocity" />`**（手臂关节有、手指没有）。

证据链（nan_diagnose v2 实测）：
- JSB `/joint_states`：**position 全正常**（POS-NaN joints: {}），
  **velocity 四手指恒 NaN**（各 4842 帧，全程）
- gz 原生 joint_state：手指 velocity **正常**（4.87e-16）→ gazebo 物理层无问题
- 缺 velocity state interface → ros2_control 手指 velocity 无数据 → JSB 发 NaN；
  gz_ros2_control `read()` 无判空读 `JointVelocity` 组件 → write() POSITION 分支
  `target_vel = -gain*(pos-cmd)*100` 得 NaN → gazebo `[Err] commanded NaN`

**修复**：`s622_gazebo_ros2_control.xacro` 给 `finger1_joint/finger2_joint`
补 `<state_interface name="velocity" />`（左右臂各一份，共 4 处由 macro 展开）。

> 注：joint_limits.yaml 补齐双臂条目（上一轮）解决的是 TOTG 警告（夹爪段已消失），
> 与本次 NaN 是**两个独立问题**——本轮实测确认 NaN 来自 velocity state interface 缺失。

**验证**：xacro 展开 OK，`state_interface name="velocity"` 共 16 处（手臂 12 + 手指 4）。
需重启仿真生效 → 观察：
1. `/joint_states` 手指 velocity 不再 NaN
2. gazebo 终端不再报 [Err] commanded NaN

> ⚠️ **2026-08-27 批注（重要）**：以上 velocity state interface 修复**仅为 gz_ros2_control
> 仿真插件所需**（read() 无判空读 JointVelocity 组件）。**真机机械臂只有位置控制接口能用**：
> `fairino_hardware` 插件强制 command=position、只导出 position state，velocity/effort 均不支持
> （真机 `/joint_states` 的 velocity 恒 NaN 为正常）。真机 ros2_control 块/控制器配置必须用
> position 命令接口（见 `docs/2026-08-26_真机部署_IP参数化/README.md` 的
> "⚠️ 真机控制接口能力边界"章节）。
