有办法，而且你现在这个阶段很常见。机械臂能动但没夹中红色方块，通常来自这几类误差：

```text
1. 相机外参误差：camera_color_optical_frame → base_link 不准
2. 深度误差：目标 3D 点算偏了
3. YOLO OBB 中心点误差：检测框中心不等于真实抓取中心
4. grasp_frame / 夹爪 TCP 定义误差：你以为末端中心在两指中间，但实际不是
5. yaw 方向误差：OBB angle 和夹爪闭合方向差 90 度或有固定偏移
6. 执行阶段锁定目标后，遮挡期间无法继续视觉修正
7. descend_z 或夹爪闭合时机不合适
```

我建议按“先工程补偿，再系统标定”的路线处理。

---

# 1. 先判断偏差类型

你先观察 3 次抓取，记录偏差方向：

## 情况 A：每次都往同一个方向偏

例如每次都偏右 3cm、偏前 2cm。

这通常是：

```text
TF 外参误差
grasp_frame 偏移
相机安装位姿误差
固定工具中心偏差
```

解决：加固定 offset 或重新标定 TF。

---

## 情况 B：靠近图像中心准，边缘偏得厉害

这通常是：

```text
相机内参不准
深度图和彩色图未对齐
pixel_to_camera 模型或 depth 尺度有问题
```

解决：检查 CameraInfo、深度对齐、内参、深度取值方式。

---

## 情况 C：位置对了，但夹爪方向不对

例如夹爪横着夹，物体长边方向不对。

这通常是：

```text
OBB angle 和夹爪 yaw 定义不一致
需要 yaw_offset
可能需要 angle + π/2
```

解决：加 `grasp_yaw_offset` 参数。

---

## 情况 D：到目标上方准，但下降后偏

这通常是：

```text
servo 下降方向不是你以为的 base z
末端姿态有偏
夹爪 TCP 不在 grasp_frame 原点
servo 控制或碰撞约束造成偏移
```

解决：检查 `grasp_frame`、EE frame 和下降轨迹。

---

# 2. 最快可用的工程修正：加目标补偿 offset

这是最实用的第一步。

你可以在 `visual_servo_node.py` 里加一个参数：

```python
self.declare_parameter("grasp_target_offset_base", [0.0, 0.0, 0.0])
```

读取参数：

```python
self.grasp_target_offset_base = np.array(
    list(self.get_parameter("grasp_target_offset_base").value),
    dtype=float,
)
```

然后在 `_observe_target_in_base()` 算出 `target_base` 后，加补偿：

```python
target_base_raw = np.array([
    pt_base.point.x,
    pt_base.point.y,
    pt_base.point.z,
], dtype=float)

target_base = target_base_raw + self.grasp_target_offset_base
```

建议日志打印 raw 和 corrected：

```python
self.get_logger().info(
    f"target correction | "
    f"raw=({target_base_raw[0]:+.4f}, {target_base_raw[1]:+.4f}, {target_base_raw[2]:+.4f}) "
    f"offset=({self.grasp_target_offset_base[0]:+.4f}, "
    f"{self.grasp_target_offset_base[1]:+.4f}, "
    f"{self.grasp_target_offset_base[2]:+.4f}) "
    f"corrected=({target_base[0]:+.4f}, {target_base[1]:+.4f}, {target_base[2]:+.4f})",
    throttle_duration_sec=1.0,
)
```

比如你发现机械臂总是落在方块右边 2cm，假设 base_link 下应该往 `y` 负方向修：

```bash
-p grasp_target_offset_base:="[0.0, -0.02, 0.0]"
```

如果总是停在目标前方 3cm，就改 `x`：

```bash
-p grasp_target_offset_base:="[-0.03, 0.0, 0.0]"
```

这个方法适合快速验证。

# 3. 加 yaw offset，解决夹爪方向偏差

你现在是：

```python
self.planned_yaw = float(det.angle)
```

建议加参数：

```python
self.declare_parameter("grasp_yaw_offset", 0.0)
```

读取：

```python
self.grasp_yaw_offset = float(
    self.get_parameter("grasp_yaw_offset").value)
```

然后改：

```python
self.planned_yaw = float(det.angle) + self.grasp_yaw_offset
```

如果你发现夹爪方向和物体方向差 90 度，就试：

```bash
-p grasp_yaw_offset:=1.5708
```

或者：

```bash
-p grasp_yaw_offset:=-1.5708
```

这很常见，因为：

```text
OBB angle 表示物体长边方向
但夹爪闭合方向可能应该垂直于长边
```

所以 yaw 是否要加 `π/2`，必须实测。

# 4. 不要只取 OBB 中心那个深度点，改成 OBB 区域深度中值

你现在是：

```python
xyz_cam = self.estimator.pixel_to_camera(
    target.center_x,
    target.center_y,
    self.depth_img,
)
```

这有风险。因为 OBB 中心点可能：

```text
刚好落在物体边缘
落在空洞深度
落在背景
被机械臂遮挡
红盒子表面反光导致深度不稳定
```

更稳的做法是：

```text
在 OBB 中心附近取 5x5 / 9x9 / 15x15 深度窗口
使用 median depth
```

你已经有 `_debug_depth_at_pixel()`，下一步可以把 `ErrorEstimator.pixel_to_camera()` 改成支持窗口中值，或者在 `visual_servo_node` 里先算一个稳健深度。

思路：

```python
def _get_median_depth(self, u, v, window=9):
    h, w = self.depth_img.shape[:2]
    x = int(round(u))
    y = int(round(v))

    r = window // 2
    x0 = max(0, x - r)
    x1 = min(w, x + r + 1)
    y0 = max(0, y - r)
    y1 = min(h, y + r + 1)

    patch = self.depth_img[y0:y1, x0:x1]
    valid = patch[np.isfinite(patch)]
    valid = valid[valid > 0.0]

    if valid.size == 0:
        return None

    return float(np.median(valid))
```

然后用这个 depth 算 3D，而不是中心单点。

如果你以后想更准，可以在整个 OBB 内采样深度，而不是只取中心附近。

# 5. 检查 `grasp_frame` 是否真的是夹爪中心

你现在用：

```python
self.declare_parameter("ee_frame", "grasp_frame")
```

伺服控制认为：

```text
grasp_frame 的原点 = 两指夹取中心
```

但如果 URDF 里 `grasp_frame` 实际偏在手腕、法兰、某个手指附近，那就会“看起来位置到了，但夹不到”。

检查方法：

```bash
ros2 run tf2_ros tf2_echo base_link grasp_frame
```

在 RViz 里打开 TF，观察 `grasp_frame`：

```text
它是否在两个手指中间？
z 轴是否朝下？
x/y 轴是否和夹爪开合方向一致？
```

如果 `grasp_frame` 不在两指中间，最正确的做法是改 URDF/Xacro，加一个真正的 TCP frame，例如：

```text
gripper_tcp
```

位置在两指中间、夹爪闭合中心。

然后参数改成：

```bash
-p ee_frame:=gripper_tcp
```

这比盲目 offset 更根本。

发布三个 marker：

```text
target_raw：相机算出来的目标点
target_corrected：补偿后的目标点

```

你会一眼看到：

```text
是视觉目标点算偏了？
还是 EE frame 不在夹爪中心？
还是 MoveIt 到了但 servo 没到？
```

建议你下一步加一个 `/visual_servo/debug_markers`。

最少先打印这几个数：

```text
target_base raw
target_base corrected
hover goal
descend goal
ee pose
final error
```

你已经打印了一部分，再加 raw/corrected 就够了。

# 7. 如果是系统误差，不要只调一个点

你应该在 3 个位置测试红盒子：

```text
左侧
中间
右侧
```

记录视觉计算的 `target_base` 和实际方块位置。

判断方式：

## 所有位置都差不多偏同一个量

加 `grasp_target_offset_base` 就能解决。

## 越靠边偏得越大

这是相机模型/外参问题，应该标定：

```text
camera intrinsics
camera optical frame 到 base_link 的 TF
depth/color alignment
```

## z 高度偏差明显

检查：

```text
depth 单位
物体高度
descend_offset_z
grasp_frame z 方向
```

# 8. 当前最推荐的落地方案

你现在先不要上复杂标定，按这个顺序来：

## Step 1：加 base offset 参数

```bash
-p grasp_target_offset_base:="[0.0, 0.0, 0.0]"
```

然后观察偏差。

例如实际夹爪落点比方块中心偏 `+y 2cm`，那就试：

```bash
-p grasp_target_offset_base:="[0.0, -0.02, 0.0]"
```

## Step 2：加 yaw offset 参数

先试：

```bash
-p grasp_yaw_offset:=0.0
```

如果夹爪方向差 90 度：

```bash
-p grasp_yaw_offset:=1.5708
```

或者：

```bash
-p grasp_yaw_offset:=-1.5708
```

## Step 3：确认 `grasp_frame`

如果 fixed offset 要调很多，比如 5cm 以上，优先怀疑 `grasp_frame` 不是真 TCP。

## Step 4：把深度取值改成窗口 median

减少单点深度噪声。

## Step 5：再考虑重标定相机外参

# 10. 我的判断

你现在最可能的问题是这两个之一：

```text
1. grasp_frame / 夹爪 TCP 和实际夹取中心有固定偏差
2. 目标 3D 点从像素 + 深度转换到 base_link 后有固定外参偏差
```

如果偏差每次方向都差不多，最快解决是：

```text
加 grasp_target_offset_base
```

如果夹爪方向不对，最快解决是：

```text
加 grasp_yaw_offset
```

如果偏差随目标位置变化明显，再去做完整相机外参标定。
