## 中等问题

### 1. S6.9 planning_core CMakeLists.txt：`add_library` 缺少 `SHARED`

```cmake
# 文档写的
add_library(${PROJECT_NAME}
  src/dh_kinematics.cpp ...
)

# 应该是
add_library(${PROJECT_NAME} SHARED
  src/dh_kinematics.cpp ...
)
```

不加 `SHARED` 在 Linux 上默认生成静态库（`.a`），后续 `fairino_planning_ros` 作为 pluginlib 插件需要动态链接。原项目的 CMakeLists.txt 是带了 `SHARED` 的。

### 2. S6.9 planning_core CMakeLists.txt：缺少 nanoflann 集成

原项目的 CMakeLists.txt 有完整的 nanoflann `find_path` + `FetchContent` 回退逻辑。文档中完全没提 nanoflann。RRT 树需要 KD 树加速近邻搜索，没有 nanoflann 就只能线性扫描（O(n) vs O(log n)），性能差距巨大。

建议至少加一段说明：

```cmake
find_path(NANOFLANN_INCLUDE_DIR
  NAMES nanoflann.hpp
  HINTS /usr/include /usr/local/include)
target_include_directories(${PROJECT_NAME} PUBLIC ${NANOFLANN_INCLUDE_DIR})
```

### 3. S13.2 control_servers：FastAPI 与 ROS 2 的通信方式未说明

`app/main.py` 是一个纯 FastAPI 应用，但文档没有说明它如何和 ROS 2 通信。原项目的 `control_servers/joint_control_app.py` 是 FastAPI + rclpy 混合节点（在同一个进程里跑 HTTP server 和 ROS 2 node）。文档建议分成两个文件（`app/main.py` + `control_servers/joint_control_app.py`），但没有解释它们之间的桥接方式。

### 4. S7.2 fairino_planner_manager.h：缺少 PlanningContext 实现

文档的 `FairinoPlannerManager` 声明了 `getPlanningContext()` 方法，但没有给出 `FairinoPlanningContext` 类的声明。MoveIt2 的规划流程是：

```
PlannerManager::getPlanningContext() → PlanningContext → PlanningContext::solve()
```

原项目虽然没有独立的 context 文件（solve 逻辑在 planner_manager 里），但返回的 context 对象仍需要实现 `solve()` 虚函数。文档缺少这部分的说明。

### 5. S16 分批编译：缺少 `--merge-install`

文档最后全量编译用的是：

```bash
colcon build --symlink-install
```

但项目实际使用的是 `--merge-install --symlink-install`。这两种模式不兼容——如果前面用 merge 模式编译，后面用 isolated 模式会导致 install 路径不一致。建议全文统一为 `--merge-install --symlink-install`。

## 建议改进

### 6. S3.3 fairino_hardware：建包命令过长

```bash
ros2 pkg create fairino_hardware --build-type ament_cmake --dependencies rclcpp hardware_interface pluginlib controller_manager fairino_msgs
```

7 个依赖挤在一行，可读性差。建议换行或分行写。另外 `controller_manager` 作为依赖可省略——它不是 link-time 依赖，只是运行时加载硬件接口的框架。

### 7. S6.2 dh_kinematics.h：`explicit` 多余

```cpp
explicit DHKinematics(const std::array<DHParam, DOF>& dh_params);
```

单参数构造函数加 `explicit` 是对的，但 `std::array<DHParam, DOF>` 不存在隐式转换的场景，不加 `explicit` 也不会出问题。不改也行，不影响正确性。

### 8. S6.1 types.h：未包含 `<random>`

`types.h` 没有定义 `std::mt19937` 或 `rng_`，但 `rrt_star.h` 里声明了 `std::mt19937 rng_`。如果在 `rrt_star.h` 中 include `<random>` 就没问题——但文档没写。建议在 `rrt_star.h` 代码模板中补上 `#include <random>`。

### 9. S7.1 moveit_collision_checker.h：缺少 `#include <memory>`

`planning_scene::PlanningSceneConstPtr` 是 `std::shared_ptr` 的 typedef，需要 `<memory>` 头文件。

### 10. S3.3 command_server 代码：service 创建出错时未处理

```cpp
srv_ = create_service<fairino_msgs::srv::RemoteCmdInterface>(
    "fairino_remote_cmd",
    [this](auto request, auto response) { ... });
```

服务可能因为 topic 名冲突等原因创建失败。生产代码应该检查返回值，但学习模板不需要，可以接受。

### 11. S10.4 servo_controller.py：视觉伺服维度简化

文档的 `ServoController` 只做了 2D 像素空间（x, y）的 PD 控制。原项目是完整的 6D 笛卡尔空间伺服（发布 `TwistStamped` 给 MoveIt Servo）。作为学习模板的第一版可以接受，但建议在文档中注明后续版本的升级方向。

### 12. S10.10 状态机：大部分状态直接跳转到下一个

```python
elif self.state == ServoState.SEARCHING:
    if self.detection_cache.get() is not None:
        self.set_state(ServoState.TARGET_FOUND)
```

目前除 SEARCHING 外，所有状态无条件跳转。这是学习模板的设计——先把状态枚举和骨架跑通，再逐个补充转移条件。建议在文档中加一行注释说明这是 intentional。

### 13. S17 Demo 4：`ros2 control` 命令需要确认是否安装

```bash
ros2 control list_controllers
```

这个命令需要 `ros2controlcli` 包。建议在文档中注明：

```bash
sudo apt install ros-humble-ros2controlcli
```

### 14. S3.1 display.launch.py：joint_state_publisher_gui 无默认配置

`joint_state_publisher_gui` 在没有配置的情况下会把所有 joint 的默认值设为 0，可能导致机械臂处于奇异位姿。建议添加 `--ros-args -p zeros:=...` 设置合理的初始关节角。

### 15. S4 camera.xacro 小节：标题有但内容未展开

文档提到了 `camera.xacro 最小示例`，但没有实际展示 xacro 内容。从原项目看，这个文件约 30 行，包含相机 link、joint、sensor 配置。建议补全或标记为 TODO。

### 16. S5.1 s622_moveit_config：说"推荐"建包但实际是从原项目复制

文档的建包命令是 `ros2 pkg create`，但 MoveIt2 配置包的正确创建方式是用 Setup Assistant 生成（`ros2 launch moveit_setup_assistant setup_assistant.launch.py`）。手工写 SRDF 和 kinematics.yaml 非常容易出错。建议保持 `ros2 pkg create` 的方式，但注明"学习阶段推荐手工写配置"。

### 17. S18.2 TF 调试：建议补充更常用的 TF 调试命令

```bash
ros2 run tf2_tools view_frames    # 生成 PDF（需要 evince）
ros2 run rqt_tf_tree rqt_tf_tree   # GUI 实时 TF 树，更直观
```

建议补充 `rqt_tf_tree`，它比 `view_frames` 更常用。

## 原项目一致性检查

| 文档描述 | 原项目实际 | 差异 |
|----------|-----------|------|
| `fairino_planning_core` namespace: `fairino_planning_core` | 原项目: `fairino_planning` | 不影响功能 |

## 总结

文档质量很高，作为主动式学习指南是合格的。5 个中等问题里，最关键的是 **#1（缺少 SHARED）** 和 **#2（缺少 nanoflann）**——这两个会导致 `fairino_planning_core` 编译失败或无法被 pluginlib 加载。建议优先修正。

其余问题大多属于"学习模板有意简化"或"小疏漏"，不影响按文档推进。
