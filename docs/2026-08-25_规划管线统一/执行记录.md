### 插曲：IK 一度返回 -31（NO_IK_SOLUTION）——**测试脚本姿态错误，非 bug**

**现象**：用纯 yaw 四元数 `(0,0,0.535,0.845)`（夹爪朝上）测 pregrasp 位姿 → fairino IK -31，KDL 成功。

**排查链**：
1. 本地复现解析 IK → GRIPPER 模型失败 `joint_limits`，FLANGE 成功
2. 对比 URDF：`wrist3_link→grasp_frame = 0.2168`，ik_core 工具偏移 `0.1168` → 一度怀疑工具偏移错
3. **确认配置正确**：0.2168 = d6(0.100) + 工具(0.1168)，插件 tool/URDF check pos_err=0
4. 本地 FK 验证：KDL 解代入 FairinoIK FK，GRIPPER 模型 pos err < 1e-5 ✅ 工具模型一致
5. **真相**：visual_servo 真实 pregrasp 姿态是 **roll=π（夹爪朝下）+ yaw**，四元数 `(0.845,0.535,0,0)`；我用纯 yaw（夹爪朝上）构造了不可达姿态 → 解析候选 j2 全部超限（+177.8° vs 上限 85°，等价角 -182.2° 合法但解析 IK 不归一化 wrap）

**教训**：验证 IK/规划时必须用系统真实姿态（roll=π 夹爪朝下），不能随手构造四元数。
