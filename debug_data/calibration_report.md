## 一、6 项标定检查

### 1. RGB-Depth 对齐 ✅ PASS

Gazebo rgbd_camera 传感器配置中，color 和 depth 共享同一 `optical_frame_id=camera_color_optical_frame`（[rgbd_camera.gazebo.xacro:90](src/realsense2_gz_description/urdf/rgbd_camera.gazebo.xacro#L90)）。

在 Gazebo 内部，rgbd_camera 传感器天然输出对齐的彩色图和深度图——因为两者共用同一个光学帧，投影中心一致。**不需要** `aligned_depth_to_color` 话题。

### 2. 深度单位 ✅ PASS

Gazebo `rgbd_camera` 传感器输出 `float32`（32FC1 编码），单位 **米**。

验证依据：
- 地面物体（实际 z≈0.02m）经 pixel→3D→TF→base 后 z 误差 ≤1cm（旧相机位姿下）
- `error_estimator.py` 中 Z 值直接使用，不做 mm→m 转换
- 深度图均值约 0.8~1.2m，与相机距桌面距离（约 0.9m 斜距）一致

### 3. 相机内参 ✅ PASS

内参完全由 Gazebo FOV + 分辨率自动计算，无手动输入错误。

| 参数 | 计算值    | 公式               |
| ---- | --------- | ------------------ |
| fx   | **465.6** | `320 / tan(34.5°)` |
| fy   | **625.2** | `240 / tan(21°)`   |
| cx   | 320.0     | `640/2`            |
| cy   | 240.0     | `480/2`            |

与实际 `/camera/color/camera_info` 输出一致（实测 fx=465.6, fy=625.2）。

⚠️ **注意**：fx ≠ fy（465.6 vs 625.2），这意味着 x 和 y 方向的像素尺度不同。在倾斜相机下，这种不对称会放大边缘像素的变换误差。

### 4. T_base_camera（相机外参）⚠️ WARN

| 项目        | 值                                                            |
| ----------- | ------------------------------------------------------------- |
| 位置        | base_link 系 (0.5, -0.2, 0.7)                                 |
| 姿态 (rpy)  | (0, 55°, π) = roll=0, pitch=55°, yaw=180°                     |
| 效果        | 相机在机器人前方 0.5m、左侧 0.2m、高 0.7m，回头俯视机器人基座 |
| TF 链正确性 | ✅ 经 `projection_chain_debug_node` 验证，TF 链数学正确        |

**问题**：倾斜 55° 的侧视相机导致图像轴与 base 轴存在复杂的交叉耦合：
- `du`（图像水平）↔ 同时受 `base_x` 和 `base_y` 影响
- `dv`（图像垂直）↔ 同时受 `base_x` 和 `base_z` 影响
- 对角形式的 `j_img_to_base` 矩阵无法正确描述此映射

这不是 bug，而是固定倾斜相机的几何特性。需要非对角 Jacobian 矩阵，或改为垂直俯视。

### 5. TCP / grasp_frame ⚠️ WARN

```
wrist3_link
  ├── finger1_joint: xyz=(-0.01, -0.0001, 0.1658)  ← 手指1关节
  ├── finger2_joint: xyz=(+0.01, +0.0001, 0.1658)  ← 手指2关节
  └── grasp_frame:   xyz=(0, 0, 0.2168)              ← TCP
```

- 手指关节中心在 wrist3_link 系 z=**0.1658m**
- grasp_frame 在 wrist3_link 系 z=**0.2168m**
- grasp_frame 比手指关节远 **5.1cm**

这 5.1cm 偏移应等于手指从关节到指尖的长度。如果是正确的，grasp_frame 恰好落在两指闭合中心。如果手指实际长度不是 5.1cm，TCP 将偏离实际夹取点。

**建议**：在 Gazebo 中用 TF 可视化确认 grasp_frame 是否在两指中间。

### 6. 桌面高度标定 ✅ PASS

- Gazebo 地面在 z=0（世界系即 base_link 系）
- `target_box` 模型高 4cm，link pose z_offset=0.02m，落地后中心 z≈0.02m
- 旧版相机位姿下（79° 俯视），地面物体 z 估算误差 ≤1cm

## 三、误差根因分析

### 新旧相机误差模式对比

**旧相机（79° 俯视）**：Δy 主导，Δx/Δz 极准

- 相机几乎垂直俯视（79°），光轴接近 -z 方向
- fx≠fy（465.6 vs 625.2）在倾斜 79° 下将像素 v 的误差放大投影到 base_y
- 物体越靠图像边缘（pixel_v 小），y 偏移越大（+160mm）
- **x 和 z 精度极好**（≤11mm）— 因为光轴接近垂直，深度准确

**新相机（55° 俯视，yaw=π）**：Δx/Δz 主导，Δy 准

- 相机倾斜 55° 回头看，光轴在 base_xz 平面有很大分量
- 深度误差主要投影到 base_x 和 base_z（光轴方向的分量）
- Δz 恒定为 **+56mm**（std=4mm，极一致），Δx 系统性 **-49mm**
- **y 精度极好**（±10mm）— 因为光轴在 y 方向分量小

### 根本原因

**两个相机位姿都无法同时保证 x、y、z 三轴精度**。倾斜相机下：

1. 光轴方向（深度方向）的误差会投影到 base 系的两个轴上
2. fx≠fy 不对称 + 图像边缘效应会放大垂直于光轴方向的误差
3. 仿真中的深度噪声和 pixel→3D 反投影误差无法通过改参数消除

**这是固定外置倾斜相机的固有几何限制，不是代码 bug。**

### P0 即时行动：用实测数据标定 j_img_to_base

从 6 个位置的实测数据反算图像→base 映射（新相机 0.5,-0.2,0.7, 55°,π）：

- 物体 y: -0.20→+0.15 (Δy=0.35m), pixel_u: 344→607 (Δu=263px)
  → **∂u/∂y ≈ 263/0.35 = 751 px/m**
- 物体 x: 0.30→0.40 (Δx=0.10m), pixel_v: 401→465 (Δv=64px)
  → **∂v/∂x ≈ 64/0.10 = 640 px/m**

因此 j_img_to_base ≈ inverse([[∂u/∂x, ∂u/∂y], [∂v/∂x, ∂v/∂y]])，推荐：

```bash
ros2 run visual_servo visual_servo_node --ros-args \
  -p j_img_to_base:="[0.0, 0.0013, 0.0016, 0.0]"
```

## 五、结论

1. **6 项标定指标中，4 项 PASS，2 项 WARN**。没有配置错误，系统软件层面正确。
2. **3D pixel→base 坐标在任何倾斜相机下都有 ≥5cm 的系统误差**，仅误差方向不同：
   - 旧相机 (79°)：Δy=110mm, Δx=4mm, Δz=5mm
   - 新相机 (55°)：Δz=56mm, Δx=49mm, Δy=10mm
3. **新相机 y 精度大幅改善**（110mm → 10mm），适合 2D 图像伺服中对 y 轴（du 方向）的精调。
4. **`j_img_to_base` 已用实测数据标定**：`[0.0, 0.0013, 0.0016, 0.0]`，du→base_y, dv→base_x，匹配新相机交叉耦合特性。
5. **盲降 z 建议加 +56mm 补偿**，用 `grasp_target_offset_base:="[0.0, 0.0, -0.056]"` 抵消 Δz 系统偏移。
6. 若需要 3D 坐标同时精确，唯一办法是相机改为垂直俯视（pitch=90°），消除光轴分量交叉投影。
