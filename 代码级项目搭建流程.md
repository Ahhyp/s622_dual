## 1. 项目总目标

你要搭建的不是一个单包 demo，而是一个完整机械臂智能抓取工程：

```text
机器人模型
  ↓
ROS 2 消息与硬件接口
  ↓
ros2_control 控制链路
  ↓
MoveIt2 规划执行
  ↓
Gazebo 仿真
  ↓
自研运动学 / IK / RRT / BiRRT*
  ↓
MoveIt2 planner / IK 插件
  ↓
YOLOv8 / OBB 感知
  ↓
手眼标定
  ↓
视觉伺服抓取
  ↓
OctoMap / GraspNet 高级抓取
  ↓
Web 控制 / 数据监控 / 工作流编排
```

主动式学习的核心原则：

```text
每一阶段都必须有：
1. 明确能力目标
2. 对应包
3. 关键文件
4. 最小代码骨架
5. 编译命令
6. 运行命令
7. 验收标准
8. 主动学习任务
```

### 3.4 编译约定

全文统一使用：

```bash
colcon build --merge-install --symlink-install
```

不要混用：

```bash
colcon build --symlink-install
```

原因：

```text
--merge-install 模式下所有包安装到同一个 install/ 前缀；
isolated 模式下每个包安装到 install/<package_name>/。
两种模式混用会导致 setup.bash、pluginlib 路径、资源索引不一致。
```

### 5.2 四个核心配置文件

#### robot_gazebo.urdf.xacro

**作用：** 把 s622 的 URDF 和 ros2_control xacro 拼在一起，包上 Gazebo 仿真标签。是所有 Gazebo 相关 xacro 的入口。

**功能拆解：**
- `<xacro:include>` 引入 `s622_moveit_descriptions` 的 URDF 本体（机械臂几何+运动学）
- `<xacro:include>` 引入 `s622_moveit_config` 的 `ros2_control.xacro`（joint interface 定义）
- `<gazebo>` 块声明三个插件：
  - `gz_ros2_control` — 让 Gazebo 跑 ros2_control 的控制器
  - `JointStatePublisher` — 发布 joint 状态到 Gazebo topic
  - `PosePublisher` — 发布 link 位姿
- `<gazebo reference="...">` 给夹爪 joint 设摩擦/刚度参数（防抖）
- 最后调用 `<xacro:s622_moveit_descriptions_ros2_control>` 实例化 ros2_control 标签

**模板（无相机版）：**

```xml
<?xml version="1.0"?>
<robot xmlns:xacro="http://www.ros.org/wiki/xacro" name="s622">
    <xacro:arg name="initial_positions_file"
        default="$(find s622_moveit_config)/config/initial_positions.yaml"/>

    <!-- 机械臂本体 URDF -->
    <xacro:include filename="$(find s622_moveit_descriptions)/urdf/s622_moveit_descriptions.urdf"/>

    <!-- Gazebo 仿真插件 -->
    <gazebo>
        <plugin filename="gz_ros2_control-system"
            name="gz_ros2_control::GazeboSimROS2ControlPlugin">
            <parameters>$(find s622_moveit_config)/config/ros2_controllers.yaml</parameters>
        </plugin>
        <plugin filename="gz-sim-joint-state-publisher-system"
            name="gz::sim::systems::JointStatePublisher"/>
        <plugin filename="gz-sim-pose-publisher-system"
            name="gz::sim::systems::PosePublisher">
            <publish_link_pose>true</publish_link_pose>
            <use_pose_vector_msg>true</use_pose_vector_msg>
            <publish_nested_model_pose>true</publish_nested_model_pose>
        </plugin>
    </gazebo>

    <!-- 夹爪摩擦参数（防 Gazebo 抖动） -->
    <gazebo reference="finger1">
        <mu1>500.0</mu1><mu2>500.0</mu2>
        <kp>30000</kp><kd>15</kd>
    </gazebo>
    <gazebo reference="finger2">
        <mu1>500.0</mu1><mu2>500.0</mu2>
        <kp>30000</kp><kd>15</kd>
    </gazebo>

    <!-- ros2_control 标签实例化 -->
    <xacro:include filename="$(find s622_moveit_config)/config/s622_moveit_descriptions.ros2_control.xacro"/>
    <xacro:s622_moveit_descriptions_ros2_control
        name="GazeboSimSystem"
        initial_positions_file="$(arg initial_positions_file)"/>
</robot>
```

### 5.3 gazebo.launch.py

**作用：** 按顺序启动 Gazebo → spawn 机械臂 → robot_state_publisher → ros2_control → MoveIt move_group → RViz。

**功能拆解：**
1. `IncludeLaunchDescription(ros_gz_sim/gz_sim.launch.py)` — 启动 Gazebo 空世界
2. `clock_bridge_node` — 把 Gazebo 的 Clock 消息桥接到 ROS `/clock`（仿真时间同步）
3. `robot_to_gazebo_node` — 用 `ros_gz_sim create` 把 xacro 生成的 URDF spawn 到 Gazebo
4. `robot_desc_node` — `robot_state_publisher` 发布 TF
5. `controller_spawner_node` — 延迟 5 秒后启动 `arm_controller` + `joint_state_broadcaster`
6. `move_group_node` — MoveIt2 move_group
7. `rviz_node` — RViz

**模板（无相机版）：**

```python
import os
from launch import LaunchDescription
from launch_ros.actions import Node
from launch.actions import DeclareLaunchArgument, IncludeLaunchDescription, TimerAction
from launch.launch_description_sources import PythonLaunchDescriptionSource
from launch.substitutions import LaunchConfiguration
from ament_index_python.packages import get_package_share_directory
from moveit_configs_utils import MoveItConfigsBuilder


def generate_launch_description():
    this_pkg = get_package_share_directory("gz_launch")
    robot_desc_pkg = get_package_share_directory("s622_moveit_descriptions")
    robot_moveit_pkg = get_package_share_directory("s622_moveit_config")

    # 1. Gazebo 空世界
    gazebo = IncludeLaunchDescription(
        PythonLaunchDescriptionSource([
            get_package_share_directory("ros_gz_sim") + "/launch/gz_sim.launch.py"
        ]),
        launch_arguments=[("gz_args", "empty.sdf -r")]
    )

    # 2. 时钟桥接
    clock_bridge = Node(
        package="ros_gz_bridge",
        executable="parameter_bridge",
        arguments=["/world/empty/clock@rosgraph_msgs/msg/Clock[gz.msgs.Clock"],
        parameters=[{"use_sim_time": True}],
        remappings=[("/world/empty/clock", "/clock")]
    )

    # 3. MoveIt 配置（告诉 move_group 用哪个 URDF/SRDF/kinematics）
    moveit_config = (
        MoveItConfigsBuilder("s622_moveit_descriptions", package_name="s622_moveit_config")
        .robot_description(this_pkg + "/config/robot_gazebo.urdf.xacro")
        .robot_description_semantic("config/s622_moveit_descriptions.srdf")
        .robot_description_kinematics(robot_moveit_pkg + "/config/kinematics.yaml")
        .planning_pipelines(pipelines=["ompl"], default_planning_pipeline="ompl")
        .to_moveit_configs()
    )

    # 4. Spawn 机械臂到 Gazebo
    gz_urdf = moveit_config.robot_description["robot_description"].replace(
        "package://s622_moveit_descriptions", robot_desc_pkg
    )
    spawn_robot = Node(
        package="ros_gz_sim",
        executable="create",
        arguments=["-string", gz_urdf,
                   "-x", "0.0", "-y", "0.0", "-z", "0.0",
                   "-R", "0", "-P", "0", "-Y", "0",
                   "-name", "robot_arm"]
    )

    # 5. robot_state_publisher
    robot_state_pub = Node(
        package="robot_state_publisher",
        executable="robot_state_publisher",
        parameters=[moveit_config.robot_description, {"use_sim_time": True}]
    )

    # 6. 控制器（延迟 5s 等 Gazebo 就绪）
    ros2_controllers_yaml = os.path.join(
        robot_moveit_pkg, "config", "ros2_controllers.yaml"
    )
    controller_spawner = TimerAction(
        period=5.0,
        actions=[
            Node(
                package="controller_manager",
                executable="spawner",
                arguments=["-p", ros2_controllers_yaml,
                           "robot_arm_controller",
                           "joint_state_broadcaster"],
                parameters=[{"use_sim_time": True}],
                output="screen"
            )
        ]
    )

    # 7. move_group
    move_group = Node(
        package="moveit_ros_move_group",
        executable="move_group",
        parameters=[moveit_config.to_dict(), {"use_sim_time": True}],
        output="screen"
    )

    # 8. RViz
    rviz_config = os.path.join(this_pkg, "rviz", "gz_launch.rviz")
    rviz = Node(
        package="rviz2",
        executable="rviz2",
        arguments=["-d", rviz_config],
        parameters=[moveit_config.robot_description,
                     moveit_config.robot_description_semantic,
                     {"use_sim_time": True}]
    )

    return LaunchDescription([
        gazebo, clock_bridge, spawn_robot, robot_state_pub,
        rviz, controller_spawner, move_group
    ])
```

### 12.3 types.h

```cpp
#pragma once

#include <array>
#include <cmath>
#include <vector>

#include <Eigen/Core>
#include <Eigen/Geometry>

namespace fairino_planning
{

constexpr int DOF = 6;

using JointArray = std::array<double, DOF>;
using JointPath = std::vector<JointArray>;
using Pose = Eigen::Isometry3d;

struct JointLimits
{
  JointArray lower;
  JointArray upper;
  JointArray velocity;
  JointArray acceleration;

  bool isWithin(const JointArray& q, double tol = 1e-6) const
  {
    for (int i = 0; i < DOF; ++i)
      if (q[i] < lower[i] - tol || q[i] > upper[i] + tol)
        return false;
    return true;
  }
};

struct PlanRequest
{
  JointArray start;
  JointArray goal;
  JointLimits limits;
  double step_size{0.05};
  double goal_tolerance{0.02};
  int max_iterations{5000};
};

struct PlanResult
{
  bool success{false};
  JointPath path;
  double planning_time{0.0};
  std::string message;
};

inline double wrapToPi(double angle)
{
  angle = std::fmod(angle + M_PI, 2.0 * M_PI);
  if (angle < 0) angle += 2.0 * M_PI;
  return angle - M_PI;
}

inline JointArray wrapToPi(const JointArray& q)
{
  JointArray result;
  for (int i = 0; i < DOF; ++i)
    result[i] = wrapToPi(q[i]);
  return result;
}

}  // namespace fairino_planning
```

说明：

```text
1. 原项目 namespace 可能叫 fairino_planning。
   文档统一采用 fairino_planning，避免和包名 fairino_planning_core 强绑定。
2. isWithin()：关节限位硬过滤，ik_selector 和规划算法都会用到。
3. wrapToPi()：角度归一化到 [-π, π]，FK/IK/规划中频繁使用。
```

### 12.5 fairino_ik.h + fairino_ik.cpp（解析逆运动学）

腕前点分离法，最多返回 8 组解（2×2×2 = 肩×肘×腕）。

**头文件：**

```cpp

private:

  DHKinematics fk_;

  static Eigen::Matrix3d R03(double q1, double q2, double q3);

  static std::vector<JointArray> uniqueSolutions(
      const std::vector<JointArray>& sols, double tol = 1e-5);
};

```

**实现文件（关键算法）：**

```cpp
#include "fairino_planning_core/ik/fairino_ik.h"
#include <cmath>
#include <algorithm>

namespace fairino_planning
{

FairinoIK::FairinoIK(const std::array<double, DOF>& d,
                     const std::array<double, DOF>& a,
                     const std::array<double, DOF>& alpha)
  : d_(d), a_(a), alpha_(alpha)
{
  std::array<DHParam, DOF> dh;
  for (int i = 0; i < DOF; ++i)
    dh[i] = {a[i], alpha[i], d[i], 0.0};
  fk_ = DHKinematics(dh);
}

Eigen::Matrix3d FairinoIK::R03(double q1, double q2, double q3)
{
  const double c1 = std::cos(q1), s1 = std::sin(q1);
  const double c23 = std::cos(q2 + q3), s23 = std::sin(q2 + q3);
  Eigen::Matrix3d R;
  R << c1*c23, -c1*s23,  s1,
       s1*c23, -s1*s23, -c1,
          s23,     c23,   0;
  return R;
}

std::vector<JointArray> FairinoIK::solve(const Pose& target) const
{
  const double d1 = d_[0], d4 = d_[3], d5 = d_[4], d6 = d_[5];
  const double L2 = std::abs(a_[1]);
  const double L3 = std::abs(a_[2]);

  const Eigen::Vector3d p = target.translation();
  const Eigen::Matrix3d R = target.rotation();
  const Eigen::Vector3d a = R.col(2);
  const double ax = a.x(), ay = a.y(), az = a.z();

  // Step 1: 腕前点
  const double xw = p.x() - d6 * ax;
  const double yw = p.y() - d6 * ay;
  const double zw = p.z() - d6 * az;

  // Step 2: q1 候选（肩左/肩右）
  const double rho_sq = xw*xw + yw*yw - d4*d4;
  if (rho_sq < -1e-10) return {};
  const double rho = std::sqrt(std::max(rho_sq, 0.0));
  const double q1_cands[2] = {
    std::atan2(yw, xw) - std::atan2(-d4,  rho),
    std::atan2(yw, xw) - std::atan2(-d4, -rho)
  };

  std::vector<JointArray> candidates;

  for (double q1 : q1_cands) {
    q1 = wrapToPi(q1);
    const double c1 = std::cos(q1), s1 = std::sin(q1);

    // Step 3: q5, q234
    double c5 = s1*ax - c1*ay;
    c5 = std::clamp(c5, -1.0, 1.0);
    const double s5_abs = std::sqrt(std::max(0.0, 1.0 - c5*c5));
    if (s5_abs < 1e-8) continue;  // 腕奇异跳过

    const double C = c1*ax + s1*ay;

    for (double s5 : {s5_abs, -s5_abs}) {
      const double q5 = std::atan2(s5, c5);
      const double c234 = -C / s5;
      const double s234 = -az / s5;
      const double q234 = std::atan2(s234, c234);

      // Step 4: 2R 平面三角形解 q2, q3
      const double Xp = c1*xw + s1*yw - d5*s234;
      const double Zp = zw - d1 + d5*c234;
      const double Xg = -Xp, Zg = -Zp;

      double D = (Xg*Xg + Zg*Zg - L2*L2 - L3*L3) / (2.0*L2*L3);
      if (D < -1.0 - 1e-10 || D > 1.0 + 1e-10) continue;
      D = std::clamp(D, -1.0, 1.0);
      const double s3_abs = std::sqrt(std::max(0.0, 1.0 - D*D));

      for (double s3 : {s3_abs, -s3_abs}) {
        const double q3 = std::atan2(s3, D);
        const double q2 = std::atan2(Zg, Xg) - std::atan2(L3*s3, L2 + L3*D);
        const double q4 = wrapToPi(q234 - q2 - q3);

        // Step 5: q6
        const Eigen::Matrix3d R03_ = R03(q1, q2, q3);
        const Eigen::Matrix3d R36 = R03_.transpose() * R;
        const double q6 = std::atan2(-R36(2,1), R36(2,0));

        JointArray q{q1, q2, q3, q4, q5, q6};
        q = wrapToPi(q);

        // FK 回代验证
        Pose T_check = fk_.forward(q);
        double pos_err = (T_check.translation() - p).norm();
        double rot_err = (T_check.rotation() - R).norm();

        if (pos_err < 1e-4 && rot_err < 1e-4)
          candidates.push_back(q);
      }
    }
  }

  return uniqueSolutions(candidates);
}

std::vector<JointArray> FairinoIK::uniqueSolutions(
    const std::vector<JointArray>& sols, double tol)
{
  std::vector<JointArray> unique;
  for (const auto& q : sols) {
    bool dup = false;
    for (const auto& u : unique) {
      double sq_dist = 0.0;
      for (int i = 0; i < DOF; ++i) {
        double dq = wrapToPi(q[i] - u[i]);
        sq_dist += dq * dq;
      }
      if (std::sqrt(sq_dist) < tol) { dup = true; break; }
    }
    if (!dup) unique.push_back(q);
  }
  return unique;
}

}  // namespace fairino_planning
```

说明：

```text
1. 腕前点分离法：WCP = p - d6 * a，将 6 关节分解为前 3 + 后 3。
2. q1：由 WCP 在 xy 平面的投影确定（肩左/肩右两解）。
3. q5/q234：由末端 z 轴方向反解（腕上/腕下两解）。
4. q2/q3：2R 平面三角形（肘上/肘下两解），共 2×2×2=8 组。
5. q6：由 R_3_6 提取 atan2 得到。
6. FK 回代验证：pos_err < 1e-4 && rot_err < 1e-4，过滤数值误差导致的无效解。
7. uniqueSolutions：去重，避免数值上近似相同的解。
8. R03 不是 FK。它是一个简化的解析公式，仅用 q1,q2,q3 计算 R_0_3。
9. 这里不做限位过滤——留给 ik_selector 做。
```

### 12.6 ik_selector.h + ik_selector.cpp（IK 解选择器）

从多组解中选最优：加权评分，先硬过滤再比成本。

最小可用版只做两项代价（关节运动量 + 限位居中度），不需要雅可比。

**头文件：**

```cpp
#pragma once

#include "fairino_planning_core/types.h"
#include <optional>

namespace fairino_planning
{

struct IKSelectParams
{
  std::array<double, DOF> move_weights{5.0, 2.5, 2.0, 1.5, 1.0, 1.0};
  double w_move  = 3.0;
  double w_limit = 2.0;
};

class IKSelector
{
public:
  IKSelector();
  explicit IKSelector(const IKSelectParams& params);

  std::optional<JointArray> select(
    const std::vector<JointArray>& solutions,
    const JointArray& q_current) const;

private:
  IKSelectParams params_;
  JointLimits limits_;

  double computeCost(const JointArray& q,
                     const JointArray& q_current) const;
};

}  // namespace fairino_planning
```

**实现文件：**

```cpp
#include "fairino_planning_core/ik/ik_selector.h"
#include <cmath>
#include <limits>

namespace fairino_planning
{

IKSelector::IKSelector() : params_(), limits_() {}
IKSelector::IKSelector(const IKSelectParams& p) : params_(p), limits_() {}

double IKSelector::computeCost(const JointArray& q,
                                const JointArray& q_current) const
{
  // 1. 关节运动代价
  double J_move = 0.0;
  for (int i = 0; i < DOF; ++i) {
    double dq = wrapToPi(q[i] - q_current[i]);
    J_move += params_.move_weights[i] * dq * dq;
  }

  // 2. 限位居中代价
  double J_limit = 0.0;
  for (int i = 0; i < DOF; ++i) {
    double mid  = 0.5 * (limits_.lower[i] + limits_.upper[i]);
    double half = 0.5 * (limits_.upper[i] - limits_.lower[i]);
    double eta  = (q[i] - mid) / half;
    J_limit += eta * eta;
  }

  return params_.w_move  * J_move +
         params_.w_limit * J_limit;
}

std::optional<JointArray> IKSelector::select(
    const std::vector<JointArray>& solutions,
    const JointArray& q_current) const
{
  double best_cost = std::numeric_limits<double>::infinity();
  std::optional<JointArray> best;

  for (const auto& q : solutions) {
    JointArray qw = wrapToPi(q);
    if (!limits_.isWithin(qw)) continue;

    double cost = computeCost(qw, q_current);
    if (cost < best_cost) {
      best_cost = cost;
      best = qw;
    }
  }
  return best;
}

}  // namespace fairino_planning
```

说明：

```text
1. 最小版只做 J_move + J_limit，不需要雅可比，compile 快。
2. 后续加 J_sing（奇异规避）需要在 DHKinematics 里补 jacobian()。
3. 后续加 J_wrist（腕部偏好）和 J_task（肘部高度）是调参工作。
4. move_weights：关节 1-3 权重大（大关节尽量少动），关节 4-6 权重小（腕部灵活）。
5. wrapToPi 在 types.h 中定义。
6. JointLimits::isWithin() 在 types.h 的 JointLimits 结构体中定义。
```

### 12.11 nanoflann 的学习任务

第一版你可以不用 nanoflann，直接线性扫描最近节点：

```text
nearest = argmin(distance(q, node.q))
```

第二版再替换为 KD-tree：

```text
O(n) linear scan
  ↓
O(log n) approximate nearest neighbor
```

主动任务：

```text

2. 随机生成 10000 个节点，统计查询耗时。
3. 再用 nanoflann 替换，并比较耗时。
```

一个检测框 vs 一帧检测结果的关系。

InferenceResult.msg — 单个检测框：

```text
string class_name      # 类别名，如 "bottle"
float32 confidence     # 置信度 0~1
float32 center_x       # 框中心 x（像素，或归一化）
float32 center_y       # 框中心 y
float32 width          # 框宽
float32 height         # 框高
float32 angle          # OBB 旋转角
```

Yolov8Inference.msg — 一帧画面里的一批检测框：

```text
std_msgs/Header header       # 时间戳 + frame_id（对应哪帧图像）
InferenceResult[] results     # 这一帧里的所有检测框
```

关系就是：一帧图像 → 模型推理 → 输出 N 个框 → 打包成 1 个 Yolov8Inference（含 N 个 InferenceResult），发到一个 topic 上。下游 yolov8_grasping 订阅这个 topic，从 results[] 里挑框算抓取位姿。

### yolov8_grasping

#### 两个包职责完全不同：

| |yolov8_obb |	yolov8_grasping|
|做什么 |	吃图像，吐检测框 |	吃检测框，吐抓取动作|
|输入 |	/camera/color/image_raw（图像） |	/yolov8/obb_detections（检测结果）|
|输出 |	YOLOv8 推理一组 OBB 框 |	机械臂运动指令（抓取位姿、轨迹）|
|核心能力 |	加载 .pt 模型、跑 model(image) 推理 |	从框算抓取点、角度筛选、IK、轨迹规划|


简单说：yolov8_obb 是眼睛（看），yolov8_grasping 是手（抓）。你现在的 yolov8_obb_node.py 发假检测框就是为了先打通"眼睛→手"这条链，验证 grasping 能正确接收检测结果并生成抓取动作。

图像 -> yolov8_obb -> obb 检测框 -> yolov8_grasping

##### 整体架构
yolov8_grasping 内部建议拆成三层（模块归模块，节点先一个），这样既不过度工程，又方便后期分裂成多个节点：
```scss
检测框 (像素+角度)
   │
   ▼  [1] TargetSelector       选哪个目标抓
   ▼  [2] PoseEstimator        像素 → 3D → 抓取位姿(base_link)
   ▼  [3] ArmExecutor          位姿 → 实际运动
   ▼
机械臂动作
```
每一层职责：
| 模块           | 输入                        | 输出                                       | 关键依赖                             |
| -------------- | --------------------------- | ------------------------------------------ | ------------------------------------ |
| TargetSelector | `Yolov8Inference.results[]` | 选中的一个 `InferenceResult`               | 无（纯逻辑：置信度/类别/距图像中心） |
| PoseEstimator  | 选中的框 + 深度图/相机内参  | `geometry_msgs/PoseStamped` (base_link 系) | depth image、camera_info、TF         |
| ArmExecutor    | 抓取位姿                    | 控制器指令                                 | MoveIt2 或自家轨迹接口               |

```bash

│   ├── target_selector.py      # 纯函数模块，无 ROS 依赖
│   ├── pose_estimator.py       # 像素→3D，吃 depth+intrinsics
```

用 tf2_ros 把 camera_color_optical_frame → base_link

就是将像素坐标转换为机械臂基座坐标系。
核心算式（针孔相机模型）：
$$
X = (u - c_x) \cdot Z / f_x , Y = (v - c_y) \cdot Z / f_y
$$
$Z$是深度图在 $(u, v)$ 处的值(通常单位 mm，要除 1000 转米), OBB 的 angle 加到末端绕 z 的旋转上，得到夹爪朝向。
其中的 $c_x, f_x, c_y, f_y$ 都是相机内参。
package.xml 这时候需要加 `cv_bridge`、`tf2_ros`、`tf2_geometry_msgs`。




**Phase 3 是整个 grasping 包里最核心、也最容易出 bug 的一步**：把"我在像素 (320, 240) 看到一个目标"翻译成"在机械臂基座坐标系下，物体真实位置是 (x, y, z) 米"。

###### 1. 拿相机内参（一次性）

订阅 `/camera/color/camera_info`，从里面读出 (f_x, f_y, c_x, c_y) 四个数存起来。这玩意是常量，收到第一帧之后就可以把订阅关掉。

```python
# K = [fx, 0, cx, 0, fy, cy, 0, 0, 1]
self.fx = msg.k[0]
self.fy = msg.k[4]
self.cx = msg.k[2]
self.cy = msg.k[5]
```

###### 2. 拿深度图（每帧）

订阅 `/camera/aligned_depth_to_color/image_raw`，注意一定是 **aligned_depth_to_color**，不是原始 depth。原始深度图和彩色图分辨率/视角对不上，YOLO 在彩色图上检测的像素坐标 ((u, v)) 直接拿去查原始深度图会查到错的位置。

用 `cv_bridge` 转成 numpy：

```python
from cv_bridge import CvBridge
self.bridge = CvBridge()
depth = self.bridge.imgmsg_to_cv2(msg, desired_encoding="passthrough")
# RealSense 默认是 16UC1，单位 mm
```

###### 3. 像素 → 相机系 3D 点（核心算式）

这是针孔相机的反投影：

$$
Z = \text{depth}(u, v) / 1000.0
$$

$$
X = (u - c_x) \cdot Z / f_x, \quad Y = (v - c_y) \cdot Z / f_y
$$

代码：

```python
u = int(round(target.center_x))
v = int(round(target.center_y))
z_mm = depth[v, u]            # 注意是 [行, 列] = [v, u]
if z_mm == 0:                 # 深度无效
    return
Z = z_mm / 1000.0
X = (u - self.cx) * Z / self.fx
Y = (v - self.cy) * Z / self.fy
# 此时 (X, Y, Z) 在 camera_color_optical_frame 下，单位米
```

**坑 1**：深度图常见单位是毫米（uint16），也有的是米（float32），看你相机驱动配置，单位错了差 1000 倍。
**坑 2**：单点深度容易踩到空洞（值=0），实际项目会取框内一个 5×5 小窗口的中位数，更鲁棒。

###### 4. 相机系 → base_link（TF 变换）

物体在相机系下的位置对机械臂没用，机械臂只认自己的基座系。用 `tf2_ros` 做坐标变换：

```python
from tf2_ros import Buffer, TransformListener
from tf2_geometry_msgs import do_transform_pose
from geometry_msgs.msg import PoseStamped

# __init__ 里
self.tf_buffer = Buffer()
self.tf_listener = TransformListener(self.tf_buffer, self)

# 用的时候

# 2. 相机系 → base_link（ROS 层）
# 2.1 设置变量
pose_cam = PoseStamped()
pose_cam.header.frame_id = "camera_color_optical_frame"
pose_cam.header.stamp = rclpy.time.Time().to_msg()
pose_cam.pose.position.x, pose_cam.pose.position.y, pose_cam.pose.position.z = xyz
pose_cam.pose.orientation.w = 1.0

try:
    # 通过调用TF变换 完成 相机系 → base_link
    pose_base = self.tf_buffer.transform(pose_cam, "base_link",timeout=Duration(seconds=0.2))
except Exception as e:
    self.get_logger().warn(f"TF transform failed: {e}")
    return
```

**前提**：TF 树里 `base_link → camera_color_optical_frame` 这条链必须连得通。一般来自：

* 机械臂的 URDF（`base_link → ... → camera_mount`）
* 手眼标定结果（`camera_mount → camera_link`，通常 `static_transform_publisher` 发布）
* 相机驱动自动发的（`camera_link → camera_color_optical_frame`）

###### 5. 加上 OBB 的旋转角

YOLO 给的 `angle` 是物体在**图像平面**里的旋转，需要把它变成夹爪绕 base_link 某个轴（一般是 z）的旋转。简化处理（俯视抓取）：

```python
import math
from tf_transformations import quaternion_from_euler

yaw = target.angle            # 注意单位 rad / deg
q = quaternion_from_euler(math.pi, 0, yaw)  # roll=π 让夹爪朝下
pose_base.orientation.x = q[0]
# ...
```

精确做法要把图像角度通过相机姿态投影到 base 系，但俯视场景下用上面这个近似就够。

抓取策略：俯视抓 vs 任意姿态抓
99% 的桌面抓取场景是俯视抓（夹爪从上往下扎），这种情况下 OBB 的 angle 直接对应夹爪绕 base_link 的 z 轴的偏航角，简单：
$$
roll = \pi ,pitch = 0, yaw = angle
$$
roll = π 是为了让夹爪 z 轴朝下（"扎下去"的姿态）。
如果是任意姿态抓（比如机械臂从侧面接近），就得做相机姿态投影，复杂度立刻翻倍。先按俯视抓做


package.xml 添加<exec_depend>tf_transformations</exec_depend>

### 14.3 hand_eye_calibration

#### 这个包是做什么的？
它是三个角色的中转站：


相机看到标记 → hand_eye_calibration → 算出相机在机械臂上的位姿
没有标定的问题： YOLOv8 检测到的物体坐标在相机坐标系下，但机械臂在基座坐标系下运动。没有手眼标定，你不知道"相机看到的东西在机械臂的什么位置"。

做了什么：

步骤	哪个组件	干什么
1	ros2_aruco（外部包）	检测画面里的 ArUco 标记，算出标记在相机坐标系下的位姿
2	hand_eye_calibration 的 launch	机械臂移动到 N 个姿态，每个姿态记录一对数据：末端位姿 + 标记位姿
3	easy_handeye2（外部包）	用 N 对位姿求解 camera→tool0 或 camera→base_link 的变换矩阵
4	发布 TF	之后 YOLOv8 检测到的物体位置就能通过 TF 转到 base_link，机械臂才知道抓哪
和你的开发顺序关系： 标定依赖实机或至少仿真中的整个链路（相机+机械臂+标记+多个姿态），是阶段五最后一个环节。先搞 yolov8_grasping（能算抓取位姿），标定后面再做。


#### 流程：

```text
1. 启动相机
2. 启动 ros2_aruco
3. 采集多个机械臂姿态下的 marker pose
4. 调用 easy_handeye2 求解
5. 发布 camera_link 到 tool0 或 base_link 的 TF
```

常用命令：

```bash
ros2 launch hand_eye_calibration calibrate.launch.py
ros2 launch hand_eye_calibration validate.launch.py
```

### 15.3 2D PD 控制器：学习版

文件：

```text
visual_servo/visual_servo/controllers/pd_controller.py
```

```python
class PDController:
    def __init__(self, kp=0.002, kd=0.0005, max_output=0.05):
        self.kp = kp
        self.kd = kd
        self.max_output = max_output
        self.last_error = None

    def compute(self, error):
        if self.last_error is None:
            derivative = [0.0 for _ in error]
        else:
            derivative = [e - last for e, last in zip(error, self.last_error)]

        self.last_error = list(error)

        output = [
            self.kp * e + self.kd * d
            for e, d in zip(error, derivative)
        ]

        return [
            max(-self.max_output, min(self.max_output, value))
            for value in output
        ]
```

说明：

```text
这是学习版 2D 像素空间控制，只处理 image_x / image_y 误差。
原项目真机版更接近 3D/6D 笛卡尔伺服，通常发布 geometry_msgs/TwistStamped 给 MoveIt Servo。
```

升级方向：

```text
2D pixel error
  ↓
pixel + depth
  ↓
camera frame 3D error
  ↓
base_link Cartesian error
  ↓
TwistStamped velocity servo
  ↓
MoveIt Servo
```

### 15.5 状态机骨架

文件：

```text
visual_servo/visual_servo/servo_yolo_grasping_node.py
```

```python
#!/usr/bin/env python3

from enum import Enum, auto

import rclpy
from rclpy.node import Node


class ServoState(Enum):
    IDLE = auto()
    INIT = auto()
    SEARCHING = auto()
    TARGET_FOUND = auto()
    POSE_ESTIMATING = auto()
    PRE_GRASP_PLANNING = auto()
    MOVING_TO_PRE_GRASP = auto()
    VISUAL_SERVOING = auto()
    DESCENDING = auto()
    GRASPING = auto()
    LIFTING = auto()
    PLACING = auto()
    COMPLETED = auto()
    ERROR = auto()


class ServoYoloGraspingNode(Node):
    def __init__(self):
        super().__init__("servo_yolo_grasping_node")
        self.state = ServoState.IDLE
        self.timer = self.create_timer(0.05, self.loop)
        self.get_logger().info("visual servo state machine started")

    def set_state(self, new_state):
        if new_state != self.state:
            self.get_logger().info(f"{self.state.name} -> {new_state.name}")
            self.state = new_state

    def loop(self):
        # 注意：
        # 这里的无条件跳转是 intentional skeleton。
        # 目的是先把 13 状态流程跑通，
        # 后续再逐个补充检测条件、规划结果、执行反馈、超时和错误处理。

        if self.state == ServoState.IDLE:
            self.set_state(ServoState.INIT)

        elif self.state == ServoState.INIT:
            self.set_state(ServoState.SEARCHING)

        elif self.state == ServoState.SEARCHING:
            # TODO: if detection_cache has target
            self.set_state(ServoState.TARGET_FOUND)

        elif self.state == ServoState.TARGET_FOUND:
            self.set_state(ServoState.POSE_ESTIMATING)

        elif self.state == ServoState.POSE_ESTIMATING:
            self.set_state(ServoState.PRE_GRASP_PLANNING)

        elif self.state == ServoState.PRE_GRASP_PLANNING:
            self.set_state(ServoState.MOVING_TO_PRE_GRASP)

        elif self.state == ServoState.MOVING_TO_PRE_GRASP:
            self.set_state(ServoState.VISUAL_SERVOING)

        elif self.state == ServoState.VISUAL_SERVOING:
            self.set_state(ServoState.DESCENDING)

        elif self.state == ServoState.DESCENDING:
            self.set_state(ServoState.GRASPING)

        elif self.state == ServoState.GRASPING:
            self.set_state(ServoState.LIFTING)

        elif self.state == ServoState.LIFTING:
            self.set_state(ServoState.PLACING)

        elif self.state == ServoState.PLACING:
            self.set_state(ServoState.COMPLETED)

        elif self.state == ServoState.COMPLETED:
            pass

        elif self.state == ServoState.ERROR:
            pass


def main():
    rclpy.init()
    node = ServoYoloGraspingNode()
    rclpy.spin(node)
    node.destroy_node()
    rclpy.shutdown()


if __name__ == "__main__":
    main()
```

主动任务：

```text
每次只补一个状态的真实条件。
不要一次性把 13 个状态全部写满。
推荐顺序：
SEARCHING → TARGET_FOUND
POSE_ESTIMATING
PRE_GRASP_PLANNING
MOVING_TO_PRE_GRASP
VISUAL_SERVOING
GRASPING
ERROR
```

## 16. 最重要的工程原则

### 25.1 不要按包学习，要按能力链路学习

错误方式：

```text
今天看 fairino_hardware
明天看 yolov8
后天看 GraphExecuter
```

正确方式：

```text
模型显示
  ↓
控制器启动
  ↓
轨迹执行
  ↓
规划成功
  ↓
视觉识别
  ↓
坐标转换
  ↓
伺服收敛
  ↓
抓取成功
```

### 25.2 每次只验证一件事

例如视觉伺服不要一开始就真机抓取。

正确顺序：

```text
假检测
  ↓
状态机收到目标
  ↓
计算像素误差
  ↓
发布 TwistStamped
  ↓
仿真移动
  ↓
真实相机
  ↓
真实机械臂低速
```

### 25.3 真机前必须有仿真验收

真机前至少确认：

```text
1. joint limit 正确
2. collision mesh 合理
3. planning scene 正确
4. 控制器方向正确
5. 夹爪开合方向正确
6. 急停可用
7. 速度比例足够低
```

```text
fairino_description
  ↓
s622_moveit_descriptions
  ↓
fairino_msgs
  ↓
fairino_hardware fake mode
  ↓
s622_moveit_config
  ↓

  ↓

  ↓

  ↓

  ↓
visual_servo 2D PD
  ↓
```

不要一开始就做：

## 19. 一句话总结

这个项目的正确搭建方式不是“复制 26 个包”，而是按能力链路逐步复现：

```text
模型 → 消息 → 硬件接口 → 控制器 → MoveIt2 → 仿真 → 自研规划 → 插件 → 感知 → 标定 → 视觉伺服 → 抓取 → 工具化
```

每一层都要做到：

```text
能编译
能启动
能观察
能验证
能解释
能替换
```

这才是主动式学习。
